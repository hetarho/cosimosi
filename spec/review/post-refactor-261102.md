# REVIEW post-refactor-261102
> st:converted@261103 | scope:all | at:1331f004 | base:ARCH@2

## summary
- 38 proposals: 1 P1, 21 P2, 16 P3. The highest risk is backend pool exhaustion: transactions borrow a second pooled connection while the pool defaults to four, so a handful of concurrent paid or launch requests can stall the whole API. Next are a picking defect that can leave stars untappable for a session and hard deletes that scan every user's rows.
- Import direction is clean on both stacks (no upward, same-layer or cross-context edges). The structural debt is ownership, not direction: T166–T180 added new mechanisms beside old ones (transaction ports, memory facade, queue runner, package surfaces) without removing the old, platform-pure controllers remain copied inside web/mobile UI forks, and the FSD layer grain (feature vs entity vs widget) is applied by three different criteria.
- No rewrite is justified. The plan in notes deletes parallel paths first, then moves shared behavior to one owner with tests, then fixes hot paths; several FE items need an ARCH criterion decided before code moves.
