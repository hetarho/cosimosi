## goal

## acceptance

- [v] The `facing` prop doc in `SkySphere.tsx` says what holds for every caller, as the `VIEW_DIRECTION` comment now does: the faced slice centres on −Z, which is frame centre for a camera looking down −Z (ARCH-39). No code change.

## result

- outcome: The slot projection test bounds each body exactly against the frustum's side planes through `insideSidePlanes`: `|offset| + r / cos(θ) ≤ depth · tan(θ)`, with θ the horizontal half-angle `atan(tan(fov/2) · 0.95)` for x and fov/2 for y. A new case shows a body that clears the centre-depth extent by 0.01 is rejected. The SkySphere "no work" test now counts reads of the spin and of the step inputs (`lambda`, `instant`). With the early return removed it fails with `{ spin: 0, step: 2 }` (checked, then restored); the other SkySphere tests stay green. The `facing` prop doc now says the slice turns onto −Z, which is the frame centre for a canvas camera looking down −Z (see `VIEW_DIRECTION`). The doc is the only change in `SkySphere.tsx`. The scene test still takes the real skin's field of view through `importOriginal`: `UNIVERSE_SKINS` is reachable only from the renderer's single root export, and a narrower read would need a new subpath entry (ARCH-27, out of scope). Measurement showed the renderer was not the main cost. The file's slowdown came from building the slot fixtures through the walkthrough content and model modules, which pull the i18n catalogue and the `@cosimosi/universe` root. The slot tests now build one plain `EpisodicMemory` per slot from `@cosimosi/emotion`, which the scene already loads.
