### 11. Change: one transforming gist star per memory

> A **change proposal** (a WHAT delta) that modifies the already-shipped behavior of [plan/42.gist-star-rendering](../../plan/42.gist-star-rendering.md).
> Filled by /cosimosi:create-change through a user interview — a reviewable doc, not a one-line prompt.

#### As-is

**A memory's gist is rendered as one body per risen stage, so the bodies accumulate.** A memory at
`semantic_stage = 4` shows **four** gist stars at once. This is not an implementation slip — the PRD states it:

- [PRD §5.4 [C7]](../../PRD.md) — "요지화가 진행되면 단계별로 _요지 별이 쌓인다_(이전 단계 별은 유지, [V5])".
- [PRD §5.4 [C6a]](../../PRD.md) — "이미 만들어진 요지 별·단계는 유지([C7], z축 단방향: 되돌리지 않음)", phrased over a
  plural set of bodies.
- [tech/rendering.md](../../tech/rendering.md) §"Gist-star / z-layer rendering" — "**One instance per risen stage.**
  `gist-star-channels.ts` emits N instances for `semanticStage = N` (risen stages persist [C7])".
- `packages/universe/src/gist-star-channels.ts` — `for (let stage = 1; stage <= risen; stage++)` pushes one instance
  per stage, and `size` is computed **once outside** that loop, so every body of one memory is the same size.

The accumulation is also load-bearing below the renderer: **each stage is its own paid read target.**

- `gistNodeId(memoryId, stage)` mints the selection id `gist:<stage>:<memoryId>`, and the star-detail resolver parses
  the pair back out, so a stage is part of a body's identity.
- `ViewSemantic(scope, operationID, memoryID, stage)` (`apps/api/internal/memory/view_semantic.go`) takes the stage as
  a **client-supplied argument**, validates it against the risen stage, and prices the read from it
  ([plan 34](../../plan/34.view-semantic-usecase.md) — "derive the gist-depth signal from the requested `stage`
  (deeper = cheaper, [R8][G4])"). Every already-risen stage therefore stays separately purchasable forever.

Two consequences we can see today:

1. **The bodies are visually one object.** All stages of a memory share the episodic `(x, y)` verbatim ([C6][I5]) and
   `GistCoordinate` spaces stages only `(45 − 27) / 4 = 4.5` world units apart, while a strong memory's gist body is
   up to `1.8` radius (`rendering.gist_star_size_max`) — a `3.6` diameter with `0.9` of gap. With additive glow and the
   bloom pass, three or four bodies merge into a single vertical capsule. Verified on the dev seed: a stage-4 memory
   reads as one smear, not four stars.
2. **The abstraction ladder is unreadable.** The only per-stage channel is `softness`
   (`rendering.gist_star_diffuse` → fully diffuse), which _increases blur_ — so the deeper stages make the capsule
   less legible rather than distinguishing themselves. A user cannot tell how many bodies are there, which stage each
   one is, or that they carry different prices.

**The model is also not what the cited science says.** [PRD §9](../../PRD.md) grounds [C5]–[C7] in Complementary Learning
Systems (McClelland 1995) and trace transformation (Winocur & Moscovitch 2011). Neither predicts accumulating gist
artifacts:

- **CLS** — "neocortical synapses change a little on each reinstatement, and remote memory is based on accumulated
  neocortical changes" ([McClelland, McNaughton & O'Reilly 1995](https://pubmed.ncbi.nlm.nih.gov/7624455/)). What
  accumulates is _synaptic change inside one structured representation_; slow interleaved learning exists precisely to
  refine that one representation without disrupting it. There is no mechanism that keeps a coarser earlier copy beside
  a later one.
- **Trace Transformation Theory** — episodic memories "**transform into** semantic or gist-like versions"
  ([Winocur & Moscovitch 2011](https://pubmed.ncbi.nlm.nih.gov/21729403/)); one representation changing form, with the
  detailed hippocampal version persisting in parallel.
- **Semanticization is graded, not staged** — "detailed, perceptually rich memories are transformed to ones retaining
  only the gist" ([Sekeres et al. 2018](https://pubmed.ncbi.nlm.nih.gov/29733974/)); the perceptual–conceptual gap
  "significantly increases across the delay" ([Nature Communications 2021](https://www.nature.com/articles/s41467-021-23288-5));
  Competitive Trace Theory states outright that "a continuum model may be better suited"
  ([Yassa & Reagh 2013](https://pmc.ncbi.nlm.nih.gov/articles/PMC3740479/)).
- **An earlier gist does not persist as a separately retrievable object.** Competitive Trace Theory: veridical episodic
  details "are only available in very recent memories. As memories get older, these details are **replaced**." What
  persists beside the gist is the _detailed episodic_ version — which in this product is already the hippocampal star,
  recoverable by 회고 ([F5]) — not a shallower gist.

**The strongest counter-argument, and why it does not license the as-is.** Updated TTT does posit multiple coexisting
representations of one memory at different abstraction levels (posterior hippocampus = detail, anterior hippocampus =
gist, mPFC = schema; [Sekeres, Winocur & Moscovitch 2018](https://pubmed.ncbi.nlm.nih.gov/29733974/)), and
Moscovitch & Gilboa hold that they "can coexist and interact"
([2022](https://pmc.ncbi.nlm.nih.gov/articles/PMC9720899/)). But that set is **fixed and small (≈3 levels), present
from inception** — "From inception, there are potentially multiple interactive forms of event representations" — and the
levels are **different kinds** (perceptual detail vs gist vs cross-episode schema), so none of them is "the older
gist". Read strictly it argues the opposite of the as-is: a bounded set that does not grow with elapsed time. Multiple
Trace Theory's plural traces are likewise **hippocampal episodic re-encodings**, with the gist side a single
neocortical establishment ([Nadel et al. 2000](https://pubmed.ncbi.nlm.nih.gov/10985275/)) — the mirror image of the
as-is, not support for it.

#### To-be

**A memory has exactly one gist star, and semanticization transforms it.** Where the as-is emits a body per risen
stage, the to-be emits **at most one gist body per episodic memory** — present once `semantic_stage ≥ 1` — whose
position and appearance are a function of the memory's **current** stage. A stage rise does not add a star; it
**changes the star that is already there**.

1. **One body, `semantic_stage ≥ 1`.** A memory at stage 0 has no gist body (unchanged). A memory at stage 1, 2, 3, or
   4 has exactly one. The count of gist bodies in a universe equals the count of memories with a risen stage.
2. **z keeps rising with the stage.** The single body sits at `GistCoordinate(x, y, semantic_stage)` — the existing
   stage→z map inside `force_sim.neocortex_z_*`, unchanged as a formula. A rise therefore **moves** the body upward
   through the neocortex band, which is what [C6] "x,y는 복사, z만 상승" describes. Deeper abstraction reads as height.
3. **Appearance is driven by the current stage alone.** The stage→`softness` channel stays (stage 1 at
   `rendering.gist_star_diffuse`, the ladder top fully diffuse). Because there is now one body rather than a stack,
   the deepening diffuseness reads as _that memory's gist becoming more abstract_ instead of blurring a capsule.
4. **The gist text is the current stage's text.** There is **no concept of a past stage's gist text as a separate
   readable artifact.** Opening the gist star reads the text of the stage the memory has reached — one read, one price.
5. **The stage stops being client input.** `ViewSemantic` derives the stage from the memory's stored `semantic_stage`
   server-side; the request carries the memory (and its operation id), not a stage. A client can no longer name which
   depth it wants, which also removes the "pick a shallower stage" surface from the paid read.
6. **The selection id identifies a memory, not a pair.** A gist body's id is a function of the memory alone; stage is
   no longer part of a body's identity.
7. **Pricing intent is unchanged** ([R8][G4]) — a gist read is still cheaper the deeper the gist. The depth signal is
   now the memory's current stage rather than a requested one, so `twinkle.gist_base_cost` /
   `twinkle.gist_stage_discount` / `twinkle.gist_min_cost` keep their meaning and their values.
8. **변천사 keeps its per-stage rows** ([R8a]). `memory_provenance` still appends one `semanticized` row per crossed
   stage with that stage's text. That is the **log of one body transforming**, which is exactly what 변천사 means — not
   a second readable artifact, and it stays free. The four pregenerated `semantic_stages` texts stay too: they are the
   **quantization of a continuous abstraction into four sampled rungs** (defensible as sampling — see As-is — never as
   four objects that exist).

#### Scope / Non-goals (regression boundary)

**In scope**

- **PRD** — [C7]'s "단계별로 요지 별이 쌓인다(이전 단계 별은 유지)" and [C6a]'s "이미 만들어진 요지 별·단계는 유지"
  are restated as one transforming body. [C7]'s **other** rule is untouched: on reconsolidation, already-published
  rungs stay and only the **remaining** stage texts regenerate.
- **plan 42** — the "one gist star per risen stage" contract, and the reserved consolidation-replay slot's description
  of a rise (a body **moving up**, not a body **appearing**).
- **plan 34** — `ViewSemantic`'s stage becomes server-derived; the request shape and the depth-signal derivation change.
- **tech/rendering.md** §"Gist-star / z-layer rendering" — the "One instance per risen stage" as-built rule.
- **Code** — `packages/universe/src/gist-star-channels.ts` (instance emission + node id), the star-detail resolver
  seam (`packages/universe/src/star-detail.machine.ts`), `packages/universe-render/src/GistStarLayer.tsx`, both apps'
  `widgets/universe-canvas` + `widgets/star-detail`, `apps/api/internal/memory/view_semantic.go` and its RPC/proto
  request, and the demo mirror (plans 77/79) so the demo shows the same single body.

**Non-goals (must NOT change)**

- **The semanticization domain.** The gist timer, `semantic.gist_units_per_stage`, `Semanticize`, `GistUnitsElapsed`,
  `ConsumeGistUnits`, the four pregenerated `semantic_stages` texts, and the stage's monotonic one-way rise ([C6a][C7])
  are untouched. This change is about how a stage is **presented and read**, never about how it advances.
- **`GistCoordinate`.** The stage→z map and the neocortex band values stay exactly as they are; only the number of
  bodies that consume the map changes.
- **The episodic star.** The hippocampal body keeps its own position, seed/shape, size, brightness and decay, and
  stays clickable for 회고 ([R1][V5]). It is the detail version that legitimately coexists with the gist.
- **[I5]** — no gist coordinate is stored or reverse-projected; x, y still come from the live hippocampal sim and z is
  still derived per frame.
- **[I1]** — nothing stored is deleted by this change. The bodies that stop rendering were never data; the
  `semantic_stages` ladder and every `memory_provenance` row are retained.
- **[I11] / [M3] / [I3]** — a gist keeps the memory's emotion through the single palette seam; abstraction never
  touches tint, and shape stays the episodic seed's alone ([V5]).
- **Twinkle values and the pricing direction** ([R8][G4]) — deeper is still cheaper; no value moves.
- **Forgetting** — the decay axis and its independence from semanticization ([F1][C6a]) are untouched.

#### Acceptance Criteria

1. A memory with `semantic_stage = N` (1 ≤ N ≤ 4) renders **exactly one** gist body; a memory at stage 0 renders none.
   The universe's gist-body count equals the number of memories with a risen stage, for every N.
2. The single body's z equals `GistCoordinate(x, y, semantic_stage)`, so a stage rise moves it **upward** within
   `force_sim.neocortex_z_*`; its x, y still equal the episodic star's live hippocampal x, y.
3. The body's `softness` is derived from the **current** stage, and no per-stage duplicate instance exists at any
   stage — asserted by a test over stages 1–4 (the as-is emitted 1, 2, 3, 4 instances respectively).
4. Selecting the gist body opens the ViewSemantic read for the memory's **current** stage; the client sends no stage
   and cannot influence which depth is read or priced.
5. `ViewSemantic` refuses a memory whose `semantic_stage` is 0 with the existing canonical unrisen refusal, and never
   fabricates text for an unreached stage (unchanged behavior, re-asserted against the new request shape).
6. A gist read's price still falls as the memory's stage deepens, using the unchanged `twinkle.gist_*` values.
7. 변천사 still lists one `semanticized` entry per crossed stage with that stage's text, and remains free.
8. Reconsolidation still keeps already-published rungs and regenerates only the remaining stage texts ([C7]).
9. The episodic star of the same memory is unchanged in position, shape, size, brightness, decay and its 회고 path.
10. The demo mirror (plans 77/79) shows the same single transforming body, so the demo and the real universe cannot
    disagree about how many gist stars a memory has.
11. Web and mobile render the change identically from the one shared projection (ARCHITECTURE §3.5).

### Decisions & outcomes

- **The quote had to move too.** A4 says the client cannot influence which depth is read **or priced**, and the price
  is computed by `QuoteSpend`, not by `ViewSemantic`. So `QuoteSpendRequest.semantic_stage` is reserved alongside the
  read's field, and the gist arm prices the memory's own rung. Both readers now call one function —
  `viewableGistStage(gist)` in `internal/memory` — instead of two copies of the same clamp, so a quote and the charge
  behind it cannot name different rungs even in principle.
- **The idempotency fingerprint dropped the stage** (T007's trap, and the one that would have cost a user real
  Twinkle). With the depth server-derived, a memory can rise between a lost response and its retry; folding the derived
  stage into `viewSemanticFingerprint` would have turned that legitimate replay into `ErrOperationConflict`. It now
  keys on the memory alone, pinned by a test that rises the memory between the two calls.
- **The rise choreography had to change its diff key.** A gist body's node id is now `gist:<memoryId>` — stable for
  the memory's whole life — so `reconcileGistRiseState` could no longer detect a rise by "an id I have not seen".
  `GistRiseState.stageSeen` tracks the stage per body, and a rise is a stage that increased; the one body then eases
  from where it is up to the new band instead of teleporting. Without this the change would have been silently
  motionless, which no type or lint would have caught.
- **`SemanticStages` is `[4]string`, not a slice**, so "clamp to the derived ladder length" is really "clamp to 4" —
  the guard only ever fires on a corrupt `semantic_stage`. The test says that rather than pretending a shorter ladder
  is reachable.
- **No values, no migration** (T021 confirmed): `rendering.gist_star_*`, `force_sim.neocortex_z_*` and `twinkle.gist_*`
  keep their values and meanings; `semantic_stages` / `semantic_stage` / `memory_provenance` are read-only here and
  every stored rung is retained [I1].
- **Demo mirror:** no fixture change was needed. The demo composes the same `GistStarLayer` over the same projection,
  so it shows the single transforming body by construction — and `packages/demo/src/integrity.test.ts`'s field-set
  assertion still holds because the DTO shape did not move (A10).
