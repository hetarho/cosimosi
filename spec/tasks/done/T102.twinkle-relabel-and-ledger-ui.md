### 67. twinkle relabel and ledger ui

> Twinkle relabel and ledger UI — the visible half of the currency promotion. Every balance surface is relabeled to
> **작은 별가루 / 별가루** by **renaming the i18n keys** (so a stale call site is a compile error, not a silently wrong
> string), the **payment charge path is removed from the UI** (deferred to v3), and the append-only ledger becomes
> readable as a **chronological history in `/me`'s stardust tab** ([G7][U9]). It edits the shipped stardust vertical
> rather than adding a parallel one; the ledger read, the reason set, and the `/me` page shell belong to siblings.
> Scope: FE | Status: built (job 102)
>
> Layer P. Home: the shipped `widgets/stardust` + `features/{twinkle-balance-hud,earn-twinkle}` verticals plus a NEW
> `features/twinkle-ledger` slice, with the pure substance in `packages/twinkle`; web + mobile. It fills the last seam
> of Epic L's presentation and leaves the server ledger read to [66.earn-and-purchase-spend](66.earn-and-purchase-spend.md)
> and the `/me` shell to [64.my-page](64.my-page.md).

#### Purpose

Epic L redefines Twinkle by **purpose** rather than provenance: `SMALL` (작은 별가루) is the daily-refilled tier that may
pay only for the recall family, `GENERAL` (별가루) is the permanent, universal tier ([G2][G2a]). The domain,
the contract and the pure mirrors are renamed by [65.twinkle-kind-redefinition](65.twinkle-kind-redefinition.md). But
the words the diarist actually reads still say **기본 별가루 / 추가 별가루** — "the default one" and "the extra one" —
which is exactly the provenance semantics v2 discards. Until the labels move, the product teaches the old model.

The second gap is honesty. The shipped charge sheet ([45.stardust-ui](45.stardust-ui.md)) offers a **buy** button that
cannot succeed: `startStorePurchase` always throws `PaymentUnavailableError` and the server binds
`UnavailablePaymentVerifier{}`. Payment is deferred to v3 (PRD §8.3), and v2 funds itself from the daily refill, diary
writing, achievements, invites and the signup bonus ([G3]). Shipping v2 with a dead purchase affordance — and an invite
**code** field, when [U8]'s invite is link-bound with no code to type — is shipping a lie. Both come out, and the
insufficient-balance recovery re-points from "채우기" (top up) to "모으기" (gather): the earn paths, and the `/me`
achievements tab where they are claimed.

The third gap is [G7]. Every purchase, claim, earn and spend already lands in one append-only ledger, and [G7] promises
it is **readable chronologically in the my-page stardust tab** ([U9]). Today no surface reads it at all — the diarist
sees a balance that moves with no account of why. This unit builds that history: newest-first, keyed by reason, with the
tier split shown on every spend so the two-kind model is taught by the record itself rather than by explanation.

What it deliberately does not do is invent a fourth surface. `widgets/stardust` already composes the balance HUD over
the running canvas; `/me` already exists as a page to be renamed. This unit **edits the shipped vertical** and adds one
feature slice.

##### The relabel is a key rename, not a value edit

Renaming the key makes every stale call site a **compile error** — `packages/i18n` generates one module per key and
`m.twinkle_balance_basic_label` simply stops existing — whereas editing the value would leave a silently wrong string
behind on whichever of the two apps was missed. Both catalogues (`packages/i18n/messages/{ko,en}.json`, every key in
both), then `pnpm gen:messages`, with `pnpm check:gen` gating freshness and `pnpm lint:raw-strings` gating any literal
that slips into JSX or an `aria-*`/`accessibilityLabel` prop.

| Key                                                                          | ko               | en                   | Note                                                     |
| ---------------------------------------------------------------------------- | ---------------- | -------------------- | -------------------------------------------------------- |
| `twinkle_balance_title` (kept)                                               | `별가루`         | `Stardust`           | the section's accessible name — the currency, not a tier |
| `twinkle_balance_small_label` (← `_basic_label`)                             | `작은 별가루`    | `Small stardust`     | the recall-only, daily-refilled tier                     |
| `twinkle_balance_general_label` (← `_additional_label`)                      | `별가루`         | `Stardust`           | the universal, permanent tier                            |
| `twinkle_earn_title` (← `twinkle_charge_title`)                              | `별가루 모으기`  | `Gathering stardust` | "채우기" implied a purchase                              |
| `twinkle_cost_earn` (← `twinkle_cost_charge`)                                | `모으는 법 보기` | `How to gather`      | the shortfall affordance                                 |
| `twinkle_earn_invite_{title,body,bonus_label}` (← `twinkle_charge_invite_*`) | unchanged values | unchanged values     | role moved from redeem to explain                        |

The general tier being the **unmarked** name is the point, not an oversight: [G2a] makes 별가루 the one currency and
작은 별가루 a purpose-restricted sub-kind, so the modifier belongs on the restricted one. `twinkle_balance_title`
sharing the string is harmless — it is a section label, never rendered beside the tier label.

**Deleted:** `twinkle_charge_pay_{title,body,action}`, `twinkle_charge_invite_code_{label,placeholder}`,
`twinkle_charge_error` (the guide performs no mutation, so it has no failure to report).
**Added:** `twinkle_earn_body`, `twinkle_earn_{daily,write,achievement,invite}_{title,body}`,
`twinkle_earn_achievement_action`, and the `me_stardust_*` set below. The one-time signup bonus ([U11]) is **not** listed
in the guide — it is not a repeatable path and naming it would read as an offer.

##### Two tiers, one currency — what each surface shows

The **HUD** keeps its shipped shape: the derived total as the headline, then `작은 별가루 N · 별가루 N` in spend order.
The total is honest there because the HUD sits over the canvas where the paying actions are recalls, and a recall draws
`SMALL`→`GENERAL` — the total is exactly what a recall can reach ([G2][G5]).

The **stardust tab** shows the two tiers and **no summed figure**. A purchase prices against `GENERAL` alone ([P9]), so
a total there would overstate what the diarist can spend. This is the presentation-layer guard for [P9]: the misleading
number is absent, not annotated.

##### The earn guide ([G3]) and the shortfall path

**As-built amendment (after this unit shipped).** On **web**, the guide is no longer a surface of its own: the balance
HUD itself became the press, and what it opens is the **별가루 panel** — held figures, the way to get more, then the earn
paths — composed at the widget layer as `widgets/stardust/ui/TwinkleDetailSheet.tsx`. `EarnGuideSheet.tsx` therefore
became `EarnGuideSections.tsx`: the same four paths and the same single affordance, minus the `Dialog` and minus any
open state, with its headings dropped to `h4` beneath the panel's group heading. `features/charge-twinkle` **returns as
a slice** — deliberately, carrying a disabled control and its reason rather than a purchase — and is re-added to
`apps/web/steiger.config.js`'s stardust block. Three keys arrive with it: `twinkle_charge_action` (별가루 더 얻기),
`twinkle_charge_unavailable` (아직 준비 중이에요.) and `twinkle_detail_held_label` (지금 가진 별가루). The NoticeIcon
affordance beside the figures is **gone**: it put a second, smaller thing in the corner to aim at while the numbers were
already what the reader was looking at. Mobile still ships the dialog form described below.
[policy/ux/stardust](../policy/ux/stardust.md) owns the current rule.

`features/earn-twinkle/ui/EarnGuideSheet.tsx` replaces `ChargeSheet.tsx`. It lists the four repeatable earn paths in
plain, unpressured copy — the daily 작은 별가루 refill, 일기 작성, 업적, 친구 초대 — with the figures read from generated
config (`twinkle.small_daily_amount`, `twinkle.earn_write`, `twinkle.earn_invite_inviter`/`_invitee`; the FE holds no
economy constant). Its single affordance opens `/me`'s **achievements** tab, because that is where earning is actually
claimed ([A4][A5]).

Navigation stays out of the widget: `pages/universe/ui/UniverseHomePage.tsx` already receives its route callbacks as
props from `apps/web/src/app/routes/route-screens.tsx` (`onOpenReader`, `onOpenSettings`) and threads them down — the
one seam the router is allowed through. The recovery re-target points at the achievements tab specifically, so that
route has to be expressible.

**As built, the seam widened as a second INTENT rather than a tab argument.** [64](64.my-page.md) shipped the `onOpenMe`
rename without a parameter, so this unit had to widen it — and `onOpenMe(tab)` turned out to be the wrong shape: a page
cannot name a tab without importing another page's tab type, which is a `pages`→`pages` cross-import FSD forbids. So the
app layer — which owns the router and therefore the tab ids — passes a distinct `onOpenAchievements`, and every layer
below states an intent it can express without knowing a route: `UniverseHomePage`/`UniversePage` thread it down, and
`widgets/stardust` takes `onOpenAchievements: () => void`. On mobile the `Me` route gained a `tab` param and `MePage` an
`initialTab` prop.

The shortfall route is unchanged in shape and renamed in substance: `packages/errors`'s `ErrorRecovery` becomes
`'sync-consent' | 'earn' | 'none'`, `classifyErrorRecovery` keeps mapping `MEMORY_INSUFFICIENT_TWINKLE` and
`TWINKLE_INSUFFICIENT` (now to `'earn'`), and the six call sites — `RecallFlowSheet`, `GistViewSheet`,
`DiaryReaderBlock` on both apps — request the guide through `useEarnRequestStore` instead of `useChargeRequestStore`.
`resetTwinkleUserState()` keeps clearing it, so `@cosimosi/auth/user-state`'s shared registry inventory is untouched.

##### Control-state: the stardust machine is retired (§3.2)

The payment retirement removes the `PAY` event and `paying` state; [66](66.earn-and-purchase-spend.md) removes
`ClaimInvite` from the wire, which kills `inviting`
with it. What remains is `idle ↔ charging` — an open/closed boolean, and the earn guide issues no request, so there is
no in-flight phase to be exclusive about. §3.2 puts _exclusive modes_ in XState; a two-state shell is data. So
`packages/universe/src/stardust.machine.ts` and its test are deleted, `@cosimosi/universe`'s export goes with them, and
`StardustOverlay` holds the sheet's open flag as local state while `useEarnRequestStore` stays the cross-widget seam.

##### The ledger read — the contract this unit consumes

[66](66.earn-and-purchase-spend.md) owns `rpc GetLedger(GetLedgerRequest) returns (GetLedgerResponse)` with
`idempotency_level = NO_SIDE_EFFECTS`, its single `twinkleRpcCachePolicies` entry in
`packages/client-cache/src/http-policy.ts` (the production transport hard-fails before I/O on a missing or
duplicate classification, so no runtime check is needed), and the keyset-cursor page shape copied from
`GetDiaries` (`page_token`/`next_page_token`, base64url `"<sort key>|<id>"` — never `LIMIT/OFFSET`).
This unit requires exactly these fields on each entry and **adds none**:

| Field                                               | Why this unit needs it                                                                                                                                                                        |
| --------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `id`                                                | the list key; stable across pages                                                                                                                                                             |
| `kind` (`earn`/`spend`)                             | the sign — `amount` is always positive in the DDL, `kind` gives its direction                                                                                                                 |
| `reason` — a proto **enum**, not a string           | so the FE's reason→copy map is a **total** `Record` over the generated values and a new reason without copy fails typecheck (the closed set becomes a compile-time obligation)                |
| `amount`                                            | the figure                                                                                                                                                                                    |
| `from_small` / `from_general`                       | the spend's tier split (the domain spelling; the columns keep `from_basic`/`from_additional`)                                                                                                 |
| `occurred_on` — the entry's date in `User.Timezone` | so the FE performs **no** timezone arithmetic. [U7] makes the server the day-boundary authority; a device-local grouping would draw day headers that disagree with the `SMALL` reset boundary |
| `occurred_at`                                       | the within-day ordering and the time shown on the row                                                                                                                                         |

**Deliberately absent:** any `episodic_memory_id`, `diary_id`, or star reference. A ledger row must not become a free
index into memories ([I11], and [G4] prices the read it would bypass) — with no field to carry it, the jump cannot be
built.

`packages/twinkle/src/react/ledger.ts` wraps [66]'s `createGetLedgerInfiniteQueryOptions(transport, pageSize)` helper
(the `createGetDiariesInfiniteQueryOptions` precedent), with `pageSize` from `VALUES.twinkle.ledgerPageSize`. It needs
no invalidation seam of its own: the shipped `useInvalidateTwinkleBalance` invalidates the whole `TwinkleService` key,
which partially matches the infinite query, so a spend or earn refreshes balance, quote and history together — no
polling (§2.7).

##### The history list ([G7][U9])

**As built, the refill marker carries no date** — only an amount. Its place is positional (always the head of the
history), so it needs no "is the newest group today?" comparison, which is the one question the client cannot answer
honestly: it has no server-supplied notion of the user's today, and reading the device clock is exactly the arithmetic
[U7] forbids. Keeping the marker date-free is therefore the same guard as keeping it reason-free.

Newest-first (the [D2] archive precedent), grouped under day headers from `occurred_on`, infinite-scrolled: an
`IntersectionObserver` sentinel on web, `FlatList onEndReached` on mobile (the mechanic
[69.diary-list-completion](69.diary-list-completion.md) uses for the diary list; no virtualization library
is added). Each row carries its reason label, the signed amount (`+`/`−`), and — for a **spend** — the tier split
("작은 별가루 3 · 별가루 2"). An **earn** row shows no tier line, because every ledgered earn credits `GENERAL`: the
`SMALL` tier is refilled by derivation and never earned. That asymmetry is a fact of the model, so the row shapes
differ rather than carrying an empty field.

**As-built amendment (after this unit shipped).** The split rides in **parentheses beside the amount** on the same
baseline — `−15 (작은 별가루 5 · 별가루 10)` — one step smaller and one step quieter, instead of on a line of its own
under the reason. It is a breakdown OF that number rather than a second fact about the row, and a full-size line gave it
the weight of one. Its introducing label was dropped with it: the parentheses and the two kind names already say what it
is, so `me_stardust_spend_split_label` ("쓴 몫") was retired for `me_stardust_spend_split`, which carries both figures.

The reason→copy map is a total record over the generated enum. `payment` **must** render: this unit retires the charge
_path_, not the _readability_ of rows written before it ([66](66.earn-and-purchase-spend.md) keeps the constant for
exactly this reason). `daily_grant` is a reserved constant that no row can carry and its entry in the record resolves
to the refill-marker copy, so the record stays total without a fallback arm.

##### The daily-refill marker

There is no `daily_grant` row and no cron ([T4] — the architecture has no per-user daily scheduler), so the history
would otherwise show a `SMALL` balance that appears from nowhere. The FE inserts **exactly one** marker, pinned above
today's group, reading `VALUES.twinkle.smallDailyAmount` — the refill **granted**, not the amount remaining, which the
balance summary above it already shows. It is rendered by its own component with no `EntryReason` and no entry id, sits
in distinct chrome, and its copy names it a refill; `me_stardust_refill_note` states plainly that it leaves no record.
Past days get no marker: their anchors are unrecoverable client-side, and inventing them would fabricate history. [G7]
is thereby amended by this plan to read "every _event_ is ledgered; the daily `SMALL` refill is a derivation, rendered
as a labeled refill marker".

##### Empty and first-run states

A new account has no ledger rows. The tab still renders the two tier figures (`SMALL` is granted from first login,
[G5]), the today refill marker, and `me_stardust_history_empty` — never a bare zero-length list. The balance summary
holds a placeholder only until the first `GetBalance` settles, matching the shipped HUD's `loaded` flag.

##### Golden-parity stance

**No golden-parity obligation.** This is presentation: every figure is either a server value (`GetBalance`, `GetLedger`)
or a generated constant. The one pure module added, `packages/twinkle/src/ledger-day.ts`, groups entries by a
**server-supplied** date string and constructs the marker model — it contains no economy math and has no Go twin to
drift from, by construction. The `smallRemaining` derivation that _does_ carry golden parity stays in
`packages/twinkle-logic` ↔ `apps/api/internal/twinkle/testdata/stardust-ledger-golden.json` ([65]) and is **not** on any
display path here. Web and mobile render the same figures from the same contract, sharing every `model`/`api` module
verbatim through `packages/twinkle`; only `ui` is authored per platform (§3.5).
