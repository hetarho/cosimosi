### 53. auth universe gate

> Auth universe gate — the **route/nav gate** that sends an authenticated user straight to their universe (`/universe`
> on web, the `Universe` route/`UniversePage` on mobile) and an unauthenticated user to login ([U4]). The gate rule as
> built is [tech/web-routing.md](../tech/web-routing.md) §8; the public surface the signed-out arrival meets is
> [81.landing-page](81.landing-page.md). A first-run user
> lands on the _empty_ universe — which already shows the gray latent field ([U2][V7]).
> Scope: FE | Status: built ([job 64](../jobs/archive/64.auth-universe-gate.md))
>
> Placement: `app` layer only (web `app/routes`, mobile `app/navigation`) + a small `pages/universe` first-run seam. This
> unit **composes** the auth session ([04.auth-session](04.auth-session.md)), the router ([15.web-router-foundation](15.web-router-foundation.md)),
> the universe canvas ([23.universe-canvas](23.universe-canvas.md)), and the latent field ([25.latent-star-field](25.latent-star-field.md))
> that already exist. It fills the **auth-gated redirect seam** that [15](15.web-router-foundation.md) deliberately left
> open; it builds **no new engine** — no renderer, no read model, no auth machine.

#### Purpose

Every substrate this unit needs is already built. Auth ([04.auth-session](04.auth-session.md)) knows whether a user is
`authenticated | signedOut | …`. The router ([15.web-router-foundation](15.web-router-foundation.md)) has `/universe` →
`UniverseHomePage` and a typed guard seam, and the mobile shell ([13.mobile-app-shell](13.mobile-app-shell.md)) has a
typed navigation registry whose `Universe` route adapts `pages/universe`. The universe reads and renders a per-user graph
([23.universe-canvas](23.universe-canvas.md)), and a first-run empty universe already shows the gray latent field
([25.latent-star-field](25.latent-star-field.md), [V7]). What is **missing** is the _product rule that binds them_:
"authenticated → your universe directly; not authenticated → login; there is no landing page."

[15](15.web-router-foundation.md) explicitly scoped that rule out — "No product auth-gated redirects. `auth-universe-gate`
(Epic I) owns that rule; this unit provides only the route/guard seam." This unit is that owner. It realizes PRD
[§4](../PRD.md) step 1 (접근: login → universe) collapsed to the v1 shape ([U4]: v1 is login → universe direct, landing is
v2 PRD), enforces per-user isolation at the entry ([U1]), and makes the empty first-run universe a **welcome**, not a
dead end ([U2]) — the user arrives to a quiet field of latent stars with the one affordance that seeds it (일기 쓰기).

Per **CC11**, it is deliberately a **thin composition unit** — the gate + the empty-first-run entry, over existing auth,
router, and universe. No onboarding, no marketing surface.

#### Scope / Non-goals

**In scope**

- **The auth gate on the product subtree (web).** A pathless `authenticated` layout route parents every product route
  (`/universe`, `/diary`, `/me`, `/admin`) and carries the `beforeLoad` guard (the guard seam
  [15](15.web-router-foundation.md) left open), so one gate is inherited rather than repeated per route that reads the session snapshot from the auth facade
  ([04.auth-session](04.auth-session.md)): `authenticated` → render the universe; `signedOut`/`expired` → redirect to the
  **login** entry; `bootstrapping`/`refreshing` → hold on a neutral loading state (do **not** flash signed-out — [04]
  preserves `userId` through refresh). The router library stays confined to `app/routes` ([15]); the guard reads auth
  through the facade, never Supabase directly.
- **The auth gate on the universe screen (mobile).** The `app/navigation` root selects the initial/authoritative stack
  from the same session snapshot: `authenticated` → the `Universe` stack; `signedOut`/`expired` → the login stack;
  `bootstrapping` → a neutral splash (`refreshing` keeps the universe stack mounted — a cold entry can never be
  `refreshing`, it only occurs from `authenticated`). Same three-state discipline, same facade source — **web↔mobile
  parity** ([ARCHITECTURE §3.5](../ARCHITECTURE.md)); the navigation library stays confined to `app/navigation` ([13]).
  The shell-era `ShellHome` placeholder screen is **retired** — the gate owns the default entry (it was scaffolding,
  not product IA).
- **Login entry composition (not the auth engine).** This unit routes _to_ login and, on successful sign-in, routes _to_
  the universe; it composes [04](04.auth-session.md)'s existing sign-in actions/adapter behind a minimal login entry
  screen. The session machine, token storage, refresh, and JWKS verification are [04](04.auth-session.md)'s — untouched.
- **No landing page ([U4]).** The **unauthenticated default is login**, and the **authenticated default is the universe**
  — there is no intermediate marketing/landing route on either app. The v2 landing slot is _reserved_ (a documented
  seam), not built.
- **First-run empty-universe entry ([U2][V7]).** A brand-new user (no memories) lands on the universe, which already
  renders the gray latent field ([25.latent-star-field](25.latent-star-field.md)) as its "empty" state. This unit adds a
  restrained **first-run welcome affordance** in `pages/universe`: the quiet field plus the single **"일기 쓰기"**
  entry point ([W1], owned by [27.writing-flow-ui](27.writing-flow-ui.md)) that turns the empty universe into a first
  star. Empty is a **welcome**, not an error.
- **Post-logout return.** Sign-out (an [04](04.auth-session.md) action) transitions the session to `signedOut`; the gate
  observes that and routes back to login on both apps — no stale universe left mounted.
- **Deep-link / direct-URL entry (web).** A directly-typed product URL while unauthenticated
  redirects to login and, after sign-in, returns to the originally-requested route (a `redirect`/`from` param carried by
  the guard). `from` is user-visible URL input and is **validated at use**: only an internal single-slash pathname is
  replayed — never `//host`/absolute URLs, and never a way IN (`/`, `/login`, `/signup`, `/invite/…`), which would hand
  a freshly signed-in user the screen they just came through; anything else falls back to `/universe`. It carries the
  pathname only (v1 product routes hold no state in the query). **`from` applies to the password path only**: a Google
  sign-in leaves the app entirely and returns to the fixed, allowlisted origin root by design ([04](04.auth-session.md)
  — one redirect URL per origin, the gate routes from `/`), so a pre-OAuth `from` is deliberately not replayed. Mobile
  has no URL bar; its auth-callback link handling is [13](13.mobile-app-shell.md)'s and is reused.
- **UI copy via i18n** (`packages/i18n` / the app `shared/i18n` seam) — the login entry and first-run welcome copy resolve
  through message keys, in a literary, restrained Korean voice ([PRD §3.1](../PRD.md)); no raw strings.

**Non-goals**

- **No auth engine.** The session machine, Supabase adapter, token refresh/skew, JWKS verification, and the per-user RPC
  isolation are [04.auth-session](04.auth-session.md)'s — this unit only _reads the snapshot_ and _routes_.
- **No landing/marketing page** ([U4] — v2 PRD). No hero, no onboarding tour, no product tutorial. The empty universe is
  the whole first-run experience in v1.
- **No new renderer, read model, or write flow.** The universe scene ([23](23.universe-canvas.md)), the latent field
  ([25](25.latent-star-field.md)), the `GetUniverse` read ([23](23.universe-canvas.md)), and the writing flow
  ([27](27.writing-flow-ui.md)) exist; this unit mounts/links them, it does not build them.
- **No settings/account UI** — account management, palette change, and the staging-layer slot are
  [52.settings-page](52.settings-page.md); the palette registry/preference is [51.palette-customization](51.palette-customization.md).
- **No sign-up funnel / email verification / password-reset flows** beyond what [04](04.auth-session.md)'s adapter
  already exposes. This unit routes to those; it does not design them.
- **No BE change.** [U1] per-user isolation is already enforced server-side ([04](04.auth-session.md) attaches the user id
  to request context; `GetUniverse` is user-scoped, [23](23.universe-canvas.md)). This unit adds no RPC and no query.
- **No new tuning scalars.** The gate is control-flow, not tuned behavior (see Policy).

#### Design

##### The gate rule (one rule, two app expressions)

The gate is a pure function of the auth session snapshot ([04.auth-session](04.auth-session.md)) → a routing decision:

| Session status ([04])              | Web subtree guard (`beforeLoad`)                            | Mobile nav root            |
| ---------------------------------- | ----------------------------------------------------------- | -------------------------- |
| `authenticated`                    | render the universe (`UniverseHomePage`)                    | the `Universe` route stack |
| `signedOut` / `expired` / `failed` | `redirect` to the **login** entry (carry `redirect`/`from`) | the **login** stack        |
| `bootstrapping` / `refreshing`     | hold on a neutral loading state (no redirect)               | a neutral splash           |

- **Neutral hold, never a flash.** `bootstrapping`/`refreshing` must **not** redirect to login — [04](04.auth-session.md)
  preserves `userId` across an in-flight refresh precisely so the UI does not flash signed-out. The gate waits for the
  session to settle before deciding. **Decided (2026-07):** the gate treats `refreshing` as _provisionally
  authenticated_ (hold on the universe if already there; hold on the splash if entering cold) — it redirects to login
  **only** on a settled `signedOut`/`expired`/`failed`. As built, the hold is a component, not an awaited settle: the
  web `beforeLoad` guard redirects only settled signed-out arrivals; a pathless **authenticated layout route** then
  renders from the **live** snapshot — the initial `bootstrapping` shows a neutral loading line, `refreshing` keeps
  the universe mounted (no blank, no re-read), and a session that settles signed-out **while mounted** navigates to
  login carrying the current pathname. The `/login` route itself holds the same way while `bootstrapping`/`refreshing`
  (a signed-in user opening `/login` cold never sees the form flash); `signingIn` stays on the form.
- The status→decision mapping is **`gateDecision(status)` in `packages/auth`** (beside the facade), consumed by both
  hosts; `signingIn` maps with the settled signed-out statuses (the login surface is where a pending sign-in lives).
- **`failed` routes to login, not an error screen.** A failed auth bootstrap is a signed-out user from the product's
  point of view; [04]'s error surfacing (observability) still fires, but the _route_ is login.
- The rule is authored **once conceptually** and expressed through each app's app-layer nav seam (web `beforeLoad`,
  mobile initial-stack selection) — disciplinary parity, not a shared route package (matching [15]'s parity stance and
  [ARCHITECTURE §3.5](../ARCHITECTURE.md)). The tiny "status → decision" mapping is the only shared logic and lives with
  the auth facade / a small `app`-layer helper.

##### Placement (FSD, [§3.1](../ARCHITECTURE.md))

```
apps/web/src/app/routes/          # web gate lives here (the only place that imports the router lib, per [15])
  route-tree.tsx                  #   / route gains beforeLoad (auth guard) + redirect-to-login
  guards/auth-gate.ts             #   the status→decision mapping reading the [04] auth facade
  + a login entry route composing [04]'s sign-in actions

apps/mobile/src/app/navigation/   # mobile gate lives here (the only place that imports the nav lib, per [13])
  NavigationRoot.tsx              #   initial/authoritative stack selection from the session snapshot
  + the login stack composing [04]'s sign-in actions

apps/{web,mobile}/src/pages/universe/   # first-run empty-universe welcome (existing screen, extended)
  ui: the quiet latent field ([25]) + the single "일기 쓰기" entry ([W1], [27]) when the universe is empty
```

- The guard/gate is **app-layer only** — `pages` and `features` never import the router/nav library name; they navigate
  through the seam ([15]/[13]). The gate reads auth through the **facade** ([04]), never Supabase directly.
- `pages/universe` (the screen [23](23.universe-canvas.md) composed) gains a first-run branch: when `GetUniverse` returns
  **no memories**, render the latent-field-only scene with the welcome affordance; otherwise render the populated
  universe. Emptiness is derived from the existing read, not a new flag.

##### Login entry (composition, not engine)

- The login entry is a thin screen that mounts [04.auth-session](04.auth-session.md)'s existing sign-in actions (the
  adapter/provider already exposes them): a Google OAuth action above the email+password form, with failure copy
  matching whichever action was last attempted. On the machine reaching `authenticated`, the gate routes to the universe
  (web: to the carried `redirect`/`from` or `/universe`; mobile: swap to the `Universe` route stack). This unit owns the
  **screen + routing**, not the auth flow.
- **web↔mobile parity ([§3.5](../ARCHITECTURE.md)):** the same gate rule and the same login-entry composition on both
  apps; only the primitives differ (web route/`beforeLoad`/`redirect` vs. mobile stack selection, DOM form vs. RN
  inputs), via each app's app-layer nav seam. No shared route-contract package (the two apps use different libraries and
  param shapes — [15]'s posture).

##### First-run empty universe as welcome ([U2][V7])

- A first-run user (no memories) sees the **gray latent field** ([25.latent-star-field](25.latent-star-field.md)) — the
  visual metaphor for a not-yet-recruited mind — with a single restrained **"일기 쓰기"** affordance ([W1], the writing
  flow entry [27.writing-flow-ui](27.writing-flow-ui.md)). No empty-state error, no tutorial overlay, no marketing.
- **Decided (2026-07):** the empty state is **not** a separate route or component tree — it is the _same_
  `widgets/universe-canvas` scene with zero real stars over the latent background, plus the welcome copy. This keeps the
  first star's appearance ([27] optimistic launch → [25] awaken) a seamless in-place transition, not a screen swap.
- The welcome copy (a line inviting the first entry) is i18n content, literary and restrained — it names the empty
  universe as a beginning, not a lack.

##### Logout + isolation ([U1][I1])

- Sign-out ([04](04.auth-session.md) action) → session `signedOut` → the gate routes to login on both apps and unmounts
  the universe view. **[I1]:** logout **never deletes** the universe — the data persists per-user; the next sign-in for
  the same user re-reads the same graph. On every stable scope-key change, a boundary below auth withholds routed
  children while clearing all Query data and registered client mirrors/drafts/targets/deferred actions; only then may
  anonymous or the next user's product subtree commit. This complements [04]'s per-user RPC scope and prevents an A
  snapshot or queued palette intent from being displayed or dispatched as B. See [tech/auth.md](../tech/auth.md).

##### v2 landing seam (reserved, not built) ([U4])

- **Decided (2026-07):** the unauthenticated default is login and the authenticated default is the universe, with **no
  intermediate route**. The v2 landing/marketing page is a _reserved slot_: the gate's status→decision mapping is the
  single place a future landing route would insert (an unauthenticated user could later resolve to `landing` instead of
  `login`), so v2 slots in without re-architecting the gate. v1 does not build it and does not route to it.

#### Acceptance Criteria

1. On **web**, the pathless `authenticated` layout route carries a `beforeLoad` **auth guard** inherited by every
   product route beneath it: an `authenticated` session renders the universe; a
   settled `signedOut`/`expired`/`failed` session **redirects to the login entry**; `bootstrapping`/`refreshing` **holds
   on a neutral loading state without redirecting** (no signed-out flash) ([U1][U4]).
2. On **mobile**, the `app/navigation` root selects the stack from the **same** session snapshot: `authenticated` →
   the `Universe` route/`UniversePage`; settled signed-out → the login stack; `bootstrapping`/`refreshing` → a neutral splash — web↔mobile
   parity ([U1][§3.5]).
3. There is **no landing/marketing page** in v1 on either app: the unauthenticated default is **login**, the
   authenticated default is the **universe**, with no intermediate route ([U4]).
4. A successful sign-in ([04]'s action reaches `authenticated`) routes to the universe — on web to the carried
   `redirect`/`from` (or `/universe`), on mobile by swapping to the `Universe` route stack.
5. **Sign-out** routes back to login on both apps and unmounts the universe view; before anonymous or another user's
   routed subtree commits, all registered Query data, client mirrors, drafts, targets, deferred actions, and palette
   operations are reset. It **never deletes** persisted user data — a subsequent sign-in re-reads that user's universe
   ([U1][I1]).
6. A **first-run** user (no memories) lands on the universe rendered as the **gray latent field**
   ([25.latent-star-field](25.latent-star-field.md), [V7]) with a single **"일기 쓰기"** affordance ([W1], [27]) — the
   empty universe is a welcome, not an error state, and is the _same_ `widgets/universe-canvas` scene with zero real
   stars ([U2]).
7. A directly-entered **web URL** while unauthenticated redirects to login and, after sign-in, returns to the originally
   requested route (`redirect`/`from` param); the router/nav library stays confined to `app/routes` / `app/navigation`,
   and the gate reads auth **through the [04] facade**, never Supabase directly ([§3.1]).
8. The gate never lets `GetUniverse` (or any product read) run without an authenticated session — the presentation-side
   complement of [04]'s server-side per-user isolation ([U1][§2.7]).
9. **All** user-visible copy (login entry, first-run welcome) resolves through the i18n seam (no raw strings;
   `lint:raw-strings` passes), in a literary / restrained Korean voice.
10. This unit adds **no** auth engine, renderer, read model, write flow, settings UI, RPC, or DB change — it composes
    [04]/[15]/[13]/[23]/[25]/[27]; `pnpm typecheck`, `pnpm lint` (incl. `lint:fsd:layout`, `lint:raw-strings`),
    `pnpm test:web`, and `pnpm build:web` pass with no BE changes.
