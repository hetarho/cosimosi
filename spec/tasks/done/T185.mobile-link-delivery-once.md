## goal

A cold-start OAuth or invite URL reaches exactly one live subscriber, once per process.

## acceptance

- [x] A subscription has an `active` flag cleared in its cleanup; `getInitialURL()` resolving after cleanup delivers nothing
- [x] The cold-start URL is consumed once per process across subscriptions; re-subscribing does not redeliver it; runtime `url` events still reach the current subscriber
- [x] `linking.test.ts`: `ignores the initial URL after unsubscribe`, `does not redeliver the initial URL to a new subscription`, `delivers later events`
- [x] task tier passes: `pnpm lint` and affected `typecheck`/`test` (ARCH-47)

## result

- outcome: Inbound auth-callback and invite links share one subscription helper that never delivers after its cleanup and delivers each URL at most once per process, so a re-subscription cannot redeliver the cold-start OAuth URL and a late `getInitialURL` cannot reach a released facade.
- at: -
- verified: Jest `linking.test.ts` (`ignores the initial URL after unsubscribe`, `does not redeliver the initial URL to a new subscription`, `delivers later events`; the first two fail on the previous implementation), shared/native and app/providers suites, mobile `tsc --noEmit`, ESLint on the touched files.
- limits: a URL identical to one already delivered in the same process is now dropped even if it arrives again later; for OAuth callbacks that is the single-use code, and for invites it is a no-op redelivery. Device deep-link behavior remains a manual check.
