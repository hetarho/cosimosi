# T182 Instanced pick volumes follow their instances

> st:done@261103 | ssot:ARCH-25 | base:ARCH@3 | dep:- | touches:packages/3d-renderer/src/layers | lane:- | explore:-

## goal

A star stays tappable after its instance moves, appears or the instance count fills from zero.

## acceptance

- [x] `attachMesh` and every compose that sets `instanceMatrix.needsUpdate` reset `mesh.boundingSphere` and `mesh.boundingBox` to `null`
- [x] The compose loop is a pure helper `composeInstances` in `packages/3d-renderer/src/layers/instance-compose.ts`; `instance-compose.test.ts` uses a real `THREE.InstancedMesh` and `Raycaster` without a GPU: `re-picks after instances move` (compose A, raycast, compose B, a ray at B hits), `picks after first coordinates arrive` (count 0, raycast, fill, hit), `picks a lifted gist` (same count, moved instance, hit)
- [x] Behavior unchanged elsewhere: existing affected suites pass: `pnpm --filter @cosimosi/3d-renderer test`, `pnpm --filter @cosimosi/universe-render test`
- [x] task tier passes: `pnpm lint` and affected `typecheck`/`test` (ARCH-47)

## impl notes

- from review/post-refactor-261102 F2
- Recomputation stays lazy: three computes the sphere on the next raycast, so no per-frame cost is added; never call `computeBoundingSphere` eagerly in the frame loop.
- T217 later edits the same layer; keep `composeInstances` the single compose path it extends.

## result

- outcome: Composing instances (the extracted `composeInstances`) and attaching a fresh mesh both drop the mesh's cached bounding sphere and box, so three recomputes the pick volume on the next pointer event; the compose loop reuses one input object and allocates nothing per frame.
- at: -
- verified: `vitest` `instance-compose.test.ts` (move, first-coordinates and lifted-gist picks; all three fail with the invalidation removed), full `@cosimosi/3d-renderer` suite (152) and `@cosimosi/universe-render` suite (26), package typecheck, packages ESLint and Prettier on the touched files.
- limits: the pick test uses a double-sided box because three's front-side sphere raycast returned no hit in the test environment; the behavior under test is the cached volume, not the body geometry. Device tap checks remain manual.
