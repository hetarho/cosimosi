## goal
A guide caption is first painted at the place the layout measured for it. It does not jump after appearing, and it does not blink when a webfont swaps in or the paragraph merely changes size. This applies to the demo and the post-signup tour on web.

## acceptance
- [ ] The caption becomes visible only in the same commit that applies its measured position. No imperative reveal precedes React's commit of that position.
- [ ] A size-only change of an already placed paragraph (font swap, ResizeObserver tick) re-measures without hiding it. The caption hides only while its layout key or room actually changes.
- [ ] Tests:
  - the first visible state carries the measured position, never the preferred fallback
  - a ResizeObserver tick on a placed caption keeps it visible
  - a real room change still hides, then reveals at the new place
  - existing sequence-guide and timing tests stay green
- [ ] A cold `/demo` load at 390x844 under 4x CPU and fast-4G throttling, run three times, shows the first visible caption frame at its final position, with no hidden frame after first reveal. The scout's recipe has median CLS above 0 coming from the caption container; after the fix it must not.
- [ ] `pnpm lint`, `pnpm typecheck:affected`, `pnpm test:affected` against the assignment start.

## impl notes

  - Mobile filmstrip `runs/mbr-demo-2/frames/`: f016 (2.37s) shows the caption mid-screen, f034 (2.69s) shows it at the top, and f038 (2.75s) shows it hidden during the font swap.
  - Caption-container layout shifts give CLS 0.1328 in every mobile run and 0.2217 on desktop.
- Cause, as observed in code:
  - `use-caption-layout.ts` sets `visibility: visible` imperatively right after `setLayout`, before React commits the position.
  - `schedule()` hides the caption on every mutation, resize or ResizeObserver tick.

- Out of scope: the destination room itself (top when the phone sheet is modal), placement rules in `packages/sequence`, and the mobile app. The mobile caption has no equivalent hook, so record parity as a limit.
