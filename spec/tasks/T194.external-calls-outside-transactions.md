## goal

No database transaction or lock is held across an HTTP call, vendor bodies are bounded, and shutdown always cleans up.

## acceptance

- [ ] The withdrawal sweep commits its claim in a short transaction, runs each purger in its own transaction and makes both Supabase Admin calls with no transaction open; a crash at any step completes on replay (test with a fake directory that asserts zero acquired pool connections while it runs)
- [ ] Directory responses are read through `io.LimitReader` with `supabaseDirectoryMaxBodyBytes = 1 << 20` beside the protocol code, and non-2xx bodies are drained through a bounded reader (tests for oversize and error bodies)
- [ ] API shutdown waits `apiShutdownTimeout`, then closes remaining connections, and runs domain and worker cleanup on both the clean and the timeout path (`TestShutdownRunsCleanupAfterTimeout`)
- [ ] `pnpm check:api` passes (gofmt, vet, Go suite, build)
