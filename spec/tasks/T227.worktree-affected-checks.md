## goal

Run the existing affected-package typechecks/tests reliably in ordinary and linked Git checkouts, with observable fail-closed selection.

## acceptance

- [v] `scripts/check-affected.test.mjs` invokes the actual runner in temporary ordinary and linked Git workspaces, recording harmless package-script executions; tracked dirty, staged and committed edits select the changed projects and all transitive dependents exactly once, in the correct checkout.
- [v] Cover multiple changed owners, cross-package rename/deletion, removed/unknown ownership, prefix collisions, spaces/Unicode/newline paths, shared configuration, narrow known non-workspace changes and untracked-only controls. Preserve tracked-diff semantics and every separate Go/generation/guard obligation.
- [v] Git/base/inventory failures, interrupted subprocesses and unexpected empty pnpm matches fail. Explicit legitimate empty selection reports its reason and executes no package checks. Tests cover explicit/environment/default base precedence and typecheck/test/list modes, with no dependency installation or real full-project checks inside fixtures.
- [v] Add `typecheck:affected` and `test:affected` root entrypoints and register the Node regression in existing `test:guards`; README explains usage and tracked-file semantics. No dependency version, lockfile, pnpm, skill, retry/skip or final-gate change.
- [v] Focused Node regressions, `pnpm test:guards`, `pnpm lint` and the new affected task commands pass. Record actual selections, including any conservative fallback; an empty command is never presented as behavioral coverage.
- [v] Existing behavior/coverage remains intact; independent review and the coordinator's final `pnpm check` precede completion/publication. Hand off the fixed candidate for any coordinator-owned generated campaign.
