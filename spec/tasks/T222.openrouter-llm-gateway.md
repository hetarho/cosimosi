## goal
Every production LLM call goes through one privacy-routed OpenRouter adapter and a model only an approved evaluation admitted, while the Voyage embedding path stays exactly as it is.

## acceptance
Phase 1: adapter, hermetic (no credentials needed)
- [v] `internal/ai/openrouter` implements `ai.LLMClient` and its model lister (AI-18, AI-20–22); `client_test.go` covers each case on an `httptest` server: one explicit model and no `models`/route/preset/plugin field; `response_format` json_schema strict with the whole schema; `provider.zdr`, `data_collection: "deny"`, `require_parameters`, `allow_fallbacks` present; returned-model mismatch rejected; non-`stop`/missing/multiple choices, empty content, malformed JSON and a provider-claimed success that fails local validation → `MalformedStructuredOutputError`; oversized body bounded; the AI-22 table arm by arm (401/403/402 → `AuthFailedError`, 429/overload/408/5xx/transport → `RateLimitedError` with delta-seconds `Retry-After` only, cancellation/deadline → `ctx.Err()`); no vendor message or body in any cause
- [v] lister tests: approved+listed, approved-but-absent, listed-but-unreviewed, lost capability, duplicate, missing metadata, listing/auth failure, empty intersection; every failure yields no selectable model
- [v] `TestAllowlistMatchesApprovedEvaluation` (`internal/ai/openrouter`): every allowlist id is an approved row of `EVALUATION.md` and vice versa; the allowlist is empty in this phase
- [v] the live harness runs from `internal/ai/openrouter` for both an OpenRouter candidate and the current direct providers; `go test ./internal/ai/...` skips it without `COSIMOSI_LIVE_LLM_EVAL=1`
- [ ] `EVALUATION.md` records the rechecked OpenRouter contract (endpoints, request fields, terminal states, catalog capability fields, error envelope, usage/cost fields, fee basis) with source URLs and retrieval date
- [v] task tier passes: `go vet ./...`, `go test ./internal/ai/...`, gofmt clean (ARCH-47)

- [ ] prompt-logging opt-in confirmed disabled on the production OpenRouter account, a real key + exact model smoke call passed with the routing controls, and the named reviewer's approval lists the admitted model ids; a failed or unevaluated candidate is excluded

## impl notes
- Replaces T165; the requirements are AI@2 and ADMIN@2/ERR@3 as cited, nothing more. Phases run in order and the gate is never waived: when phase 2 lacks keys, an operator or a reviewer, set `blocked` with that reason after phase 1 and leave the direct adapters in place.
- Re-run `/library-setup` for OpenRouter at the start of phase 1 and again before phase 2: prices, fees and routing are rechecked at every evaluation (AI-19), never kept as constants.
- Shape: start from `internal/ai/deepseek/client.go` (OpenAI-compatible chat completions, `jsonschema/v6` local validation, `maxResponseBytes`/`maxErrorBodyDrainBytes` bounded reads, `drainErrorBody`, `retryAfter`) but write `openrouter` as its own package; nothing is shared with `deepseek`, which phase 3 deletes. Plain `net/http`, no SDK (AI-20).
- Endpoints are adapter constants: `POST https://openrouter.ai/api/v1/chat/completions`, `GET https://openrouter.ai/api/v1/models`. The lister requires both `structured_outputs` and `response_format` in a row's `supported_parameters` and matches allowlist ids against the row `id` (AI-18). The returned `model` is compared under the normalization the rechecked docs state; record that rule in `EVALUATION.md`.
- Error envelope `{"error":{"code","message","metadata"}}`; only status and category cross the adapter (AI-9, AI-22).
- Allowlist: an unexported `approvedModels` slice in `openrouter/allowlist.go`, empty until phase 3. `New` (the registered factory) refuses an empty or non-allowlisted model (AI-17). The harness reaches candidates through `export_test.go`'s `NewCandidateClient`, which skips only the allowlist check, so no production root can build an unreviewed model.
- Harness: move `internal/ai/live_evaluation_test.go` to `internal/ai/openrouter/live_evaluation_test.go` (package `openrouter_test`). OpenRouter candidates inject `NewCandidateClient` through `ai.FactoryOptions.LLMClient`, which keeps the production ports, metering and cache with a fresh synthetic user scope per sample; direct baselines keep the registry path with blank imports of `anthropic`/`deepseek` until phase 3 drops that branch. The corpus stays at `internal/ai/testdata/llm-evaluation-corpus.json` (AI-19). Env names stay `COSIMOSI_LIVE_LLM_EVAL{,_PROVIDER,_API_KEY,_MODEL,_WARMUPS,_SAMPLES}`.
- Record: `internal/ai/openrouter/EVALUATION.md`, beside the allowlist it licenses. Approved rows use the form `| <vendor/model> | ... | approved |` so the allowlist test can parse them. Never commit a real diary, a key, a raw payload or a prompt (AI-19).
- Preflight: `ai.PreflightLLMConfig(ctx, ConfigReader, getenv)` in `internal/ai/runtime.go` returns an actionable error naming the replacement (`openrouter` + an allowlisted `vendor/model`); `cmd/internal/wiring` calls it in both roots before serving. It never deletes key rows (AI-24).
- Wiring: `cmd/internal/wiring/ai.go` blank-imports `openrouter` and `voyage` only; `openRouterHTTPTimeout` replaces `deepSeekHTTPTimeout` at 120 s, a deployment budget to revisit against the recorded p95.
- Admin: the curated check sits in `internal/admin/ai_config.go` behind the existing `ModelCatalog` port; new domain errors map in `rpc/reasons.go` to the ERR-12 rows; `packages/errors/src/core.ts` gains both reasons, and only `ADMIN_MODEL_NOT_CURATED` gets copy (`error_admin_model_not_curated`, ko/en) per ERR-15. The proto changes in comments only; no RPC, field, table, query or migration change (ADMIN-19).
- Web: T221 has already moved admin IO into the feature's `api` segment; the LLM row consumes those hooks.
- DB-backed admin integration tests need a local database (ADMIN constraints); list them under limits if none is available.
