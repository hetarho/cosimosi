# tech: i18n seam

> As-built rules for cosimosi's UI string seam (web + mobile). The architectural
> frame lives in [ARCHITECTURE.md](../ARCHITECTURE.md) §3.1 (shared/i18n) and §5
> (English code, i18n'd copy with Paraglide); this doc is the detailed rulebook the
> foundation (plan/08) installed. Canonical domain terms remain owned by
> [ubiquitous-language.md](../ubiquitous-language.md) and never become message keys.

## 1. Packages and the app seam

| Concern                                                                 | Location                                                                          | Depends on                        |
| ----------------------------------------------------------------------- | --------------------------------------------------------------------------------- | --------------------------------- |
| Message sources (canonical)                                             | `packages/i18n/messages/{en,ko}.json`                                             | inlang message-format plugin      |
| inlang project config                                                   | `packages/i18n/project.inlang/settings.json`                                      | —                                 |
| Compiled message functions + runtime                                    | `packages/i18n/src/gen/**` (committed, generated)                                 | none at runtime (self-contained)  |
| Platform-pure facade (`m`, locale store, locale/timezone reads)         | `packages/i18n/src/{index,locale,timezone}.ts`                                    | the generated runtime only        |
| React i18n seam (store bridge, render boundary, profile bootstrap, `m`) | `@cosimosi/i18n/react`; apps re-export it from `shared/i18n/index.ts`             | React, Connect Query, profile API |
| Platform locale negotiation                                             | `apps/{web,mobile}/src/app/providers/i18n-provider.tsx` + platform locale adapter | platform locale sources           |

Product code consumes each app's `shared/i18n/index.ts` entry point. That barrel re-exports the optional
`@cosimosi/i18n/react` seam and domain-owned projections such as `moodLabel`; platform locale-storage adapters are the
only app-local modules that import the pure package directly. The web lint gate rejects any other direct
`@cosimosi/i18n` import. The package stays free of DOM/native dependencies so the same `m.*` calls and locale store run
verbatim on web, React Native, and in Node tests. Locale **negotiation** remains platform-specific in the app provider.

Domain-specific localized projections remain with their owning domain package: for example,
`@cosimosi/emotion/i18n` owns `moodLabel`, while consuming this package's generated message functions. App
`shared/i18n` barrels may re-export such projections for UI ergonomics; they do not implement a second mapping.

## 2. Messages

- Add or change copy in `packages/i18n/messages/en.json` and `ko.json`. English is
  the base locale; every key exists in both files.
- Keys are snake_case and name a UI role, not a product noun
  (`app_greeting`, `common_retry`), never a domain term.
- Run `pnpm gen:messages` (also part of `pnpm gen`) to compile. The output lands in
  `packages/i18n/src/gen/`, is committed, and is freshness-checked by
  `pnpm check:gen` (a second run is byte-identical). The compiler's auto-emitted
  `.gitignore`/`README.md` are stripped so the output stays tracked and
  machine-independent; the inlang plugin cache (`project.inlang/cache/`) is
  gitignored.
- Scope is the platform seam, not product copywriting: hello-world remnants,
  auth/session proofing, harness labels, and common primitive labels. No
  marketing/blog localization (the Astro blog keeps its own pipeline), no
  server-side or AI translation, no DB-stored localized content.

### Renaming a key is the mechanism, not revaluing it

**When a product concept is renamed, rename its keys — do not quietly change their values.** The
compiler emits one module per key, so a rename makes `m.<old_key>` stop existing and every stale call
site becomes a **compile error**. Editing the value in place is silent, and on a two-app repo the app
nobody remembered to check ships the wrong string.

The worked example is the 별가루 relabel: `twinkle_balance_basic_label` → `twinkle_balance_small_label`
and `twinkle_balance_additional_label` → `twinkle_balance_general_label`. Both apps' HUDs and both
tests failed to compile until they were updated — which is the whole point. Keys that only changed
value (`twinkle_cost_earn`) were renamed anyway, because the role had changed too.

Two rules follow:

- **A deleted affordance's keys are deleted with it.** The retired payment path took
  `twinkle_charge_pay_*` and the invite-code field took `twinkle_charge_invite_code_*`. A key kept "just
  in case" is copy nobody owns.
- **`pnpm lint:language` scans the catalogues for SYNONYMS ONLY** (`packages/i18n/messages/*.json`).
  They are the one place a retired user-facing name survives a rename — the code stops compiling, a JSON
  string does not. The **rendering**-term scan deliberately does not reach them: `star_detail_*` keys are
  legitimate there, and a visual word inside a user-facing string is the poetic register, which is the
  point.

Error presentation extends this seam deliberately:

- `@cosimosi/errors` decodes a stable backend reason and selects
  `error_<reason>` copy only for reasons on which current UI recovery or
  presentation branches.
- An unmapped reason falls back to coarse Connect-code copy; a non-Connect error
  falls back to `error_unknown`. Raw exception messages and `debug_detail` are
  never user copy.
- `error_internal` is the only copy with a `{requestId}` placeholder. This gives
  the user an operator join key without exposing it on ordinary domain refusals.
- Web and mobile call the same headless presentation function; only Toast and
  boundary rendering are platform-specific.

### Domain id → copy projections

The wire carries **ids, integers and enums only** for both the mood vocabulary and the achievement catalog — no title, no
body, no label — so a domain package owns the words. `@cosimosi/emotion/i18n`'s `moodLabel` established the shape and
`@cosimosi/achievement`'s `achievement-copy.ts` follows it: a **`Record` of static `m.*` accessors**, never a constructed
key.

The static-accessor rule is load-bearing rather than stylistic. A key assembled at runtime
(`m[`achievement_${id}_title`]`) is invisible to `gen:messages`, to `check:gen` and to `lint:raw-strings` at once, so a
missing string would ship as a blank row nobody notices. Written out, every key this surface can render is a reference the
tooling can see.

The achievement family is `achievement_<id>_title` / `_body`, plus nine `achievement_axis_*` labels and the surface's own
lines. An id with **no** entry falls back to `achievement_untitled` and keeps its progress meter and its claim button:
copy completeness is a content gate, claimability is a correctness one, and a server that shipped a row before its words
must not hold a reward hostage.

## 3. Locale resolution and the active-locale store

`packages/i18n/src/locale.ts` owns an in-memory active-locale store and drives
Paraglide through `overwriteGetLocale`/`overwriteSetLocale`, so message functions
read the locale each app set — with no cookie/URL/DOM coupling. The compile uses
the `globalVariable` strategy precisely so the generated runtime references no
browser globals.

Both app providers bridge the active locale into `ActiveLocaleProvider`, and both composition roots build their product
provider tree inside `LocaleRenderBoundary`. A later profile-driven or optimistic locale write therefore makes React
evaluate every mounted synchronous `m.*()` call instead of re-rendering only the provider with an identical `children`
element. The boundary recreates the same element tree for React reconciliation; it does **not** key or remount that
tree, so auth, query-cache, navigation, form, and in-flight mutation state survive a language switch. This context
boundary was chosen over a keyed subtree specifically to preserve those long-lived providers while retaining the
platform-pure, synchronous message API for non-React consumers. Negotiation still writes only from effects, and the
locale store remains platform-pure.

- `defaultLocale` is the inlang `baseLocale` (**en**); `supportedLocales` is
  `["en", "ko"]`.
- `matchLocale(tag)` maps a BCP-47-ish tag to a supported locale or `undefined`:
  exact, then primary subtag, case-insensitive, across both `-` and `_`
  separators ("en-US" / "ko_KR" → "en" / "ko").
- `resolveLocale(candidates)` returns the first candidate that matches, else the
  default. Providers pass candidates in precedence order, which keeps resolution
  pure and unit-testable **without** browser globals (the suites run in Node).
- `setActiveLocale` / `getActiveLocale` / `subscribeLocale` are the store API;
  `subscribeLocale` pairs with `useSyncExternalStore`.

Provider precedence:

- **Signed in:** the server profile locale has highest precedence. The single platform-pure `LocaleBootstrap` in
  `@cosimosi/i18n/react` mounts beside each app's palette bootstrap, reuses the `GetProfile` query, and applies a
  supported server locale in an effect without withholding product render. There is no native sibling.
- **Web** (`apps/web`): when no signed-in profile has taken precedence, stored explicit choice
  (`localStorage["cosimosi.locale"]`) → `navigator.languages` → default. Negotiation runs in an effect (never during
  render), keeping render free of `window`/`navigator`. The provider also syncs
  `<html lang>` to the resolved locale. The test/storybook override uses the same
  effect path; server rendering reads the already-active locale instead of mutating
  the external store during render.
- **Mobile** (`apps/mobile`): device locale (RN `NativeModules`, best-effort, no
  extra native dependency) → default. There is deliberately no durable native
  preference store; the server owns signed-in persistence. The app shell owns final composition order.

The profile language control is the only preference write. It applies the next locale immediately, writes the
complete profile, and rolls the active locale back when the server refuses it. Web also writes
`localStorage["cosimosi.locale"]`; mobile's storage seam is an honest no-op. The shared user-state reset registry in
`@cosimosi/auth/user-state` owns every platform-pure reset and each app contributes only its `locale` leg: a scope change
restores the stored/browser negotiation on web and the device negotiation on mobile before a new profile can take
precedence.

## 4. The raw user-facing string rule

`scripts/lint-raw-strings.mjs` (wired into `pnpm lint` as `lint:raw-strings`)
parses every `.tsx`/`.jsx` under `apps/{web,mobile}/src` with the TypeScript AST
and fails on user-facing copy that bypasses message functions:

- JSX text nodes containing letters (`<h1>hello</h1>`);
- string literals — bare or `{"..."}` — on user-facing attributes (`title`,
  `placeholder`, `alt`, `label`, `aria-label`/`aria-*`, `accessibilityLabel`/
  `accessibilityHint`).

Everything else is intentionally out of scope, which is how documented non-UI
cases stay quiet: developer logs, thrown `Error` messages, route ids,
`className`/`id`/`testID` and other structural attributes, `{m.x()}` expressions,
and domain names in model/proto/SQL (those are not `.tsx` JSX literals). Tests,
generated code, and stories are skipped by path. A line carrying `i18n-ignore`
opts that node out for a documented exception. `pnpm lint:raw-strings:probe`
self-tests the rule: it must catch a deliberate UI string and ignore the
documented cases beside it.

## 5. Design-system primitives

Primitives accept copy as **props** — labels, aria-labels, descriptions,
validation messages — and never embed product strings. Callers pass the result of
a message function; the primitive stays domain- and copy-agnostic. Shared primitive
examples may use message calls or test-only placeholders. (The primitives
themselves follow the design-system primitive contract.)

## 6. Non-goals

No product copywriting for final flows, no marketing/blog localization, no server-side/AI/DB translation, and no
changes to canonical domain terms.
