# 78. sequence engine

> Sequence engine — the one guided-step engine that both the public demo and the post-signup onboarding run on
> ([O1]). It highlights the next control the user should press, shows a caption at bottom center, keeps a skip
> affordance visible at all times, and can be replayed ([O2][O4][O5]). It drives the **real** screens — not video, not
> slides — so the engine performs nothing itself: a step names a control and waits for the user. Two very different
> hosts consume it (a fixture-driven sandbox on `/demo`, the user's live universe right after signup), so the engine is
> pure, host-agnostic, and knows nothing about either. Script _content_ — the ten demo beats ([Z3]) and the onboarding
> wording — belongs to [79.demo-page](79.demo-page.md) and [80.onboarding-tour](80.onboarding-tour.md).
> Scope: FE | Status: planning
>
> Layer U/P. Home: a NEW pure package `packages/sequence` (`@cosimosi/sequence`) for the step model, the run machine
> and the anchor seam, plus three `features/*` chrome slices and one `widgets/sequence-guide` host in **both** apps.
> It fills the seam [O1] asserts and leaves open the two feeds, the two routes, and every caption string.

## Purpose

cosimosi's core loop is only legible in motion. A first-time visitor cannot tell from a screenshot that writing a
diary splits into stars, that neurons get reused into a constellation, that unrecalled stars dim and lose words, or
that a recall reshapes one — those are changes over time, on a 3D surface, driven by controls the visitor has never
seen. PRD [O2] answers this by refusing the usual demo shortcut: no video, no carousel. Instead the product teaches
itself **on the real screen** — highlight the control, put one line of guidance at bottom center, let the person press
it. [O1] then makes the same machinery serve two audiences: the public demo feeds it hardcoded fixtures ([Z4]), and
onboarding feeds it the user's own first diary. "다른 것은 주입 데이터뿐" is a requirement, not an aspiration, so the
engine that walks the steps must be one artifact.

That single sentence is the whole design pressure. One host is an unauthenticated sandbox deliberately exempt from the
invariants ([I13], [Z2]) and reachable by anyone on the internet ([I12] governs every word it renders). The other host
is a real signed-in account where **no** invariant is relaxed — universe time is still monotonic ([I10]), a recall
still costs Twinkle ([G1]), the `Diary` is still immutable ([I2]). If the engine could _do_ anything — advance a clock,
fire a recall, apply a palette — then either the onboarding tour becomes an invariant bypass or the demo's exemptions
leak into shared code, which is exactly the failure [I13] and the demo's isolation rules
([79.demo-page](79.demo-page.md)) exist to prevent. So this plan's central decision is
subtractive: **a step can point and wait, and that is all it can express.** There is no action field, no host-kind
field, no data payload, and no `isDemo`.

This unit closes three gaps concretely. First, there is nothing in the repo today to build on — a `grep` for
`onboard|tour|highlight` across `apps/` and `packages/` returns only unrelated shader and palette comments, so the
step model, the run lifecycle, and the highlight/caption/skip chrome are all new. Second, the two hosts are structurally
unlike each other (a public route with no session versus an overlay on `pages/universe`, plus web-only versus web +
mobile — [00.overview](00.overview.md) §4), so the seam by which a pure engine points at a live control has to be platform-neutral by
construction rather than by convention. Third, [O5]'s replay turns a one-shot tutorial into a durable product surface
reachable from `/me` — which only works if a run is a value that can be started again from zero, with nothing left over
from the previous pass.

## Scope / Non-goals

**In scope**

- **`packages/sequence` — the step model.** `SequenceStep` (a stable id, an i18n caption accessor, an optional anchor
  naming the control to highlight, and how the step advances) and `SequenceScript` (an ordered, readonly list of them,
  generic over the host's anchor and signal unions). Pure TypeScript, no React, no DOM, no RN, no transport ([O1][O2]).
- **The run machine** — one XState v5 machine (`idle → running → completed | skipped | abandoned`) holding only
  control state: run id, step index, step count, outcome (§3.2, [07.state-machine-foundation](07.state-machine-foundation.md)
  conventions). Advancement is an echo-guarded event, so a duplicate signal or a late timer cannot double-advance
  ([O2]).
- **The anchor seam** — a registry keyed by host-owned anchor ids, holding one platform-neutral `measure()` handle per
  registered control, so the engine can locate a control it does not own and never imports ([O2]).
- **The chrome, as three feature slices in both apps** ([O2][O4]): the **highlight** (a non-modal spotlight over
  the measured rect, plus the `SequenceAnchor` wrapper hosts use to register a control), the **caption** (bottom-center
  band, with a pure placement rule that moves it out of the way when the highlighted control is under it), and the
  **skip** (always visible while a run is active, with a quiet step-progress readout).
- **`widgets/sequence-guide`** in both apps — composes the three chrome features over whatever screen is beneath and
  mounts nothing of its own; hosts own the actor and the outcome.
- **Replay as a first-class start** ([O5]) — starting a run is idempotent from any state, clears the previous run's
  index and outcome, and requires no teardown by the caller. The engine records nothing durable.
- **Run outcomes as the host's contract** — `completed`, `skipped` (the user pressed skip, [O4]) and `abandoned` (the
  host unmounted) are distinguishable, so [80.onboarding-tour](80.onboarding-tour.md) can treat a skip and a finish
  differently and [79.demo-page](79.demo-page.md) can show its signup CTA on either ([Z3]-10).
- **Reduced-motion and a11y contract** — the pulse honors `useReducedMotion` (`@cosimosi/ui`); the caption is a polite
  live region; the highlight is decorative and never captures pointer or focus.
- **User-scope reset registration** — the engine's stores are cleared on an account boundary, along
  `resetUniverseUserState()` / `resetTwinkleUserState()` / the palette reset, so a run cannot straddle two accounts
  ([U1]).
- **Engine chrome copy through i18n** (`sequence_*` keys) — restrained, literary, no decorative emoji.

**Non-goals**

- **No script content.** The ten demo beats ([Z3]), their captions, their anchors and their order are
  [79.demo-page](79.demo-page.md); the onboarding wording and beat set are [80.onboarding-tour](80.onboarding-tour.md).
  This plan defines the _shape_ a script must have and asserts it can express both.
- **No fixtures, no domain math.** `DemoScenario` / `DemoDiarySet`, the precomputed splits, gist stages and decay
  texts are [77.demo-fixtures-and-mirror](77.demo-fixtures-and-mirror.md) ([Z4][Z5]).
- **No route, no host page.** The public `/demo` route and its canvas host are [79.demo-page](79.demo-page.md);
  the onboarding overlay on `pages/universe` and the mobile `Universe` screen are
  [80.onboarding-tour](80.onboarding-tour.md).
- **No exposure policy and no durable "already seen" record.** [O3]'s "가입 직후 최초 1회만" and the `/me` replay entry
  (the page itself is [64.my-page](64.my-page.md)'s) are [80.onboarding-tour](80.onboarding-tour.md)'s; the engine never reads or writes whether a tour was seen.
- **No product action.** The engine never calls `Recall`, `Decorate`, `applyPalette`, a clock advance, or any RPC. It
  highlights; the user acts. Time travel and unlimited `SMALL` ([Z2]) live in `pages/demo/model` only
  ([79.demo-page](79.demo-page.md)).
- **No modal enforcement.** The engine does not block the screen, does not disable un-highlighted controls, and does
  not undo a wrong tap — a mis-tap simply does not advance the step.
- **No landing-page or store-listing copy** ([I12] surfaces owned by [81.landing-page](81.landing-page.md)).
- **No new visual identity.** Spotlight, caption band and skip look are applications of
  [56.2d-ui-design-language](56.2d-ui-design-language.md) over [09.design-system](09.design-system.md) primitives and
  tokens; no new token, no new primitive.

## Design

### Placement (FSD §3.1)

```
packages/sequence/src/
├── script.ts            SequenceStep · SequenceScript · SequenceCaption types + defineScript()
├── sequence.machine.ts  the run machine (control state only)
├── select.ts            pure selectors: currentStep · progress · isActive · resolveCaptionPlacement
├── anchor-registry.ts    Zustand: anchorId → { measure() }; register/unregister/reset
├── user-state-reset.ts   resetSequenceUserState()
├── react.ts             the optional React seam: useSequenceRun · useSequenceAnchorRegistration
└── index.ts             public API (named exports, no wildcard barrel)

apps/{web,mobile}/src/features/
├── highlight-next-control/  ui: SequenceSpotlight (the ring) · SequenceAnchor (the register wrapper)
├── show-sequence-caption/   ui: SequenceCaption (bottom-center band, live region)
└── skip-sequence/           ui: SequenceSkip (always-visible skip + quiet progress readout)

apps/{web,mobile}/src/widgets/sequence-guide/
├── ui/SequenceGuide.tsx  composes the three features from a view + handlers passed by the host
└── index.ts
```

The package root stays React-free so the machine and selectors run in plain tests and on both platforms; the optional
`/react` export owns the binding seam once (the `@cosimosi/state-machine` + `@cosimosi/twinkle` precedent, plan 07).
Each app hand-writes its own `ui` — DOM + Tailwind on web, RN `StyleSheet` + `@cosimosi/ui` tokens on mobile — which
is the as-built convention ([45.stardust-ui](45.stardust-ui.md)): **no app slice carries a `*.native.tsx` sibling**;
the parallel mobile slice _is_ the fork (§3.5). No slice imports `three` or a visual entity (§3.4). Each new
feature/widget slice gets a scoped `'fsd/insignificant-slice': 'off'` block in `apps/web/steiger.config.js` with a
stated reason, following the existing per-vertical blocks (their count is the config's, never asserted here).

The engine is a package rather than app-local code for three independent reasons, and any one would suffice: two apps
consume it (lint R4 fails a byte-identical app-local `model`), [79.demo-page](79.demo-page.md)'s import-boundary lint
bans
`@cosimosi/universe`'s server-backed mirrors so the engine may not live there, and the machine must be testable with
no renderer.

### The step model — and the fields it deliberately lacks

```ts
type SequenceCaption = () => string // an i18n accessor, e.g. m.sequence_step_launch

interface SequenceStep<Anchor extends string, Signal extends string> {
  readonly id: string // stable, for tests and telemetry
  readonly caption: SequenceCaption
  readonly anchor?: Anchor // absent ⇒ narration-only step
  readonly advance: { readonly on: 'signal'; readonly signal: Signal } | { readonly on: 'dwell' }
}

interface SequenceScript<Anchor extends string, Signal extends string> {
  readonly id: string
  readonly steps: readonly SequenceStep<Anchor, Signal>[]
}
```

`Anchor` and `Signal` are **host-owned string-literal unions**, so a typo in a script is a compile error in the host
while the engine stays host-agnostic. The engine never enumerates anchors and never validates a script against the
mounted tree.

What the shape omits is the design:

| Absent field                                   | What it would allow                                  | Requirement protected                                                           |
| ---------------------------------------------- | ---------------------------------------------------- | ------------------------------------------------------------------------------- |
| any `run`/`onEnter`/`action`/`effect`          | the engine performing the step for the user          | [O2] direct manipulation; [I13] isolation; [I10][I2][I11][G1] during onboarding |
| `skippable` / `mandatory`                      | a step that cannot be skipped                        | [O4] skip always available                                                      |
| `text` / `caption: string`                     | a hardcoded, unreviewed public sentence              | [I12] honest copy; the `sequence_*` i18n contract                               |
| any domain number (strength, brightness, days) | a formula smuggled into a script                     | [Z6] as amended by plan 77 — the engine holds no domain math                    |
| a data payload                                 | the engine knowing about fixtures or a live universe | [O1] "the difference is only the data fed in"                                   |
| `isDemo` / `hostKind`                          | a sandbox branch in shared code                      | the no-`isDemo` rule (plan 79); [I13]                                           |

`defineScript()` is a type-narrowing identity helper only — it performs no validation, because the interesting
properties are types, not runtime checks.

**Two advance kinds, one rule.** `dwell` is for reading time (the caption holds for `sequence.caption_dwell_ms`, then
the step advances by itself); `signal` is for waiting on the world (the user pressed the highlighted control, or a host
animation finished). A step that waits on something the user must do is **always** a `signal` step — a dwell step must
never be used to fake progress the user has not made.

**Script vs scenario.** The engine's `SequenceScript` carries no data. `DemoScenario`
([77.demo-fixtures-and-mirror](77.demo-fixtures-and-mirror.md)) is the demo's script **plus** its `DemoDiarySet` feed —
the script names steps, the scenario names data. Onboarding supplies a script with no fixture at all, because its data
is the user's real first diary ([O1]).

### The run machine (XState v5, §3.2)

`sequence.machine.ts` — states `idle → running → completed | skipped | abandoned`; every terminal state accepts
`START` again, which is what makes [O5] replay a start rather than a reset ritual.

| Context field | Why it is control state                                                            |
| ------------- | ---------------------------------------------------------------------------------- |
| `runId`       | caller-supplied id for the current pass; distinguishes replays in tests/telemetry  |
| `stepIndex`   | the only cursor; joined to the script by a pure selector                           |
| `stepCount`   | supplied on `START`, so the machine knows the last step without holding the script |
| `outcome`     | `null` while running; `completed`/`skipped`/`abandoned` afterwards                 |

Events: `START { runId, stepCount }`, `ADVANCE { fromStepIndex }`, `SKIP`, `ABANDON`. Rules, all structural:

- **The script never enters context** (§3.2, plan 07's context rule): no arrays, no functions, no accessors. Context is
  JSON-serializable and asserted so by the package's own context-rule test, mirroring
  `packages/state-machine/src/context-rule.test.ts`.
- **`ADVANCE` carries the index it observed** and is guarded out unless `fromStepIndex === context.stepIndex` — the
  `asyncCommandMachine` `attempt`-echo precedent. A double-tap, a duplicated host signal and a late dwell timer from a
  superseded step are all rejected at the machine, not by caller discipline.
- **`ADVANCE` on the last step lands in `completed`.** `SKIP` is accepted in `running` unconditionally — no state
  omits it, which is [O4]'s guarantee expressed as a transition table rather than as a UI habit.
- **The machine never reads a clock.** Dwell timing lives in the React seam (a `setTimeout` cleared on step change and
  on unmount, per the mobile Jest guard that fails a suite leaving a pending timer), so the machine stays a pure
  `(state, event) → state` — the `panelMachine` `openedAt` discipline.

The host owns the actor (`useActorRef`, the `universeNavigationMachine` precedent on `UniverseHomePage`), so it can
observe the outcome and decide what happens next; `widgets/sequence-guide` receives a derived view and handlers as
props and holds no state of its own. Pure selectors in `select.ts` join snapshot + script: `currentStep`, `progress`
(`{ current, total }`), `isActive`.

### The anchor seam — how a pure engine points at a control it does not own

`anchor-registry.ts` is a Zustand store mapping `anchorId → { measure(): Promise<SequenceRect | null> }`, where
`SequenceRect` is `{ x, y, width, height }` in **logical (density-independent) pixels relative to the app window**.
Web's implementation reads `getBoundingClientRect()`; mobile's uses `measureInWindow`. The promise return type is what
makes one seam serve both — RN measurement is callback-based and cannot be synchronous.

**Anchors are registered at composition sites, never inside product feature slices.** Hosts wrap an existing child:
`<SequenceAnchor id="write-diary"><WritingFlowSheet /></SequenceAnchor>`. This is the rule that keeps
`features/write-diary`, `features/recall-star`, `features/change-palette` and every other shipped slice completely
unaware that a sequence exists — the same discipline [79.demo-page](79.demo-page.md) imposes with "no `isDemo` in
`features/*`". Consequently the
highlight's granularity is **the control cluster a page already lays out**, which is the right grain for a spotlight
anyway.

**An unresolved anchor is not an error.** If the step's anchor is not registered (the control has not mounted yet, or
the host mislabeled it), the spotlight renders nothing while the caption and the skip stay — and the step still
advances on its signal. There is therefore **no anchor timeout and no fallback timer**: the caption is the guaranteed
channel, the highlight is an enhancement. Rects are re-measured on step change, on window resize/orientation change,
and on registry change — never per frame.

### The chrome ([O2][O4]) — non-modal by construction

- **Highlight.** A ring/scrim drawn over the measured rect, `pointer-events: none` and `aria-hidden`, with the real
  control keeping its own semantics and focus. Unlike `Dialog`, the sequence chrome **never** calls `useFocusTrap`,
  never renders a blocking backdrop, and never disables anything: the underlying screen stays fully operable including
  controls the current step does not name. A pulse animation of `sequence.highlight_pulse_ms` draws the eye and
  collapses to a static ring under `useReducedMotion` (the `SkySphere` reduced-motion precedent, applied in 2D).
- **Caption.** One line at bottom center ([O2]), rendered in a polite live region so a step change is announced. It is
  resolved by calling the step's accessor at render time, so a locale switch mid-run re-renders the caption through the
  app's existing locale provider. `resolveCaptionPlacement(anchorRect, viewport, bandHeight)` is a pure function
  returning `'bottom' | 'top'`: when the highlighted control's rect intersects the bottom band the caption moves to the
  top band. This is not cosmetic — the shipped universe page puts `WritingFlowSheet` bottom-center, which is exactly
  where the first onboarding beat points.
- **Skip.** Rendered unconditionally whenever a run is active ([O4]) — a single restrained control with no confirmation
  step (replay exists, [O5], so a mis-skip is cheap), beside a quiet `current / total` progress readout. It is the one
  interactive element the chrome owns.

### Replay, exposure, and what the engine refuses to remember ([O3][O5])

Replay is `START` with a fresh `runId`: the index returns to 0, the outcome clears, no teardown is required, and the
run is byte-identical to the first pass because the engine stores nothing durable. Anchor registrations are owned by
the mounted hosts, so a replay re-measures whatever is on screen now.

The engine deliberately holds **no** record of whether a tour was seen. [O3]'s "가입 직후 최초 1회만" needs a durable
per-user fact, and no v2 plan provides one — [60.account-profile-model](60.account-profile-model.md) fixes `users` to
nickname/timezone/locale only and its `AccountService` RPC list has no such field. That gap belongs to
[80.onboarding-tour](80.onboarding-tour.md), which owns exposure policy and the `/me` replay entry; the engine
would otherwise become a persistence owner with two hosts, one of which must persist nothing at all ([Z1][Z7]).

`resetSequenceUserState()` clears the registry and any run-scoped store and joins
`@cosimosi/auth/user-state`'s shared user-state reset registry once. The demo needs nothing from this — it mounts no server-backed mirror
([79.demo-page](79.demo-page.md)) — but the onboarding tour runs
inside a real session, so an unregistered store would leak one account's run into another's subtree.

### Golden-parity stance

This unit re-implements **nothing** and therefore carries **no golden-parity obligation**. It defines no pure function
over the domain: the only arithmetic is the step cursor, `progress`, and a rect/viewport comparison — derived values
with no Go counterpart and no fixture. Every domain function the demo needs **already has a shared TS mirror that is
already parity-pinned**, and they are _consumed_, not re-written: `effectiveStrength`, `effectiveBrightness`,
`effectiveElapsedDays`, `decayStage`, `decayDepth`, `decayStageText`, `accessibilityCostWeight`,
`semanticize`, `gistCoordinate`, `potentiate`/`depress`/`downscale`/`applyTemporalBonus`/`initialStrength`, `reshape`
(`@cosimosi/memory-logic`), `@cosimosi/twinkle-logic`, and `arousalToInitialStrength` (`packages/emotion`) — each
pinned by a TS test that reads a Go fixture directly, across six fixtures; `elapsedUniverseDays`,
`createEmotion`/`moodColor` sit under their own unit suites, and the unpinned stragglers (`slowFactor`,
`toEmotionSlices`) get their pins **in plan 77** before the demo reuses them (77's reuse ledger is the authority on
which pin covers what). The single genuine gap (synapse formation has no TS mirror) is answered by
[77.demo-fixtures-and-mirror](77.demo-fixtures-and-mirror.md) with hardcoded synapse rows, not by a fourth mirror.
[Z6]'s "수식 이중 구현 허용" is therefore not exercised by this unit at all, and plan 77's amendment
("the demo reimplements nothing") stands.

The drift guard is the step model itself: `SequenceStep` has **no numeric domain field**, so a formula cannot be
expressed in a script and cannot be copied into the engine; `scripts/lint-fsd-layout.mjs` R4 catches a copy-pasted pure
module between the apps; and `packages/sequence`'s dependency list (`xstate`, `zustand`, React only as a peer for the
`/react` export) keeps `@cosimosi/memory-logic`, `@cosimosi/api-client` and `@cosimosi/demo` out of the engine
entirely.

### Copy (i18n) — restrained, and reviewed once

The engine's own chrome keys use the `sequence_*` prefix and name a UI role, never a domain term
(`spec/tech/i18n.md` §2):
`sequence_skip_action`, `sequence_progress` (with `{current}`/`{total}` placeholders — the `error_internal`
`{requestId}` precedent). Script captions belong to their feeding plan: `demo_*` for [79.demo-page](79.demo-page.md),
`sequence_*` for [80.onboarding-tour](80.onboarding-tour.md). Both catalogues
(`packages/i18n/messages/{en,ko}.json`) are edited together, `pnpm gen:messages` runs, the generated files are
committed and `pnpm check:gen` gates freshness. `pnpm lint:raw-strings` covers the chrome; the caption type covers the
scripts. The voice is plain and unhurried — an instruction, not a sales line, no decorative emoji, no translation-ese.

## Acceptance Criteria

1. A single engine (`@cosimosi/sequence`) runs both feeds: the demo's fixture-driven script and onboarding's script over
   the user's real first diary differ **only** in the injected script and data, with no branch, flag or host-kind field
   anywhere in the package ([O1]; the no-`isDemo` rule, [79.demo-page](79.demo-page.md)).
2. `SequenceStep` carries a stable id, an i18n caption accessor, an optional host-typed anchor, and one of exactly two
   advance kinds (`signal`, `dwell`) — and carries **no** action/effect field, **no** `skippable` field, **no** string
   caption, **no** domain number, and **no** data payload ([O2][O4][I12][I13]).
3. The engine performs no product action and issues no RPC: every state change during a run is the user pressing the
   real control on the real screen, so during onboarding [I10] monotonic time, [I2] `Diary` immutability, [I11] the
   untouched meaning layer and [G1] paid recall all remain in force ([O2][I13]).
4. `packages/sequence` depends on `xstate` and `zustand` only (React as a peer for its `/react` export) and imports
   neither `@cosimosi/api-client`, `@cosimosi/demo`, nor any `@cosimosi/universe` read mirror; the package is
   importable from [79.demo-page](79.demo-page.md)'s import-boundary lint scope without exception ([I13]).
5. The run machine is one XState v5 machine (`idle → running → completed | skipped | abandoned`) whose context holds
   only `runId`, `stepIndex`, `stepCount`, `outcome`; the script, rects and registry live outside it and the context is
   JSON-serializable, asserted by a context-rule test (§3.2, plan 07).
6. `ADVANCE` echoes the step index it observed and is ignored when stale, so a duplicate signal, a double tap, or a
   dwell timer from a superseded step cannot advance the run twice; the machine never calls `Date.now()` ([O2]).
7. While a run is active, a skip affordance is visible on every step — `SKIP` is accepted in every non-terminal state
   and no step can opt out of it — and skipping ends the run immediately with the `skipped` outcome and no confirmation
   prompt ([O4]).
8. A caption renders at bottom center for every step, in a polite live region, resolved from an i18n accessor (never a
   hardcoded string) and re-rendered on a locale change; when the highlighted control's measured rect intersects the
   caption band, the caption relocates by the pure placement rule ([O2]).
9. The step's anchor is highlighted by a non-modal spotlight over its measured rect: it never traps focus, never
   intercepts pointer events, never disables un-highlighted controls, and its pulse collapses to a static ring under
   reduced motion ([O2], plan 09).
10. An unregistered or unmeasurable anchor degrades to caption-only with no timeout, no error surface and no change to
    how the step advances; the run remains completable ([O2][O4]).
11. Anchors are registered only at composition sites via the `SequenceAnchor` wrapper — no `features/*` product slice
    and no `entities/*` slice imports `@cosimosi/sequence` ([I13]; the no-`isDemo` rule,
    [79.demo-page](79.demo-page.md)).
12. A run can be replayed at any time by starting again with a fresh run id, from any terminal state, with no teardown
    by the caller and no residue from the previous pass; the engine persists nothing about a run and holds no
    "already seen" record ([O5][O3][Z7]).
13. The engine's stores are cleared on an account boundary through `resetSequenceUserState()`, registered in both apps'
    shared user-scope reset inventory ([U1]).
14. The engine's chrome ships in **both** apps (`features/highlight-next-control`, `features/show-sequence-caption`,
    `features/skip-sequence`, `widgets/sequence-guide`), sharing every `model`-level artifact verbatim through
    `packages/sequence`, with each app hand-writing its own `ui` and no app slice carrying a `*.native.tsx` sibling
    (§3.5, [00.overview](00.overview.md) §4).
15. The machine and selectors are unit-testable with no renderer, no DOM and no transport: a scripted event sequence
    yields deterministic view snapshots, and every dwell timer is cleared on step change and unmount (no suite leaves a
    pending timer, ARCHITECTURE §4).
16. All engine-owned user-visible copy resolves through the i18n seam under the `sequence_*` prefix with both
    catalogues populated and `pnpm check:gen` / `pnpm lint:raw-strings` green ([I12], `spec/tech/i18n.md` §2).

## Policy / Values Impact

- **policy / ux:** the rules this engine makes true land in a new `spec/policy/ux/sequence.md` at `/implement-job`
  (**do not** pre-create): guidance happens on the real screen, never as video or slides ([O2]); one caption at a time,
  bottom center, relocated only to avoid the control it points at; skip is always visible and never confirmed ([O4]);
  the chrome is non-modal — nothing is blocked or disabled, and a mis-tap is simply not progress; the engine points and
  waits, it never acts for the user; a replay is a fresh run and nothing carries over ([O5][Z7]); the highlight is
  decorative and the caption is the guaranteed channel. Exposure policy ([O3]) is written by
  [80.onboarding-tour](80.onboarding-tour.md) in its own doc, not here.
