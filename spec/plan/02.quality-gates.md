# 02. quality gates

> Quality gates - reproducible local and CI checks for clean roots, architecture boundaries, and vocabulary drift.
> Scope: Infra | Status: built

## Purpose

The clean platform is only useful if every later unit can trust the same guardrails. This unit turns "does it still fit
the architecture?" into runnable gates: formatting, linting, typechecking, tests, generated-code freshness, FSD
boundaries, Go vet/test/build, and a ubiquitous-language drift check. It catches architectural mistakes before feature
work accumulates on top of them.

## Scope / Non-goals

**In scope**

- Root scripts for fast local checks and the full merge gate: `lint`, `typecheck`, `test`, `check`, plus app-specific
  scripts where each app needs them.
- Web gates: TypeScript build, oxlint, Vitest, Steiger FSD checks, ESLint boundary checks, and the React Compiler
  diagnostics (`eslint-plugin-react-hooks` recommended-latest) over `apps/web/src`. The **diagnostics only** — the
  compiler's babel transform is deliberately not in the build, and job 144 records why: the app reads copy by calling
  `m.*()` during render, against a module global `setActiveLocale` mutates, so the compiler correctly caches a
  component that has no reactive input and the copy keeps its first language. Making locale a real React input is the
  prerequisite, and it is a change with its own UX decision in it rather than a build-config flag.
- Mobile gates: React Native ESLint and TypeScript checking without requiring an emulator.
- Workspace-package gates: one shared ESLint flat config over `packages/**`, with `react-hooks` scoped to the React
  seams.
- Blog gates: Astro build and TypeScript/type generation through the existing build path.
- Backend gates: `gofmt` check, `go vet`, `go test ./...`, and `go build ./...`; Docker is the fallback path when the
  host Go toolchain is not available.
- Generated-code freshness checks for proto, sqlc, and values generation: a full check runs `pnpm gen` and fails if a
  generator changes committed generated outputs.
- Ubiquitous-language lint that prevents domain/visual vocabulary drift across active source roots.
- CI workflow updates so pull requests and direct pushes run the same logical gates against the clean roots only.

**Non-goals**

- No product feature tests, golden-parity tests, Playwright journeys, or visual regression. Those arrive with domain
  and presentation units.
- No deployment gate and no production secrets.
- No attempt to make reference app roots pass anything. They stay outside every active gate.
- No domain vocabulary expansion except the lint allowlist/rules needed to enforce the existing glossary.

## Design

### Gate shape

The repo has two levels of command:

- **Fast local gates**: commands a developer can run while building a slice, scoped by app/package when possible.
- **Full repo gate**: one root command, `pnpm check`, that runs every non-deployment validation required before a
  commit is considered healthy.

The full gate is composed from:

1. `pnpm check:node`: the Node floor and its `.node-version` pin, **and** that every declared `workspace:` dependency
   is actually installed — a stale tree fails here rather than as a confusing `TS2307` later.
2. `pnpm lint`: web oxlint + FSD checks, mobile ESLint, **`packages/**` ESLint**, api gofmt cleanliness, and the
   repo-wide scanners — `lint:fsd:layout`, `lint:observability`, `lint:language`, `lint:raw-strings`,
   `lint:style-escapes`, `lint:persistence`, `lint:spec`, `lint:comments`, `lint:public-copy`, `lint:error-reasons`,
   `lint:test-reachability`.
3. `pnpm typecheck`: every package, web TypeScript, mobile TypeScript, and blog Astro build/type generation.
4. `pnpm test`: values generator fixtures, package/web/mobile Vitest suites, `test:guards` (every scanner's negative
   `--probe`), and api `go test ./...`.
5. `pnpm build:site`: the blog build, then the web build, then `stage-blog.mjs` — the production build command, in the
   production order (see _The production build is the gate's build_). Never `build:web` and `build:blog` on their own.
6. `pnpm vet:api` and `pnpm build:api`.
7. `pnpm check:gen`: run `pnpm gen` and fail if generated output paths are dirty.

The commands deliberately skip reference app roots and archived spec directories.

### Frontend and workspace checks

`apps/web` keeps oxlint as the fast lint. Steiger and ESLint boundaries enforce the FSD layer direction from the empty
shell onward:

- one-way layer imports (`app -> pages -> widgets -> features -> entities -> shared`);
- structural FSD rules from `@feature-sliced/steiger-plugin`;
- a probe command, `pnpm --filter @cosimosi/web lint:boundaries:probe`, that proves a forbidden `entities -> pages`
  import fails through `boundaries/dependencies`.

Vitest is the unit-test runner for pure TS and React logic. The gate does not invent product tests for empty slices;
`vitest run --passWithNoTests` proves the runner is wired until real tests land.

`apps/mobile` has a host-only gate: ESLint and TypeScript pass without booting iOS or Android. Native simulator
verification is a later implementation concern for mobile-facing slices.

`packages/**` has its own ESLint pass, `pnpm lint:packages`, over one shared flat config at the repo root
(`eslint.config.packages.mjs`). It exists because a gate's scope is part of the rule: `lint:web` runs with cwd
`apps/web` and `lint:mobile` with cwd `apps/mobile`, so neither could ever see the cross-app core — 23 packages went
unlinted by any JS/TS linter while both reported green.

- `@eslint/js` recommended + `typescript-eslint` recommended over every `packages/**/*.{ts,tsx}`;
- `eslint-plugin-react-hooks` recommended-latest, **path-scoped** to where a React seam actually lives
  (`packages/**/react.{ts,tsx}`, `packages/**/react/**`, `packages/ui/**`, and both scene packages —
  `packages/3d-renderer/src/**`, `packages/universe-render/src/**`, which are React top to bottom without a single
  file named `react.*`). Package roots outside those globs are deliberately React-free, so a blanket config would
  report hook rules against files that can never grow a hook. `exhaustive-deps` is raised from the plugin's `warn`
  to **`error`**.
- `--max-warnings=0`, and generated output is ignored (owned by its generator, per `.prettierignore`'s principle).
- **`react-hooks/immutability` is off for the two scene packages.** Every layer mutates preallocated objects each
  frame — a uniform's `.value`, a matrix, a pose record — because that is the renderer's architecture (§3.2/§3.3:
  per-frame values never enter React state). The rule reported 17 such writes and no drift; React Compiler itself does
  not apply that restriction to `useFrame` bodies. Scoped to those two packages, on everywhere else.
- **`react-hooks/refs` and `react-hooks/set-state-in-effect` are off for a named list of ten files**, not for
  `packages/**`. Three idioms account for all 26 sites: the latest-ref idiom, ref-guarded lazy creation (a `useState`
  initializer there runs twice under StrictMode and orphans a live actor, timer or GPU device), and effects that must
  notify and commit in one pass. A file list is a ratchet: a new file reaching for either idiom fails the gate, and the
  list can only shrink. Every other rule in the set is on and the tree is green against them.
- `pnpm lint:packages:probe` (`scripts/probe-packages-lint.mjs`) proves it bites: an unused import, a missing hook
  dependency, a conditional hook, and a missing dependency in an ordinary renderer layer must each be reported, **and**
  the same hook violation written outside the React file scope must not be — otherwise the config's scoping is
  decoration.

`apps/blog` keeps the explicit Astro gate: `astro build` performs the static build and type generation used by CI.

### Probe hermeticity

**A probe never writes fixtures where another process's ordinary scan can see them.** The negative
probes (web/mobile boundary, demo isolation, sequence isolation, packages lint) plant deliberate rule
violations to prove the real configs report them; planted inside the scanned source roots, those
fixtures made the gates non-hermetic — any two overlapping gate invocations (two agent sessions, a
husky pre-commit racing a manual `pnpm check`) could fail each other with no code at fault, and a red
gate that self-heals trains people to rerun until green.

The mechanism is `scripts/probe-workspace.mjs`: each probe builds a throwaway `.probe-ws-*` workspace
directly under its app root (repo root for the packages probe), lays the fixtures out at the app's
own relative paths, and lints them with the app's own ESLint installation through a thin wrapper
config that re-exports the real config. Three constraints shape it:

- The workspace anchors under the app root, not the OS temp dir, because config machinery resolves
  modules from its own location — mobile's eslintrc resolves `extends`/plugins by walking
  node_modules up from the config file.
- The wrapper pins `boundaries/root-path` to the workspace root, because `eslint-plugin-boundaries`
  matches element patterns against process.cwd() by default and ESLint's `cwd` option does not move
  it.
- Legacy eslintrc vs flat config is discriminated by the real config's filename, so an app migrating
  config formats flips the wrapper automatically.

Belt-and-braces, every ordinary scanner also excludes the probe-fixture name patterns
(`**/.probe-*/**`, `**/__boundary_probe_*/**`): oxlint, the web/mobile/packages ESLint configs,
steiger, prettier (`.prettierignore`), and `lint:fsd:layout`'s walkers — so even an interrupted
probe's leftovers cannot fail an unrelated run (they are also gitignored). The exclusions are
narrow by construction: only probe-named directories are invisible, and a violation planted in a
real slice path still fails the ordinary lint. `scripts/probe-hermeticity.test.mjs` (in
`test:guards`) pins both halves: it overlaps a live probe with an ordinary oxlint sweep and asserts
both pass, then plants every leftover shape (`.probe-*` inside three scanned roots,
`__boundary_probe_*` under src, a `.probe-ws-*` workspace at the app root) and asserts every
scanner stays green while they exist.

Because the fixtures no longer ride the ordinary scan, each boundary probe also pins the gate
wiring itself: it fails if the app's `lint` chain stops invoking the boundary scan or the scan's
`src/**` glob narrows — the workspace lint proves the rules fire, and the wiring assertion proves
the gate still routes the real tree into them.

New probes follow the same rule: fixtures go through `createProbeWorkspace`, never into a scanned
root, or stay in memory the way the ubiquitous-language probes do.

### Backend checks

The Go gate is intentionally plain and lives behind `scripts/go-check.mjs`:

- `gofmt` must be clean;
- `go vet ./...` must pass;
- `go test ./...` must pass;
- `go build ./...` must pass.

When host Go is missing or blocked, the helper runs the same commands in `golang:1.26` with `apps/api` mounted at
`/app`. The fallback is not a weaker gate; it is the same command surface in a controlled toolchain.

### Generated-code freshness

`scripts/check-generated.mjs` runs `pnpm gen`, then checks the generated output pathspecs with `git status --porcelain`.
The generated pathspecs include proto, sqlc, values, package `gen/` folders, and generated TS/CSS files, so the full
gate fails whenever committed generated outputs are stale.

### Ubiquitous-language lint

The lint reads [ubiquitous-language.md](../ubiquitous-language.md) as the vocabulary source and scans active source
roots only. It catches:

- a rendering word (`star`, `cell-star`, `filament`, `constellation`) appearing outside visual/UI paths;
- a direct memory-to-memory edge type/table/message that would model an emergent relationship;
- known forbidden synonyms for canonical domain terms.

The probe modes `--probe=visual` and `--probe=edge` deliberately fail those two core drift classes without writing
fixture files into the tree. False positives are resolved by narrowing path allowlists, not by weakening the vocabulary
rule.

### Runners, segments, and the installed tree

Four gates cover the class of defect where a rule exists, a scanner exists, and nothing connects them.

- **`check:node` also verifies the installed tree.** Beside the runtime/pin check it compares every
  `workspace:` dependency declared under `apps/*` and `packages/*` against what is on disk, and fails with "run
  `pnpm install`". A tree installed before a dependency was added otherwise surfaces as
  `TS2307: Cannot find module` on a package whose dependency IS declared and IS locked — which reads as a broken
  `tsconfig` or `exports` map. It runs first, before any compiler can produce that error, and does no network I/O.
- **`lint:test-reachability`** (`scripts/check-test-reachability.mjs`) asserts no file under `apps/*/src` or
  `packages/*` reads as a test or check while being collected by nothing. Both runners collect by filename — Jest's
  defaults (which the React Native preset does not override) and Vitest's both match `*.test.*` / `*.spec.*` and
  `__tests__/` — so a `*.probe.ts` in an app's source tree typechecks, reviews like a test, and never runs. Its
  `--probe` proves the rule fires on such a name and leaves plain test helpers alone.
- **The app-layer segment set is enforced against directories, not only loose files.** `lint:fsd:layout` previously
  rejected a stray file at the app root while an entire unknown segment passed — the violation that actually occurs,
  since nobody drops one file at `app/`'s root. The closed set is per platform (`routes` for web, `navigation` for
  mobile; that difference is the contract, so neither app may borrow the other's name), and
  `lint-fsd-layout.test.mjs` carries the negative case plus one proving a crashed probe fixture is still ignored.
- **`lint:observability` gained the composition root, the blog, and a negative probe.** `apps/api/cmd` is scanned
  with an empty allowlist — the composition root sees every concrete (§2.4), which is exactly why the SDK is tempting
  there and why it must still arrive through the platform adapter — and `apps/blog/src` is listed so the rule holds
  the first time the blog gains telemetry. The gate already had a liveness anchor (the allowlisted files must still
  contain the SDK import, proving the detector works on real content); `--probe` adds the half an anchor cannot see,
  that the allowlist is narrow enough to spare only the boundary file it names and not a lookalike beside it.

### The production build is the gate's build

`pnpm check` builds the site through **`pnpm build:site`** — the same command `DEPLOY.md` §2 and `wrangler.jsonc`
name — rather than calling `build:web` and `build:blog` itself. Those two were run in the opposite order from the real
build and the staging step was skipped entirely, so `scripts/stage-blog.mjs` never ran in CI. That script exists
because Vite empties its `outDir`: a blog staged before the web build is silently deleted and the deploy ships with
`/blog/**` missing, a production 404 nothing in the build output complains about. It carries two assertions that turn
that into a build error, and until now neither executed anywhere except the Cloudflare Pages build. One command is the
only build path, so the order cannot diverge again.

### Error-reason registry parity

`pnpm lint:error-reasons` (`scripts/check-error-reasons.mjs`) asserts that every stable reason the backend can put on
the wire is registered on **both** sides of the seam: the FE `ERROR_REASONS` union in `packages/errors/src/core.ts` and
the §2 registry table in `spec/policy/platform/errors.md`, whose own closing rule already requires that row.

The gate exists because an unmapped reason legitimately falls back to the coarse Connect-code copy. That default is
right, and it is also what makes an unregistered reason invisible — nothing fails, and the surface shows a sentence
written for a different failure. So the rule is **membership only**: bespoke FE copy stays optional, and demanding it
would contradict the error taxonomy's deliberate non-goal.

Two parsing details are load-bearing:

- The FE set is read from the `ERROR_REASONS` **object literal**, not from every uppercase string in the file. The
  `codeName()` helper below it returns bare code names (`NOT_FOUND`, `ABORTED`, …) which are not registry entries;
  counting them would mark an unregistered reason as present, which is exactly how one hides.
- The check is one-directional by design. `apperr`'s platform fallbacks (`INTERNAL`, `UNKNOWN`, the named
  `PLATFORM_*`) have no emitting `reasons.go`, and `PLATFORM_<CONNECT_CODE>` is built at runtime, so a strict two-way
  diff would fail on all of them. They sit in a named allowance; a registry entry outside it that nothing emits is
  reported as a note, since it is either stale or newly platform-owned.

`pnpm lint:error-reasons:probe` (in `test:guards`) proves it bites: an unregistered reason must fail on both sides, a
fully registered one must pass, and a `codeName()` string must not be mistaken for a member. The probe runs the
scanner's pure functions over in-memory fixtures and writes no file, so it is hermetic by construction and needs none
of the `.probe-ws-*` workspace machinery the ESLint-config probes require.

### CI

CI runs the root gate itself — one `check` job: `pnpm install --frozen-lockfile` then `pnpm check`, with the Go
toolchain pinned to match `apps/api/go.mod` rather than the runner's ambient version. Running the same command rather
than a re-split of it is what keeps CI parity a property instead of a promise: a gate added to `pnpm check` is in CI the
same commit, with no workflow edit. No job touches reference app roots. No job needs production secrets.

## Acceptance Criteria

1. The root package exposes documented `lint`, `typecheck`, `test`, and `check` scripts; `pnpm check` runs every active
   non-deployment gate.
2. CI runs the same logical gates on pull requests and direct pushes to the active branches, with no references to
   reference app roots.
3. Web gates include TypeScript, oxlint, Vitest, Steiger, and ESLint boundary checks; a deliberate forbidden layer
   import fails.
   3a. `apps/web/src` carries the React Compiler diagnostics through `eslint-plugin-react-hooks`; oxlint's
   `react/rules-of-hooks` alone cannot express them, and the packages config never sees the app. `refs` and
   `set-state-in-effect` are off for a named list of fifteen app files carrying the same three idioms the packages
   config names, so a new file reaching for one fails the gate.
4. Mobile gates include TypeScript and ESLint and run on a host machine without launching an emulator.
   4a. `packages/**` is linted by `pnpm lint:packages` inside `pnpm lint`; `react-hooks/exhaustive-deps` and
   `rules-of-hooks` are errors on the React seams, and `pnpm lint:packages:probe` proves both fire while a hook rule
   outside the React file scope does not.
5. Backend gates include `gofmt` cleanliness, `go vet ./...`, `go test ./...`, and `go build ./...`; the Docker
   fallback runs the same checks.
6. Generated-code freshness is enforced: after `pnpm gen`, changed generated outputs fail the full gate.
7. Ubiquitous-language lint fails for domain/visual vocabulary drift and for a modeled memory-to-memory edge.
8. The checks do not import, install, lint, typecheck, test, or build reference app roots.
9. Gate probes are hermetic: no probe writes fixtures into a scanned source root, every ordinary
   scanner excludes the probe-fixture name patterns, and `scripts/probe-hermeticity.test.mjs` (in
   `test:guards`) proves a probe overlapping an ordinary lint scan leaves both green — while a
   violation planted at a real (non-probe-named) path still fails the ordinary lint.
10. Error-reason registry parity is enforced: a reason constant in any `internal/*/rpc/reasons.go` that is absent from
    `ERROR_REASONS` or from the `policy/platform/errors.md` §2 table fails `pnpm lint:error-reasons`, the check demands
    registry membership only (never bespoke copy), and `pnpm lint:error-reasons:probe` proves the rule and the
    object-literal parser both fire.
11. `pnpm check` builds the frontend through `pnpm build:site`, so `scripts/stage-blog.mjs` and its ordering
    assertions run in CI; no gate builds web and blog in an order the real build never uses.
12. A test-shaped file no runner collects fails `pnpm lint:test-reachability`; a stale install fails `pnpm check:node`
    with an actionable message; an unknown app-layer **segment** fails `pnpm lint:fsd:layout`; and the observability
    boundary covers `apps/api/cmd` and `apps/blog/src` with a negative probe proving its allowlist is not over-broad.
