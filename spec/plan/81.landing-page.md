# 81. landing page

> Landing page — the product's front door: the public `/` a signed-out visitor lands on, laid out in the exact seven
> sections [K1] prescribes, ending in a demo CTA before a signup CTA. It takes `/` from the universe (which moves to
> `/universe`) by adding the one `gateDecision` arm reserved for it, states the honest [M5] definition on the page
> because §1.4 makes it the core product message, summarizes PRD §9's five strands as lay cards that link to the blog
> rather than citing a paper, and speaks Korean and English off the shipped negotiation plus a manual switch. It owns
> the origin's SEO root and corrects two stale "no real deployment yet" claims. Scope: FE | Status: planning
>
> Layer P. Home: `apps/web/src/pages/landing/{index.ts, ui/, model/, config/}` on a public route under `rootRoute`.
> It fills the entry seam `packages/auth/src/gate-decision.ts` has
> carried since v1 ("Reserved, not built"), and leaves the moving version of every claim it makes to
> [79.demo-page](79.demo-page.md).

## Purpose

Today the product has no front door. A stranger who opens `https://cosimosi.haeram.me` is redirected to a sign-in form
by [53.auth-universe-gate](53.auth-universe-gate.md)'s gate — a password field for a product they have never heard of.
[U4] calls the marketing page a MUST for exactly this reason: it is the first contact for everyone who is not already a
user, and every other v2 acquisition surface (the demo, the blog, the invite link) assumes it exists to send people
onward.

The harder problem is what the page must say. cosimosi's pitch is unusually easy to overclaim: it is built on memory
neuroscience, it moves, and it looks like a brain if you squint. [I12] forbids all three temptations — the copy says
"inspired by engram theory", never "works like a brain"; it never presents the 3D coordinates as the brain's real
coordinates ([I5] — they are emergent visualization); it claims no therapeutic or clinical effect. [K2] adds the
discipline that makes honesty easy to keep: the landing carries only the summary a non-specialist reads (§1.5 says
neuroscience knowledge is never required of a user), and every paper and DOI lives on the blog. A landing page with a
citation list is a landing page that will eventually cite something it does not implement.

And one thing the page must say, whether or not it sells: **[M5]**. The universe's color is not the average of your
emotions — it is a mirror of the ones you keep returning to. §1.4 makes that definition the core of the product
message, and [K1] step 4 requires it on the page, because a user who believes the sky averages their feelings will read
their own universe wrong for months. It is the one place where the honest sentence is also the interesting one.

Finally, this is where the app's routing becomes an information architecture: `/` has meant "the universe, or a redirect
to login" since v1, and now means "the universe if you are signed in, the landing if you are not" — the single reserved
gate change, made so that a visitor, a returning user mid-refresh and a deep link each resolve without a flash.

## Design

### Placement (FSD §3.1 — a whole screen is a page, and nothing here is reused)

```
apps/web/src/pages/landing/
├── index.ts                      public API = LandingPage
├── ui/LandingPage.tsx            renders the section tuple, in order, and nothing else
├── ui/LandingHeroScene.tsx       the hero canvas + its poster fallback
├── ui/sections/*.tsx             one component per section id
├── model/sections.ts             the [K1] order as a literal tuple + the section→component record
└── config/theory-cards.ts        the five §9 strands and the five tour items (authored content)
```

Every section is single-reference by design and none is reused anywhere, so **no `features/` or `widgets/` slice is
created** — which is also why `apps/web/steiger.config.js` needs **no** new `fsd/insignificant-slice` exemption block
(one is required only per new feature/widget slice). Layer direction is respected in the one place it bites: `pages`
may not import `app`, so the locale-persistence seam (`app/providers/i18n-config.ts`) reaches the page as an injected
callback from the route wrapper, exactly as `onOpenReader`/`onExit` do today.

### The route change — `/` becomes public, the universe becomes `/universe`

`packages/auth/src/gate-decision.ts` adds `'landing'` to the `GateDecision` union, and **exactly one arm changes**:
settled `signedOut` → `'landing'`. `signingIn`/`expired`/`failed` stay `'login'` (a returning user whose token died is
not a marketing arrival); `bootstrapping`/`refreshing` stay `'hold'`, which is what stops the landing flashing for a
returning user mid-refresh; `authenticated` stays `'universe'`, so a signed-in user never sees the landing.

Widening the union would silently pass every `=== 'login'` comparison in the consumers, so the same file exports
**`requiresSignIn(decision: GateDecision): boolean`** — an exhaustive `switch` true for `'login'` and `'landing'`. Every
consumer asks that question instead of comparing strings, so a future fifth arm becomes a compile error inside one pure
function rather than a silent behavior change in four files. That is the structural guard for the widening.

| Consumer                                            | Change                                                                                                                                                                                                                                                                         |
| --------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `app/routes/route-tree.tsx`                         | `landingRoute` at `/` under `rootRoute`, no `beforeLoad`; `universeRoute` re-parented to `/universe` under `authenticatedRoute` (the other three product routes untouched)                                                                                                     |
| `app/routes/guards/auth-gate.ts`                    | the guard redirects on `requiresSignIn(...)` — a deep link into a product route still goes to `/login?from=…`, never to the marketing page, so the return target survives; `loginReturnTarget`'s fallback becomes `/universe` and `/` joins `/login` in the never-replayed set |
| `app/routes/route-screens.tsx`                      | `AuthenticatedLayout` navigates away on `requiresSignIn(...)`; a new `LandingRoute` wrapper supplies `onTryDemo` / `onSignUp` / `locale` / `onSelectLocale`; `LoginRoute` needs no change (`'landing'` never reaches it)                                                       |
| `apps/mobile/src/app/navigation/NavigationRoot.tsx` | the stack selector uses `requiresSignIn(gateDecision(status))`, so `'landing'` maps to the login stack — mobile has no landing (the web-only waiver)                                                                                                                           |

`LandingRoute` reads the live snapshot and resolves by decision: `'universe'` → navigate to `/universe`; `'hold'` → the
shipped neutral `AuthHold`; `'login'` → navigate to `/login`; `'landing'` → the page. So `/` is the app's single
decision point, and no URL means two things at once.

**Trailing slash.** `createAppRouter` pins `trailingSlash: 'never'` explicitly, making the canonical client form
slashless (`/demo`, `/universe`) with the root as the sole exception; the shell's `<link rel="canonical">` and the root
sitemap publish that same form. `/blog/` is outside the client router — the Worker's asset handler serves it — so
[82.blog-site](82.blog-site.md)'s Astro `trailingSlash: 'always'` does not conflict, and no product route's matching
behavior changes ([tech/web-routing.md](../tech/web-routing.md) §7).

The Worker needs no change: `assets.not_found_handling: "single-page-application"` already serves `/universe` and
`/demo` deep links from the same `index.html` ([DEPLOY.md](../../DEPLOY.md) §1).

### The section contract — [K1]'s order is a type, not a layout convention

`model/sections.ts` declares the order as a **fixed-length literal tuple**:

```ts
export const LANDING_SECTIONS = [
  'hero',
  'demo-cta-top',
  'feature-tour',
  'mirror',
  'theory',
  'blog',
  'closing-cta',
] as const satisfies readonly [
  'hero',
  'demo-cta-top',
  'feature-tour',
  'mirror',
  'theory',
  'blog',
  'closing-cta',
]
```

with `LandingSectionId = (typeof LANDING_SECTIONS)[number]` and a `Record<LandingSectionId, ComponentType>` the page
maps over as its **only** render path. Dropping the `'mirror'` section, putting the theory cards ahead of the [M5]
definition, or adding an eighth section without placing it in the tuple is a `tsc` failure, not a review catch — which
is what the risk register's Epic Q row asks for when it says the honest [M5] definition is _required_ on the landing
page ([00.overview](00.overview.md) §3).

CTA order gets the same treatment one level down. `'demo-cta-top'` renders a `DemoCta` alone; `'closing-cta'` renders a
single `LandingClosing` that hardcodes `DemoCta` then `SignUpCta` and **exposes no ordering prop**, so [K3]'s
"demo before signup" is not something a call site can get wrong. Both demo CTAs target `/demo`; the signup CTA targets
`/signup` ([63.signup-flow-ui](63.signup-flow-ui.md)).

### The hero — the empty universe

The hero mounts the real renderer through `@cosimosi/3d-renderer`'s `UniverseCanvas` with exactly two layers:
`SkySphere` (the shipped `rendering.active_skin` emotion sky, fed an authored illustrative stop set built from
`packages/emotion`'s `moodColor`) and `LatentField` (`rendering.latent_star_count` / `latent_field_radius` /
`latent_star_size`), at `rendering.max_pixel_ratio`. There is **no** `StarField`, cell-star or filament layer, no
`NebulaField`, no `CameraControls`, no sim bridge and no frame pump: the hero is not navigable, and a marketing page is
not where the frame budget the demo needs one click later should go.

It reads as the sky before any memory is in it — honest twice over: it is literally what a new account looks like
([U2], "the first universe is empty"), and it puts nothing on screen that copy could mis-describe as anatomy ([I5]).
**Rejected:** a fixture-backed hero showing real stars and a constellation. It would duplicate
[79.demo-page](79.demo-page.md)'s `DemoUniverseScene`, pull `@cosimosi/demo` and `packages/force-sim` into the first
paint of the page a stranger opens on mobile data, and preempt the very thing [K1] step 2's CTA exists to deliver.

`useReducedMotion()` from `@cosimosi/ui` and a failed renderer init both fall back to a committed raster poster in
`apps/web/public/`; the poster is the default and the canvas replaces it once initialized, so a visitor never waits on
WebGPU to see the hero.

### The fun-first tour, the [M5] mirror, and the five theory cards

- **Feature tour ([K1] step 3)** — five items in a fixed five-tuple, each `{ id, titleKey, bodyKey }`, written from the
  user's point of view and in the order the PRD lists: `write` (a diary becomes a star), `constellate` (stars share
  neurons and drift into constellations), `fade` (unremembered stars dim and lose their words), `revive` (recalling one
  brings it back, changed), `color` (the whole sky takes your color). Each item is a static, token-styled treatment —
  no canvas. Five live canvases on a marketing page is a battery decision, and [K3] sends anyone who wants motion to
  `/demo`.
- **The mirror ([K1] step 4, [M5])** — the definition, stated plainly: 우주의 색은 내 감정의 평균이 아니라, 내가 자주
  떠올리는 감정의 거울입니다. Beside it, a labelled illustrative pair of swatch rows built from `moodColor` — the same
  set of memories, averaged versus weighted by what was re-read — marked as illustration, never as anyone's data.
- **Theory cards ([K1] step 5, [K2])** — five cards, one per §9 strand, ids `engram`, `spatial-representation`,
  `synapse-time`, `reconstructive-recall`, `forgetting-accessibility`. Each is a lay paragraph whose type has **no
  citation field**, and each links to `/blog/#<id>` — the same five strings **owned by
  [82.blog-site](82.blog-site.md)** as its closed `pillar` enum, which the blog index emits as `id="<pillar>"` group
  headings. A landing unit test asserts the tuple is exactly those five ids; an unknown pillar fails the blog's own
  build. Both blog links are plain anchors with an absolute path, never
  router `Link`s: `/blog/` is Worker-served static HTML, and a client navigation would land in the SPA fallback.
- **Blog link ([K1] step 6)** — one restrained line to `/blog/`, for the reader who wants the depth. Nothing else on
  the page competes with it.

### Locale — auto-detect plus a manual switch ([K4])

Detection is the shipped negotiation, unchanged: `WebI18nProvider` resolves `resolveWebLocale({ stored, languages })`
(stored choice → `navigator.languages` → `defaultLocale`) and syncs `document.documentElement.lang`. A visitor has no
session, so there is no server `users.locale` in the precedence
([60.account-profile-model](60.account-profile-model.md)) — `localStorage["cosimosi.locale"]` is the whole
of persistence. Note the seam is **not empty**: `writeStoredLocale()` is fully implemented and a manual switch
already ships on `/me` (the signed-in `AccountProfile` control, which also writes `UpdateProfile`). What this unit
adds is the **public, signed-out** switch — the first writer reachable without a session.

The switch is a two-option control in the landing's header. It reads `useActiveLocale()` from
`apps/web/src/shared/i18n` and writes through the `onSelectLocale` callback `LandingRoute` injects, which calls
`setActiveLocale` and persists the choice — keeping `pages → app` off the import graph. It is deliberately **not** a
shared slice: [64.my-page](64.my-page.md)'s language control writes `UpdateProfile` for a signed-in user ([K6]), a
different operation with a different authority, and the only genuinely common part (the negotiation) already lives
below both.

All copy is `landing_*` in both `packages/i18n/messages/{en,ko}.json`, regenerated with `pnpm gen:messages`; keys name a
UI role, never a domain term (`spec/tech/i18n.md` §2). `pnpm lint:raw-strings` covers every rendered string on the page.

### Copy honesty ([I12], [K2]) — and where the gate lives

Beyond the citation-free card type, this unit ships `pages/landing/model/copy-honesty.test.ts`, whose inputs are (a)
every `landing_*` message in **both** catalogues and (b) `apps/web/index.html` — the two places public prose reaches a
visitor from this unit. It fails on:

1. brain-equivalence claims (뇌처럼 작동 · 뇌와 동일 · "works like a brain" · "like your brain does");
2. therapeutic or clinical claims (치료 · 치유 · 효능 · therapy · cure · clinically);
3. any sentence presenting the 3D coordinates as the brain's real coordinates;
4. mechanics the product does not have — emotion driving position or link strength, memories attracting one another,
   radius meaning recency ([I3][I4][I7]);
5. **academic-citation shapes** — a DOI (`10.\d{4,9}/…`), "et al.", or a parenthesized author-year — which is [K2]'s
   rule made mechanical;

and it asserts the `landing_*` key sets in `en.json` and `ko.json` are identical.

A test rather than a lint script, deliberately: [82.blog-site](82.blog-site.md) owns `scripts/lint-public-copy.mjs` and
lands **after** this plan ([00.overview](00.overview.md) §5.6), so a script here would collide with the one that plan
already specifies. The hand-off
is stated in both directions — 82's root list gains `packages/i18n/messages/*.json` (scoped to `landing_*`) and
`apps/web/index.html`, while this test stays as the unit's own regression guard. The positive framing is fixed too: the
page says the product is **inspired by engram theory**, and describes the 3D layout as a visualization that emerges
from shared neurons and synapse strength.

**Store-listing copy** ([I12]) is authored here as policy text — the same five rules applied to the app-store
description that stands in for a mobile marketing route.

### The origin's SEO root, and two stale deployment claims

This unit takes ownership of the origin root — it belongs to the app, not to the blog served beneath it
([82.blog-site](82.blog-site.md)):

- `apps/web/public/robots.txt` — indexable: `/` and `/demo`. Disallowed: `/universe`, `/diary`, `/me`, `/admin`,
  `/login`, `/signup`, `/invite/`, `/test`, `/design` — the SPA answers all of them with the same `index.html`, so
  without this a crawler would index landing content under half a dozen wrong URLs. Two `Sitemap:` lines: the root one
  and `/blog/sitemap.xml` ([82.blog-site](82.blog-site.md) depends on that naming).
- `apps/web/public/sitemap.xml` — a plain urlset for `/` and `/demo` in the canonical slashless form.
- `apps/web/index.html` — title, description, absolute canonical, OG/Twitter tags over a committed 1200×630 raster,
  `theme-color`, and a `<noscript>` block carrying the hero line, the [M5] definition and a link to `/blog/`. The
  origin literal is `https://cosimosi.haeram.me` with [DEPLOY.md](../../DEPLOY.md) §1 named in a comment as its SSOT —
  an address, not a tuning number. `lang="en"` stays the shell default and `WebI18nProvider` corrects it once resolved.
- **The honest limitation:** the landing is client-rendered, so a crawler that does not execute JS sees the shell only.
  Prerendering is deferred, not forgotten — the theory tier is real static HTML on the blog, and the trigger for

### Parity waiver

`landing-page` ships **web only**. A native app has no marketing route — a person who installed the app has already
converted — and mobile's entry mapping instead sends `'landing'` to the login stack. The waiver is written out in full
here because `scripts/lint-fsd-layout.mjs` does **not** enforce web↔mobile page peering, so an unstated waiver is
silently broken rather than caught; it follows the admin-console precedent (`spec/policy/ops/admin.md` §6: "the
web↔mobile parity rule is deliberately waived for it", echoed in `spec/tech/admin-console.md` §8 and
[58.admin-console](58.admin-console.md)). The parity matrix pairs the waiver with an obligation
([00.overview](00.overview.md) §4): the [I12]-reviewed **store-listing copy** is this plan's deliverable in place of
the route.

### Golden-parity stance

**No parity obligation, by dependency shape.** This unit defines no pure domain function, mirrors none, and reads no
domain value: it renders authored prose over two rendering layers. It imports none of the golden-parity-pinned packages
(`@cosimosi/memory-logic`, `@cosimosi/twinkle-logic`, `packages/force-sim`) — its only `packages/emotion` use is
`moodColor`, a palette lookup over illustrative data. `scripts/lint-fsd-layout.mjs` R4 has nothing to catch: the slice
is web-only and has no mobile twin.

The one shared module it edits, `packages/auth/src/gate-decision.ts`, is pure, unit-tested and consumed by both apps,
and it has **no Go counterpart** — server-side gating is `platform.AuthInterceptor`, a different mechanism with a
different authority — so there is no fixture to align. Its drift guard is the exhaustive switch in `requiresSignIn`.
The hero's five numbers are generated `@cosimosi/config` constants whose freshness `pnpm check:gen` already gates.

## Acceptance Criteria

1. A signed-out visitor opening the origin root sees the landing page, not a sign-in form; a signed-in visitor opening
   the same URL reaches the universe at `/universe` without the landing rendering for a frame; a `bootstrapping` or
   `refreshing` session renders the neutral hold at `/` and never flashes either surface ([U4]).
2. `gateDecision` returns `'landing'` for settled `signedOut` and for **no other status**; `signingIn`, `expired` and
   `failed` still return `'login'`, `bootstrapping` and `refreshing` still return `'hold'`, and `authenticated` still
   returns `'universe'`. Every consumer branches through `requiresSignIn`, whose exhaustive switch fails to compile if
   a further decision is added without deciding about it.
3. A deep link to a product route while signed out still redirects to `/login` carrying the requested pathname as
   `from`, and a completed sign-in returns there; with no valid `from`, or with `from` of `/` or `/login`, it returns to
   `/universe`.
4. The mobile app compiles and behaves unchanged: `'landing'` maps to the login stack, and no landing screen, route or
   copy exists in `apps/mobile` — the web-only waiver is written into the as-built docs with its admin-console citation
   ([00.overview](00.overview.md) §4).
5. The page renders exactly the seven [K1] sections in order — hero, demo CTA, feature tour, the [M5] definition, five
   theory cards, the blog link, the closing CTA pair — and that order is a **compile-time** tuple: removing, reordering
   or duplicating a section fails `pnpm typecheck` ([K1]; [00.overview](00.overview.md) §3, Epic Q row).
6. A demo CTA appears above the fold and again at the foot; in the closing block the demo CTA precedes the signup CTA,
   and no exported component or prop can render them in the other order. Both demo CTAs resolve to `/demo`; the signup
   CTA resolves to `/signup` ([K3]).
7. The [M5] definition — the universe's color is a mirror of the emotions you return to, not their average — is present
   as its own section in both locales, and its illustrative swatch pair is labelled as illustration ([M5], [K1] step 4,
   §1.4).
8. The feature tour has exactly five items, written from the user's point of view, covering the five behaviors [K1]
   step 3 lists, and mounts no canvas ([K1]).
9. The theory section has exactly five cards matching PRD §9's five strands; the card type has **no** citation field;
   the page renders no DOI, no "et al." and no author-year citation; each card links to `/blog/#<pillar>` using the
   same five ids [82.blog-site](82.blog-site.md)'s `pillar` enum declares ([K2], §9).
10. No sentence on the landing page or in the HTML shell claims the product works like a brain, claims a therapeutic or
    clinical effect, presents the 3D coordinates as the brain's real coordinates, or describes emotion driving position
    or links, memories attracting one another, or radius meaning recency; the framing is "inspired by engram theory",
    and `copy-honesty.test.ts` fails on each class across both catalogues and `apps/web/index.html`
    ([I12][I3][I4][I5][I7]; [00.overview](00.overview.md) §3, Epic Q row).
11. The page renders in Korean and English: the locale is auto-detected from the browser on a first visit, the manual
    switch changes it immediately and persists across reloads, `<html lang>` follows, and no server preference is read
    or written for a visitor. Every rendered string is a `landing_*` message present in **both** `en.json` and
    `ko.json`, the `pnpm gen:messages` output is committed, and `pnpm lint:raw-strings` passes ([K4]).
12. The hero shows the empty universe — the emotion sky plus the latent field, no episodic stars, no camera controls,
    no simulation — at the generated pixel-ratio cap; under `prefers-reduced-motion: reduce` or a failed renderer init
    a committed poster raster renders instead, and the hero is legible before the canvas initializes ([K1] step 1,
    [U2], [I5]).
13. `pages/landing` can import no transport: `@connectrpc/*`, `@cosimosi/api-client` and `@cosimosi/client-cache` are
    unreachable from it (the public-page import closure, extended from the block [79.demo-page](79.demo-page.md) owns),
    the renderer ban still applies to it, and the page issues **zero** calls to `apps/api` on load ([U1]).
14. `robots.txt` and `sitemap.xml` are served from the origin root; `robots.txt` disallows every authenticated, auth and
    diagnostics route and names both the root sitemap and `/blog/sitemap.xml`; the shell carries a title, description,
    absolute canonical, OG/Twitter tags over a committed 1200×630 raster, and a `noscript` fallback with the hero line,
    the [M5] definition and a link to `/blog/`.
15. [00.overview](00.overview.md) §4 and [ARCHITECTURE.md](../ARCHITECTURE.md) §5 no longer claim there is no real
    deployment; both point at [DEPLOY.md](../../DEPLOY.md) as the deployment SSOT, and no doc this unit writes names
    `cosimosi.com`.
16. `pnpm lint`, `pnpm typecheck`, `pnpm typecheck:mobile`, `pnpm test`, `pnpm lint:fsd:layout` and the web build all
    pass, and `apps/web/steiger.config.js` gains no new exemption block — no feature or widget slice was created.
