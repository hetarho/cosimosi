# 64. my page

> My page — the app's one signed-in account surface: the shipped `/settings` route is **renamed to `/me`** and
> restructured from three sections into **five tabs** — profile (nickname · language · timezone), stardust (the two
> balances, and the mount point for the chronological ledger), achievements, diary management (Export), account (linked
> providers · sign out · withdraw). It is also the app's **first and only language switch** ([K6]), which the product
> has never had. General decoration deliberately does not live here — [P5] puts it on a panel over
> the universe — while plan 51's per-mood emotional vocabulary editor is the one profile-level
> presentation preference hosted here. Scope: FE | Status: implemented
>
> Layer P. Home: `apps/{web,mobile}/src/pages/me` composing five `features/*` slices, plus a new `tabs` primitive pair
> in `packages/ui` and the account query helpers in `packages/api-client/src/account.ts`. It fills the "where does a
> signed-in user see and change their own account" seam, and leaves the ledger body ([67]), the achievement list
> ([76]) and the onboarding replay control ([80]) as named mount points inside tabs it owns.

## Purpose

The product has an account but no account surface. What ships today is `/settings` with three sections: a read-only
`userId` line plus sign-out, the palette picker, and a disabled placeholder ([52]). Meanwhile v2 grows a real profile
([U6][U7], nickname · timezone · locale in a real `users` table, [60]), a currency the user is expected to read
([G7]), achievements that must be **claimed by hand** ([A4]), an `Export` RPC that has shipped on the server since
[46] with **no client that calls it** ([W6]), and a withdrawal path ([U10]). Each of those needs a home, and [U9]
names exactly one: `/me`, tabbed.

Two of those gaps are worse than missing features. First, **the app has no way to change its language** ([K6]): the
locale is negotiated once from `navigator.languages` (web) or the device (mobile) and nothing ever writes the storage
key the negotiation reads — `WEB_LOCALE_STORAGE_KEY`'s own comment says "a future language switcher writes here", and
this is that switcher. A Korean-first product with two shipped locales and no switch is a defect, not a backlog item.
Second, **`Export` is unreachable**: `MemoryService.Export` is implemented, classified in the client cache policy, and
called by nobody — so [W6]'s promise ("일기가 사라질까 걱정 마세요 — 언제든 CSV·MD로 내보낼 수 있어요") is currently
false, and [U10] requires that same export to be offered at the withdrawal confirm step.

This unit is deliberately a **composition**: every fact it shows and every write it makes belongs to a headless
sibling — the profile and providers to [60.account-profile-model](60.account-profile-model.md), withdrawal to
[62.withdrawal-usecase](62.withdrawal-usecase.md), the export to
[46.provenance-export](46.provenance-export.md), the balances to [43.stardust-ledger](43.stardust-ledger.md). What it
owns is the surface: one route, five tabs, the language and timezone controls, the export control, the withdraw
confirm, and the tab-hosting contract three later plans slot into without re-plumbing.

## Grounding

  guards is [00.overview](00.overview.md) §3:
  - **[I1] the system does not delete.** The only delete verb reachable from this page is [62]'s `Withdraw`, which

## Design

### Placement (FSD §3.1)

```
apps/web/src/pages/me/
├── ui/MePage.tsx          the five-tab shell + the TAB_VIEWS composition table (mobile hand-writes its own)
├── model/tabs.ts          ME_TABS ids + MeTabId + parseMeTab() coercion   (web only — R4)
└── index.ts

apps/web/src/features/
├── account-profile/       ui (nickname · language · timezone rows) · api (profile read/update)
├── export-diaries/        ui (format choice + trigger) · lib (bytes → the platform sink, forked)
├── withdraw-account/      ui (confirm → withdraw → local sign-out)
└── account-settings/      EXTENDED — identity line + linked providers + sign out

packages/ui/src/primitives/tabs.tsx | tabs.native.tsx     NEW — the first tabbed surface
packages/api-client/src/account.ts                        EXTENDED — profile/provider/withdraw helpers
apps/web/src/shared/lib/locale-storage.ts                 NEW — the durable web locale write
apps/mobile/src/shared/native/locale-storage.ts           NEW — the honest RN no-op
packages/i18n/src/locale-bootstrap.ts                     NEW — the shared non-blocking server-locale apply
```

Mobile mirrors every slice name and **inlines** its tab order in `pages/me/ui/MePage.tsx` (the shipped
`SettingsPage.tsx` precedent): a normalized-equivalent `pages/me/model/tabs.ts` in both apps fails `lint:fsd:layout` R4
(`PURE_MODULE_SEGMENT` digest compare), so the ids are not copied sideways. Each new single-reference slice
gets a scoped `'fsd/insignificant-slice': 'off'` block in `apps/web/steiger.config.js`, replacing the plan-52 settings
block — `export-diaries` earns two references on its own (the tab and the withdraw confirm) and needs none.

The page holds **no** domain logic: it reads no store, issues no RPC, and owns nothing but the tab ids and the
composition table. Every tab body is a feature's public API. It imports no `three`, no visual entity, and no router
(§3.1/§3.4) — navigation arrives as an `onExit`/`onBack` callback from the app layer, exactly as `/settings` does.

### The route rename and how a tab is addressed

Web: `settingsRoute` becomes `meRoute` at path `/me` under the same `authenticatedRoute`, wrapper renamed `MeRoute`;
`spec/tech/web-routing.md` §2's and §8's `/settings` rows are corrected. Mobile: `ROUTES.me = 'Me'`,
`Me: undefined` in `RootStackParamList`, the `<Stack.Screen>` and the `'me'` deep link.

**The active tab is navigation state on web and screen state on mobile** — the asymmetry [68.diary-search-and-filter](68.diary-search-and-filter.md) already pins for the
diary filters. Web adds `validateSearch` to `meRoute` producing `{ tab?: MeTabId }` (the shipped `loginRoute`
`{from?: string}` precedent), so `/me?tab=achievements` is deep-linkable, survives reload, and gives [80] a stable
target for its replay entry; an unknown or absent value coerces to `profile` through `parseMeTab()` (the
`resolvePaletteById` coercion precedent). Mobile carries no route param (`Me: undefined`) and holds the
active id in the screen's local state. Because the router is the state holder on web, **no XState machine is
introduced for tab selection** — a tab is a location, not a mode (§3.2).

| `profile`      | `me_tab_profile`      | `features/account-profile`                                                    | [80] adds the replay row        |

### Profile tab — nickname · language · timezone ([U6][U7][K6])

One row per fact, each with its own explicit save; the tab never composes two edits into one `UpdateProfile` call.

- **Nickname** ([U6]) — a text field pre-validated against the generated constants
  `values.account.nickname_min_length` / `nickname_max_length` (owned by [60], read through `@cosimosi/config`; never
  a literal). The server remains the authority — the client guard exists to avoid a pointless round trip, and the
  length notice interpolates the same two numbers.
- **Language** ([K6]) — two options, labelled by their **autonyms** (`한국어` / `English`, identical in both message
  catalogues, because a language name is not translated). Selecting one: (1) calls `setActiveLocale(next)`
  immediately, so the whole app re-renders in the chosen language before any network call; (2) writes the durable
  local copy through the platform seam below; (3) issues `UpdateProfile{locale}`. On failure the previous locale is
  reapplied and the error surfaces through the shipped error-toast host — the optimistic-then-rollback shape
  `change-palette` already uses.
- **Timezone** ([U7]) — the row shows the stored zone and offers exactly one action: **match this device**.
  The only writable value is a zone the platform itself names, read through `resolveDeviceTimeZone()`
  (`Intl.DateTimeFormat().resolvedOptions().timeZone`, `undefined` on failure). There is **no free-text field and no
  ~600-row zone list**: an invalid IANA string is unrepresentable in this UI, which is the structural guard for the
  single authority `users.timezone` holds over the `SMALL` reset day, the diary default date ([W5]) and the
  monotonic check ([T1]). When the reader returns `undefined` or the stored zone already equals the device zone, the
  row renders read-only. The row also states plainly, once, that changing the zone does not refill today's 작은 별가루
  — the monotonic reset anchor makes that true on the server, and hiding it would invite the attempt.
- **`resolveDeviceTimeZone()` is one shared function, in `packages/i18n`** (platform-pure: `Intl` is neither DOM nor
  native, and this is the same "regional settings the platform reports" concern `resolveLocale` already lives with).
  [63] needs the identical read for [U7]'s signup detection; the contract — one file, one signature, no second copy —
  is pinned here and whichever job lands first creates it.
- **The onboarding replay row** ([O5]) is the last row of this tab, owned by [80]; this plan names the position and
  adds nothing for it.
- **The emotion-color editor** ([51]) shows all thirteen moods and their recommendations. Its live
  presentation write is independent of `UpdateProfile`, uses no universe refetch, and cannot write
  a render parameter other than the mood-color projection.

### The locale seam ([K6])

[60.account-profile-model](60.account-profile-model.md)'s precedence is **server `users.locale` > the stored local
choice > device/browser > `defaultLocale = 'en'`**, and this page is its single write. Three small pieces make that true without a second locale store:

1. **The durable local copy** — `apps/web/src/shared/lib/locale-storage.ts` writes and reads
   `localStorage['cosimosi.locale']`; `apps/web/src/app/providers/i18n-config.ts`'s inline read moves onto it so one
   module owns the key. A `features/*` slice may import `shared` (§3.1), which the app layer's own module could not
   have offered. **Mobile has no durable key-value seam** (the only storage seam is
   `createInMemorySecureTokenStorage`, process-lifetime by design), so `apps/mobile/src/shared/native/locale-storage.ts`
   is an honest no-op: a signed-out mobile app falls back to the device locale. That asymmetry is deliberate and
   recorded — inventing a native storage dependency for a preference the server already holds is not worth a new
   native module.
2. **`LocaleBootstrap`** — the single component lives in `@cosimosi/i18n/react`; the server read cannot live in
   `WebI18nProvider`, which sits **above**
   `WebClientCacheProvider` in `App.tsx` and therefore has no transport. Instead a `LocaleBootstrap` mounts beside
   `PaletteBootstrap` inside `AuthenticatedLayout` (mobile: beside `MobilePaletteBootstrap` in `NavigationRoot`),
   reads the same `GetProfile` query the profile tab uses, and calls `setActiveLocale(profile.locale)` in an effect.
   Unlike the palette gate it **withholds nothing**: a first frame in the negotiated locale is a text swap, whereas a
   first frame in the wrong palette is a wrong-coloured universe. No blocking spinner is added.
3. **The reset registry** — `@cosimosi/auth/user-state` owns the shared reset inventory and both app cache providers extend
   it with only their `locale` negotiation leg. Switching accounts therefore returns the active locale to the local
   negotiation instead of inheriting the previous user's server value. An unregistered locale leaks across accounts
   exactly the way an unregistered ornament-preview store would leak ([73.decoration-panel](73.decoration-panel.md)).

### Stardust tab — a mount point this page does not fill ([G2][G7])

The tab body is **`features/twinkle-ledger`, owned by [67.twinkle-relabel-and-ledger-ui](67.twinkle-relabel-and-ledger-ui.md)**:
both tier figures _and_ the `GetLedger` history _and_ the labelled daily-refill marker arrive together from that
slice. The reuse is of `packages/twinkle`'s shared store and query, not of the shipped
`features/twinkle-balance-hud`, which is an over-canvas overlay — [67] renders the summary itself, so this page adds
**no** `tone` variant to the HUD and mounts the shipped overlay nowhere. Until [67] lands the tab shows the same quiet unavailable
line the achievements tab uses. This tab **offers no purchase or charge affordance** — payment is retired to v3 by [66]/[67], and its
absence here is what keeps [G3]'s earn set the only story the page tells.

### The invite share surface ([U8][G6])

`features/invite-link` sits inside the profile tab because it is a fact about _you_, not a transaction. It renders
`GetInviteLink†`'s `{token, expires_at}` through [63]'s `inviteLinkPath(token)` — the single definition of the link
shape, so the capture route and the share surface cannot drift — plus one line naming what a settled invite pays,
read from generated values, never computed. It exposes **no** invitee list, no invite count and no reward status: the
response carries none of that, and [61.signup-and-invite-usecase](61.signup-and-invite-usecase.md) settles rewards
with no wire surface at all. Copy uses the `invite_*` key prefix.

### Diary management tab — Export ([W6][D4])

`features/export-diaries` renders the [W6] reassurance line, a CSV | MD choice, and one trigger. Two decisions:

- **The export is an imperative call, never a cached query.** `Export` is classified `userScopedUnaryReadPolicy` in
  `packages/client-cache/src/http-policy.ts`, so a `useQuery` would retain a whole account's diary text in the query
  cache and could replay it. The feature calls `createMemoryClient(transport).export({ format })` through a mutation,
  hands the bytes straight to the platform sink, and drops them — nothing is stored, so nothing needs resetting on a
  user switch.
- **The sink forks by platform, the decode does not.** `ExportResponse{content, content_type, filename}` is decoded
  once with `TextDecoder` (already a mobile dependency via `text-encoding`); web builds a `Blob` and downloads it
  under the server-supplied filename, mobile hands the text to React Native's core `Share` API. **No new native
  dependency** — the same accepted asymmetry [68.diary-search-and-filter](68.diary-search-and-filter.md) records
  for the missing native date picker.

This one feature has two mount points: this tab, and the withdrawal confirm step, where [U10] makes the offer
mandatory. It is composed, never duplicated.

### Account tab — providers, sign out, withdraw ([U5][U10])

`features/account-settings` keeps its identity line and its confirm-then-sign-out (both shipped) and gains the
**linked providers** list from `ListAuthProviders`† — `GOOGLE` / `PASSWORD` with their `linked_at`, read-only.
Linking or unlinking a provider is not offered: [U5] states that multiple providers may exist, not that this page
manages them, and a contract with no link/unlink call cannot grow one by accident. Email, when [60]'s directory read
supplies it, is display-only.

`features/withdraw-account` ([U10]) is a two-step confirm and nothing more:

1. **The confirm step** states what withdrawal means and reuses `features/export-diaries` in place ("지금 CSV·MD로
   내보내시겠어요?"). The 30-day promise interpolates `values.account.withdrawal_retention_days` — the account key
   used server-side by [62], never a literal `30`, so the copy cannot drift from the sweep.
2. **On confirm** it calls [62]'s `Withdraw`, then the shared auth coordinator attempts remote sign-out. If that
   adapter call fails after the withdrawal commit, it falls back to a local session teardown rather than reporting the
   withdrawal itself as failed. This runs the user-scope reset registry and lets the gate route to login. After
   `Withdraw` [62]'s withdrawn-scope interceptor rejects the scope before any context read, so every mounted query
   would fail — holding a withdrawn session on screen would be a page full of errors.

There is deliberately **no restore control here**, and this is structural rather than a choice: `/me` is inside the
authenticated subtree and behind the withdrawn-scope interceptor, so a withdrawn user cannot reach this page at all.
[62] owns where `RestoreAccount` is reached; the confirm copy states the promise without promising a button.

### The `tabs` primitive and web↔mobile parity (§3.5)

`packages/ui` has no `tabs` primitive and `/me` is the app's first tabbed surface, so this plan adds the pair:
`tabs.tsx` (a `role="tablist"` / `role="tab"` group with `aria-selected`, `aria-controls` and roving arrow-key focus)
and `tabs.native.tsx` (a horizontally scrollable pressable row with `accessibilityRole="tab"`). It is **controlled** —
`value` + `onValueChange` — so the router stays in the app layer and the primitive stays domain-agnostic. It is not
the diary reader's sort toggle or view switch ([69]/[70]): a toggle group sets a value, tabs swap panels, and the two
must not be collapsed into one primitive.

[00.overview](00.overview.md) §4's parity matrix gives this unit **web ✅ / mobile ✅, all five tabs** — no
parity waiver is available. `model` and `api` are
shared verbatim (the tab id list is the one exception, by lint rule); `ui` forks only for the screen chrome, the row
layout and the tabs primitive. Every string comes from the same message keys on both apps.

### Control state, cache, copy (§3.2)

**Control state.** Nothing here is a mode machine. The tab is a location (web) or trivial screen state (mobile); each
row's edit is an inline `idle → editing → saving` swap plus a mutation status — the shipped `AccountSection`
`confirming` precedent. Per §3.2 the criterion for XState is an exclusive _mode/phase_, and a mutation's pending flag
is data, not control state; introducing a machine (and the `packages/account` it would have to live in)
for a two-step confirm would be ceremony this page does not need. **Server truth is TanStack Query with invalidation
only, never polling**: a successful `UpdateProfile` invalidates the `GetProfile` key.

**Copy.** All strings resolve through `packages/i18n` (`pnpm lint:raw-strings` gates it), in both `en.json` and
`ko.json`, regenerated with `pnpm gen:messages` and gated by `pnpm check:gen`. New keys name a **UI role**:
`me_title`, `me_back`, `me_tab_{profile,stardust,achievements,diary,account}`, `me_nickname_*`,
`me_language_*` (`me_language_option_ko` / `_en` carry the autonyms), `me_timezone_*`, `me_achievements_pending`,
`me_export_*`, `me_identity_label`, `me_provider_*`, `me_sign_out*`, `invite_*` for the share surface, and
`withdraw_*` for the withdrawal step.
Retired with their former surfaces: `settings_title`, `settings_back`, `settings_section_{account,palette,staging}`,
`settings_identity_label`, `settings_sign_out`, `settings_sign_out_confirm`, `settings_staging_{items,notice,boundary}`.
The per-mood editor uses `palette_editor_*` and `palette_recommendation_*`, not the retired
whole-settings palette copy.

The voice stays literary and restrained. `me_title` is ko `나` / en `You` — the quietest possible label for the
affordance that today reads 설정, with the five tab names carrying the meaning. The unavailable achievements line, the
timezone notice and the withdrawal confirm are plain and honest: no tease, no marketing, no decorative emoji.

### Golden-parity stance

The nickname predicate is mirrored TS↔Go and pinned by one fixture:
`packages/auth/fixtures/nickname-validation.json`. Both runtimes assert the generated `2…24` boundaries plus trimmed
Unicode, newline, control-character, and line/paragraph-separator cases. The bounds still come from one generated
`spec/values.yaml` source; the fixture holds cases, not tuning numbers. Likewise the 30-day withdrawal copy and the
server sweep both read `account.withdrawal_retention_days`.

## Acceptance Criteria

1. The shipped settings route is **renamed, not duplicated**: web `/me` (`pages/me`, wrapper `MeRoute`, under the
   existing `authenticatedRoute`) and mobile `ROUTES.me = 'Me'` with the `'me'` deep link; no `/settings` path,
   `pages/settings` directory, or `onOpenSettings` prop remains in either app, and the universe affordance navigates
   to `/me` ([U9]).
2. `/me` renders exactly **five tabs** in the order profile · stardust · achievements · diary management · account;
   the web ids live in `pages/me/model/tabs.ts`, mobile inlines the same order, and the two are **not** byte-identical
   (`pnpm lint:fsd:layout` R4 passes) ([U9]).
3. The active tab is **URL state on web** — `/me?tab=<id>` via `validateSearch`, deep-linkable and reload-stable,
   with an unknown or missing value coerced to `profile` — and local screen state on mobile; no XState machine is
   introduced for tab selection (§3.2, the diary-filter precedent [68] sets).
4. The **profile tab** shows and edits nickname, language and timezone, each with its own explicit save issuing one
   `UpdateProfile` per confirmed edit; the nickname guard reads the generated
   `account.nickname_min_length`/`nickname_max_length`, rejects the server's control and line-separator classes, and
   shares its accept/reject fixture with Go ([U6][U7][K6], [60]).
5. Choosing a language **switches the app's language immediately** (`setActiveLocale`), persists to the server
   (`UpdateProfile{locale}`), and on web also writes the durable local copy so a signed-out visit keeps the choice;
   a failed write rolls the locale back and surfaces the error. This is the app's only locale write ([K6], [60]).
6. On an authenticated boot the **server locale is applied** by a `LocaleBootstrap` mounted beside
   `PaletteBootstrap`, which blocks no render; `'locale'` is registered in the user-scope reset registry, so a user
   switch does not inherit the previous account's locale ([60]; the user-scope reset-registry rule).
7. The **timezone control writes only a zone the platform reports** — one "match this device" action over
   `resolveDeviceTimeZone()`, no free-text field and no shipped zone list — and renders read-only when no device zone
   is available or it already matches; the row states that changing the zone does not refill today's `SMALL`
   ([U7][G2], [60]/[65]).
8. The **stardust tab** exists and is reachable and exposes a named mount point that
   [67.twinkle-relabel-and-ledger-ui](67.twinkle-relabel-and-ledger-ui.md)'s `features/twinkle-ledger` fills with both
   tier figures and the ledger; this page adds no `tone` variant to `features/twinkle-balance-hud` and presents **no**
   purchase, charge or payment affordance ([G2][G7]; the charge path is retired by [66]/[67]).
9. The **achievements tab** exists and is reachable, its body a quiet unavailable line that [76] replaces by editing
   one row of the page's composition table ([A4][A5]).
10. The **diary-management tab** calls the shipped `MemoryService.Export` for CSV and MD, imperatively (never a
    cached `useQuery`), decodes the bytes once, downloads on web and shares on mobile, adds **no** native dependency,
    and retains nothing after delivery ([W6][D4], [46]).
11. The **account tab** lists the linked `AuthProvider`s read-only (`GOOGLE`/`PASSWORD`) beside the identity line and
    the shipped confirm-then-sign-out; there is **no** link, unlink, email-change or password-change control ([U5]).
12. **Withdrawal** is a confirm step that states the 30-day promise with the interpolated
    `account.withdrawal_retention_days` (never a literal), offers Export in place at that step, then calls
    `Withdraw` and immediately signs the local session out; the page exposes **no** `RestoreAccount` control and no
    hard-delete of any kind ([U10][X2][I1], [62]).
13. `/me` has **no general decoration or ornament control** — no background, star shader, camera,
    effect, catalog, or staging slot. The Profile tab's single exception is plan 51's per-mood
    emotion-color editor; its contract writes only presentation color and cannot reach a star's
    position, stored emotion, strength, forgetting, connections, or gist ([P5][I11][V10]).
14. `/me` is **time-inert and read-scoped**: it mounts no clock control, issues no RPC that advances universe time,
    and every request it sends carries no `user_id` ([I10][T3][U1]).
15. The page **holds no domain logic** — it owns only the tab ids and the composition table, imports no `three`, no
    visual entity and no router, and reaches each tab through a feature's `index.ts` (§3.1/§3.4).
16. **web ✅ mobile ✅ for all five tabs** ([00.overview](00.overview.md) §4, no waiver), sharing `model`/`api` verbatim while each app hand-writes
    its own `ui` for the screen chrome and the row layout; the only `*.native.tsx` sibling added is the new
    `packages/ui` `tabs` primitive (no app slice carries one — the as-built convention); **all**
    user-visible copy resolves through `packages/i18n` in both locales (`lint:raw-strings` and `check:gen` pass),
    with no `settings_*` key left except `settings_palette_selected`.
