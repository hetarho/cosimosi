# 77. demo fixtures and mirror

> Demo fixtures and mirror — the Epic P root: one new pure package `@cosimosi/demo` holding the **`DemoDiarySet`**
> fixtures (neuron-overlapping three-diary sets, fully precomputed splits · names · emotions · neurons · synapses ·
> four gist stages · decay-stage texts, [Z5]) and the **`DemoScenario`** feed that names the ten fixed beats ([Z3]).
> Frontend-only, no DB, no LLM. It also settles the mirror question: **the demo re-implements no pure function** —
> every function [Z6] anticipated already exists in `packages/**` behind a Go golden fixture, so this unit ships
> **data** and the guard for data, not math. It leaves the clock, the unlimited `SMALL`, the canvas host and every
> beat's effect to [79.demo-page](79.demo-page.md), and the step engine to [78.sequence-engine](78.sequence-engine.md).
> Scope: FE | Status: built ([job 116](../jobs/archive/116.demo-fixtures-and-mirror.md))
>
> Layer D. Home: a new pure cross-app package `packages/demo` (`@cosimosi/demo`) — no app slice, no `entities/`,
> no `three`, no transport. It fills the data seam Epic P's two presentation units read; it opens no server seam
> and closes the "second implementation" seam [Z6] left ajar.

## Purpose

The demo is not the product, it is the trailer ([Z] preamble): a signed-out visitor arriving from the landing page
must decide in a few tens of seconds whether cosimosi is worth an account. That means the demo has to show, in
seconds, changes the real product takes days to produce — forgetting, reconsolidation, gist rise, the universe taking
on a color — and it has to do so with **no auth, no server call, no DB write and no LLM call** ([Z1]). Everything the
visitor sees therefore has to be **already decided and shipped in the bundle**. This unit is that shipped content.

It exists as its own unit because of one non-obvious requirement: the demo's data must be **set-granular**. Beat 4 of
the fixed sequence is 뉴런 재사용 → 별자리 창발 ([Z3]-4), and a constellation only emerges from shared neurons plus
synapse strength ([I4][L2] — there is no memory↔memory edge). Three diaries drawn at random from a flat pool would
share no `Neuron`, no `Synapse` would form between their neurons, the force-sim would settle them as three unrelated
clumps, and the single most convincing beat of the demo would simply not appear. So the unit of randomness is the
**`DemoDiarySet`** — three diaries designed together to overlap ([Z4]) — and the only thing that varies run to run is
which set is drawn ([Z5]).

The second reason this unit is the epic's root is the mirror question. [Z6] licensed the demo to re-implement the pure
domain functions in TypeScript and to accept two copies. That license is now obsolete and re-reading it literally would
be actively harmful: `packages/memory-logic`, `packages/twinkle-logic` and `packages/emotion` already hold TS mirrors
of exactly those functions, each pinned to a Go golden fixture read by relative path from the TS test — six fixtures
in total (the reuse ledger is in Design). A third copy inside the demo would drift silently and would be the
first crack in the [I13] isolation boundary, because a demo-only formula is a demo-only _rule_. This plan therefore
states the reuse list explicitly and makes the fixture shape **incapable of holding a derived value**, so there is
nowhere for a second implementation's output to go.

## Scope / Non-goals

**In scope**

- **`packages/demo` (`@cosimosi/demo`)** — a new pure cross-app package (one of v2's new FE packages): fixture types,
  the fixture content, the resolver that turns a fixture into production-shaped domain objects, and the
  fixture-integrity test suite. No React, no store, no IO ([Z1]).
- **`DemoDiarySet`** ([Z4][Z5]) — three diaries per set, authored as **structure** (ids, activation weights, moods,
  intensities, synapse pairs and strengths, day offsets) plus **text** (diary body, memory name, current text, the four
  gist-stage texts, the decay-stage texts, neuron display names), with the shared-neuron topology declared and proven.
- **Precomputed splits** ([Z5]) — each diary's `EpisodicMemory` members, their names, their `Emotion`, their
  `Neuron` set and activation weights, their four `SemanticStages` texts and their decay-stage texts are all authored.
  The same diary always yields the same star, the same neurons and the same words.
- **Hardcoded `Synapse` rows** — the one genuine mirror gap: neuron↔neuron links are authored per set with
  canonical `neuronAId < neuronBId` ordering, not computed by a TS copy of `computeLinkStrength`.
- **`DemoScenario`** ([Z3]) — the fixed ten-beat feed: the beat identifier order, which set member each beat acts on
  (the diary of beat 1, the recall target of beat 6, the memory that rises at beat 7, the ornament **ids** of beat 9),
  and the epoch resolution rule. It carries no copy, no price and no engine type.
- **The resolver** — `DemoDiarySet` + locale + epoch → a `UniverseSnapshot` and a `Diary[]` **identical in shape to
  what `universeFromResponse` / `diariesFromDtos` produce**, so every downstream consumer receives production input
  and no demo branch exists anywhere below the page ([I13]).
- **The reuse ledger and the drift guard** — the enumerated list of already-parity-pinned functions the demo consumes,
  the enumerated list of functions deliberately **not** mirrored, and the fixture-integrity suite that proves the
  authored data still satisfies the contracts those functions assume.
- **Locale-complete fixture text** — the text half is typed per supported locale, so a fixture that exists in Korean
  only cannot compile ([K3]'s ko/en visitor arrives here from the landing page).

**Non-goals**

- **No route, page, canvas host or clock.** `/demo`, its scene host, the demo-local mutable universe date, the free
  time travel, the unlimited `SMALL`, the beat effects and the `pages/demo` import-boundary lint rule are
  [79.demo-page](79.demo-page.md), which owns that lint rule.
- **No step engine, caption, highlight or skip.** `SequenceStep`, the caption dwell, the highlight pulse and the replay
  entry are [78.sequence-engine](78.sequence-engine.md); this package must not import it (it lands after this one).
- **No new pure function, no new golden fixture, no new parity harness.** The six existing fixtures already cover the
  math; this unit adds no `.golden.json` and no Go testdata file.
- **No LLM, no `ai` port.** `Extractor` / `Semanticizer` / `Embedder` are never called and never mirrored
  ([ubiquitous-language](../ubiquitous-language.md) §5, [Z1]).
- **No price, purchase, achievement or payment data.** The fixture carries no ornament data at all — the demo's
  decorating surface reads the client's own ornament-name map ([Z8];
  [00.overview](00.overview.md) §3's Epic-P row); no ornament price, `Twinkle` amount or achievement row appears in any fixture.
- **No coordinates.** Positions stay emergent from `packages/force-sim` ([19.force-sim-layout](19.force-sim-layout.md));
  the fixture authors no x/y/z, unlike the diagnostics-only `apps/web/src/pages/test/lib/engram-demo-scene.ts`.
- **No change to the shared mirrors.** `EpisodicMemory` does not grow a `semanticStages` field for the demo's benefit —
  widening `packages/memory` for the sandbox is an `isDemo` leak by another name, and no `isDemo` flag, prop or branch
  may exist in `packages/*`, `features/*` or `entities/*`.
- **No mobile surface.** `demo-page` is web-only by explicit waiver ([00.overview](00.overview.md) §4); this package is pure and shared by
  construction, so it carries no parity question of its own.
- **No carry-over.** Nothing here is written anywhere durable, so [Z7] holds by construction.

## Design

### Placement (ARCHITECTURE §3.5 — pure cross-app code lives in `packages/`)

```
packages/demo/
├── package.json          @cosimosi/demo — deps: @cosimosi/memory, @cosimosi/emotion,
│                         @cosimosi/memory-logic, @cosimosi/config. Nothing else, ever.
│                         (@cosimosi/i18n is a devDependency — imported type-only, for Locale.)
└── src/
    ├── index.ts              the public API (types + DEMO_DIARY_SETS + resolvers), named exports
    ├── diary-set.ts          the DemoDiarySet type: structure half + text half + its scenario
    ├── diary-sets/*.ts       the three authored sets, one module per set (content)
    ├── diary-sets/index.ts   DEMO_DIARY_SETS — a non-empty tuple, so the draw is total
    ├── scenario.ts           DEMO_BEAT_IDS (the ten in order) + the DemoScenario binding type
    ├── resolve.ts            resolveDemoDiarySet(set, locale, epoch) → UniverseSnapshot + Diary[]
    ├── pick.ts               pickDemoDiarySet(sets, draw01) — pure; the caller supplies the draw
    └── integrity.test.ts     the fixture-integrity suite (below)
```

As built, a `DemoScenario` is a **field on the set** rather than a standalone table: every binding it carries names a
member of one particular set, so the two cannot be drawn apart. The root `package.json` gained `typecheck:demo` and
`test:demo`, which is how the integrity suite reaches CI.

There is no `apps/web/src/entities/demo` and no `pages/demo/model` fixture module: every v1 domain mirror was promoted
to a package and the demo's data is domain-mirror data. There is no `apps/demo` app root either — a second app root
would duplicate the renderer host, the build and the deploy for a page whose value is showing the _real_ renderer. The
package is pure, so it is shared by construction: the fact that only the web mounts `/demo` (the web-only parity
waiver, stated with the admin-console precedent in [79.demo-page](79.demo-page.md) per `spec/policy/ops/admin.md` §6)
does not make the fixtures web-only code.

### `DemoDiarySet` — structure authored once, text authored per locale

A set is **three tutorial diaries plus a free-play pool of extras** ([Z4], extras added as change 10's consequent)
and splits into two halves that are authored and reviewed differently:

| Half          | Holds                                                                                                                                                                                                                                        | Why here                                                              |
| ------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------- |
| **structure** | set id · neuron ids + `NeuronType` · per-diary day offset · per-diary memory ids · per-memory `Mood` + `intensity` · `NeuronActivation` weights · `seed` · synapse pairs + `strength` + `coActivationCount` · the declared shared-neuron ids | locale-free domain facts; reviewed against [I3]/[I4]/[I6]             |
| **text**      | diary body · memory `name` · `currentText` · the four `SemanticStages` texts · the decay-stage texts · the recall target's reconsolidated text · neuron display names                                                                        | public copy; reviewed against [I12] and the literary/restrained voice |

One field arrived with [79.demo-page](79.demo-page.md) rather than here: **`reconsolidatedText`**, how a memory reads
after it has been recalled once. This plan's text list omitted it while 79's beat 6 assumed it, and 79 is right — a recall
that changed only the star's form would show reconsolidation as a cosmetic event. It is **optional** and present only on
a set's recall target — the one memory the tutorial teaches recall on — and the integrity suite proves the target has
one in every locale. Free play (change 10) recalls any star: a memory without the text still re-brightens, re-anchors
and reshapes; only the reworded reading is the target's own. In production the equivalent text is whatever the diarist
re-narrates through the recall use-case, so there is no shared field to widen.

**The free-play extras** (`structure.extraDiaries`, non-empty by type) are authored against the SAME neuron roster as
the triple: every extra activates at least one neuron the tutorial already lit, so a diary launched in free play joins
the cluster instead of settling as an unrelated clump ([I4][L2]); new co-firing pairs get authored synapse rows like
any others. Extras carry the full text half — body, names, current texts, gist ladders, word-loss ladders, both
locales — and their day offsets extend past the triple's, so a free-play launch arrives as the universe's newest diary
and moves the clock forward the way a real launch does. The **word-loss ladders across the whole corpus are
byte-identical `decayStageText` outputs** (produced at authoring time with each memory's own seed) and the integrity
suite now asserts that equality, so a hand-edited stage — a second erosion rule wearing a fixture's clothes — cannot
ship ([Z5][Z6]).

The text half is a `Record<Locale, …>` over `supportedLocales` from `@cosimosi/i18n` (a **type-only** import, so the
package stays IO-free). A set whose English text is missing is a type error, not a Korean string shown to an English
visitor. Fixture text is **content, not UI chrome**: it does not become `packages/i18n` message keys and does not
inflate the message catalogue — `demo_*` keys belong to the demo's captions and controls, which are
[78.sequence-engine](78.sequence-engine.md)/[79.demo-page](79.demo-page.md)'s. Because a `.ts` data module is outside
`pnpm lint:raw-strings`' reach (it inspects JSX text and a fixed prop list), the `Record<Locale, …>` type **is** the
completeness guard.

Counts are content, not configuration: the shipped pool is **three sets of three tutorial diaries plus three extras
each** and all the numbers are **derived array lengths** — `DEMO_DIARY_SETS.length`, the per-set diary tuple's arity
and `extraDiaries.length`. Three-per-set is structural, not tunable: two diaries cannot demonstrate reuse
convincingly and four dilute the beat. The extras exist so free play outlasts the tutorial (the integrity suite
floors them at three per set); their count is a depth choice, not a rule.

### What makes a set a set ([Z4] — the reason this unit exists)

Each set declares `sharedNeuronIds` as a **non-empty tuple**, and the integrity suite proves the claim rather than
trusting it. Per set:

1. **Cross-diary overlap** — at least one `Neuron` is activated by memories belonging to **two or more different
   tutorial diaries**, and every declared shared neuron actually is. Proven over the triple, because the
   constellation beat happens before any extra can have launched. This is the beat-4 precondition ([Z3]-4).
2. **Synapses only between neurons that co-fire** — every authored `Synapse` connects two neurons that share at least
   one memory, canonically ordered `neuronAId < neuronBId` ([I6], and the shipped mappers' invariant).
3. **All three `NeuronType`s present** so the cell-star layer's type reading is exercised.
4. **≥3 distinct `Mood`s among the memories on screen at the colour beat** (the first two diaries — the tutorial
   launches exactly two before beat 8, per change 10), and the beat-6 recall target lives in those diaries. The sky
   carries those moods from the first launch onward, so their spread IS what the visitor sees overhead: one mood
   across two diaries would make beat 8 (우주 색, [M4][M5]) name a single flat wash and the product's honest promise
   (§1.4) would go undemonstrated.
5. **A decay spread** — the diaries' day offsets are far enough apart that beat 5's time acceleration puts the
   set's memories at different `decayStage`s, so word loss reads as a gradient rather than a switch.
6. **Every extra stays attached** — each free-play diary reuses at least one tutorial neuron, and its word-loss
   ladder is the byte-identical `decayStageText` output (change 10's two additions).

Because these are properties of authored data, the suite is a **fixture-integrity** test, not a golden-parity test:
data cannot drift, but it can be edited into an invalid state, and that is what the suite catches.

### Determinism and the fields the fixture may not have ([Z5], §2.9 #3)

[Z5] is satisfied structurally: there is no generator, no PRNG and no clock in the package, so a diary's split, names,
emotions, neurons, gist texts and decay texts are literally the same objects on every run. The only run-to-run variance
is the set draw, and even that is a parameter — `pickDemoDiarySet(sets, draw01)` takes a number in `[0, 1)`, so the
package is deterministic under test and [79.demo-page](79.demo-page.md) supplies `Math.random()` at the boundary.
Inside a run the per-diary draw is deterministic too (change 10): `demoDiaryPool(set)` fixes one canonical order —
the triple, then the extras — and `pickDemoDiary(pool, drawNumber)` cycles it without back-to-back repetition, so
free play's "random prepared diary" varies only by how many draws the visitor has taken.

The fixture types have **no field** for: position or any coordinate ([I5]), `EffectiveBrightness`, `EffectiveStrength`,
`decayDepth`, decay stage-at-a-time, gist stage-at-a-time, accessibility cost weight, a `Twinkle` amount, or an
ornament price. Two consequences, both structural rather than reviewed:

- a second TypeScript implementation of the domain math would have **nowhere to write its output**, which is this
  unit's answer to [Z6] (the same style as [71.ornament-catalog-model](71.ornament-catalog-model.md)'s star-variant
  struct, which has no field for tint);
- [Z8] holds by absence: no price can render on `/demo` because no price exists in the data the page reads.

Two values that _look_ like fixture numbers are deliberately derived instead:

- **`baseStrength`** = `arousalToInitialStrength(createEmotion(mood, intensity).arousal)` — the arousal-only
  modulation of [17.emotion-model](17.emotion-model.md), already pinned by
  `apps/api/internal/memory/testdata/arousal-strength.golden.json`. The fixture authors `mood` + `intensity` only, so
  the demo shows the real relationship instead of a hand-tuned number ([I3] — valence never enters).
- **`Neuron.connectivity`** = the neuron's degree over the set's authored synapses, computed at resolve time (the
  `engram-demo-scene.ts` precedent), because it is a derived projection ([V1], §2.9 #3).

`recallCount` starts at 0 and `lastRecalledUniverseTime` at `null`; beat 6's recall is a mutation of
[79.demo-page](79.demo-page.md)'s demo-local copy, never a second fixture variant.

### Time — day offsets and a resolved epoch

Diary dates are authored as **integer day offsets** from the set's own start, never as absolute ISO dates. The resolver
takes an `epoch` ISO date and stamps `diaryDate` / `createdUniverseTime` / the `Synapse.lastActivatedUniverseTime`
values (that field lives on the synapse mirror, not on `EpisodicMemory`) — and fills the mirror's required
`forgettingOffsetDays` (zero for fresh fixtures) — from it. Two
reasons: a fixture with hardcoded 2026 dates shows a visitor in 2029 a stale universe, and every quantity the reused
mirrors compute is a **difference** of dates (`elapsedUniverseDays`), so shifting the epoch changes displayed calendar
dates and nothing else. Determinism ([Z5]) is therefore preserved exactly where it matters: identical splits, identical
neurons, identical texts, identical derived values for a given elapsed time.

The package reads no clock — `epoch` is a parameter, and `resolveDemoEpoch(today, set)` is a pure function returning
`today − span(set)` so the newest fixture diary lands on the visitor's today. The demo's mutable universe date, its
advance grains (`demo.time_travel_month_days` and the fixed day/week units) and the [I10] exemption are [79.demo-page](79.demo-page.md)'s
([Z2] — real time may pace the demo's presentation; nothing here measures it).

### `DemoScenario` — the ten beats as data, with no engine type ([Z3])

`DemoScenario` is the injectable feed [O1] describes, expressed without importing the engine that will consume it
(this unit lands before [78.sequence-engine](78.sequence-engine.md) — [00.overview](00.overview.md) §5.6):

- **`beats`** — the ten identifiers of [Z3] in order (`diary_appears`, `split`, `launch`, `neuron_reuse`,
  `time_accelerates`, `recall`, `gist_rise`, `color`, `ornament_taster`, `signup_cta`). This is an identifier union,
  **not a new UL noun**: the engine-side noun is plan 78's `SequenceStep`, and [Z3] fixes these ten members, so one
  concept keeps one name ([ubiquitous-language](../ubiquitous-language.md), `한 개념 = 한 이름`). Beat 4 is
  **`neuron_reuse`**, not `constellation`: the emergent cluster is the renderer's word for it, and `lint:language`
  correctly refuses rendering vocabulary inside a domain-mirror package (§3.4). The domain half owns the id; the page
  and the engine own what the visitor is told.
- **the per-beat bindings** — which diary appears first (the pool's own first draw), which memory beat 6 recalls,
  and the ornament ids beat 9 tastes (ids only, no price, [Z8]). There is no gist binding anymore: since change 10
  gist stages rise per memory from each one's own timer, so beat 7 needs no scripted id. Each taste is a
  `{ kind, ornamentId }` pair whose
  `kind` is a plain `string` rather than `@cosimosi/store`'s `OrnamentKind` — the dependency list closes at four domain
  packages, so the page pins the pairing against the real union where it applies the taste, and the integrity suite
  asserts each id's prefix matches its kind.
- **no copy, no i18n key, no highlight target, no dwell time.** Captions and highlights are the engine's
  (`sequence.caption_dwell_ms` / `sequence.highlight_pulse_ms`, owned by plan 78) and each beat's _effect_ on the
  demo-local state is [79.demo-page](79.demo-page.md)'s. The page maps beat id → caption through an exhaustive
  `Record<DemoBeatId, …>`, so a missing caption is a compile error.

### The resolver — production shapes, no demo branch below the page

`resolveDemoDiarySet(set, locale, epoch)` returns exactly what the real read path returns:

- a **`UniverseSnapshot`** (`memories` / `neurons` / `synapses` / `universeTime`) — the same interface
  `universeFromResponse` produces, so `buildUniverseGraph`, `useEpisodicMemoryStore` / `useNeuronStore` /
  `useSynapseStore`, `starChannels`, `cellStarChannels`, `filamentChannels`, `currentDecayStage` / `currentDecayText`
  and `generateLatentField` all receive production input;
- a **`Diary[]`** (`packages/memory`'s mirror shape) for the beat-1 diary and the "born stars" affordance;
- a **text sidecar** carrying the four `SemanticStages` strings per memory. These are **not** added to
  `EpisodicMemory`: the production mirror has no gist-text field because gist text is a paid `ViewSemantic` read, and
  widening the shared mirror for the sandbox would be an `isDemo` leak into `packages/memory`.

Writing domain shapes straight into the three stores skips the proto/DTO mappers entirely, which sidesteps
`bigint`↔`int64` and `optional` handling; `seed` is a literal `bigint` in the fixture (the `10_007n` precedent).

The **`slowFactor` row is this unit's own pre-work**: the demo's honesty argument ("reimplement nothing — everything
shown is the pinned real math") only holds if every reused function actually has a pin, so the missing pin was added
here rather than assumed. `toEmotionSlices` turned out not to be reused by this unit at all (the emotion blend the demo
shows goes through the shipped render channels, not through a slice projection), so it owes no pin here.

Reuse also required one **signature repair** in `@cosimosi/emotion`: `createEmotion`'s `intensity` parameter took its
type by inference from `VALUES.emotion.defaultIntensity`, and because the generated values table is `as const` that
inferred the literal `0.7` — so the function accepted no other intensity. It is now annotated `intensity: number`. The
demo is the first caller that authors a real per-memory intensity, which is how a latent defect in a shipped mirror
surfaced.

The word-loss texts are literal strings in the fixture — as they are stored columns in production — produced by running
the real `decayStageText` over each authored `currentText` and `seed`. Hand-authoring them would have shipped redactions
the algorithm does not produce, which is a subtler kind of second implementation.

**Genuinely new — and it is data, not math.** Synapse formation has no TS mirror (`memory/link.go`'s `LinkLaunched`,
`computeLinkStrength`, `canonicalPair`, `temporalNear`), and beat 4 needs synapses. **Decision: the synapse rows
are authored in the fixture.** A fixture cannot drift; a fourth mirrored function can. The guard for the authored rows
is the integrity suite's canonical-ordering and co-firing checks, plus the requirement that every authored `strength`
lie inside `[synapse.initial_same_memory, synapse.strength_cap]` so the filament layer reads at the same scale it does
in production.

**Deliberately not mirrored, and the plan says so:** `LinkLaunched`/`computeLinkStrength`/`canonicalPair`/`temporalNear`
(authored as data); `AdvanceClock`/`CanLaunchAt` ([Z2] exempts [I10] — the demo clock is a plain mutable ISO date owned
by plan 79); `ConsumeGistUnits` ([Z5] precomputes all four gist stages, so nothing consumes units);
`Extractor`/`Semanticizer`/`Embedder` ([Z1], UL §5). The residual drift risk is a copy-paste of an existing pure
function into the package, which `scripts/lint-fsd-layout.mjs` R4 and the acceptance criterion below both catch — and
which has no motive, since the fixture has no field for a computed result.

## Acceptance Criteria

1. A new pure package `@cosimosi/demo` exists at `packages/demo`, free of React, DOM, native and transport deps, whose
   manifest declares **only** `@cosimosi/memory`, `@cosimosi/emotion`, `@cosimosi/memory-logic` and `@cosimosi/config`;
   no other package or app lists `@cosimosi/demo` as a dependency ([I13][Z1], ARCHITECTURE §3.5).
2. `DemoDiarySet` holds **three** tutorial diaries plus a non-empty `extraDiaries` free-play pool (≥3 per set, each
   extra reusing at least one tutorial neuron), and separates locale-free **structure** from a `Record<Locale, …>`
   **text** half; a set missing text for a supported locale fails typecheck ([Z4] as amended by change 10, [Z5], [K3]).
3. Every diary in every set — tutorial and extra alike — carries its fully precomputed split: `EpisodicMemory`
   members with `name`, `Emotion` (`Mood` + intensity), `NeuronActivation` weights, `seed`, four `SemanticStages`
   texts, and decay-stage texts for stages 1..N where N = `forgetting.stage_word_removal_ratios`' length, each
   byte-identical to the production `decayStageText` output for that text and seed ([Z5]).
4. Every set declares a non-empty `sharedNeuronIds` tuple, and the fixture-integrity suite proves that at least one
   `Neuron` is activated by memories from **two or more different diaries** of that set ([Z4], the beat-4 precondition).
5. Every authored `Synapse` is canonically ordered (`neuronAId < neuronBId`), connects two neurons that co-fire in at
   least one memory, and carries a strength within `[synapse.initial_same_memory, synapse.strength_cap]`
   ([I6][I4]).
6. Each set covers all three `NeuronType`s; its first two diaries (the ones on screen at the colour beat) carry at
   least three distinct `Mood`s and contain the beat-6 recall target, so the sky those launches paint has a spread for
   beat 8 to name ([M4][M5], [Z3]-8, change 10).
7. The fixture types contain **no** field for a coordinate, `EffectiveBrightness`, `EffectiveStrength`, decay depth,
   decay stage, gist stage, accessibility weight, `Twinkle` amount or ornament price — every such value is computed by
   a reused mirror at read time ([I5][I11][Z8], §2.9 #3/#8).
8. `resolveDemoDiarySet(set, locale, epoch)` returns a `UniverseSnapshot` and a `Diary[]` **shape-identical** to
   `universeFromResponse` / `diariesFromDtos` output, plus a gist-text sidecar; `EpisodicMemory` gains no new field and
   no `isDemo` branch is introduced in any package ([I13]).
9. Diary dates are authored as integer day offsets and stamped from an `epoch` **parameter**; the package accesses no
   clock, no randomness and no storage, so the split/emotion/neuron/gist/decay results are byte-identical on every run
   and only the drawn set and the displayed calendar dates vary ([Z5][Z2]).
10. `pickDemoDiarySet(sets, draw01)` is pure and total over `[0, 1)`; `demoDiaryPool(set)` fixes one canonical
    per-diary order (triple, then extras) and `pickDemoDiary(pool, drawNumber)` is deterministic per draw number,
    cycling without back-to-back repetition; the pool and set counts are **derived array lengths** with no
    `values.yaml` key ([Z4] as amended below and by change 10).
11. `DemoScenario` names the ten [Z3] beats in order and binds the members the tutorial acts on — the first diary
    (the pool's own first draw) and the recall target — plus the beat-9 ornament **ids**; there is no gist binding
    (stages rise per memory, change 10); it carries no copy, no i18n key, no engine type, no price and no
    achievement data ([Z3][Z8]).
12. **No new pure domain function is defined in `packages/demo`**, no new `.golden.json` or Go testdata file is added,
    and the reuse ledger in Design is exhaustive — every derived value the demo displays comes from an existing
    parity-pinned function ([Z6] as amended in Design; ARCHITECTURE §2.9 #1).
13. The package makes no network, DB or LLM call and imports no `ai` port, no `@cosimosi/api-client` symbol and no
    server-backed read mirror ([Z1], UL §5).
14. All authored fixture text passes an [I12] review: no "works like a brain" claim, no description of the 3D
    coordinates as the brain's real coordinates, no therapeutic claim; the voice is literary and restrained, with no
    decorative emoji, in both locales.
15. The fixture-integrity suite runs in CI as part of `pnpm test` and fails on any violation of criteria 3–6, so an
    edit that breaks a set's constellation topology is caught by a gate rather than by watching the demo.
16. No rendering-vocabulary word (`star`, `cell-star`, `filament`, `constellation`, `nebula`, `latent-star`) appears in
    a type, field or identifier in this package (UL §4, §3.4).
