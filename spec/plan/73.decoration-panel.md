# 73. decoration panel

> Decoration panel — the presentation unit of Epic N: the **over-universe panel** ([P5]) through which a diarist wears
> their universe differently. It opens over the running canvas without a scrim, lists the **whole catalog regardless of
> ownership** with **live preview on the user's real universe** ([P6]), carries a **floating save button showing the
> unowned total** ([P8]), and **reverts on close** ([P8]). Ownership is never a noun here — it shows up only as the
> presence or absence of a price ([P7]). It leaves the catalog itself to [71.ornament-catalog-model](71.ornament-catalog-model.md)
> and the atomic buy-and-apply transaction to [72.decorate-usecase](72.decorate-usecase.md).
> Scope: FE | Status: built ([job 112](../jobs/archive/112.decoration-panel.md))
>
> **As built, the panel has two groups, not three.** A feeling's colour was retired from the ornament catalog before
> this unit shipped (change 08 / job 109): it is a free per-mood preference with its own surface, so there is no palette
> group, no palette write path to flip, and no `applyPalette` leg in the preview bridge. The panel points at where
> colours live instead. Everything else below is as built.
>
> Layer P. Home: `widgets/decoration-panel` (+ `features/{preview-ornament,buy-ornament}`) mounted by
> `pages/universe/ui/UniverseHomePage.tsx` beside `<DetailPanel/>` / `<RecallFlowSheet/>`, with the preview store and
> phase machine in the new `@cosimosi/store` package. It fills the **preview lifecycle + the save affordance**
> and becomes the **first production caller** of the runtime skin seam [14.rendering-foundation](14.rendering-foundation.md)
> reserved.

## Purpose

[P4]'s customization promise has been a reserved slot since v1 — and after Epic K it is not even a slot anymore:
`features/customize-staging` was **deleted** by [64.my-page](64.my-page.md)'s job, `/settings` no longer exists, and
the only real customization that shipped — the palette picker
([51.palette-customization](51.palette-customization.md), `features/change-palette`) — is **orphaned dead code**,
mounted on no page (its write-on-every-click model died with the settings page). Meanwhile `packages/3d-renderer`
carries a finished runtime skin seam (`setSkinKey`) with **zero production callers**, and a registry of tuned
emotion-sky effects of which exactly one (the authored default) is reachable, because the effect id is hardwired into
the single `emotion` skin's `sky.effect`. The universe can already look many ways; the user has never been able to
ask for any of them.

This unit is where that becomes a thing a person does. [P5] fixes the shape: **not a page** — a bottom sheet / sidebar
over the universe page, so the universe stays visible **while** you choose, because the point of decoration is watching
your own sky change. [P6] fixes the ethics of the shop: every item is listed and selectable **whether or not you own
it**, and selecting it applies to your real universe immediately — _사고 나서 보는 게 아니라, 보고 나서 산다_. [P8]
fixes the commitment: one floating save button carrying the sum of the unowned items, one atomic transaction, and
**closing without saving puts everything back**.

[P7] is the rule that shapes almost every decision below: there is **no 보관함, no inventory, no equip** in this UI.
The user has one world, they pick from a list, they save. Ownership is not a screen, a badge, or a filter — it is
**only** the absence of a price on a row. `OrnamentOwnership` and `OrnamentSelection` exist in the data model and must
never surface as user vocabulary.

Finally this unit is the one place where [I11] can be broken by a _feature_, not a bug: a decoration surface that could
reach a star's color, size, brightness or position would let a user buy the meaning of their own memories. The design
below makes that unrepresentable rather than reviewed — the panel's whole vocabulary is three opaque ids.

## Scope / Non-goals

**In scope**

- **`widgets/decoration-panel`** — the over-canvas panel ([P5]): a **non-modal, scrim-less** sheet mounted by
  `pages/universe` over the running `widgets/universe-canvas`; the renderer is **never remounted** ([A1], [14]). Owns
  the panel's composition and hosts the two features. Web + mobile ([00.overview](00.overview.md) §4).
- **`features/preview-ornament`** — the catalog list + selection ([P6]): all rows of all three `OrnamentKind`s,
  selectable regardless of ownership, each selection immediately applied to the user's real universe as a **client-only
  preview**.
- **`features/buy-ornament`** — the floating save button ([P8]): renders the **unowned total** of the current preview,
  calls `store.v1.Decorate` once, surfaces the insufficient-balance refusal naming the item ([P8],
  [72.decorate-usecase](72.decorate-usecase.md)'s `STORE_INSUFFICIENT_TWINKLE`), and blocks save when the preview
  holds an unowned **achievement-only** ornament ([P11]).
- **The preview lifecycle** ([P6][P8][P11]) — in-memory only, reverted on panel close, route navigation, reload,
  process death, sign-out and user switch; registered in the user-scope reset registry; never captured by any other
  mutation.
- **The runtime render seams becoming user-driven** ([V10]): one bridge inside `widgets/universe-canvas` translates the
  previewed ids into the `3d-renderer` sky seam (BACKGROUND) and the
  star-layer variant remount key (STAR_SHADER). The panel itself imports no renderer.
- **The boot gate seeds every confirmed kind** — the shipped colour bootstrap provider is extended with a
  parallel `store.v1.GetSelection`† read so the universe never paints a default sky before settling on the user's own.
- **`packages/ui` gains a `Sheet` primitive pair** (`sheet.tsx` / `sheet.native.tsx`) — the repo has no
  bottom-sheet primitive today.
- **Copy via i18n** under the `store_*` prefix, restrained literary Korean, **no `inventory_*` / `equip_*` key may
  exist** ([P7]).

**Non-goals**

- **No catalog content, registry, or price table.** The `Ornament` rows (derived from the registries — counts are
  never declared), the `SkyEffectKey`/`StarShapeKey` vocabularies, `GetCatalog`†/`GetSelection`†, and the two kind
  prices (`store.background_price`/`store.star_shader_price`) belong to
  [71.ornament-catalog-model](71.ornament-catalog-model.md). (The retired PALETTE
  section renders with no price on any row.
- **No `Decorate` transaction, spend, or migration.** The one-transaction buy-and-apply, the `SpendGate` leg, the
  `ornament_purchase` ledger row, the `palette_preferences` → `ornament_selections` migration and its drop are
  [72.decorate-usecase](72.decorate-usecase.md).
- **No new proto.** This unit adds no RPC and no message field; it consumes three methods owned by 71/72.
- **No `/me` surface.** [U9] keeps decoration out of `/me`; [64.my-page](64.my-page.md) **already shipped** that page
  (the `/settings`→`/me` rename and the staging-section deletion are done — job 93).
- **No earn surface, ledger view, or payment.** Shortfall recovery points at [76.achievement-ui](76.achievement-ui.md)'s
  tab; the ledger UI is [67.twinkle-relabel-and-ledger-ui](67.twinkle-relabel-and-ledger-ui.md); payment is
  retired to v3. **No achievement grant path** either — an achievement-granted ornament arrives as an
  `OrnamentOwnership` row written by [75.achievement-tracking-usecase](75.achievement-tracking-usecase.md) and the
  panel only sees a row with no price.
- **No bloom, camera, or colour editor.** Bloom and `camera.fov` are outside the catalog
  ([71.ornament-catalog-model](71.ornament-catalog-model.md)) and the free palette-editing UI is deferred
  (PRD §8.3); the panel exposes no numeric control of any kind.
- **No `Tabs` / `Select` / `Chip` primitive.** The three kinds are labeled sections in one scroll — and `Tabs` /
  `Select` already **ship** in `packages/ui` (`Tabs` is live on `/me`; `Select` was promoted by job 104), so there is
  nothing to add and nothing to wait for. This unit adds only `Sheet`.
- **No price on the demo.** [79.demo-page](79.demo-page.md)'s beat-9 taster reads catalog **ids only** ([Z8]) and
  never mounts this panel.

## Design

### Placement (FSD §3.1)

```
packages/store/src/                       (package created by 71; these files are this unit's)
├── ornament-preview-store.ts   previewActive + previewed Record<OrnamentKind, OrnamentId|null> + confirmed seed
│                               + preview()/revert()/commit()/resetStoreUserState()
├── decoration.machine.ts       the panel phase machine (§3.2)
├── decoration-request-store.ts the one-slot open signal (recall-target-store precedent)
├── decorate.ts                 requestDecorate(transport, selection) + the scope-epoch guard
└── save-eligibility.ts         pure: unownedTotal(catalog, preview) + saveVerdict(...)

packages/ui/src/primitives/sheet.tsx | sheet.native.tsx    the scrim-less sheet pair

apps/{web,mobile}/src/widgets/decoration-panel/
├── ui/DecorationPanelSheet.tsx   the sheet host: three labeled groups + the floating save button
├── config/panel.ts               slice-local layout constants (widths, breakpoint, sheet height fraction)
└── index.ts                      public API = the sheet

apps/{web,mobile}/src/features/
├── preview-ornament/   ui (the catalog rows per kind) · api (GetCatalog read → view model)
└── buy-ornament/       ui (the floating save button + refusal line) · api (Decorate + invalidation)
```

- The panel is **mounted by `pages/universe/ui/UniverseHomePage.tsx`** beside `<DetailPanel/>` / `<RecallFlowSheet/>` /
  `<DeletionFlowSheet/>`, and is **opened** by a restrained HUD affordance through `useDecorationRequestStore` — a
  widget may not import another widget (§3.1), and the shipped `recall-target-store` / `deletion-target-store` are the
  precedent. Mobile mounts it on the universe screen and gates consumption on `useIsFocused()` (the deletion-flow
  precedent), so a background screen cannot open the panel.
- **Parity (§3.5, [00.overview](00.overview.md) §4):** both apps ship the widget and both features;
  `model`/`api`/`config` are shared through `@cosimosi/store` and the app slices differ only in `ui`. Web renders a right-hand `<aside>` column at the `md`
  breakpoint and a bottom sheet below it; mobile renders the bottom sheet. Each new slice gets a scoped
  `'fsd/insignificant-slice': 'off'` block in `apps/web/steiger.config.js`.
- **`Dialog` is rejected as the host.** The shipped `Dialog` primitive is modal — scrim plus focus trap — which hides
  the universe and contradicts [P5]'s stated reason. `Sheet` therefore has **no `scrim`/`overlay`/`modal` prop at all**:
  the forbidden thing has no field. It renders no backdrop, traps no focus, and the camera stays interactive outside the
  panel's bounds.

### The consumed contract (owned by 71/72 — §2.7, unary)

This unit defines no proto. What it requires of the three methods:

- **`GetCatalog(GetCatalogRequest{}) → GetCatalogResponse{ repeated Ornament ornaments }`**† — the **whole** catalog
  in one read ([P6]); [71](71.ornament-catalog-model.md) owns the message and its fields are exactly
  `{ornament_id, kind, acquisition, price, owned, selected}`. **No label, blurb, asset URL or colour crosses the
  wire** — every string this panel shows is resolved FE-side from `ornament_id` under the `store_*` i18n keys, the same
  `mood_<value>`/`moodLabel` projection the product already uses. No pagination (the catalog is tens of rows), no
  `user_id` on the request, and **no `ListInventory` sibling to call**.
- **`GetSelection(GetSelectionRequest{}) → GetSelectionResponse{ … }`**† — the confirmed selection, read once per auth
  scope at boot to seed the three confirmed ids. Absence of a row means the configured default.
- **`Decorate(DecorateRequest{ background_ornament_id, star_shader_ornament_id, palette_ornament_id }) →
DecorateResponse{ repeated OrnamentSelection selection, int64 spent_twinkle }`** — one transaction ([P8]);
  the field names are [72.decorate-usecase](72.decorate-usecase.md)'s. **Structural guard: the request carries the
  three ids and nothing else** — no total, no price, no `owned` claim, no ornament attributes. The client therefore
  cannot influence what it is charged; the authoritative unowned total is computed inside the transaction. The
  response echoes the confirmed selection in 71's `OrnamentSelection` shape, so the commit is server truth rather than
  client optimism.
- Both reads are `NO_SIDE_EFFECTS` and must be classified **exactly once** in
  `packages/client-cache/src/http-policy.ts` (71 owns the entries; the transport hard-fails before I/O otherwise).

### The item view model — where [P7] becomes structural

The `api` mapper collapses the wire's `owned` boolean into a **cost discriminant**, so the UI has no ownership boolean
to render:

```
type OrnamentCost =
  | { kind: 'none' }                              // owned — the row simply shows no price
  | { kind: 'price'; amount: number }             // unowned & buyable ([P8] adds it to the total)
  | { kind: 'condition'; achievementId: string }  // achievement-only & unachieved ([P11])
```

The `condition` arm's `achievementId` does **not** come from `store`: 71's `Ornament` message carries
`acquisition = ORNAMENT_ACQUISITION_ACHIEVEMENT` and no achievement id, deliberately (no enum or id is reused across
contexts). The mapper joins on the other side — `ListAchievements`'
`AchievementEntry.reward_ornament_id` ([74.achievement-catalog-model](74.achievement-catalog-model.md)) — so an
achievement-only row with no matching catalog entry degrades to `{ kind: 'none' }` and stays unbuyable rather than
rendering a broken condition.

There is no `owned` field, no "보관함" grouping, no ownership filter, no equip verb, and no sort by ownership — a row
is either priced or it is not. The `selected` flag survives only as the group's single-selection mark. Together with
the absent `ListInventory`/`Equip` messages and plan 65's `inventory|equip|장착|보관함` lint rule over
`apps/*/src` + `packages/*/src`, [P7] has three independent mechanical guards and needs no copy review.

### The preview lifecycle — the decided answer to every boundary

`ornament-preview-store.ts` holds `{ previewActive, previewed, confirmed }`. `preview(kind, id)` is a **no-op while
`previewActive` is false**, so nothing outside the open panel can install a preview. The bridge (below) reads
`previewActive ? previewed : confirmed`. Each boundary, decided:

| Boundary                                                             | Behavior                                                                                        | Why it holds                                                                                                                                                                                   |
| -------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Panel closed without saving                                          | revert to `confirmed`                                                                           | the machine's only path to `closed` from `browsing` runs through the transient `reverting` state, whose entry action is the revert ([P8])                                                      |
| Route navigation (web `/me`, `/diary`; mobile screen blur)           | revert                                                                                          | the sheet unmounts → cleanup sends `CLOSE`; mobile additionally reverts on losing focus                                                                                                        |
| Reload / process death                                               | reverts by construction                                                                         | no `persist` middleware, no URL parameter, no server write — the boot gate re-seeds from `GetSelection`†                                                                                       |
| Sign-out / user switch                                               | revert + clear                                                                                  | `resetStoreUserState()` joins `@cosimosi/auth/user-state`'s shared user-state reset registry once, so both apps consume it                                                                     |
| A recall, diary write, or any other mutation while a preview is live | the preview **survives and is never captured**                                                  | no `memory.v1` or `twinkle.v1` message has an ornament field; the preview lives outside TanStack Query, so a `GetUniverse` invalidation re-renders with the previewed render parameters intact |
| `Decorate` fails                                                     | preview stays, `confirmed` unchanged, retriable                                                 | the machine returns to `browsing`; nothing was written                                                                                                                                         |
| `Decorate` succeeds                                                  | previewed becomes confirmed; `GetCatalog`/`GetSelection`/`GetBalance` invalidated; panel closes | the transient `committing` state's entry action, from the response's confirmed selection                                                                                                       |

**The palette reuses the shipped mechanism, it does not get a second one.** `usePalettePreferenceStore`
already has exactly the right shape — `paletteId` (display) vs `confirmedPaletteId` (server-confirmed) — so PALETTE
preview is `applyPalette(id)` and PALETTE commit is `applyConfirmedPalette(id)`. What changes:
`packages/emotion/src/preference/change-palette.ts`'s write-on-change (`changePalette`/`useChangePalette` calling
`setPalettePreference` on every click) is **deleted**, `features/change-palette` (with its `PaletteSection` and the
`settings_palette_selected` key) is **removed** as a slice here — `features/customize-staging` is
[64.my-page](64.my-page.md)'s deletion, not this unit's — and the canvas widget imports `usePaletteVersion` from
`@cosimosi/emotion/react` directly instead of through the deleted feature barrel.
`initializePaletteSession`/`resetPaletteSession`/`paletteSessionMatches` **stay** — the boot gate and the reset registry
use them — and the auth-epoch guard those functions embody moves, unchanged in shape, into
`packages/store/src/decorate.ts` so a `Decorate` that resolves after a user switch cannot commit into the new scope.
**Sequencing note ([00.overview](00.overview.md) §5.6):** plan 72 removes `SetPalettePreference` from the wire and
must delete the now-dangling call site in its own job; plan 73 owns everything that replaces it.

### The preview bridge — one translation point (§3.4)

`widgets/universe-canvas` gains a single `OrnamentPreviewBridge` mounted **inside** `<SkinProvider>` (the provider is
scoped to the canvas widget, so nothing outside it can reach `setSkinKey`). It subscribes to the effective selection
and drives the three seams, all of which already exist:

- **PALETTE** → `applyPalette(id)` (module-level `setMoodPalette` — the single [M6] entry point, [V10]) plus the
  existing `usePaletteVersion()` remount keys on the color-bearing layers.
- **BACKGROUND** → 71's effect-selection seam (the per-user `SkyEffectKey` that feeds the `emotion` skin's
  `sky.effect`). The **two production** `<SkinProvider defaultSkin={…}>` call sites (the universe-canvas widgets on
  both apps; the four `/test`-surface providers stay untouched) are re-pointed from the authored default to the
  confirmed/previewed effect with that default as the fallback-when-absent.
- **STAR_SHADER** → the shape is folded into the existing `StarLayer` remount key (`star-${paletteVersion}` becomes
  `star-${paletteVersion}-${shape}`), which disposes and rebuilds the material through `InstancedNodeLayer` exactly as
  a palette swap does today (the sibling `nebula-${paletteVersion}` / `gist-${paletteVersion}` keys are untouched — a
  background or shape change never remounts them).

The renderer itself is **never remounted** ([A1], [14]) — only the affected layer. `widgets/decoration-panel` never
imports the renderer; the eslint import ban makes that structural rather than conventional.

### The floating save button ([P8][P9][P11])

`features/buy-ornament` renders one persistent button over the panel content. `save-eligibility.ts` is a pure function
pair shared web + mobile:

- `unownedTotal` = the sum of `cost.amount` over the previewed rows whose cost is `price`. Already-owned rows and the
  unchanged rows cost nothing ([72.decorate-usecase](72.decorate-usecase.md)), so re-selecting a palette you own is
  free and the button reads plainly `저장`.
- `saveVerdict` returns one of `ready | free | shortfall(amount) | locked(achievementId) | unchanged`. It compares
  against the **`GENERAL` balance only** ([P9]) read from the shared twinkle mirror — the panel mounts no second
  `GetBalance` query and never mentions `SMALL`.
- `shortfall` disables the save and shows the missing amount **and the item that is short** ([P8]), with the recovery
  path pointing at the achievements tab / earn explainer, never a purchase.
- `locked` disables the save and states the acquisition condition ([P11]); the preview itself stays applied, which is
  exactly what [P11] asks for ("미리보기까지만 가능하고 저장할 수 없다"). The server refuses it too, with its own
  reason ([72.decorate-usecase](72.decorate-usecase.md)) — the FE predicate is a courtesy, not the gate.
- A stale balance that passes the client check is caught by `STORE_INSUFFICIENT_TWINKLE`, whose item-name payload feeds
  the same copy through `error_store_insufficient`.

### Panel control-state (XState v5, §3.2)

`packages/store/src/decoration.machine.ts` holds **phase and last-failure reason only**; the previewed ids, the catalog
and the balance are data (Zustand / TanStack Query).

| State        | Meaning                                                                                | Exits                                                                    |
| ------------ | -------------------------------------------------------------------------------------- | ------------------------------------------------------------------------ |
| `closed`     | panel hidden                                                                           | `OPEN` → `browsing`                                                      |
| `browsing`   | panel open, preview live                                                               | `SAVE` → `saving`; `CLOSE` → `reverting`                                 |
| `saving`     | `Decorate` in flight; the sheet's close is **inert** and this state has **no `CLOSE`** | `done` → `committing`; `error` → `browsing` (retriable, nothing written) |
| `committing` | transient — entry: commit previewed → confirmed, invalidate catalog/selection/balance  | → `closed`                                                               |
| `reverting`  | transient — entry: revert to confirmed                                                 | → `closed`                                                               |

Making `reverting` and `committing` **transient states rather than actions on a transition** is the structural form of
[P8]'s revert-on-close: there is no path from an open panel back to `closed` that skips one of them. `saving` carrying
no `CLOSE` is the deletion-flow precedent — a stale completion cannot land on a freshly-reopened panel.

### The boot gate

`apps/{web,mobile}/src/app/providers/palette-bootstrap.tsx` (and its sibling `palette-bootstrap.test.tsx`) is renamed
`decoration-bootstrap.tsx` and its gate moves to a **single** `GetSelection`† read, which serves all three confirmed
ids — the surviving `GetPalettePreference`† (72's read-through onto the same `ornament_selections` row) is **not**
also awaited, because gating on two reads of one underlying fact is a wasted parallel round trip. The read is cached
and `NO_SIDE_EFFECTS`, and gating on it avoids painting a default sky that then jumps. Its import of the session
helpers moves from the deleted `features/change-palette` barrel to `@cosimosi/emotion/react` (which requires
splitting `change-palette.ts` — `initializePaletteSession`/`resetPaletteSession`/`paletteSessionMatches` stay, in
their own module, while `changePalette` itself is deleted; the module-level session state moves with the survivors
and `change-palette.test.ts` is re-scoped).

### Golden-parity stance

**No golden-parity obligation, and none is added.** `unownedTotal`/`saveVerdict` are display arithmetic over
server-supplied prices, and the authoritative total lives in `internal/store`'s transaction. Because
`DecorateRequest` has **no total field**, a TS↔Go divergence cannot mis-charge anyone — it can only mislabel a button,
which the server's refusal immediately corrects. No fixture, no `packages/*-logic` function, no mirrored formula. The
preview mechanism is likewise pure presentation: it changes render parameters, never a domain value, so nothing here
belongs in `packages/memory-logic` or `packages/twinkle-logic`.

### Copy (i18n)

All strings resolve through `@cosimosi/i18n` under `store_*`; `pnpm lint:raw-strings` gates it. Keys name a **UI role**:
`store_panel_title`, `store_panel_close`, `store_group_background_title`, `store_group_star_title`,
`store_group_palette_title`, `store_price_amount`, `store_condition_locked`, `store_save_action`,
`store_save_action_priced`, `store_shortfall_notice`, `store_locked_notice`, `store_saving_notice`,
`store_open_action`. **No `inventory_*` / `equip_*` key may be added** ([P7]) and the 13 mood labels keep coming from
`packages/emotion`'s `moodLabel`. Voice: restrained and literary — `우주 꾸미기` for the panel,
`저장 · 별가루 {amount}` when something is being bought and a bare `저장` when nothing is,
`별가루가 {amount} 모자라요` for the shortfall, `업적으로 얻을 수 있어요` for a locked row. No sales pressure, no
decorative emoji, no ownership vocabulary. Final wording is authored at implement against
[policy/ux/design-review.md](../policy/ux/design-review.md).

## Acceptance Criteria

1. An affordance on the universe HUD opens `widgets/decoration-panel` over the running canvas through
   `useDecorationRequestStore`; the panel renders **no scrim and traps no focus**, the universe stays visible and
   camera-interactive beside/behind it, and the renderer is **not remounted** ([P5], [A1], [14]).
2. The panel lists the **entire catalog** from a single `GetCatalog`† read — all three `OrnamentKind`s, every row
   selectable **regardless of ownership** ([P6]) — as three labeled groups in one scroll, with no tab, no ownership
   filter and no separate owned/unowned view.
3. Selecting any row — owned or not — applies **immediately to the user's real universe**: a palette through
   `applyPalette`, a background through the `3d-renderer` skin seam, a star variant through the star-layer remount key.
   Only the affected layer remounts ([P6], [V10]).
4. Ownership is visible **only** as the presence or absence of a price: the item view model carries a cost discriminant
   (`none | price | condition`) and **no `owned` boolean**; no screen, badge, section, verb or i18n key uses
   inventory/보관함/equip/장착 vocabulary, and no `ListInventory` or `Equip` method exists to call ([P7]).
5. A **floating save button** shows the **sum of the previewed unowned items' prices** and calls `Decorate` **once**;
   already-owned and unchanged rows contribute nothing, so re-selecting something owned reads as a free save ([P8]).
6. `DecorateRequest` carries **only the three selected ids** — no total, no price, no ownership claim, no ornament
   attribute — so the client cannot influence what it is charged; the authoritative total is the server's ([P8], [P9]).
7. When the previewed unowned total exceeds the **`GENERAL`** balance the save is **blocked**, and the copy names both
   the shortfall and the item that is short; recovery points at the achievements/earn path, never a purchase. A stale
   balance is caught by `STORE_INSUFFICIENT_TWINKLE` and rendered through the same copy ([P8], [P9]).
8. The panel reads and displays **`GENERAL` only** — `SMALL` appears nowhere in it, and it mounts no second
   `GetBalance` query ([P9]).
9. An **achievement-only, unachieved** ornament shows its **condition instead of a price**, **previews normally**, and
   **cannot be saved**; the server refuses it independently with its own reason ([P11]).
10. Closing the panel without saving **restores the confirmed selection completely** — palette, background and star
    variant — and the machine has **no transition from an open state to `closed`** that bypasses the transient
    revert/commit states ([P8]).
11. The preview survives **nothing**: navigating away, reloading, process death, sign-out and user switch all restore
    the confirmed selection. There is **no `persist` middleware, no URL parameter and no server write** in the preview
    path, and `resetStoreUserState()` is listed in the shared user-state reset inventory.
12. A recall, a diary write, or any other mutation while a preview is live **neither cancels the preview nor captures
    it**: no `memory.v1` or `twinkle.v1` request carries an ornament id, and a `GetUniverse` invalidation re-renders
    with the previewed render parameters intact.
13. A successful `Decorate` promotes the previewed ids to confirmed **from the response**, invalidates
    `GetCatalog`/`GetSelection`/`GetBalance`, and closes the panel; a failed `Decorate` writes nothing, keeps the
    preview and returns to a retriable state; the sheet cannot be closed while the call is in flight ([P8]).
14. The panel exposes **no control over any meaning-layer or scene-level value**: no color, size, brightness, seed,
    position, mood, bloom or camera control exists in its UI, its stores, its machine context or the request, and
    `widgets/decoration-panel` is banned from importing `three` / `@react-three/fiber` / `@cosimosi/3d-renderer`
    ([I11], [V10]).
15. The palette write path is **preview-then-save**: `changePalette`'s write-on-change is gone and the orphaned
    `features/change-palette` slice is removed (the `/settings` page and staging placeholder are already gone —
    job 93); the palette is one of the panel's three groups, **every palette row is free and priceless** ([P10] as
    amended), and the default's encoding stays absence-of-a-row.
16. **web + mobile parity:** the same widget and both features run on both apps, sharing `model`/`api`/`config` through
    `@cosimosi/store`; the only fork is the new `Sheet` primitive pair, and the mobile host gates on `useIsFocused()`
    (§3.5, [00.overview](00.overview.md) §4).
17. **All** user-visible copy resolves through the i18n seam under `store_*` (`lint:raw-strings` passes), in restrained
    literary Korean, with no ownership vocabulary and no sales pressure.
