## Acceptance Criteria (from code-review/15.full-codebase-runtime,-gate,-and-cross-p)

Finding: R008 (P3). Both apps carry `src/shared/model/xstate-react.ts`, a pure re-export barrel over
`@cosimosi/state-machine/react` and the only file in either app importing it. They have drifted on
both halves:

|                        | web                                                                           | mobile                                                                 |
| ---------------------- | ----------------------------------------------------------------------------- | ---------------------------------------------------------------------- |
| exports                | 4 (`shallowEqual`, `useActorRef`, `useMachine`, `useSelector`)                | 5 (+ `createActorContext`)                                             |
| `useActorRef` guidance | "Use this in R3F components and read `actor.getSnapshot()` inside `useFrame`" | "Use this for non-UI subscriptions (gesture handlers, native modules)" |
| app-shell machine      | none — no `app/model/` segment at all                                         | `app/model/app-shell.machine.ts` + `machine-actors-provider.tsx`       |

§3.5 says everything under `model` is shared verbatim and §3.1 says both apps follow the app-layer
segmentation identically. The drift is also what evades the gate: `lint:fsd:layout` compares
_normalized-equivalent_ same-relative pure modules, so two files that stopped being equivalent form no
pair and nothing fires.

- [ ] A1 The two `shared/model/xstate-react.ts` files no longer disagree. Either they are identical
      (same export set, same guidance) or the seam is promoted so there is only one copy — decided in
      T001, not left as two hand-maintained files that happen to match today.
- [ ] A2 The `useActorRef` guidance documents the R3F pattern on **both** platforms. §3.5 puts the
      `react-native-webgpu` renderer in scope, not deferred, so mobile runs R3F too and its copy
      currently points developers away from the one pattern §3.2 mandates for per-frame reads
      (`getSnapshot()` in `useFrame`, never React state at 60fps). Mobile's "non-UI subscriptions"
      framing may be _added_, but not at the cost of dropping the R3F rule.
- [ ] A3 Whatever the seam exports, both apps can reach it. Today a web app-layer provider needing
      `createActorContext` would have to import `@cosimosi/state-machine/react` directly, bypassing the
      `shared/model` seam that exists to be the single import point.
- [ ] A4 The drift cannot silently recur. Either the promotion in T001 removes the second copy
      entirely, or a guard notices same-path files across apps whose content diverges — the
      same-content comparison `lint:fsd:layout` already does cannot see this class, because divergence
      is the thing that hides it.
- [ ] A5 The web app-shell question is answered on the record, not by omission: web either gains an
      `app/model/` control-state machine mirroring mobile's, or `spec/tech/state-machine.md` /
      `ARCHITECTURE.md` §3.1 states that web's shell control state is deliberately the router and why.
      §3.2 makes this a control-state decision ("the exclusive modes/phases/lifecycle … lives in XState
      machines"), so a gap is not a neutral default.
- [ ] A6 No behavior change. This is a re-export barrel and a documentation convergence: mobile's
      `AppShellActor` keeps working identically, web gains no new runtime behavior, and both apps'
      suites pass unchanged. If T001 promotes the seam, the promotion is import-path-only.

- [ ] T001 Decide the shape (A1). Two viable ends:
      **(a) Converge the two copies** — same five exports, same guidance, in both apps. Cheapest, keeps
      the per-app `shared/model` seam §3.1 describes, but leaves two files to keep in step (so A4 needs
      the guard).
      **(b) Promote the seam** — the barrel is platform-pure and identical in intent, which is exactly
      what §3.1's promote-on-reuse rule targets ("normalized-equivalent same-relative pure modules under
      app-local `api`/`model`/`lib`/`config` paths … fail until promoted to their owning package").
      `packages/state-machine` already owns `react.ts`, so the seam may simply _be_ that entry point with
      each app re-exporting it unchanged — or the app-local file disappears and product code imports the
      package's React seam directly. Check §3.1's own carve-out before choosing: it exempts "the
      identical two-line shells two apps end up with when each injects its own copy resolver into one
      packaged hook", and this barrel may be exactly that shape, in which case (a) is the sanctioned
      answer and (b) is over-engineering. Record the reasoning either way.
      Invoke `/fe-architecture` (and `/mobile-architecture`) for this call — it is a placement decision.
- [ ] T002 Apply T001. If (a): reconcile the export lists and merge the two doc comments into one text
      that covers both platforms. If (b): move/rename per the package's conventions and update every
      importer.
- [ ] T003 (A2) Write the merged `useActorRef` guidance so it carries the R3F pattern **and** the
      native-subscription note, with the `spec/tech/state-machine.md` §R3F-pattern reference web
      currently has and mobile lost. Follow `spec/principle/code-comments.md` — the comment explains the
      current rule, never the history of the drift.
- [ ] T004 (A3) Verify both apps' `shared/model/index.ts` barrels re-export whatever T002 settled on;
      mobile's already lists `createActorContext` (`apps/mobile/src/shared/model/index.ts:2`), web's
      needs to match. Confirm no product file imports `@cosimosi/state-machine/react` directly
      afterwards (today only the two seam files do — keep it that way).
- [ ] T005 (A4) If T001 chose (a), add the divergence guard. The natural home is
      `scripts/lint-fsd-layout.mjs`, which already walks both apps and already normalizes source for
      comparison — it needs the inverse check: same relative path + platform-pure + content **not**
      equivalent ⇒ report. Scope it carefully so genuinely-forked `ui` files and the documented
      `*.native` siblings do not trip it; §3.1's `ui`-conditional rule already defines the "platform
      marker" test to reuse. Add a negative case to `lint-fsd-layout.test.mjs`. If T001 chose (b), the
      second copy is gone and this step is unnecessary — say so rather than adding a guard with nothing
      to guard.
- [ ] T006 (A5) Answer the web app-shell question. Read `apps/mobile/src/app/model/app-shell.machine.ts`
      and compare against how web actually holds shell state (`app/routes/guards/auth-gate.ts`,
      `app/providers/profile-gate.tsx`, `WebRouterProvider`). If web's router genuinely is its shell
      control state, record that in `spec/tech/state-machine.md` as a deliberate platform difference
      with the reason. If web is simply missing the machine, **do not build it here** — that is new
      control-state behavior, so raise it as a `spec/changes/` proposal via `/create-change` and link it
      from this job. This job's scope is the seam plus the recorded decision.
- [ ] T007 Confirm the `pages/design/index.ts` barrel drift found alongside R008 (web exports
      `SHOWCASE_GROUPS`/`SHOWCASE_SECTION_IDS`, mobile does not) is intentional, or fold it into T002.
      It is one line and the same class of divergence; decide rather than leave it.
