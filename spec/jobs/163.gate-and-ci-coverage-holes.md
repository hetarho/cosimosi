## Acceptance Criteria (from code-review/15.full-codebase-runtime,-gate,-and-cross-p)

Findings: R005, R006, R007, R009, R010 — the report's "a guard was written, and then not run" theme.
Each of these has a rule written down and a scanner that exists; what is missing is the wiring that
makes an offender fail. Grouped as one job because they share that root cause and all land in
`scripts/`, `package.json` and `.github/workflows/`.

- [ ] A1 (R005) CI builds the site the way production does. `pnpm build:site` — the command
      `DEPLOY.md` §2 and `wrangler.jsonc` both name as the production build — runs in CI, so
      `scripts/stage-blog.mjs` and its two deliberate assertions execute there. A regression in the
      staging step, the blog output path, or the build **order** fails CI instead of failing at the
      Cloudflare Pages build (or shipping `/blog/**` missing, the "production 404 that nothing in the
      build output complains about" the script's own header describes).
- [ ] A2 (R005) There is one build path, not two. `check`'s `build:web && build:blog` no longer
      disagrees in order with `build:site`'s `build:blog && build:web && stage-blog`, so the ordering
      the script exists to protect cannot be validated in an order production never uses.
- [ ] A3 (R006) The mobile shared-client probe runs. `probeSharedPlatformClientImport` and
      `probeSharedClientCacheFacade` execute under `pnpm test:mobile` with real assertions, giving
      mobile the coverage web already has via `apps/web/src/app/providers/api-client.test.ts` — plus
      the client-cache half, which no web test covers.
- [ ] A4 (R006) The class is closed, not just the instance: no file under `apps/*/src` can be a
      probe/test that its app's runner silently ignores. Either `.probe.*` is deliberately added to the
      mobile `testMatch`, or a guard asserts every such file is reachable by that app's runner. (Root
      cause: `apps/mobile/jest.config.js` sets no `testMatch`/`testRegex` and
      `@react-native/jest-preset` defines neither, so Jest's defaults apply and `.probe.ts` matches
      nothing.)
- [ ] A5 (R007) The app-layer segment set is enforced against **directories**, not only files.
      `scripts/lint-fsd-layout.mjs` currently guards with `!entry.isDirectory() && CODE_EXT.test(...)`
      (`:158`), so an unknown _segment_ passes while a single loose file fails — even though the
      failure message already enumerates the closed set (`:160-162`) and the main block only `note()`s
      the segments it finds (`:231-235`). After this job, an unknown app-root directory fails, and
      `lint-fsd-layout.test.mjs` has a negative case proving it.
- [ ] A6 (R007) `apps/mobile/src/app/diagnostics/` is resolved — moved into a documented segment (or a
      `pages` slice), or `ARCHITECTURE.md` §3.1 is amended to admit it explicitly. The gate and the
      doc agree either way; §3.1 must not keep claiming a closed set the tree violates.
- [ ] A7 (R009) The observability boundary gate covers `apps/api/cmd` (the composition root, where a
      direct SDK import is most tempting and where §2.4's "sees everything" makes it look permitted)
      and `apps/blog/src` (a shipped build target with no telemetry today). Neither has a live
      violation now, so this is closing a latent hole, and the allowlist for both is empty.
- [ ] A8 (R009) That gate has a negative probe, like every other guard in the gate: a forbidden import
      planted in a non-allowlisted path inside a hermetic `.probe-ws-*` workspace makes it fail. Its
      existing three-file liveness anchor (`check-observability-boundaries.mjs:49-70`) proves the
      detector works on real content but never proves the allowlist is not over-broad — that is the
      untested half.
- [ ] A9 (R010) A stale install fails the preflight with an actionable message, not a misleading type
      error. `pnpm check` on a tree whose `node_modules` predates a `package.json` dependency change
      says "run `pnpm install`" rather than surfacing
      `TS2307: Cannot find module '@cosimosi/config'` from a package whose dependency is correctly
      declared and correctly locked. The check runs in the same first position as `check:node`, before
      any linter or compiler can produce the confusing error.
- [ ] A10 No gate becomes slower than it needs to be, and none becomes flaky. A9 in particular must not
      add a network round trip to every `pnpm lint` — a lockfile/tree comparison is local.
- [ ] A11 No behavior change to what the gates _accept_: every guard this job widens is green on the
      tree as it stands after A6, and the full `pnpm check` still passes.

- [ ] T001 (R005/A1,A2) Make one build path. Preferred: replace `check`'s
      `pnpm build:web && pnpm build:blog` with `pnpm build:site`, so the ordering and the staging
      assertions are exercised by the same command production runs. Check what else depends on the two
      separate scripts first (`build:web` alone is useful for the FE DoD line in every job doc — keep
      the script, just stop `check` from being the only caller of the split pair).
- [ ] T002 (R005) Confirm the CI runner can actually run it: `build:blog` is Astro and `sharp`'s
      postinstall is among pnpm's ignored build scripts (no `onlyBuiltDependencies` in
      `package.json`). `build:blog` passes today, so this is a verification step, not a fix — but if
      `build:site` newly exercises a `sharp` path, decide whether `sharp` joins
      `pnpm.onlyBuiltDependencies` rather than letting CI depend on a skipped postinstall.
- [ ] T003 (R006/A3) Rename `apps/mobile/src/app/providers/api-client.probe.ts` to
      `api-client.test.ts` and give it real assertions — mirror the web test's
      `expect(response.requestId).toBe(...)` shape for the platform client, and add the client-cache
      assertion for `probeSharedClientCacheFacade`. Keep it in `app/providers` (it tests the provider
      seam) so the app-layer segmentation stays intact.
- [ ] T004 (R006/A4) Close the class. Simplest durable form: a small guard that, for each app, lists
      files under `src` matching `*.probe.*` or `*.test.*` and asserts each is matched by that app's
      configured runner pattern — failing on any file the runner would skip. Wire it into
      `test:guards` beside the other probes. If instead you choose to widen mobile's `testMatch`, the
      guard is still worth having, because the next `.probe.ts` under `apps/web` would hit the same
      trap with vitest.
- [ ] T005 (R007/A5) In `scripts/lint-fsd-layout.mjs`'s `findFsdLayoutProblems`, validate app-root
      **directories** against the same closed set the error message names
      (`providers` · `routes`|`navigation` · `model` · `styles`). Keep the web/mobile asymmetry the set
      already encodes (`routes` for web, `navigation` for mobile) rather than accepting both everywhere.
      Leave the `note()` of found segments — it is useful output — but stop it being the only check.
- [ ] T006 (R007/A5) Add the negative case to `scripts/lint-fsd-layout.test.mjs`: an unknown app-root
      segment is reported. Follow the hermetic-fixture convention (`scripts/probe-workspace.mjs`) so a
      concurrent ordinary scan cannot sweep the fixture up.
- [ ] T007 (R007/A6) **Decide `app/diagnostics/` before T005 can go green.** Read
      `apps/mobile/src/app/diagnostics/{DiagnosticsScreen.tsx,index.ts}` and place it: a screen reached
      by navigation is a `pages` slice; a dev-only surface wired by a provider belongs under
      `app/providers`. Amending §3.1 to admit a fifth segment is the last resort — the closed set is
      load-bearing for the whole app-layer rule. Invoke `/mobile-architecture` for the placement call.
- [ ] T008 (R009/A7) [P] Add `apps/api/cmd` (Go, forbidden `github.com/getsentry/sentry-go`, empty
      allowlist) and `apps/blog/src` (TS/TSX/Astro, forbidden the web SDK set, empty allowlist) to the
      `checks` array in `scripts/check-observability-boundaries.mjs`. Note `walk()` currently filters
      by extension — add `.astro` if the blog needs it, or state why the blog's `.astro` files are out
      of scope.
- [ ] T009 (R009/A8) [P] Add the negative probe in the `probe-packages-lint.mjs` style: plant a
      forbidden import in a non-allowlisted path in a hermetic workspace, assert the guard reports it,
      and assert an allowlisted path does **not** trip — the second half is what tests the allowlist.
      Wire into `test:guards`.
- [ ] T010 (R010/A9) Extend the preflight. `scripts/check-node-version.mjs` is already first in both
      `lint` and `check` and already cross-checks a declared floor against a pin, so it is the natural
      home — or add a sibling `check:install` invoked immediately after it. Compare the installed tree
      against the lockfile locally (e.g. `pnpm install --frozen-lockfile --dry-run`, or compare each
      workspace importer's declared links against what exists on disk) and fail with "run
      `pnpm install`". Keep it offline and fast (A10).
- [ ] T011 Reflect the gate inventory into `spec/plan/02.quality-gates.md`: the new gates, the widened
      scopes, and the new probes — that doc is where the gate set is enumerated, and job 152 set the

      A guard that cannot be shown failing is the exact defect this job exists to remove.
