# Job 136: Canvas host lifecycle correctness (refactor)

> Implementation work doc. Source spec: [code-review/12.frontend-rendering-performance-audit](../code-review/12.frontend-rendering-performance-audit.md).
> /cosimosi:implement-job 136 builds it via the two checklists below. When done, reflect the result into the
> SSOT (plan/policy/values) and set status: done. Write it in English.

Fixes the review's two P1s — the two canvas hosts made **opposite** lifecycle mistakes around the same
R3F-doesn't-know-WebGPU gap: the native host tears the device down on every re-render (R001), the web host never
tears it down at all (R002). **Build after job 139, then before jobs 137/138**: the renderer bump establishes the
visual/test baseline, and the two later jobs touch the same host files.

## Acceptance Criteria (from code-review/12 — R001, R002)

- [ ] A1 **A native host re-render never touches the WebGPU device.** With the scene mounted, a re-render of the
      composing widget (new `children` identity — e.g. a sweep-clock sample, a GetUniverse refetch, `useIsFocused`
      flipping, a mood pick) results in `root.render(children)` only: the same `WebGPURenderer` instance survives,
      `dispose()` is not called, no re-`init()` runs. (R001.)
- [ ] A2 **Native DPR/backing-size, camera, tone-mapping, exposure, and clear-color changes hot-apply without
      teardown.** A DPR step resizes the live backing store/R3F root in place; `fov`/`far` reconfigure the live
      camera; tone/exposure mirror the web host's hot-apply pattern (`UniverseCanvas.tsx:78-83`), while native
      clear-color uses `renderer.setClearColor` in the new live-config effect (web currently sets clear only in its
      one-time `gl` factory). Genuinely device-shaped inputs (`forceWebGL`) may still rebuild, but only those, and
      the rebuild path stays leak-free (dispose-then-recreate exactly once).
- [ ] A3 **The web host disposes its `WebGPURenderer` on unmount.** Unmounting a `<UniverseCanvas>` (route change,
      panel close) calls `renderer.dispose()` exactly once; a mount→unmount→mount cycle does not accumulate devices
      and produces no WebGPU validation errors. (R002 — R3F's own unmount path calls WebGL-shaped methods
      (`renderLists?.dispose()` / `forceContextLoss()`) that do not exist on `WebGPURenderer`, so our host must own
      this.)
- [ ] A4 **The fork owns its test (§3.5).** The native host has a lifecycle test asserting: re-render with new
      children → same renderer, no dispose; unmount → dispose exactly once. The web host has the mirror test for
      dispose-on-unmount. Both survive StrictMode-style double-invoke where the platform runs it.
- [ ] A5 **No behavior or visual change otherwise.** Scene output identical (headless CDP screenshot parity on web);
      all gates green (`pnpm check`).

## Implementation Checklist

- [ ] T001 `packages/3d-renderer/src/canvas/UniverseCanvas.native.tsx`: split the single effect
      (`:47-109`, deps `[children, dpr, fov, far, clearColor, forceWebGL, toneMapping, exposure]`) into
      (a) a **mount/device effect** — `getContext`, initial backing-store sizing, `createRoot(canvas)`,
      `configure({...})`, with cleanup (`unmountComponentAtNode` + `renderer.dispose()`) keyed **only** on inputs
      that genuinely require a new device (`forceWebGL`; keep the list minimal and comment why each is there);
      (b) a **children effect** — `root.current?.render(children)` keyed `[children]`, no cleanup;
      (c) a **live-config effect** — resolve `PixelRatio`/`dpr` to a number, resize `canvas.width`/`height`, update
      the existing root's size/camera (`fov`/`far`) through the supported configure/state seam, and write
      `toneMapping`/`exposure`/`clearColor` onto the live renderer. None of these changes may enter the device
      effect's dependency key. Update the `:46` comment ("memoize nothing here") to describe the new split.
- [ ] T002 [P] `apps/mobile/src/widgets/universe-canvas/ui/UniverseCanvasWidget.tsx:263`: stop passing a fresh
      `dpr={[1, VALUES.rendering.maxPixelRatio]}` array literal per render (hoist to a module constant) — belt and
