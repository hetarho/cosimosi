# Job 141: Per-frame efficiency and adaptive quality (refactor)

> Implementation work doc. Source spec: [code-review/12.frontend-rendering-performance-audit](../code-review/12.frontend-rendering-performance-audit.md).
> /cosimosi:implement-job 141 builds it via the two checklists below. When done, reflect the result into the
> SSOT (plan/policy/values) and set status: done. Write it in English.

Cuts the steady-state per-frame cost and adds the missing quality levers. Today five instanced layers recompose and
re-upload every matrix every frame even when the coordinate buffer did not change (R009), and the only quality
control anywhere is a static DPR cap — no fps-adaptive DPR, no background gate, and reduced motion freezes time but
keeps full frame cost (R010). Measurement lands first so every change gets a number.

## Acceptance Criteria (from code-review/12 — R009, R010)

- [ ] A1 **Clean frames are (near-)free for contiguous-slot layers.** When the coordinate buffer version, the
      channels, and the animation inputs are unchanged, `InstancedNodeLayer` skips matrix recomposition and does not
      set `instanceMatrix.needsUpdate` — a converged, untouched universe spends ~zero CPU in the instanced layers.
      Projection layers with per-frame animation (`getInstancePosition` — gist rise, awaken flare) keep animating
      correctly. (R009.)
- [ ] A2 **The awaken layer is idle-free.** With no flare playing, `AwakenNeuron` writes no matrices (today it
      rewrites its full 32-slot capacity every frame).
- [ ] A3 **Per-frame name lookups are gone from the hot loop** (the `geometry.getAttribute(name)` per frame — held
      as a ref; the gist `Map.get` per instance per frame — indexed once per channel change).
- [ ] A4 **DPR adapts to sustained fps.** A small monitor steps the canvas DPR between 1 and
      `rendering.max_pixel_ratio` on sustained-fps windows with hysteresis (no oscillation); thresholds/windows are
      values-seamed (gen:values). Works on both platforms (web `setDpr`; native's manual sizing path).
- [ ] A5 **A backgrounded native app stops rendering.** `AppState !== 'active'` pauses the native frameloop (and
      the inline sim pump); returning foregrounds cleanly. (Web already inherits rAF's hidden-tab pause.)
- [ ] A6 **The change is measured.** A dev-only perf HUD (`r3f-webgpu-perf`, behind the existing diagnostics gate)
      is available on web, and this doc's Result section records before/after frame cost for: converged scene,
      acceleration sweep, and launch — desktop + one phone.
- [ ] A7 **No visual/behavior change** at steady fps: same output, same interactions; full gate green.
