## Acceptance Criteria (from plan/60.account-profile-model)

- [ ] A1 Migration `apps/api/db/migrations/00016_account_identity.sql` creates `users(user_id TEXT PRIMARY KEY, nickname TEXT NOT NULL, timezone TEXT NOT NULL, locale TEXT NOT NULL, created_at TIMESTAMPTZ NOT NULL DEFAULT now(), deleted_at TIMESTAMPTZ)`, `auth_providers(… PRIMARY KEY (user_id, provider), CHECK (provider IN ('GOOGLE','PASSWORD')))` and `invites(… token TEXT NOT NULL UNIQUE, invitee_user_id TEXT NOT NULL, bound_at TIMESTAMPTZ NOT NULL, CHECK (invitee_user_id <> user_id))` with a unique index on `invites.invitee_user_id` and **no foreign key to `users`**; `pnpm db:migrate` applies and `pnpm db:down` reverses cleanly ([U1][U5][U8]).
- [ ] A2 Every new statement in `db/queries/account/**` is conjunctively scoped by a `user_id` parameter, `pnpm lint:persistence` passes, and **no entry is added** to `globalQueries` or `platformTables` in `scripts/check-persistence-isolation.mjs` ([U1]).
- [ ] A3 `users` has **no email column**, `platform.UserIdentity` still carries only `UserID`, and the email in `GetProfile` comes from the Supabase Auth Admin adapter — so a Supabase email change is visible with no write to our database ([U5][K6]).
- [ ] A4 The directory adapter lives in `apps/api/internal/platform/supabase`, returns platform-owned DTOs (it imports no context package), and `account` and `admin` each bind it through their own consumer-owned port at `cmd/api/{account,admin}.go`; `admin`'s existing behavior and tests are unchanged (ARCHITECTURE §2.2/§2.4).
- [ ] A5 `GetProfile†` returns an **absent** `profile` message for an authenticated user with no `users` row, never a synthesized nickname, and **no read path writes a `users` row** (there is no lazy provisioning) ([U6]).
- [ ] A6 `UpdateProfile` is the only writer of nickname/timezone/locale; it rejects a nickname whose trimmed **rune** length falls outside `account.nickname_min_length … account.nickname_max_length`, a timezone `time.LoadLocation` cannot resolve, and a locale outside the shipped set — none of which is ever stored ([U6][U7][K6]).
- [ ] A7 A stored timezone that no longer resolves coerces to `UTC` on read (never an error, never an empty boundary), and both `cmd/api` and `cmd/worker` embed the tz database so IANA lookup works on the distroless-static production image ([U7]).
- [ ] A8 `account` publishes the zone and `memory` consumes it through a **memory-owned** `UserZone` port bound by a composition-root adapter; `account` imports neither `memory` nor `twinkle` and neither imports `account`; the shipped default binding resolves `time.UTC` and an integration test asserts production binds the real reader (§2.4).
- [ ] A9 Every truncation of the **real** clock to a calendar day in the memory context resolves in the user's zone — the four sites `launch.go` (future-date rejection, **with the one-day UTC+14 slack removed**), `sync.go` `SyncStatus`, `sync.go` `syncToToday`, `spend_signals.go` — while every universe-time DATE derivation (`forgetting.go`, `semanticization.go`, `clock.go`) is unchanged and `AdvanceClock`/`CanLaunchAt` keep their zone-free signatures ([U7][W5][T1][I10]).
- [ ] A10 A timezone change through `UpdateProfile` writes only the `users` row: it produces no `twinkle_balances`, `twinkle_ledger_entries` or `universe_state` write, so no grant window, balance or clock can be moved by a profile edit ([G2]).
- [ ] A11 `ListAuthProviders†` returns only members of the closed set `{GOOGLE, PASSWORD}` with membership read through the directory and `linked_at` from `auth_providers` (falling back to the stored rows when the directory is unavailable), and **no unlink RPC, message, or query exists anywhere in `cosimosi.account.v1`** ([U5]).
- [ ] A12 `GetInviteLink†` performs **no database access**, returns an HMAC-signed token carrying inviter id, issued-at and a fresh nonce plus an `expires_at` of `issuedAt + account.invite_link_ttl_days`, and fails with `ACCOUNT_INVITE_LINK_UNAVAILABLE` when no signing key is configured rather than issuing an unsigned token ([U8]).
- [ ] A13 `VerifyInviteToken` recovers the inviter id from the **verified payload** with a constant-time MAC comparison and rejects a tampered, malformed or expired token; there is **no query anywhere that selects from `invites` by token** ([U8][G6]).
- [ ] A14 The `invites` schema makes the illegal states unrepresentable: a self-invite (`CHECK`), an invitee bound twice (unique index), the same token consumed twice (`UNIQUE (token)`), and an unbound invite row (`NOT NULL` on `invitee_user_id`/`bound_at`); `invites` has **no `deleted_at`** — withdrawal hiding derives from the inviter's `users.deleted_at` ([G6]).
- [ ] A15 No message in this unit's proto surface has a `user_id` field, `UpdateProfileRequest`'s entire writable surface is `{nickname, timezone, locale}`, and `GetProfile`/`ListAuthProviders`/`GetInviteLink` are each classified **exactly once** as `userScopedUnaryReadPolicy` in `packages/client-cache/src/http-policy.ts` (§2.7, [I11]).
- [ ] A16 The locale set is pinned by a byte-identical fixture pair (`packages/i18n/fixtures/locales.json` ↔ `apps/api/internal/account/testdata/locales.json`) asserted from both the TS and Go suites, following the shipped `palette-ids.json` guard ([K6]).
- [ ] A17 `apps/api/internal/account/doc.go` states the identity/profile charter (not "per-user account preferences"), and `User`/`AuthProvider`/`Invite` are present in [ubiquitous-language.md](../ubiquitous-language.md) §1.1 with the timezone-authority clause before any of this unit's code names them.

## Grounding

- Constitution ([I1]–[I13]): [00.overview](../plan/00.overview.md) §3 (_The constitution_), incl. the v2 risk
  register. Most at risk here, each with its structural guard (plan 60 Grounding):
  - **[U1] per-user isolation, now that a real `users` table exists** — the PK is named `user_id` so
    `check-persistence-isolation.mjs` sees an owned scope column; **no request message in this job's proto surface
    has a `user_id` field**, so the only id a caller can name is their own scope; no `globalQueries`/`platformTables`
    entry is added. Note the property that makes T004 safe rather than lucky: the gate is _syntactic_, so job 90's
    inviter-liveness read of another user's row also passes it — [U1] for `users` is upheld one layer up, in the
    contract.
  - **[I10]/[T1] time flows forward only** — the zone is consumed **only** where the _real_ clock is truncated to a
    calendar day (T018). `CanLaunchAt` keeps its zone-free date-vs-date signature and no universe-time derivation
    gains a zone parameter, so a timezone edit has no expressible path into the monotonic comparison.
  - **[I11] the meaning layer is untouchable** — `UpdateProfileRequest`'s writable surface is
    `{nickname, timezone, locale}` and nothing else: the same "no field for it" defense the shipped `account.proto`
    already documents for the palette. A profile write has no mood, coordinate, strength or memory id to reach.
  - **[I1] the system never deletes** — this job writes no delete of any kind; `deleted_at` exists as a column only,
    and the one sanctioned account hard delete is job 91's sweep.
