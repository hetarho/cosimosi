# Job 144: React Compiler adoption on web (refactor)

> Implementation work doc. Source spec: [code-review/12.frontend-rendering-performance-audit](../code-review/12.frontend-rendering-performance-audit.md).
> /cosimosi:implement-job 144 builds it via the two checklists below. When done, reflect the result into the
> SSOT (plan/policy/values) and set status: done. Write it in English.

Adopts React Compiler 1.0 (stable 2025-10) on `apps/web` — automatic memoization across all the canvas-adjacent
React UI, on the React 19.2 the repo already runs. The review's Questions section records the compatibility posture:
the compiler memoizes render code, not `useFrame` loops, so the R3F idiom is unaffected, but the scene packages
must be spot-checked (mutation-adjacent components may need `"use no memo"`). Build after job 138 and stage it:
lint/diagnostics first (no compiler transform), compiler second, mobile deferred until web proves it out.

## Acceptance Criteria (from code-review/12 — Candidate Job 9 + Questions)

- [ ] A1 **The compiler's rules run in lint over `apps/web/src`.** Today nothing there carries them: `apps/web`
      lints via oxlint with only `react/rules-of-hooks` (`apps/web/.oxlintrc.json`) plus a boundaries-only
      ESLint config (`apps/web/eslint.config.js` — no `eslint-plugin-react-hooks`), while the root
      `eslint-plugin-react-hooks ^7.1.1` serves `lint:packages` only and is ALREADY on `recommended-latest`
      (job 133). Closing the gap is NEW wiring — bring `eslint-plugin-react-hooks` with the v7 compiler-rule
      preset into `apps/web/eslint.config.js`; an unreferenced root block cannot affect the app command, and oxlint
      cannot carry the v7 compiler diagnostics. Any surfaced violations are fixed or explicitly dispositioned —
      including the `COMPILER_MODEL_DEFERRED` block in `eslint.config.packages.mjs` (T002c).
- [ ] A2 **`apps/web` compiles through React Compiler 1.0** (`babel-plugin-react-compiler` via
      `@vitejs/plugin-react`'s babel option). The build stays green and the bundle-size delta is recorded here.
- [ ] A3 **The scene packages are explicitly dispositioned.** For `packages/universe-render`,
      `packages/3d-renderer`, and the widget layer: either they compile clean under the compiler, or the files that
      must not be compiled carry `"use no memo"` with a one-line why — no silent skips. R3F `useFrame` behavior
      verified unchanged (the canvas renders identically; no new per-frame allocations).
- [ ] A4 **No behavior change.** Full gate green; headless CDP screenshot parity on landing + universe; interaction
      spot-checks (hover glimpse, pick/fly, ornament preview) behave as before. React DevTools confirms memoized
      components ("Memo ✨") on the previously hand-memoized hot paths.
- [ ] A5 **Mobile is deferred on record.** RN/babel adoption is explicitly out of scope here; a note in this doc
      states the trigger for a follow-up (web soak, one release without compiler-attributed regressions).

## Implementation Checklist

- [ ] T001 Per `/library-setup`: fetch current React Compiler docs; confirm the exact package versions
      (`babel-plugin-react-compiler` stable line, `eslint-plugin-react-hooks` latest) before installing.
- [ ] T002 Lint/diagnostic stage — three distinct pieces; land all three green before T003.
      (a) NEW wiring for `apps/web/src`: add `eslint-plugin-react-hooks` with the v7 compiler-rule preset to
      `apps/web/eslint.config.js`. The web lint path has no react-hooks ESLint plugin today — oxlint carries only
      `react/rules-of-hooks` (`apps/web/.oxlintrc.json`) and the web ESLint config is boundaries-only; the root
      `eslint-plugin-react-hooks ^7.1.1` serves `lint:packages` only, where `recommended-latest` already runs (job
      133).
      (b) Expand `eslint.config.packages.mjs`'s React-file scope to the actual scene sources
      (`packages/3d-renderer/src/**/*.{ts,tsx}`, `packages/universe-render/src/**/*.{ts,tsx}`). Its current
      `REACT_FILES` glob sees only `*/react.{ts,tsx}`, `*/react/**`, and `packages/ui/**`, so ordinary canvas/layer
      TSX and `3d-renderer/src/skin-context.ts` are silently outside the compiler-model lint rules. Extend
      `scripts/probe-packages-lint.mjs` with a positive renderer-scope probe, then run and record a fresh survey.
      (c) Disposition the recorded deferral this job is the successor to: `eslint.config.packages.mjs`'s
      `COMPILER_MODEL_DEFERRED` block keeps `react-hooks/refs` (22 findings) and
      `react-hooks/set-state-in-effect` (3 findings) off, on the record that reviewing those idioms against the
      compiler model "is its own change with its own reasoning — not a lint-wiring job" — job 144 IS that
      change. Re-enable the rules for a fresh count and review every current site/idiom; job 133's baseline 25 were
      `ui` 14 + `auth` 6 + `observability` 3 + `sequence` 2. (Its two `3d-renderer` findings were separate,
      already-fixed unused-variable errors, not part of the deferred 25.) Fix/refactor each compiler-model violation
      or record a per-idiom/site reason to retain the smallest explicit exclusion. Leaving the broad deferral
      untouched without a fresh count and disposition is not an acceptable branch. Run `pnpm lint` and record the
      result.
- [ ] T003 Compiler stage: add `babel-plugin-react-compiler` to `apps/web/vite.config.ts`'s `react()` plugin babel
      options (target React 19). Confirm which sources it covers (app `src/` vs source-imported workspace packages)
      and record the coverage boundary here; if the workspace scene sources are outside the default transform,
      configure an explicit include rather than silently exempting packages required by A3.
- [ ] T004 Scene-package disposition pass (A3), against job 138's post-unification shared core and thin shells:
      build + run the universe with the compiler on; for each compiler-flagged scene file decide fix vs
      `"use no memo"` + comment; verify `useFrame` hot paths did not gain allocations (dev-tools profile or the
      job-141 HUD if merged).
- [ ] T005 Verification: `pnpm check` green; CDP screenshot parity (landing, universe, design panels); record the
