# Job 138: Unify universe canvas hosts (refactor)

> Implementation work doc. Source spec: [code-review/12.frontend-rendering-performance-audit](../code-review/12.frontend-rendering-performance-audit.md).
> /cosimosi:implement-job 138 builds it via the two checklists below. When done, reflect the result into the
> SSOT (plan/policy/values) and set status: done. Write it in English.

The web and mobile `UniverseCanvasWidget`s are a ~330-line duplicated fork of the same host logic, guard-invisible
(both files carry platform markers, so the promote-on-reuse comparison exempts them), and already drifted twice:
mobile still resolves picks through the graph — the exact optimistic-launch bug the web file documents having fixed
(R006) — and the two hosts disagree on `antialias` while both mount PostFX (R007). **Build after jobs 136–137** so
the extraction carries their host-side fixes once instead of rebasing the fork twice.

## Acceptance Criteria (from code-review/12 — R006, R007)

- [ ] A1 **The platform-pure host core exists once, in `packages/`.** The subscriptions, pick/navigation callbacks,
      sim-bridge wiring, latent-field generation, anchor resolution, and the composed scene layers live in one
      shared module consumed by both apps; each app's widget shrinks to a thin shell (canvas host + genuinely
      platform-different seams).
- [ ] A2 **A just-launched star is pickable on mobile.** Mobile pick resolution goes through the entity stores
      (server truth + optimistic tail), matching the web's documented fix — tapping the newest star opens it before
      the next GetUniverse read. (R006.)
- [ ] A3 **`antialias` is decided once, with the rationale in code.** Both hosts make the same choice (expected:
      `antialias: false` with AA in the post chain, per the web comment that swapchain MSAA fights the post
      pipeline's resolve target) — or a native exception exists with a comment explaining why the tradeoff differs
      there. (R007.)
- [ ] A4 **Genuinely platform-different seams remain forked and owned.** The hover/glimpse seam stays web-only; the
      worker-vs-inline sim spawner stays per-app; each remaining fork keeps its own test (§3.5).
- [ ] A5 **No behavior change beyond A2/A3.** Scene composition, navigation, palette/ornament behavior identical;
      `pnpm lint:fsd:layout` and the whole gate stay green.
