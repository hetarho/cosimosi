## Acceptance Criteria (from plan/68.diary-search-and-filter)

<!-- The source spec's acceptance criteria. After building, verify each is true in the running code. -->

- [x] A1 `GetDiaries` accepts `query`, `moods`, `from`, `to`, `sort` on the **existing** RPC — no new list RPC exists — and remains unary, `NO_SIDE_EFFECTS`, per-user scoped and keyset-paginated ([D7][D8][D9]).
- [x] A2 Keyword search matches a **case-insensitive substring of `diaries.body`** and of nothing else; `CurrentText`, `DecayStages`, `SemanticStages`, `memory_provenance` and neuron text are not read by any statement in this unit, and no response field or read port in it can carry them ([D9][D10][I2]).
- [x] A3 `ORDER BY` reads only `diary_date` and `id`, in both directions, via two static sqlc queries; there is **no** runtime-built `ORDER BY` and no relevance/similarity sort key ([D7]).
- [x] A4 Migration `00020_diary_search_trgm.sql` creates `pg_trgm` and a GIN `gin_trgm_ops` index on `diaries.body`, with a `Down` that drops both; a Korean substring query (e.g. "커피" against "커피를 마셨다") returns the diary ([D9]). _(The plan text says `00019`, but numbers are reserved from the tree ([00.overview](../../plan/00.overview.md) §5.6) and `00019_twinkle_purchase_spend.sql` is taken — only the filename moves.)_
- [x] A5 A keyword shorter than `diary_reader.search_min_query_length` after trimming is **refused** with a typed reason, not silently ignored; `%`, `_` and `\` typed by the user match literally.
- [x] A6 The date filter is inclusive on both ends over `diary_date`, each side independently optional, and `from > to` or a non-ISO date is refused with a typed reason ([D8]).
- [x] A7 A diary matches the mood filter iff **at least one of its live `EpisodicMemory` rows** has one of the requested moods, implemented as an `EXISTS` semi-join; page size and cursor stability are unaffected by a diary having 2–5 memories ([D8][E2]). An unknown mood name is refused.
- [x] A8 A diary with **no live memory** (never launched, or all let go) **never matches a mood filter**, yet still appears in an unfiltered list with zero mood chips ([I1][X3][X4]).
- [x] A9 A **released** diary is absent from the list, search results, filtered results and the calendar; after `Restore` it reappears in all four with no additional write, and the exclusion is an anti-join on `release_groups` — **no `diaries.deleted_at` column exists** ([D10][X2][I1]).
- [x] A10 Flipping `sort` mid-scroll with a stale `page_token` is **refused** (`MEMORY_DIARY_PAGE_TOKEN_INVALID`); with a fresh request the oldest-first page is exactly the reverse of the newest-first page over the same filter, and same-date ties break on `id` ([D7]).
- [x] A11 `GetDiaryCalendar` is unary, `NO_SIDE_EFFECTS`, per-user scoped, classified exactly once in `packages/client-cache/src/http-policy.ts`, and returns per written day the day's `(mood, weight)` pairs where weight is the sum of `EffectiveStrength` over that day's live memories of that mood ([D12]).
- [x] A12 **No color and no diary id crosses the wire** from the calendar; a written day whose memories are all gone returns an **empty** mood list (never a `NEUTRAL` row), and a day absent from the response was never written ([M3][M6][I11]).
- [x] A13 Calendar pages are **day-grained** — no day is split across two pages — the page size is server-owned (`diary_reader.calendar_month_page_size`, no request field), and days are ascending ([D12]).
- [x] A14 `GetDiaries` and `GetDiaryCalendar` **advance no universe time, write nothing and spend no Twinkle**: neither receives a clock port or a `SpendGate`, and `db/queries/memory/diaries.sql` contains no `INSERT`/`UPDATE`/`DELETE` ([D11][T3][G4][I2][I10]).
- [x] A15 Every statement is user-scoped and `pnpm lint:persistence` (`scripts/check-persistence-isolation.mjs`) passes with no new `globalQueries` or `platformTables` entry; all SQL is plain sqlc, with no hand-built pgx string ([U1]).
- [x] A16 `DiaryQuery`, `DiaryFilter`, `DiarySort` and `DiaryDayMood` appear in `spec/ubiquitous-language.md` §1 **before** they appear in code, and [D10]'s "봉인·소프트 딜리트된 일기" wording is amended to "released (soft-deleted)" in [PRD.md](../../PRD.md) §5.6.
- [x] A17 `createGetDiariesInfiniteQueryOptions` takes the request input, the invalidation key is built **without** input so it matches every filter/sort variant, and both `use-release.ts` / `use-restore.ts` use it — a release or restore leaves no stale filtered page ([X2]).
