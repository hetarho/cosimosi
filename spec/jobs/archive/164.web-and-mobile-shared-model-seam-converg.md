## Acceptance Criteria (from code-review/15.full-codebase-runtime,-gate,-and-cross-p)

Finding: R008 (P3). Both apps carry `src/shared/model/xstate-react.ts`, a pure re-export barrel over
`@cosimosi/state-machine/react` and the only file in either app importing it. They have drifted on
both halves:

|                        | web                                                                           | mobile                                                                 |
| ---------------------- | ----------------------------------------------------------------------------- | ---------------------------------------------------------------------- |
| exports                | 4 (`shallowEqual`, `useActorRef`, `useMachine`, `useSelector`)                | 5 (+ `createActorContext`)                                             |
| `useActorRef` guidance | "Use this in R3F components and read `actor.getSnapshot()` inside `useFrame`" | "Use this for non-UI subscriptions (gesture handlers, native modules)" |
| app-shell machine      | none — no `app/model/` segment at all                                         | `app/model/app-shell.machine.ts` + `machine-actors-provider.tsx`       |

§3.5 says everything under `model` is shared verbatim and §3.1 says both apps follow the app-layer
segmentation identically. The drift is also what evades the gate: `lint:fsd:layout` compares
_normalized-equivalent_ same-relative pure modules, so two files that stopped being equivalent form no
pair and nothing fires.

- [x] A1 The two `shared/model/xstate-react.ts` files no longer disagree. Either they are identical
      (same export set, same guidance) or the seam is promoted so there is only one copy — decided in
      T001, not left as two hand-maintained files that happen to match today.
- [x] A2 The `useActorRef` guidance documents the R3F pattern on **both** platforms. §3.5 puts the
      `react-native-webgpu` renderer in scope, not deferred, so mobile runs R3F too and its copy
      currently points developers away from the one pattern §3.2 mandates for per-frame reads
      (`getSnapshot()` in `useFrame`, never React state at 60fps). Mobile's "non-UI subscriptions"
      framing may be _added_, but not at the cost of dropping the R3F rule.
- [x] A3 Whatever the seam exports, both apps can reach it — today a web app-layer provider needing
      `createActorContext` cannot get it through `shared/model`. **Superseded by the T001 decision:** under
      promotion the seam is deleted, so importing `@cosimosi/state-machine/react` directly stops being a
      bypass and becomes the intended path. Read this as "no app may be missing a hook the other has".
- [x] A4 The drift cannot silently recur. Either the promotion in T001 removes the second copy
      entirely, or a guard notices same-path files across apps whose content diverges — the
      same-content comparison `lint:fsd:layout` already does cannot see this class, because divergence
      is the thing that hides it.
- [x] A5 The web app-shell question is answered on the record, not by omission: web either gains an
      `app/model/` control-state machine mirroring mobile's, or `spec/tech/state-machine.md` /
      `ARCHITECTURE.md` §3.1 states that web's shell control state is deliberately the router and why.
      §3.2 makes this a control-state decision ("the exclusive modes/phases/lifecycle … lives in XState
      machines"), so a gap is not a neutral default.
- [x] A6 No behavior change. This is a re-export barrel and a documentation convergence: mobile's
      `AppShellActor` keeps working identically, web gains no new runtime behavior, and both apps'
      suites pass unchanged. If T001 promotes the seam, the promotion is import-path-only.

## T001 is already answered — by the gate, and the answer is (b)

**Attempted, then reverted.** Converging the two copies (option a) was tried first: same five exports,
one merged doc comment, and web's barrel widened to match. It works, and `pnpm lint:fsd:layout` then
reports both files immediately:

```text
✗ shared/model/index.ts — byte-identical pure module exists in both apps. Promote the implementation
  to its owning domain package and let both apps import it.
✗ shared/model/xstate-react.ts — byte-identical pure module exists in both apps. Promote the
  implementation to its owning domain package and let both apps import it.
```

So the repo's own rule decides it: **option (b), promote.** Option (a) is reachable only by leaving the
drift in place, which is R008 restated — the divergence is what buys the silence. Landing (a) would mean
suppressing a gate in order to keep a redundant indirection.

And it is redundant: `packages/state-machine/src/react.ts` is itself a re-export of the same five names
from `@xstate/react`, so the swap seam the app-local file's comment claims to provide already exists one
layer down. `shared/model/index.ts` adds only the aggregation with `@cosimosi/errors/react`.

**A second reason to promote, found while measuring:** `shared/model/` is not a documented segment at
all. §3.1 segments `shared` into `ui`/`lib`/`i18n`; `model` is a slice-level segment, not a shared one.
No gate checks the shared layer's segment names (the directory-level check added by job 163 covers the
app layer only), so this has been invisible. Promoting removes the directory and the question with it —
the alternative is amending §3.1 to admit `shared/model`, which is the weaker answer.

**Scope, measured:** 48 files import from `shared/model` — 25 web, 23 mobile. By symbol:
`useErrorToast` ×28, `useMachine` ×18, `ErrorToastContext` ×6, `useSelector` ×5, `useActorRef` ×5,
`shallowEqual` ×1, `createActorContext` ×1. Mechanical (identical names, new specifier) but broad.

**Explored and rejected: carving barrels out of the duplication rule.** A pure re-export barrel holds no
implementation, so there is nothing to promote — the same reasoning §3.1 already applies to a wiring
shell in `ui`. The appealing shape was to exempt barrels from the equality rule and _invert_ it, making
divergence the violation. Sound in principle, wrong in practice on this tree:

- It fires on legitimate platform forks. `shared/config/index.ts` diverges because mobile carries real
  platform config (`resolveMobileApiBaseUrl`, `mobileAppVersion`, …) the web has no analogue for, and
  `shared/i18n/index.ts` diverges because the mobile seam is deliberately narrow and probe-enforced.
- A statement-splitting barrel detector mis-reads this repo's semicolon-free style: a test file's whole
  body parses as one statement beginning with `import`, so `*.test.tsx` files were classified as
  barrels.

A correct version would compare only the names re-exported from specifiers **both** apps share, letting
an app-only specifier add exports freely. That is worth building, but it is its own piece of work and
not a precondition for this one.

**Why this is still `todo`.** The fix is a 48-file import rewrite across both apps, and a second Claude
Code session was editing web and mobile source in this same working tree while this ran — it committed
`4bdb6b89` mid-flight, and the two sessions collided twice on `.git/index.lock`, once with its `git add`
placing four of its files into the shared index. A broad mechanical sweep is the worst possible change
to land beside that. Fixing A2 (the lost R3F guidance) alone is not a partial win either: the gate's
normalized digest strips comments, so the export-set difference is the only thing keeping the pair
unflagged, and correcting the comment without the exports trades a documentation bug for a red gate.

**Do it as one job when the tree is quiet:**

1. Delete `apps/{web,mobile}/src/shared/model/` (both `xstate-react.ts` and `index.ts`).
2. Repoint the 48 importers at `@cosimosi/state-machine/react` and `@cosimosi/errors/react`.
3. Fold the `useActorRef` selection guidance — including the R3F `getSnapshot()`-in-`useFrame` pattern,
   which mobile's copy had dropped even though `react-native-webgpu` renders R3F too — into
   `packages/state-machine/src/react.ts`, where both platforms read one copy.
4. Then reconsider the barrel-divergence rule separately, using the shared-specifier comparison above.

## As built

Executed on 2026-08-26, once the resumption condition held (tree clean, no lock, the concurrent
session dormant ~18h).

- **The guidance moved to the package, not between the copies.** `packages/state-machine/src/react.ts`
  now carries the whole selection guide, including the R3F `getSnapshot()`-in-`useFrame` rule that
  mobile's copy had dropped — stated for both platforms, since `react-native-webgpu` renders R3F too
  (§3.5). Both apps read that one copy.
- **Both apps' `shared/model/` is deleted** (`xstate-react.ts` + `index.ts` × 2). The directory is
  gone, which also retires the undocumented shared-layer segment it occupied.
- **48 importers repointed, to two destinations.** The barrel aggregated two packages, so the sweep
  split by symbol: `useErrorToast` / `ErrorToastContext` → `@cosimosi/errors/react`;
  `useMachine` / `useActorRef` / `useSelector` / `createActorContext` / `shallowEqual` →
  `@cosimosi/state-machine/react`. One import mixed both groups and became two statements. Both apps
  already declared both dependencies, and only `@cosimosi/i18n` carries a restricted-import rule, so
  no boundary config changed.

**T006 answered — and the opposite of what this job expected.** It anticipated either building web an
app-shell machine or raising a change doc. Neither: web is not missing anything. Mobile's
`appShellMachine` is a **reserved seam with no reader** — `READY` is sent nowhere in the app and
nothing selects from `AppShellActor`; its own docstring says stack selection is deliberately _not_
read from it, so there is no competing authority. Web's shell lifecycle is the router's auth gate, and
it has simply never needed the mount point. The asymmetry is about when each app needed the seam, not
about one app breaking a rule. Recorded in `spec/tech/state-machine.md` §1.1, with mobile's actor
described honestly as reserved rather than live. No change doc.

**T007 was a segment leak, not a barrel preference.** Web's `pages/design/index.ts` re-exported
`SHOWCASE_GROUPS` and `SHOWCASE_SECTION_IDS` out of the slice while the only consumers — the page and
its test — import them from `../lib/showcase-sections.ts` directly. `lib` is slice-internal by rule
(§3.1), so the export was a leak with no consumer; removing it fixes that _and_ makes the two barrels
agree. Verified it does not re-trip promote-on-reuse: `pages/design/index.ts` matches neither the
pure-module segment pattern nor the conditional `ui` rule, so identical copies there form no pair.

**A4 holds by construction now.** The drift cannot recur for this seam because there is no second copy
to drift from — which is why T005's divergence guard was not needed (see above). The guard remains
worth building for the barrels that legitimately remain, and stays indexed as a follow-on.
