## Acceptance Criteria (from plan/65.twinkle-kind-redefinition)

<!-- The source spec's acceptance criteria. After building, verify each is true in the running code. -->

- [x] A1 The domain names the two tiers by purpose: `twinkle.TwinkleKind` exists with exactly `SMALL` and `GENERAL`, and `Balance{Small, General}`, `BalanceRecord{General, SmallSpentThisWindow, SmallResetWindow}` and `SpendPlan{FromSmall, FromGeneral, OK}` carry no `Basic`/`Additional` identifier anywhere in `apps/api/internal/twinkle` outside `pg/` ([G2][G2a], §2.9 #1).
- [x] A2 `SmallRemaining` and `DeriveBalance` take the user's zone; **no zone-free variant and no `utcDay` helper remains**, so a caller cannot silently read a UTC day ([G2][U7]).
- [x] A3 `ResetWindowOf(now, zone)` returns the user's **local** calendar date, and `SmallRemaining` derives a fresh full grant when that date is later than the stored anchor and `grant − spentThisWindow` otherwise ([G2]).
- [x] A4 An empty, blank or unknown IANA zone resolves to UTC on both the Go and TS sides, returns no error, and never suppresses a refill ([G5]).
- [x] A5 `twinkle.UserZoneReader` is declared in `apps/api/internal/twinkle/ports.go`, returns an IANA name as a scalar, is bound only at `apps/api/cmd/api/twinkle.go`, and `NewService` fails with `ErrZoneReaderRequired` when it is nil; `apps/api/internal/twinkle` imports neither `internal/account` nor any `users` query (§2.2/§2.4).
- [x] A6 The stored window anchor never moves backward: after a spend under an eastward zone change and then a westward one, the derived SMALL tier for the same calendar date is never a second full grant ([G2]).
- [x] A7 `PlanSpend(smallRemaining, general, cost, kind)` returns `FromSmall: 0` for every kind that is not in the recall family, draws SMALL first for `RECALL`/`GIST_VIEW`/`DIARY_RECALL`, sets `OK` from the GENERAL remainder, and never produces a negative tier ([G2][G5][P9]).
- [x] A8 `SmallEligible` is a closed switch whose default arm returns **false**, proven by a test that an unlisted `SpendKind` value is ineligible ([P9][I11], [00.overview](00.overview.md) §3).
- [x] A9 `QuoteSpend`'s shortfall is tier-aware — `ShortfallFor` counts SMALL only for an eligible kind — so a quote for a SMALL-ineligible purpose never reports itself covered by SMALL ([G4][P9]).
- [x] A10 The Go purpose enum is named `SpendKind` (the shipped `QuoteKind` is gone), `SPEND_KIND_PURCHASE` does **not** exist in `twinkle.v1.SpendKind`, and `quoteCost` has no purchase arm — a purchase cannot be quoted over the wire (§2.9 #1).
- [x] A11 `twinkle.v1.GetBalanceResponse` carries `small = 1`, `general = 2`, `total = 3`; `admin.v1.AdminUser` carries `small`/`general`; `admin.Balance{Small, General, Total}` follows; `pnpm gen` + `pnpm check:gen` pass and no RPC is added, removed or reclassified in `packages/client-cache/src/http-policy.ts`.
- [x] A12 `packages/twinkle-logic` exposes `smallRemaining`, `resetWindowOf`, `planSpend`, `smallEligible`, `shortfallFor` and `SpendPlan{fromSmall, fromGeneral, ok}`, and produces **identical** outputs to the Go functions for every case in `apps/api/internal/twinkle/testdata/stardust-ledger-golden.json` within the fixture's tolerance — including the new zone cases and the per-kind `plan_spend` cases (golden parity).
- [x] A13 `packages/twinkle/src/twinkle-balance-store.ts` exposes `TwinkleBalance{small, general}` and both `TwinkleBalanceHud.tsx` files compile against it; **no i18n key, copy string or layout changes in this unit** — [67.twinkle-relabel-and-ledger-ui](67.twinkle-relabel-and-ledger-ui.md) owns the relabel.
- [x] A14 `spec/values.yaml` has `twinkle.small_daily_amount` (= 100) and no `twinkle.basic_daily_amount`; the generated `values.TwinkleSmallDailyAmount` / `VALUES.twinkle.smallDailyAmount` are the only sources of the grant, in the domain and in the `basic_grant` query argument alike (§4).
