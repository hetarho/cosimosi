# Job 133: Lint the workspace packages (refactor)

> Implementation work doc. Source spec: [code-review/11.jobs-116-128-demo,-sequence,-landing-and](../../code-review/11.jobs-116-128-demo,-sequence,-landing-and.md).
> /cosimosi:implement-job 133 builds it via the two checklists below. When done, reflect the result into the
> SSOT (plan/policy/values) and set status: done. Write it in English.

Covers **R004 (P2)** — the largest gate hole in the repo.

**The gap.** No `package.json` under `packages/` declares a `lint` script (all 23 checked), and no
ESLint or oxlint config exists anywhere under `packages/`. The root `pnpm lint` reaches packages only
through the bespoke Node scanners (`lint:language`, `lint:raw-strings`, `lint:comments`,
`lint:style-escapes`, `lint:fsd:layout`); the two real JS/TS linters are `lint:web`
(`oxlint --deny-warnings`, cwd `apps/web`) and `lint:mobile` (`eslint .`, cwd `apps/mobile`), and
neither can see `packages/`. So the cross-app core — the highest-leverage code in the repo — is the
least checked code in the repo.

This batch alone added `packages/sequence/src/react.ts`: four `useEffect`s, a `setTimeout` lifecycle, a
promise whose result is written to state after an `await`, and a nine-entry `useMemo` dependency array
— none of it checked by `react-hooks/exhaustive-deps`, `no-floating-promises` or `no-unused-vars`.

Build this **after job 132**, so the ratchet baseline is measured on a tree whose manifests are already
correct.

**Owner decision to settle before building** (review 11, _Questions / Tradeoffs_): a first run over 23
packages will almost certainly report a backlog. Land the gate at the **current warning count and
ratchet down**, rather than blocking this job on a clean sweep. That temporarily sits awkwardly beside
§4's "gates fail loudly", so it is an explicit, time-boxed exception — record the starting count and
the target in the SSOT step so the ratchet is visible rather than forgotten.

## Completion note

### T001 — the survey, before configuring anything

A throwaway ESLint over every `packages/**/*.{ts,tsx}` with the intended rule set
(`@eslint/js` recommended + `typescript-eslint` recommended + `react-hooks` recommended-latest on the
React seams) reported **28 findings**, all at error severity:

| count | rule                                |
| ----- | ----------------------------------- |
| 22    | `react-hooks/refs`                  |
| 3     | `react-hooks/set-state-in-effect`   |
| 2     | `@typescript-eslint/no-unused-vars` |
| 1     | `no-useless-assignment`             |

| count | package         |
| ----- | --------------- |
| 14    | `ui`            |
| 6     | `auth`          |
| 3     | `observability` |
| 2     | `3d-renderer`   |
| 2     | `sequence`      |
| 1     | `api-client`    |

**`exhaustive-deps` reported zero** — the rule the finding named as the concrete risk found nothing to
say about the seams it was worried about. Worth recording: the gap was real, the backlog behind it was
not.

### The owner decision did not need to be taken

Review 11 pre-authorised landing at the current warning count and ratcheting down. **It was not needed.**
28 findings over 23 packages is small enough to resolve outright, and 25 of them turned out to be two
idioms rather than 25 problems. The gate ships at **zero findings**, so §4's "gates fail loudly" needs no
time-boxed exception and there is no ratchet to forget.

### Two rules are off, by name, with the tree measured

`react-hooks/refs` (22) and `react-hooks/set-state-in-effect` (3) come from `react-hooks` v7's
recommended-latest set, which encodes the **React Compiler's** stricter model. Every instance was read
individually; none is a bug, and all sit on idioms already carrying a prose comment:

- **the latest-ref idiom** — `measureRef.current = measure` during render, read from a callback
  (`packages/sequence/src/react.ts`, `packages/ui`, `packages/observability/src/react.tsx`);
- **ref-guarded lazy creation** — `packages/auth/src/react.ts:29-31`, where the existing comment already
  says why a `useState` initializer is wrong: it runs twice under StrictMode and orphans a live actor, an
  adapter subscription and a refresh timer with no dispose handle;
- **presence / commit-in-effect state** — `packages/ui`'s `usePresence` (exit animation) and
  `SessionScopeBoundary` (must fire a callback and commit in the same pass).

Turning them on today would mean **25 inline suppressions to land a green gate**, which is precisely what
§4 forbids ("no gate uses suppression to stay green"). Reviewing those two idioms against the compiler
model is its own change with its own reasoning, not something a lint-wiring job should decide. The other
15 rules in the set are on and the tree is green against them, so this is a **named exclusion, not a
tolerated count** — recorded in the config and in
[02.quality-gates](../../plan/02.quality-gates.md).

### The three fixed (A5 — behaviour-preserving)

- `packages/api-client/src/platform.ts` — dropped a dead `= null` initializer that both the `try` and the
  `catch` arm immediately overwrite. Kept the `try`/`catch` rather than collapsing to `.catch(() => null)`,
  which would **not** be equivalent: a provider can throw synchronously as well as reject. Added a comment
  saying so, since the next reader's instinct will be that collapse.
- `packages/3d-renderer/src/assets/sky/sky-emotion.ts` — `colorSeed` / `scalarSeed` exist only so
  `ReturnType<typeof …>` has something to read; nothing calls them. Two scoped disables with the reason,
  because satisfying the rule would mean spelling out TSL's operator-node type by hand, which is the exact
  indirection those two lines exist to avoid.

### T007 — no real bugs to file

Nothing in the survey was a latent defect, so there is no proposed finding for the next review. The two
deferred rules are a design question about idiom, not a bug list.

### Scoping, and the probe that proves it

`react-hooks` is **path-scoped** to `packages/**/react.{ts,tsx}`, `packages/**/react/**` and
`packages/ui/**`. Package roots are deliberately React-free — a `packages/*` index exports pure logic and
the React mirror is a separate `./react` export — so a blanket React config would report hook rules
against files that can never grow a hook.

`scripts/probe-packages-lint.mjs` (wired as `lint:packages:probe`, in the `lint` chain) asserts an unused
import, a missing hook dependency and a conditional hook are each reported, **and** that the same missing
dependency written in a pure package is **not** — without that negative, the scoping above would be
decoration rather than a rule.

### T009 — CI needs no edit, confirmed

`.github/workflows/ci.yml` runs exactly two commands: `pnpm install --frozen-lockfile` and `pnpm check`.
`pnpm check` runs `pnpm lint`, which now contains `lint:packages` and `lint:packages:probe`. No workflow
file was touched.

### A6 — the existing setups are untouched

`apps/web`'s oxlint + Steiger + boundaries and `apps/mobile`'s ESLint are unchanged, and **no package
gained a `lint` script** — the root pass is the only one, so there is nothing to duplicate or drift.

New root devDependencies: `eslint`, `@eslint/js`, `typescript-eslint`, `eslint-plugin-react-hooks` (the
root had no JS/TS linter at all before this).
