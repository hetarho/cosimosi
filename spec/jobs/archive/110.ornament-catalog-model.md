> **As-built deltas (all reflected into plan 71 and the SSOT docs).**
>
> - **No `PALETTE` kind.** The named-palette registry this plan's third kind wrapped was retired with its table before
>   implementation (change 08 / job 109); a feeling's colour is now the free per-mood `mood_colors` override with its own
>   surface. There was nothing to enumerate, so `OrnamentKind` is closed at `BACKGROUND | STAR_SHADER` and no palette
>   price key can exist. PRD [P4]/[P10] and UL §1.1 were amended to match.
> - **Migration `00024`, not `00021`** — `00021`–`00023` went to the mood-colour work; the number is reserved from the
>   tree.
> - **One drift fixture, not a byte-identical pair.** `internal/store/testdata/ornament-ids.json` is read by both
>   runtimes (the shipped `stardust-ledger-golden.json` precedent), which removes the drift a twin would have to guard.
> - **The purge is its own port** (`store/purge.go`, `twinkle`'s shipped shape) so both tables' deletes commit in one
>   transaction, and it is registered in the **worker** composition too — the sweep runs there.
> - **`errors.go` declares a fifth error**, `ErrAcquisitionNotGrantable`: an ownership row must be recorded with the
>   acquisition path the catalog assigns that row, so buying an achievement-only row is impossible whatever the caller
>   passes.
> - **`packages/store` also carries `useAppliedOrnaments()`** (`@cosimosi/store/react`) — the one hook both canvas
>   mounts read the applied selection through. A per-app copy would be a lint R4 failure.
> - **`db/queries/store/purge_user.sql`** is a separate file from `ornaments.sql`, matching every other context's purge
>   naming.
>
> **Two decisions this job authoring owes the plan.**
>
> 1. **The two achievement-only ornament ids are pinned** (plan 57 signed off 2026-07-29, so the registries are final):
>    **`star_shader.spire`** — the eight-point crystalline body, paid by plan 74's `STAR_TOTAL` capstone (500 memories
>    is a hand-cut star) — and **`background.floating-lines`** — "glowing filaments threading the sky", paid by
>    `NEURON_SHARING` (a sky of threads for the achievement about memories sharing one). One background, one star
>    shape, never a palette; the 1:1 pairing is asserted in plan 74's `cmd/api` catalog test.
> 2. **The free star-shader default is `star_shader.facet`, not `orb`.** Plan 71 was written before job 39's sign-off
>    chose `facet` as the free entry point; `orb` stays in the registry as the bench baseline. The catalog reads
>    `DEFAULT_STAR_SHAPE` rather than a literal, so this is a plan-text correction (T015), not a code choice.

## Review

- [x] Codex review (gpt-5.5, read-only) applied — 4 findings, all fixed, none rejected:
      **GrantOwnership accepted an acquisition path the catalog did not assign the row** (an achievement-only row could
      be recorded as a purchase) → the row's own `Acquisition` is now the check;
      **`GetCatalog` read ownerships before selections**, so a purchase-and-apply committing between the two statements
      could answer "worn but unowned" → the order is reversed, and the remaining race is the harmless one;
      **the `LIKE lower(kind) || '.%'` prefix CHECK was weaker than its comment** (`_` is a LIKE wildcard, `%` matches
      empty) → `starts_with(...) AND length(...)`, with both escapes pinned by the schema test;
      **`resolveStarShape` fell back to the registry's first row (`orb`), not the declared default (`facet`)** → both
      registries now fall back by name. `/code-review` is not model-invocable in this session; the diff was
      self-reviewed against the architecture self-audits instead.
