**Note (dim 8, deferred):** the native open option list can only be scored on a device. The primitive
owns its own `open` state, and staging it from the showcase would mean adding an `open` prop purely for
a screenshot — a review concern leaking into the API. The specimen is tappable in the running native
showcase, which is where that half gets scored; recorded as deferred to the device pass rather than
faked here.

**Not a design finding, fixed in the same pass:** the first web adoption built its `MOODS` item list at
module scope, which would have frozen the labels at whatever locale the bundle evaluated under. The list
is now built per render.

## Review

- [x] Self-review of the diff, plus a **measured** pass over the running `/design` surface (CDP: geometry,
      type and colour of the picker vs `TextField`, and the label/error style sets across the section) —
      the design-review round above is that evidence. Findings applied: - **The `MOODS` item list was computed at module scope**, freezing i18n labels at the locale active
      when the bundle evaluated. Now built per render, in both adoptions. - **The model select's `error` slot would have been dead code.** A failed model listing forces
      manual entry, so the Select is not rendered in that state at all. The message moved to the
      control that actually replaces the list — as its `description`, since the field is not invalid,
      the list is simply missing — and the duplicate banner below the row is gone. That is the "say so
      beside the control" the change asked for, in the only place it can be true. - **The native showcase's "open the list" button could not work** — the primitive owns its open
      state. Replaced with a comment stating where that half is actually reviewed.
- [x] `/codex:review` **skipped deliberately.** This unit adds no async logic, no state machine and no
      data path: it is a presentational primitive plus three mechanical adoptions, and its risk lives in
      geometry and a11y wiring, which the measured pass and the primitive tests cover directly. The two
      prerequisite units in this series were codex-reviewed because they carried paging, transaction and
      invariant logic.
