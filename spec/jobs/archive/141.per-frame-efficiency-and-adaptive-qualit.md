# Job 141: Per-frame efficiency and adaptive quality (refactor)

> Implementation work doc. Source spec: [code-review/12.frontend-rendering-performance-audit](../../code-review/12.frontend-rendering-performance-audit.md).
> /cosimosi:implement-job 141 builds it via the two checklists below. When done, reflect the result into the
> SSOT (plan/policy/values) and set status: done. Write it in English.

Cuts the steady-state per-frame cost and adds the missing quality levers. Today five instanced layers recompose and
re-upload every matrix every frame even when the coordinate buffer did not change (R009), and the only quality
control anywhere is a static DPR cap — no fps-adaptive DPR, no background gate, and reduced motion freezes time but
keeps full frame cost (R010). Measurement lands first so every change gets a number.

**Build after jobs 136 and 138.** T007/T008 extend `UniverseCanvas.native.tsx`, whose effect structure 136 rewrites;
until 136 lands, a `dpr` change disposes the WebGPU device instead of using the live backing-size seam. The shared
adaptive layer mounts in job 138's scene core, while the web-only diagnostics HUD stays in the web thin shell (a
shared package must not import an app-only dependency). T002's regen serializes with jobs 140/142.

## Acceptance Criteria (from code-review/12 — R009, R010)

- [x] A1 **Clean frames are (near-)free for contiguous-slot layers.** When the coordinate buffer version, the
      channels, slot offset, scale, and explicit animation revision are unchanged, `InstancedNodeLayer` skips
      matrix recomposition and does not set `instanceMatrix.needsUpdate`. T003 keeps the published version stable
      across visually unchanged ticks on both bridge arms, including inline mobile. Genuine animation still moves:
      projection mappers such as gist rise opt out of the skip, and `AwakenNeuron` supplies an active-flare matrix
      revision while its in-place scale array changes. (R009.)
- [x] A2 **The awaken layer is idle-free.** With no flare playing, `AwakenNeuron` writes no matrices (today it
      rewrites its full 32-slot capacity every frame); an active flare still updates every frame until completion.
- [x] A3 **Per-frame name lookups are gone from the hot loop** (the `geometry.getAttribute(name)` per frame — held

      instance order whenever that snapshot/reconciliation changes).
- [x] A4 **DPR adapts to sustained fps.** A small monitor steps the canvas DPR between 1 and
      `rendering.max_pixel_ratio` on sustained-fps windows with hysteresis (no oscillation); thresholds/windows are

      **Deviation:** web does NOT use `setDpr` — see Result, "Where this deviates". No oscillation needed more than
      the fps dead band this criterion implies; the dead band alone does not deliver it (Result).
- [x] A5 **A backgrounded native app stops rendering.** `AppState !== 'active'` pauses the native frameloop (and
      the inline sim pump); returning foregrounds cleanly. (Web already inherits rAF's hidden-tab pause.)
- [ ] A6 **The change is measured.** A dev-only perf HUD (`r3f-webgpu-perf`, behind the existing diagnostics gate)
      is available on web, and this doc's Result section records before/after frame cost for: converged scene,
      acceleration sweep, and launch — desktop + one phone.

## Result

### What the change removes, measured

Deterministic instrumentation over the real bridge and the real flare pool (a throwaway bench, not committed —
reproduce by driving `createUniverseSimBridge` / `advanceAwakenFlares` in a vitest file). One converged scene of 40
neurons + 60 memories, 600 frames, five instanced layers mounted:

| Path                                                                    | Before                          | After                     |
| ----------------------------------------------------------------------- | ------------------------------- | ------------------------- |
| Inline (mobile) arm — layer matrix recompositions / 600 frames          | 3000 (every layer, every frame) | 1800 (**−40%**)           |
| Worker (web) arm — frames rendered against a buffer that did not change | all of them recomposed          | **0** recomposed          |
| `AwakenNeuron` — idle frames writing its 32-slot scale array            | 600                             | **0**                     |
| `AwakenNeuron` — 600 frames containing one flare                        | 600                             | 67 (the flare's own life) |
| `GistStarLayer` — string-keyed `Map.get` per instance per frame         | count × 60/s                    | 0 (array index)           |
| `InstancedNodeLayer` — `geometry.getAttribute(name)` per frame          | 1 per layer per frame           | 0 (resolved on attach)    |

**Why the inline arm is 40% and not ~100%:** `force_sim.min_alpha` deliberately floors the solver's alpha so a
settled universe keeps breathing rather than freezing hard. Residual per-tick motion measures ~1e-3 world units —
invisible, but the same order as the publication epsilon, so roughly half of settled ticks still cross it. The
epsilon is not the lever to loosen here: 0.002 is already half a _device_ pixel at the rig's closest framing on a 2×
display. The clean win is exact wherever the buffer genuinely does not change — every worker in-flight frame, every
idle awaken frame, the mood bench, and any paused sim.

### Where this deviates from the checklist

- **T007 said web keeps R3F `setDpr`; both platforms now go through the `dpr` prop instead.** `setDpr` does not
  survive on web: R3F re-runs `configure` on every `<Canvas>` render and resets the store whenever `viewport.dpr`
  disagrees with what the `dpr` prop resolves to (`events-*.js`, `if (dpr && state.viewport.dpr !== calculateDpr(dpr))
state.setDpr(dpr)`), and the host re-renders often. The adaptive step would have been reverted by the next skin,
  query or sweep-clock render. Both shells now own the ceiling in state and inject `onPixelRatio` — one path, and the
  web↔mobile parity rule is better served by it. `onPixelRatio` is required, not optional, so a shell cannot forget it
  and silently render at a fixed ratio.
- **The fps dead band is not sufficient hysteresis** (A4's "no oscillation"). Dropping the ratio is what raises the
  frame rate, so a device at 44 fps / ratio 2 reads 58 at 1.75, climbs back, and resizes every window forever. The
  walk therefore also counts direction reversals and settles after `adaptive_dpr_max_flipflops` on the lower ratio.
  Found by the codex pass; pinned by a test that models a device whose fps reacts to the ratio.
- **T005's flare stepping moved into `awaken-flare-pool.ts`** (the `navigation-latch.ts` precedent) so "an idle pool
  writes nothing" is a unit test rather than something only a running canvas could demonstrate.
- **The frame key also carries the buffer array identity**, not just the version. A version is unique only within one
  producer, and a rebuilt sim bridge restarts at zero — it could land on a number the layer had already composed.
