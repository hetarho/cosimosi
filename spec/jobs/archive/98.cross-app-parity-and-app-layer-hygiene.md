# Job 98: Cross app parity and app layer hygiene (refactor)

> Implementation work doc. Source spec: [code-review/09.epic-k-account-runtime-and-gate-audit](../../code-review/09.epic-k-account-runtime-and-gate-audit.md).

> SSOT (plan/policy/values) and set status: done. Write it in English.

Covers **R007** (P2), **R010** and **R011** (P3) — the _two copies, one contract_ theme on the frontend side.
The R4 promote-on-reuse guard exists and passes while missing a genuinely shared module, for two independent reasons:
its path filter does not cover `app/providers`, and its byte-identity test is defeated by a one-token rename.

Sequencing: land **after job 95**, which fixes the locale reactivity bug in the same two provider files. Promoting a
still-broken module just moves the bug.

## Acceptance Criteria (from code-review/09.epic-k-account-runtime-and-gate-audit)

- [x] A1 `locale-bootstrap` exists once, in the package that owns the concern (`@cosimosi/i18n`'s React seam), and both
      apps import it. It is platform-pure today — react, connect-query, react-query, `@cosimosi/api-client`,
      `@cosimosi/i18n` and nothing else — so no `.native` sibling is needed.
- [x] A2 The user-scope reset inventory exists once as a shared registry each app extends with only its platform leg
      (web: `localStorage` locale; mobile: device negotiation). A user-scoped store added to the registry is cleared on
      **both** platforms — a store added to one app's list and not the other's is currently a stale-prior-user-state leak
      with no gate to catch it.
- [x] A3 The R4 guard can no longer be evaded. Its path filter covers `app/providers` and `app/model` in addition to
      `api`/`model`/`lib`/`config`/`shared`, and it compares normalized content rather than raw bytes, so renaming an
      export (`LocaleBootstrap` → `MobileLocaleBootstrap`) no longer buys an exemption.
- [x] A4 A probe proves A3: a deliberately duplicated module under `app/providers`, and a byte-different-but-equivalent
      copy, both fail `pnpm lint:fsd:layout`. The guard is proven by a violation, not by reading it.
- [x] A5 Client nickname validation agrees with the server's predicate. `validateNickname` rejects control characters and
      line/paragraph separators as `normalizeNickname` does, so a pasted newline no longer passes the client check and
      comes back as `InvalidArgument` during the one flow the user cannot skip.
- [x] A6 The agreement in A5 is pinned by a shared case table — the same fixtures asserted on both the Go and TS side —
      so the two predicates cannot drift apart silently.
- [x] A7 `ProfileGate`'s `enabled` guard is resolved: either dropped (the mount site already guarantees a non-null
      `userId`) or made explicit, so a disabled query can never present as a permanent loading screen. Fixed in both apps.
- [x] A8 **No behavior change.** The negotiation precedence, the reset inventory's effective coverage, the nickname
      bounds from generated config, and the profile gate's rendered states (hold / refused+retry / nickname step /
      children) are all identical before and after. Nickname validation becomes _stricter on the client only_ — the
      server was already authoritative and unchanged.
