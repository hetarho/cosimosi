## Completion note

### R005 · R006 — the manifests now match the import graph

Both directions re-confirmed by grep before editing, not assumed:

- `packages/demo/src/{diary-set,resolve}.ts` import `@cosimosi/i18n` (type-only, for `Locale`) — moved to
  `dependencies`. Only `src/integrity.test.ts` imports `@cosimosi/config` — moved to `devDependencies`.
- **No file under `packages/onboarding/src/` imports React**, and the package has no `./react` export for
  a seam to live behind, so `peerDependencies.react` plus the `react` / `@types/react` devDependencies
  are gone. `anchors.test.ts` now asserts `peerDependencies` is **absent** rather than pinning the stale
  entry — the field is removed, so `Object.keys(undefined)` would have thrown.
- `pnpm install --frozen-lockfile` resolves cleanly against the edited manifests; the lockfile delta is
  exactly the four moved links and the two dropped React entries, nothing more.

`packages/demo` gained the closure assertion it was missing (A2), framed the way onboarding's is: the
list is the `[I13]` argument, with a line on what each entry buys and which packages are absent by
necessity (`store` per `[Z8]`, `twinkle`, `api-client`, `universe`).

### R007 — `landing:` group, byte-identical

`spec/values.yaml` gained `walkthrough_fade_span_days: 150` and `walkthrough_mirror_recalls: 5`, with the
tuning rationale moved out of the code comments and into the YAML — including _why_ each is tuning rather
than a literal (the fade span is sized against `forgetting.stage_interval_days` and
`stage_word_removal_ratios`; the mirror count against what `synapse.recall_*` growth buys a recall count).
`pnpm gen:values` regenerated both outputs; the generated values are `150` and `5`, so the walkthrough
renders identically (A6). `walkthrough.test.ts` needed no change — it restated neither literal, so it was
already testing the wiring rather than the number.

`WALKTHROUGH_EPOCH` and the visual constants named in A5 were left alone, deliberately.

**Note on `pnpm check:gen`:** it diffs generated files against **git**, so a regenerated file that is
merely written to the working tree still reads as stale. The generated outputs have to be staged (or
committed) alongside the `values.yaml` edit for the gate to pass.

### Deviation — the group inventory was 18 entries stale

T004's SSOT step was "add `landing` to §1's Current groups list". On opening it, the list held **9 of the
27** groups in `values.yaml`: `errors`, `account`, `nebula`, `palette`, `semantic`, `reconsolidation`,
`consolidation`, `forgetting`, `twinkle`, `store`, `achievement`, `admin`, `diary_reader`, `deletion`,
`release`, `sequence`, `demo` and `landing` were all absent. Appending one entry would have made a list
that is wrong about 18 groups _look_ current, which is worse than an obviously partial one.

So the inventory was completed to all 27 in file order, and the section now says outright that
**`values.yaml` is the registry and the list is a reading aid** — when they disagree, the YAML wins. That
removes the second source of truth rather than restocking it. Checked programmatically: listed set ==
actual set, and the order matches the file's.
