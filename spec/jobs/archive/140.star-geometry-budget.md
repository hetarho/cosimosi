# Job 140: Star geometry budget (refactor)

> Implementation work doc. Source spec: [code-review/12.frontend-rendering-performance-audit](../code-review/12.frontend-rendering-performance-audit.md).
> /cosimosi:implement-job 140 builds it via the two checklists below. When done, reflect the result into the
> SSOT (plan/policy/values) and set status: done. Write it in English.

Puts a number on every triangle the scene ships. Today the purchased star shapes vary per-instance geometry cost by
~900× with no guard (`facet` 20 tris → `urchin` ≈18k tris, R004), the decorative star backdrop alone is ~291k
triangles with no mobile knob (R008), and BandFog compiles four materials that differ by one constant (R012). The
budget lands in `spec/values.yaml` so a future shape/backdrop change has to state its cost. (gen:values)

**Build after job 138** so platform-specific backdrop inputs land on the shared scene core rather than being wired
twice into the old widget fork. Serialize this job's `gen:values` run with jobs 141/142.

## Results

### T001 — impostor spike: RUN, then REJECTED

Built as a real branch of `StarField`: four vertices at the mote's centre plus a corner attribute and a per-instance
size attribute, expanded in the vertex stage against the camera basis (two `Vector3` uniforms the layer writes per
frame from `camera.matrixWorld` through the mesh's inverse world matrix), with a radial alpha falloff so the quad reads
round — 2 triangles / 4 vertices per mote. It **rendered correctly** under the headless CDP harness (round motes,
correctly billboarded, no shader error).

Rejected on the look, which is A3's bar ("adopted if visually equal"):

- Spreading each mote's light over a soft additive disc changes the sky's grain — individual stars read fainter and
  hazier at the same twinkle amplitude, so matching the current field would mean re-tuning the twinkle floor/gain. That
  is a look change on the product's most-seen surface, not a free win.
- It also converts the backdrop from an opaque depth-writing draw into a sorted transparent one, and adds a hand-rolled
  vertex path plus two per-frame uniform writes to the layer job 141 is about to take over.

The numbers behind the call (web profile, 2600 motes):

| mote                                     | triangles | vertices         | field triangles |
| ---------------------------------------- | --------- | ---------------- | --------------- |
| `SphereGeometry(0.18, 8, 8)` (before)    | 112       | 81 (indexed)     | 291,200         |
| `IcosahedronGeometry(0.18, 0)` (adopted) | 20        | 60 (non-indexed) | 52,000          |
| impostor quad (rejected)                 | 2         | 4                | 5,200           |

The adopted shell is where R008's cliff was: 291,200 → 52,000 on web and → 20,000 on mobile (1000 motes), with a
silhouette at least as round as before — an 8-segment UV sphere is already an octagon, an icosahedron is a decagon.
The impostor's remaining 46,800 triangles are small against one decorated star ring (13 × 5,120 = 66,560) and are not
worth the blend-class change. Evidence: `/design#nebula` (the pure-backdrop bench) captured on all three variants;
before↔after is indistinguishable, the impostor is visibly softer and sparser.

### T004 — per-shape triangle counts (budget 5120)

Every displaced look moved onto the indexed `icosphere(segments)` shell; `facet`/`prism`/`spire`/`orb` are untouched.

| shape     | before (tris / verts) | after (tris / verts)      |
| --------- | --------------------- | ------------------------- |
| `urchin`  | 18,240 / 9,409        | **5,120 / 2,562**         |
| `contour` | 8,064 / 4,225         | 2,880 / 1,442             |
| `plasma`  | 4,512 / 2,401         | 1,620 / 812               |
| `bubble`  | 3,120 / 1,681         | 1,280 / 642               |
| `haze`    | 1,104 / 625           | 320 / 162                 |
| `geode`   | 320 / 960             | 320 / 162 (indexing only) |

Worst-case per-instance cost drops 3.6×, and the registry spread narrows from 912× (20 → 18,240) to 256×. Visual
character verified per shape against `/design#star-forms` (10 before/after captures): the urchin keeps its needles —
`icosphere(16)` puts the vertex spacing at the 96×96 UV sphere it replaces — the contour keeps its isolines (they are
drawn per-fragment off `positionGeometry`, so they never depended on tessellation), and haze/bubble are
indistinguishable.

### Review

`/code-review` (self, on the staged diff) — 2 applied:

- `BandFog` initially set `frustumCulled = false`. Reverted: `InstancedMesh.computeBoundingSphere()` already accounts
  for instance matrices, so the discs stay culled exactly as the four separate meshes were — the refactor's bar is
  behaviour unchanged, and the flag was an unneeded deviation.
- `LatentField`'s `segments` default was spelled `VALUES.rendering.latentStarSegments` next to a
  `LATENT_FIELD_SEGMENTS.web` that means the same thing; collapsed onto the named profile.

`/codex:review` (gpt-5.5, xhigh) — 2 findings, both real, both applied:

- **`LatentField` could go blank on a tessellation change.** A new `segments` rebuilds the geometry, which rebuilds the
  `InstancedMesh` through `args`; the attach ref hides it at count 0, and the matrix effect's deps did not include the
  geometry, so nothing would refill it. Latent today (the profile is fixed per platform) but a trap the seam just
  created — `geometry` added to the deps. Codex also caught that the single dispose effect took the still-mounted
  material down with a geometry-only change (pre-existing, since geometry already depended on `instanceCount`); split
  into one effect per resource.
- **`BandFog` was not actually one draw.** three renders a `transparent` + `DoubleSide` material in two passes (back
  faces, then front) unless `forceSinglePass` is set — the mitigation is pointless for additive flat discs, where the
  sum is order-independent. Set, and asserted in the test. This makes the win 8 draws → 1, not 4 → 1.

Codex also independently verified the `icosphere()` dedup (min distinct vertex spacing at `segments: 16` is 0.058,
four orders above the `toFixed(5)` tolerance), that a fragment-stage `attribute()` read is auto-routed through a
varying, that `mesh.dispose()` after geometry/material disposal is not a double-free, and that no
`createBandFogGroup`/`disposeBandFogGroup` callers survive. Its snapshot of `BandFog.test.ts` predated the
`frustumCulled` revert above, so that one line in its quoted diff is stale.

### Not verified here

The band fog's runtime LOOK. `BandFog` mounts only in the live universe (behind auth) and in `/demo`, whose gist-rise
stage the headless harness could not be driven to within a bounded run — it reached step 4 of 10, where the fog's z band
is off-camera. What the run does establish is that the layer mounts and builds clean: no `aFogStrength` attribute
warning, no shader or validation error in the page console across the whole session (contrast the pre-existing
`aFieldTint` warning from another layer, which the same log does show). The rest of its evidence is the rewritten
construction test, which pins the instance count, the four slice z positions, the 1-|t| strength envelope, the
blending/depth/side/single-pass/renderOrder contract, raycast invisibility and disposal.
