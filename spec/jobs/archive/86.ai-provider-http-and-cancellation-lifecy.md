## Acceptance Criteria (from code-review/07 · R003, R004)

<!-- The source spec's acceptance criteria. After building, verify each is true in the running code. -->

- [x] A1 (R003) Caller cancellation and caller deadlines remain observable through the DeepSeek, Anthropic, and
      Voyage capability clients: when the request context is done, the client returns `ctx.Err()` unchanged, so
      `errors.Is(err, context.Canceled|context.DeadlineExceeded)` succeeds and the error is not classified as
      `RateLimitedError`.
- [x] A2 (R003) A genuine transport failure while the request context is still active remains a retryable
      `RateLimitedError`, and its standard underlying cause remains available through the error chain. Anthropic SDK
      error types remain confined to its provider package.
- [x] A3 (R004) DeepSeek and Voyage consume a bounded amount of every non-success HTTP response body before closing
      it. A representative non-empty error body is read to EOF so its HTTP/1 connection can be reused; oversized or
      sensitive vendor text is neither retained nor logged.
- [x] A4 Cancellation, deadline, wrapped transport-cause, and non-empty error-body lifecycle tests exercise the
      public provider operations rather than only private mapping helpers.
- [x] A5 Except for the corrected failure-path semantics above, behavior does not change: successful response bytes
      and vectors, provider/model/auth/request contracts, typed HTTP status mapping, `Retry-After`, metering, caching,
      and provider selection remain unchanged.
- [x] A6 Plan 28, the AI-worker as-built SSOT, and the shared error-set comments state the real boundary: vendor
      failures normalize to the typed set, while standard caller cancellation/deadline identity crosses the seam
      unchanged as a control-flow signal.
