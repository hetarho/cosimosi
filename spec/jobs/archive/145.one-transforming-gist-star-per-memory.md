- [x] A1 A memory with `semantic_stage = N` (1 ≤ N ≤ 4) renders **exactly one** gist body; a memory at stage 0 renders none. The universe's gist-body count equals the number of memories with a risen stage, for every N.

- [x] A6 A gist read's price still falls as the memory's stage deepens, using the unchanged `twinkle.gist_*` values.
- [x] A7 변천사 still lists one `semanticized` entry per crossed stage with that stage's text, and remains free.
- [x] A8 Reconsolidation still keeps already-published rungs and regenerates only the remaining stage texts ([C7]).

## Decisions & outcomes

- **The quote had to move too.** A4 says the client cannot influence which depth is read **or priced**, and the price
  is computed by `QuoteSpend`, not by `ViewSemantic`. So `QuoteSpendRequest.semantic_stage` is reserved alongside the
  read's field, and the gist arm prices the memory's own rung. Both readers now call one function —
  `viewableGistStage(gist)` in `internal/memory` — instead of two copies of the same clamp, so a quote and the charge
  behind it cannot name different rungs even in principle.
- **The idempotency fingerprint dropped the stage** (T007's trap, and the one that would have cost a user real
  Twinkle). With the depth server-derived, a memory can rise between a lost response and its retry; folding the derived
  stage into `viewSemanticFingerprint` would have turned that legitimate replay into `ErrOperationConflict`. It now
  keys on the memory alone, pinned by a test that rises the memory between the two calls.
- **The rise choreography had to change its diff key.** A gist body's node id is now `gist:<memoryId>` — stable for
  the memory's whole life — so `reconcileGistRiseState` could no longer detect a rise by "an id I have not seen".
  `GistRiseState.stageSeen` tracks the stage per body, and a rise is a stage that increased; the one body then eases
  from where it is up to the new band instead of teleporting. Without this the change would have been silently
  motionless, which no type or lint would have caught.
- **`SemanticStages` is `[4]string`, not a slice**, so "clamp to the derived ladder length" is really "clamp to 4" —
  the guard only ever fires on a corrupt `semantic_stage`. The test says that rather than pretending a shorter ladder
  is reachable.
- **No values, no migration** (T021 confirmed): `rendering.gist_star_*`, `force_sim.neocortex_z_*` and `twinkle.gist_*`
  keep their values and meanings; `semantic_stages` / `semantic_stage` / `memory_provenance` are read-only here and
  every stored rung is retained [I1].
- **Demo mirror:** no fixture change was needed. The demo composes the same `GistStarLayer` over the same projection,
  so it shows the single transforming body by construction — and `packages/demo/src/integrity.test.ts`'s field-set
  assertion still holds because the DTO shape did not move (A10).
