## Acceptance Criteria (from plan/78.sequence-engine)

<!-- The source spec's acceptance criteria. After building, verify each is true in the running code. -->

- [x] A1 A single engine (`@cosimosi/sequence`) runs both feeds: the demo's fixture-driven script and onboarding's script over the user's real first diary differ **only** in the injected script and data, with no branch, flag or host-kind field anywhere in the package ([O1]; the no-`isDemo` rule, [79.demo-page](79.demo-page.md)).
- [x] A2 `SequenceStep` carries a stable id, an i18n caption accessor, an optional host-typed anchor, and one of exactly two advance kinds (`signal`, `dwell`) — and carries **no** action/effect field, **no** `skippable` field, **no** string caption, **no** domain number, and **no** data payload ([O2][O4][I12][I13]).
- [x] A3 The engine performs no product action and issues no RPC: every state change during a run is the user pressing the real control on the real screen, so during onboarding [I10] monotonic time, [I2] `Diary` immutability, [I11] the untouched meaning layer and [G1] paid recall all remain in force ([O2][I13]).
- [x] A4 `packages/sequence` depends on `xstate` and `zustand` only (React as a peer for its `/react` export) and imports neither `@cosimosi/api-client`, `@cosimosi/demo`, nor any `@cosimosi/universe` read mirror; the package is importable from [79.demo-page](79.demo-page.md)'s import-boundary lint scope without exception ([I13]).
- [x] A5 The run machine is one XState v5 machine (`idle → running → completed | skipped | abandoned`) whose context holds only `runId`, `stepIndex`, `stepCount`, `outcome`; the script, rects and registry live outside it and the context is JSON-serializable, asserted by a context-rule test (§3.2, plan 07).
- [x] A6 `ADVANCE` echoes the step index it observed and is ignored when stale, so a duplicate signal, a double tap, or a dwell timer from a superseded step cannot advance the run twice; the machine never calls `Date.now()` ([O2]).
- [x] A7 While a run is active, a skip affordance is visible on every step — `SKIP` is accepted in every non-terminal state and no step can opt out of it — and skipping ends the run immediately with the `skipped` outcome and no confirmation prompt ([O4]).
- [x] A8 A caption renders at bottom center for every step, in a polite live region, resolved from an i18n accessor (never a hardcoded string) and re-rendered on a locale change; when the highlighted control's measured rect intersects the caption band, the caption relocates by the pure placement rule ([O2]).
- [x] A9 The step's anchor is highlighted by a non-modal spotlight over its measured rect: it never traps focus, never intercepts pointer events, never disables un-highlighted controls, and its pulse collapses to a static ring under reduced motion ([O2], plan 09).
- [x] A10 An unregistered or unmeasurable anchor degrades to caption-only with no timeout, no error surface and no change to how the step advances; the run remains completable ([O2][O4]).
- [x] A11 Anchors are registered only at composition sites via the `SequenceAnchor` wrapper — no `features/*` product slice and no `entities/*` slice imports `@cosimosi/sequence` ([I13]; the no-`isDemo` rule, [79.demo-page](79.demo-page.md)).
- [x] A12 A run can be replayed at any time by starting again with a fresh run id, from any terminal state, with no teardown by the caller and no residue from the previous pass; the engine persists nothing about a run and holds no "already seen" record ([O5][O3][Z7]).
- [x] A13 The engine's stores are cleared on an account boundary through `resetSequenceUserState()`, registered in both apps' shared user-scope reset inventory ([U1]).
- [x] A14 The engine's chrome ships in **both** apps (`features/highlight-next-control`, `features/show-sequence-caption`, `features/skip-sequence`, `widgets/sequence-guide`), sharing every `model`-level artifact verbatim through `packages/sequence`, with each app hand-writing its own `ui` and no app slice carrying a `*.native.tsx` sibling (§3.5, [00.overview](00.overview.md) §4).
- [x] A15 The machine and selectors are unit-testable with no renderer, no DOM and no transport: a scripted event sequence yields deterministic view snapshots, and every dwell timer is cleared on step change and unmount (no suite leaves a pending timer, ARCHITECTURE §4).
- [x] A16 All engine-owned user-visible copy resolves through the i18n seam under the `sequence_*` prefix with both catalogues populated and `pnpm check:gen` / `pnpm lint:raw-strings` green ([I12], `spec/tech/i18n.md` §2).

## Implementation Checklist

<!-- How to build it, top to bottom. [P] = parallel (different files, no dependency). Flag (gen)/(migrate)/(gen:values). -->

> **Lands after [job 116](116.demo-fixtures-and-mirror.md)** (which pins `slowFactor` and owns the beat ids) and before
> the two hosts (plans 79 · 80). Frontend-only: no proto, no migration, no RPC — **the engine issues none, ever.**
> Invoke `/fe-architecture` **and** `/mobile-architecture`: three features and a widget land on both apps, and each app
> hand-writes its own `ui` (no `*.native.tsx` sibling — the parallel mobile slice _is_ the fork).

**Tuning**

- [x] T001 **(gen:values)** NEW `sequence` group in `spec/values.yaml`: `caption_dwell_ms` (how long a `dwell` step's
      caption holds before the run advances itself) and `highlight_pulse_ms` (the spotlight's pulse period), both
      confirmed at implement. `pnpm gen:values`.

**The engine package (`@cosimosi/sequence`) — React-free at its root**

- [x] T002 `packages/sequence/package.json` — dependencies are **`xstate` and `zustand` only**, with React a _peer_ for
      the `/react` export. It must import neither `@cosimosi/api-client`, nor `@cosimosi/demo`, nor any
      `@cosimosi/universe` read mirror — that list is what makes the package importable inside plan 79's
      import-boundary lint scope without an exception.
- [x] T003 `src/script.ts` — `SequenceCaption = () => string` (an i18n accessor), `SequenceStep<Anchor, Signal>`
      (`id`, `caption`, optional `anchor`, and `advance` as exactly `{on:'signal', signal}` **or** `{on:'dwell'}`), and
      `SequenceScript`. `Anchor`/`Signal` are **host-owned string-literal unions**, so a typo in a script is a compile
      error in the host while the engine stays host-agnostic. `defineScript()` is a type-narrowing identity helper that
      performs **no validation** — the interesting properties are types, not runtime checks.
- [x] T004 The step shape omits, deliberately and permanently: any `run`/`onEnter`/`action`/`effect` field (the engine
      must never perform the step for the user), `skippable`/`mandatory` (a step that cannot be skipped), a string
      `caption` (an unreviewed public sentence), **any** domain number (a formula smuggled into a script), a data payload,
      and `isDemo`/`hostKind` (a sandbox branch in shared code). Record each absence in the package doc comment — the
      omissions _are_ the design.
- [x] T005 `src/sequence.machine.ts` — one XState v5 machine, `idle → running → completed | skipped | abandoned`, where
      **every terminal state accepts `START` again** (that is what makes replay a start, not a reset ritual). Context is
      exactly `{runId, stepIndex, stepCount, outcome}` — JSON-serializable, asserted by a context-rule test; the script,
      the rects and the registry live outside it. `ADVANCE` **echoes the step index it observed and is ignored when
      stale**, so a duplicate signal, a double tap or a dwell timer from a superseded step cannot advance twice. The
      machine never calls `Date.now()`.
- [x] T006 `SKIP` is accepted in **every** non-terminal state and ends the run immediately with the `skipped` outcome and
      no confirmation prompt — no step can opt out, because there is no field with which to.
- [x] T007 [P] `src/select.ts` — pure selectors: `currentStep`, `progress`, `isActive`, and
      `resolveCaptionPlacement(anchorRect, viewport, bandHeight) → 'bottom' | 'top'` (the caption moves to the top band
      when the highlighted rect intersects the bottom one — not cosmetic: the shipped universe page puts the writing
      sheet bottom-center, exactly where the first onboarding beat points).
- [x] T008 [P] `src/anchor-registry.ts` — a Zustand store of `anchorId → { measure(): Promise<SequenceRect | null> }`,
      where the rect is in **logical pixels relative to the app window**. The promise is what lets one seam serve both
      platforms (web reads `getBoundingClientRect()`, mobile uses `measureInWindow`, which is callback-based). Rects are
      re-measured on step change, on resize/orientation change and on registry change — **never per frame**.
- [x] T009 [P] `src/user-state-reset.ts` — `resetSequenceUserState()` clears the registry and any run-scoped store and
      joins `@cosimosi/auth/user-state`'s shared reset registry once. The demo needs nothing from it; the onboarding tour
      runs inside a real session, where an unregistered store would leak one account's run into another's subtree.
- [x] T010 `src/react.ts` — the optional React seam only: `useSequenceRun`, `useSequenceAnchorRegistration` (the
      `@cosimosi/state-machine` + `@cosimosi/twinkle` precedent). `src/index.ts` exports named symbols, no wildcard barrel.

**The chrome (three features + one widget, per app — non-modal by construction)**

- [x] T011 `features/highlight-next-control` — `SequenceSpotlight` draws a ring/scrim over the measured rect with
      `pointer-events: none` and `aria-hidden`; it **never** traps focus, **never** renders a blocking backdrop and
      **never** disables anything, including controls the current step does not name. The pulse runs at
      `highlight_pulse_ms` and collapses to a static ring under `useReducedMotion`. `SequenceAnchor` is the register
      wrapper hosts wrap an existing child with.
- [x] T012 [P] `features/show-sequence-caption` — `SequenceCaption`, one line at bottom center in a **polite live
      region** so a step change is announced, resolved by calling the step's accessor at render time so a mid-run locale
      switch re-renders it.
- [x] T013 [P] `features/skip-sequence` — `SequenceSkip`, rendered unconditionally whenever a run is active: one
      restrained control with no confirmation (replay makes a mis-skip cheap) beside a quiet `current / total` readout.
      It is the **one** interactive element the chrome owns.
- [x] T014 `widgets/sequence-guide` composes the three features from a view + handlers the host passes in. **Anchors are
      registered at composition sites, never inside product feature slices** — hosts wrap an existing child
      (`<SequenceAnchor id="write-diary"><WritingFlowSheet /></SequenceAnchor>`), which is what keeps
      `features/write-diary`, `features/recall-star` and every other shipped slice unaware that a sequence exists. The
      highlight's grain is therefore the control cluster a page already lays out.
- [x] T015 An unresolved anchor is **not an error**: the spotlight renders nothing while the caption and the skip stay,
      and the step still advances on its signal. **No anchor timeout and no fallback timer** — the caption is the
      guaranteed channel, the highlight is an enhancement.
- [x] T016 Scoped `'fsd/insignificant-slice': 'off'` blocks with stated reasons for each new slice in
      `apps/web/steiger.config.js` (following the existing per-vertical blocks).

**Copy, tests, SSOT**

- [x] T017 i18n: the engine's own chrome keys under `sequence_*` naming a **UI role** — `sequence_skip_action`,
      `sequence_progress` (with `{current}`/`{total}`, the `error_internal` `{requestId}` precedent). Script captions
      belong to their feeding plan (`demo_*` for plan 79, `sequence_*` for plan 80). Edit both catalogues, run
      `pnpm gen:messages`, commit the generated files, and let `check:gen` gate freshness. Voice: plain and unhurried —
      an instruction, not a sales line.
- [x] T018 Tests: the machine's five states and the replay-from-terminal path; a stale `ADVANCE` is ignored; `SKIP` works
      in every non-terminal state; the context stays JSON-serializable; `resolveCaptionPlacement` flips only on
      intersection; an unregistered anchor degrades to caption-only; the reduced-motion ring is static; the package's
      dependency list holds (an import-boundary assertion, not a review habit).
- [x] T019 SSOT at implement: NEW `spec/policy/ux/sequence.md` (guidance on the real screen; one caption at a time;
      skip always visible and never confirmed; the chrome blocks and disables nothing; the engine points and waits and
      never acts; a replay is a fresh run; the highlight is decorative and the caption is guaranteed) — exposure policy
      ([O3]) is plan 80's, not this doc's. Record the step model and its omissions, the machine's echo guard, the
      registry contract and rect units, and the placement rule in `spec/tech/state-machine.md`. Register
      `SequenceStep` · `SequenceScript` · `SequenceRun` in `spec/ubiquitous-language.md` §1.1 as FE-only, no-DB rows
      **before** the code lands, stating that a script names steps while a `DemoScenario` names data.
