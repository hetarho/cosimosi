## Decisions & outcomes

- **T002 — the envelope is 8, and it is now one constant.** `UNIVERSE_CAMERA_ENVELOPE`
  (`packages/universe/src/camera-rig.ts`) holds `minDistance`/`maxDistance`; `UNIVERSE_CAMERA_RIG`
  spreads it, and the eight `CameraControls` mounts spread it too — so the rig and the inspection controls cannot
  disagree again. `CameraControls`' props are required (no default to drift back to), pinned by
  `CameraControls.test.tsx`. No universe→renderer dependency: the pages feed the constant down.
  **Zoom check (A6):** headless CDP on `/test` (Universe + chrome tab), 80 identical wheel-zoom-in ticks, before
  (`minDistance` 20) vs after (8). At 20 the camera halts with two star bodies still framed at the right edge; at 8
  the same input carries it ~2.5× closer, past the bodies to a filament ribbon. Both frames render correctly — no
  near-plane clipping, sky still enclosing, backdrop intact. The extra inner range is the only behavior change.
- **T003 — SkySphere's 12 was not deliberate.** It predates the other two (job 39) and no sky effect is
  non-periodic in `time`, so any instant is as valid as any other. All three now read
  `REDUCED_MOTION_FROZEN_TIME = 8` (`layers/reduced-motion.ts`), whose comment records the one real constraint:
  not 0, where the twinkle/noise fields start aligned and dark.
- **T004 — `EdgeLineLayer` deleted** (the job's default arm). `FatLineLayer` is the shipped edge renderer and the
  thin-line variant had no consumer, no test, and no owner. Removed with its `index.ts` export, the mobile jest
  mock line, and the `spec/tech/rendering.md` prose that claimed it was a kept primitive.
- **T005 — defaults derived, `far` kept in code.** `canvas/canvas-defaults.ts` derives `DEFAULT_CANVAS_DPR` from
  `rendering.max_pixel_ratio` and `DEFAULT_CANVAS_FOV` from the active skin, so neither host can shadow a value it
  is supposed to follow. `far` stays `UNIVERSE_CANVAS_FAR` (code, `backdrop-scale.ts`): it is one end of the
  backdrop nesting chain that `universe-render/backdrop-scale.test` walks as a single invariant, and a
  deployment-tunable knob is exactly what would break it. The reason is now stated on the prop.
- **Trackball feel:** only the genuinely identical settings moved (`applyTrackballFeel` — `staticMoving`,
  `dynamicDampingFactor`, `zoomSpeed`); the deliberate `rotateSpeed` split (1.8 inspection / 1.4 navigation) and
  `panSpeed` stay named at each layer with the reason.
