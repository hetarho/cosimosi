## Review

- [x] `/code-review` applied (rejections noted with reason) · `/codex:review` run (gpt-5.5, background)
  - Both reviewers converged on a **P2**: a late adapter `signedOut` emission (Supabase `INITIAL_SESSION(null)`,
    which can trail a network refresh attempt for an expired stored session) could clobber the OAuth-error `failed`
    state — either by bumping the epoch mid-operation (skipping `SIGN_IN_FAILURE`) or by driving `failed → signedOut`
    after it landed. **Applied**: the facade now skips adapter `signedOut` events while a sign-in operation is in
    flight or the machine sits in `failed` (redundant "no session" information; safe because any in-flight operation
    already bumped the epoch, so a pending bootstrap can never late-restore) + a regression test covering both
    orderings. **Also applied** (P3s): OAuth-error bridge scoped to `pathname === '/'` (Google's only documented
    return path — an `?error=` on any other route keeps its URL state); hash-fragment error callbacks
    (`#error=…`, a real GoTrue emission class) now parsed by the shared `callbackUrlError` and stripped by the
    bridge; plan 04's stale `app/auth-provider.tsx` paths corrected to `app/providers/`; the LoginPage null-method
    comment now names the bootstrap-failure case too.
  - Rejected: replacing `history.replaceState` with router-history integration (transient router/URL desync converges
    via the gate redirect; coupling the auth provider to the router isn't worth it) · guarding the mobile
    openUrl-in-flight cancel window (a trailing deep link recovers the session; accepted tradeoff, noted by reviewer
    as such).
