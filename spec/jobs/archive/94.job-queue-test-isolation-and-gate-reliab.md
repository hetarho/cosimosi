## Acceptance Criteria (from code-review/09.epic-k-account-runtime-and-gate-audit)

- [x] A1 No test in `apps/api/internal/memory/pg` concludes that _its_ job ran from the fact that `RunOnce` returned
      `worked == true`. Each drain assertion is identity-bearing: it names the job (or the target row) it expects to be
      terminal, so an unrelated due row in the shared queue can no longer satisfy it.
- [x] A2 `TestSyncDefersRiseThenWorkerMaterializesIt` passes deterministically when an unrelated due job is present in
      the queue at the moment it drains — proven by a test that seeds exactly that condition, not by re-running until
      green.
- [x] A3 Every test in the package that enqueues jobs removes them again (`t.Cleanup`, or an equivalent scoped teardown
      that also runs when an assertion fails), so a failing test cannot poison a later one in the same run.
- [x] A4 No assertion message in the package prints a pointer address. The R001 failure text
      (`pending 0x36c45ad387b8`) reports the dereferenced pending stage or an explicit `nil`.
- [x] A5 **No behavior change.** `ClaimDueJob` stays a deliberately global, cross-user claim (§4 allowlisted) and the
      runner's semantics are untouched — this job changes tests and their teardown only, never production queue code.
- [x] A6 `pnpm check` passes end-to-end, including the stages the audit never reached (`build:web`, `build:blog`,
      `vet:api`, `build:api`, `check:gen`), and passes on 5 consecutive full runs.
