## Implementation Checklist

<!-- How to build it, top to bottom. [P] = parallel (different files, no dependency). Flag (gen)/(migrate)/(gen:values). -->

> **Lands after [job 117](117.sequence-engine.md)** (the engine, its chrome and the `sequence` values group). **No
> parity waiver** — unlike the demo, the tour ships on both apps, which is why the script is a package. It adds no
> values key, no proto, no migration. Invoke `/fe-architecture` · `/mobile-architecture`.

**The package (`@cosimosi/onboarding`) — the fifth of v2's five new FE packages**

- [x] T001 `packages/onboarding/package.json` — depends on `@cosimosi/sequence` + `@cosimosi/i18n` and **nothing else**.
      It cannot live inside `packages/sequence` (whose dependency list is pinned to `xstate` + `zustand` precisely so
      plan 79's import closure can admit it, and a caption accessor needs i18n) and it cannot be app-local `model`
      (byte-identical on both apps → lint R4).
- [x] T002 `src/anchors.ts` — the **two closed unions**, and they are the whole safety argument:
      `OnboardingAnchor = 'universe-write-entry' | 'writing-draft' | 'writing-proposal' | 'writing-confirm' |
'universe-clock'` and `OnboardingSignal = 'writing-flow-opened' | 'split-succeeded' | 'launch-succeeded'`. A step
      naming anything outside those eight strings is a compile error. Record what they omit and why: **no recall anchor
      or signal** (a step waiting on a paid reconsolidation), **no 놓아주기/delete anchor** (a tutorial that destroys a
      memory), **no clock or sync signal** (a step moving universe time to make dimming visible), **no
      palette/ornament anchor** (changing a render parameter for effect), **no star anchor** (a star's position comes out
      of the force-sim and changes every frame — there is no composition site to register and no rect to measure), and
      **no anchor inside a `features/*` slice**.
- [x] T003 `src/script.ts` — `ONBOARDING_SCRIPT = defineScript<OnboardingAnchor, OnboardingSignal>(…)`, the nine steps:
      `welcome` (dwell) · `entry` (signal `writing-flow-opened`) · `draft` (signal `split-succeeded`) · `proposal`
      (dwell) · `confirm` (signal `launch-succeeded`) · `arrival` (dwell) · `clock` (dwell) · `revisit` (dwell) ·
      `closing` (dwell). Every step representing progress the user must make is a **signal** step; `dwell` is reading
      time only. **Step 8 is the deliberate stopping point**: recall costs Twinkle and requires consent, so the tour
      _names_ recall and stops rather than walking a first-minute user into a spend.
- [x] T004 [P] `src/signal-channel.ts` — `useOnboardingSignalStore` + `reportSequenceSignal(signal): void`, pushing
      `{signal, nonce}` into a Zustand channel (the shipped `useRecallTargetStore` / `useDeletionTargetStore` shape).
      **The signature is the guard**: it takes one id and returns nothing, so a reporting site cannot learn whether a
      tour is running, cannot read a step index, and cannot branch on either.
- [x] T005 [P] `src/start.ts` — `takeOnboardingStart(): 'signup' | 'replay' | null`, a pure take-once read, plus
      `requestOnboardingReplay()`. That is the **entire** exposure policy: the signup completion signal plan 63 already
      sets, a replay request, or nothing. **No "already seen" record exists, on the server or the client, and adding one
      is out of scope by decision** — plan 60 closed the `users` shape and the RPC inventory, and a `localStorage` flag
      would turn "가입 직후 최초 1회" into "once per browser". The guarantee is a property of the trigger: plan 63's
      profile gate makes `SignUp` reachable only while no `users` row exists, so the signal has no second occasion.
- [x] T006 [P] `src/user-state-reset.ts` — `resetOnboardingUserState()`, plus `'onboarding'` in
      `packages/auth/src/user-state-reset.ts`'s shared inventory (the tour runs inside a real session, so an
      unregistered store would leak one account's run into another's subtree).

**The hosts — the tour observes and reports; it never intercepts**

- [x] T007 `pages/universe` owns the run actor with `useActorRef` (exactly as it already owns
      `universeNavigationMachine`), calls `takeOnboardingStart()` on mount, subscribes to the signal channel and
      translates a matching signal into the machine's **echo-guarded** `ADVANCE`. It mounts `widgets/sequence-guide`
      above the HUD so the caption band, the spotlight and the always-visible skip render over the live scene **without
      remounting the renderer**.
- [x] T008 Register the five anchors by **wrapping an existing child at a composition site**: `pages/universe` wraps the
      일기 쓰기 cluster and the `UniverseTimeOverlay`; `widgets/writing-flow`'s sheet wraps its three inner panels around
      the shipped `features/write-diary`, `features/split-diary` / `features/revise-split` and `features/launch-stars`
      children. A widget is a composition site, not a product slice, so **no `features/*` or `entities/*` slice imports
      `@cosimosi/sequence` or `@cosimosi/onboarding`** and nothing is passed down through a wrapper — no prop, no flag,
      no callback.
- [x] T009 Report the three signals from the writing-flow sheet's existing `OPEN`, `SPLIT_OK` and `LAUNCH_OK`
      transitions. The sheet's own behaviour is unchanged with or without a tour: with no run active the channel write is
      inert, and the engine's index echo makes a stale or duplicated report a no-op. **The tour cannot get ahead of the
      product** — a failed `SplitDiary` returns the shipped machine to `writing` and emits nothing, so step 3 simply
      holds its caption; there is no retry logic, no timeout and no tour-owned error surface.
- [x] T010 `features/replay-onboarding/ui` — the `/me` profile-tab row: it calls `requestOnboardingReplay()` and then the
      page's existing exit callback (the page imports no router), the universe page mounts, `takeOnboardingStart()`
      returns `'replay'`, and the run begins at step 1. **No teardown is needed** — a replay is `START` with a fresh run
      id. A replay over a populated universe behaves identically; steps 3–5 wait for a genuine second diary, which is a
      welcome act rather than a cost. Scoped `'fsd/insignificant-slice': 'off'` block with a stated reason.
- [x] T011 All three outcomes end the same way: `completed`, `skipped` and `abandoned` (the route unmounted) leave the
      chrome gone and **nothing recorded**. The tour draws no distinction between finishing and skipping — no "are you
      sure", no re-offer, no follow-up prompt, because replay makes a mis-skip cheap and a nagging tutorial is worse than
      a missed one.

**Copy, tests, SSOT**

- [x] T012 Captions under the existing `sequence_*` prefix in a `sequence_tour_*` sub-namespace (v2 adds no
      `onboarding_*` prefix): the nine `_caption` keys plus `sequence_tour_replay_action` and
      `sequence_tour_replay_description`. **Every caption is a zero-parameter accessor** — no star name, memory count,

- [x] T013 Tests: a step naming an unknown anchor fails to typecheck (a type-level assertion); `takeOnboardingStart`

      in their after-state; the writing-flow sheet's behaviour is unchanged with the tour absent; sign-out clears the
      run.
- [x] T014 SSOT at implement: append an `## Onboarding` section to `spec/policy/ux/sequence.md` (job 117 creates the

      nothing deleted), highlights no paid or destructive control (which is why recall is named at step 8 and not

- [x] Self-review applied (`/code-review` is not model-invocable in this harness, so the diff was walked by hand against

**Codex findings — 4 of 5 applied, 1 partially:**

1. **The chrome rendered under the writing dialog** (all three dialog-hosted steps lost their caption, ring and skip).
   Real and the most serious: the engine's chrome was built over a modal-free demo page, and the tour is the first host
   to put it over a dialog. **Web fixed** with a new foundation token `tokens.z.guide` (1250, between `z.modal` and
   `z.toast`), pinned by a guide test. **Mobile left as a recorded gap** — RN's `Modal` presents in its own window above
   the app tree (the repo's toast host has the same limitation), and closing it needs a `packages/ui` portal seam or an
   overlay slot on the native `Dialog`, which is plan 78's chrome to change. Written up in plan 80 and
   `tech/state-machine.md` §6.8.1 with the fix path.
2. **A signal reported during a dwell step was swallowed, stranding the next step.** Real and unrecoverable in the launch
   case. Fixed: the run host now **holds** a report the current step is not waiting for until the step that waits for it
   arrives, and clears it only when no run is active (so nothing survives into a later run). Pinned by a mobile
   app-shell assertion, mutation-checked — it fails with the hold removed.
3. **Mobile did not end the run when the universe screen lost focus** (the native stack keeps it mounted, so dwell timers
   walked the tour to its end behind `/me` with the skip unreachable). Fixed: blur reports `abandon`, which is what web
   gets for free by unmounting the page. **Not covered by a test** — the jest native-stack harness hides an unfocused
   screen from queries and appears to remount on pop, so an assertion either way passes vacuously; a first attempt was
   removed rather than shipped as a false green.
4. **A split/launch whose RPC resolved after the sheet closed still reported.** Real: the machine ignores `SPLIT_OK` in
   `idle`, so the tour would have advanced past a step the user never completed. Fixed: the three reports now come from
   one effect over the machine's **real phase transitions** rather than the promise arms.
5. **The app-shell test was shallow** — fair. Strengthened with the held-report assertion above; a full walk of
   split→launch would need `MemoryService` split/launch fakes the mobile harness does not have, which is left undone.

Also added beyond the checklist, because AC 5 asked for structure and had none: a `no-restricted-imports` block over
`features/**` + `entities/**` in both apps refusing `@cosimosi/sequence` / `@cosimosi/onboarding`, and
`scripts/probe-sequence-isolation.mjs` (wired into `test:guards`) proving it bites in each app's own config. It caught a
real boundary question in the process — `features/replay-onboarding` needs the request — resolved by exempting the
sequence's own four slices with the reason stated in both configs.

## Deviations from the checklist (as-built)

- **`universe-clock` moved from `pages/universe` to `widgets/universe-time`** (T008). The page composes that widget as a
  fragment of absolutely-positioned children, so a page-level wrapper would have measured the acceleration veil on web
  and a zero-height full-width box in RN. Still a composition site, so [78] AC 11 is untouched.
- **`takeOnboardingStart` takes the signup flag as a parameter** (T005). `@cosimosi/auth` imports this package for the
  reset inventory, so the dependency edge forbids reading auth's one-shot flag from inside it; the page passes
  `takeSignupCompletion()`.
- **The three signal reports are one phase-transition effect, not three inline calls** (T009) — see Codex finding 4.
- **The mobile leg keys its start on focus and abandons on blur** (T007), because the native stack keeps the screen
  mounted under `/me`.
- **A11's enforcement is the dependency closure + a manifest test**, not an ESLint rule on the package: an undeclared
  workspace package is not resolvable at all, which is stronger, and it is the pattern `packages/sequence` already uses.
