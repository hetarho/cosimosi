- [x] `/code-review` applied (rejections noted with reason) · `/codex:review` run (gpt-5.5, background)
  - Adversarial review (fresh-context agent) + Codex converged; both **mutation-verified** the behavioral
    tests fail if masking/gate regresses. **Applied** (P3, both): the `EnvDeployEnvironment` comment
    overstated the Sentry coupling (sentry.go never sets `ClientOptions.Environment`) — reworded to "the
    same env var sentry-go reads," and it now states the var must be `production` on a prod stack even when
    Sentry is disabled. **Applied** (P3): `.env.production.example` now documents `SENTRY_ENVIRONMENT` as the
    error-detail hard-gate (set `production` even with Sentry off; staging must set `staging`).
  - **Deferred with rationale** — both reviewers' **P2**: the gate keys off the operator-maintained
    `SENTRY_ENVIRONMENT`, so a prod `.env` that omits/misspells it AND leaks `COSIMOSI_ERROR_DETAIL=verbose`
    would bypass the gate. This is defense-in-depth by design (R013 framed it as belt-and-suspenders; the
    primary control — `COSIMOSI_ERROR_DETAIL` unset by default — still masks). A boot-time assertion that a
    prod stack sets the var is a deploy-workflow change that belongs with the CI/toolchain hygiene work
    (job 84 / R017), not this behavior-preserving hardening; documented the requirement instead.
  - **A2 registry-consistency** (reason↔code vs `errors.md` table) left partial: the concrete named blind
    spot (`connect.NewWireError`) is now caught by the boundary audit; parsing the markdown registry table
    in a Go test is brittle and A2 was optional — deferred.
