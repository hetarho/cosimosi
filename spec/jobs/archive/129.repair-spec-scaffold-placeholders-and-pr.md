# Job 129: Repair spec scaffold placeholders and probe scaffold output (refactor)

> Implementation work doc. Source spec: [code-review/11.jobs-116-128-demo,-sequence,-landing-and](../../code-review/11.jobs-116-128-demo,-sequence,-landing-and.md).

> SSOT (plan/policy/values) and set status: done. Write it in English.

Covers **R002 (P1)**. Build this **first**: it is the cheapest job in the set, and until it lands every
`pnpm spec:code-review` and `pnpm spec:change` keeps emitting documents whose frontmatter is garbage.

**The trap to understand before editing.** The naive fix — writing `title: {{TITLE}}` back into the
template — makes `pnpm format:check` **fail**, and `format:check` is the second step of `pnpm lint`.
Prettier's YAML pass is what corrupted these placeholders in the first place: unquoted `{{TITLE}}` in a
frontmatter block parses as a nested flow mapping, so Prettier normalizes it to `{ { TITLE } }`. The fix
is therefore to **quote** them, which review 11 verified passes `prettier --check` under the repo's
pinned 3.9.4 _and_ still substitutes through `fill()`. `review: '{{NN}}'` in the same file is the
existing precedent, and `scripts/templates/job.md` (9 quoted placeholders, all intact) is the proof the
pattern holds.

## Outcome

**T002 found nothing to change.** `job.md`'s five placeholders were already quoted, and `plan.md` has no
frontmatter at all (it opens on `# {{NN}}. {{TITLE}}`), so only `code-review.md` and `change.md` carried
the defect. The guard covers all four regardless, which is what makes the two currently-clean templates
stay clean.

**Deviation from T004 — the guard renders in-process instead of scaffolding into a temp directory.** The
four `new-*.mjs` scripts resolve their output directory from `repoRoot` with no override, so a probe that
really invoked them would create numbered documents under `spec/**` and advance the `NN` counter on every
gate run. Giving four production scripts a test-only output seam to enable a probe is a larger change than
the fix itself. Instead the guard reads each template, applies the same literal `{{KEY}}` replacement using
the key set **read out of that scaffold's own `fill()` call**, and asserts nothing placeholder-shaped
survives — the rendered document is checked, only the file write is skipped. The real end-to-end scaffold
(all four kinds, frontmatter inspected, artifacts deleted) was run as manual verification for A3.

**Two checks, not one.** Beyond the spaced-brace corruption, the guard fails on a template placeholder the
scaffold never supplies — the other way a live `{{X}}` reaches a real document. `lint:spec:probe` proves
both shapes bite and that the real template still passes, so the check cannot earn a green by rejecting
everything.

**Incidental:** removed a pre-existing unused `statSync` import from
`scripts/check-spec-hygiene.mjs` — the file was already being substantially edited, and `scripts/` is
outside every current linter's scope (which is job 133's finding).

## Review

- [x] `/code-review` applied (rejections noted with reason)

`/code-review` is user-invocation-only in this harness, so the pass was run manually against the same
checklist. Findings applied: the section-C `note()` asserted "no placeholder survives substitution" before
the problems were reported, so it printed a conclusion on a failing run — reworded to state only what it
did; the `fill()`-key regex matched any uppercase identifier followed by `:`, so an uppercase name inside a
value expression could have widened the key set and made the check more permissive — anchored to a key
position (`{` or `,`); and one comment explained the defect as something that happened rather than as a
live constraint, which `spec/principle/timeless-documents.md` and the `lint:comments` rule both reject —
rewritten as the rule a future editor must not break.

Rejected: adding a guard for `SCAFFOLDS.find(kind === 'code-review')` returning `undefined` if that entry
is ever renamed. The probe would throw and redden the gate, which is the correct outcome, and a branch that
can never fire is the speculative-code smell review 11 flags elsewhere.

Codex review: not run — this is a small, mechanical tooling change with no concurrency, lifecycle or
domain logic, which is the case the job's Review section scopes to `/code-review` alone.
