- [x] A6 A claim invalidates the `AchievementService` read and the twinkle balance, and — only for an ornament reward — [71]'s `GetCatalog`; the stardust tab shows the credit as an ordinary ledger row on next open. No surface polls. ([G7], ARCHITECTURE §3.2)

## Review

- [x] `/code-review` applied (rejections noted with reason) · for non-trivial logic, `/codex:review --background`

**As-built notes:**

- **A17's placeholder retirement went further than the copy.** `me_achievements_pending` is gone from both locales and
  both apps, and the two tests that asserted it now assert the real body: the mobile tab test waits for the list's empty
  line, and the web deep-link test asserts the achievements **panel** (server-rendered, the read has not resolved, so the
  list's pending surface is what proves the body mounted rather than a placeholder).
- **The error provider was refitted rather than replaced.** It no longer holds state and a `Toast`; it pushes into the
  shared queue. `ErrorToastContext` and `presentAppError` are untouched, so no `useErrorToast` consumer changed — but both
  apps' provider TESTS now mount the toast host, because the host is what renders the one Toast.
- **`ACHIEVEMENT_NOT_FOUND` / `_NOT_ACHIEVED` refetch from the feature, not from `packages/errors`.** The reason→copy map
  is presentation; deciding to invalidate a query is the surface's call, and putting it in the shared presenter would give
  every consumer a side effect it did not ask for.

**Reviewed by codex (gpt-5.5) plus a parallel review agent. Fixes applied:**

- **`groupByAxis` was reordering the server's answer and could DROP a row.** It walked a local axis list, so groups came
  out in the client's order and a row on an axis this build did not know rendered nowhere — an achieved row that never
  renders is a reward nobody can claim. It now derives the groups from the response, first-seen order, losing nothing.
  This is A1's actual requirement; the original grouping test asserted the reordering.
- **The toast queue could carry one user's notice into another's session.** The queue lives above auth (an auth error has
  to be able to toast), so unmounting the notice host was not enough for an entry already queued behind a long error.
  Entries now carry an owner and the host drops its own on unmount — which is sign-out — while an error, having no owner,
  is never touched.
- **`invalidateAchievements()` was firing in catch branches** on the three paid-action surfaces. A refused action records
  no progress, and refetching after it could surface an unlock notice that reads as though the failure had earned
  something. The balance still refreshes on both paths (a refusal can still have moved it); achievements only on success.
- **`durationMs` is now required on a queued entry.** The shipped `Toast` has no manual-dismiss affordance, so an entry
  without a duration would sit at the head forever and block every later toast behind it.
- One missing effect dependency (`invalidateAchievements` in the stardust overlay).

**Rejected, with reason:**

- **Lifting the reward reveal to an auth-scoped host** so it survives leaving `/me` mid-claim. The reveal would then live
  outside the feature that owns the claim, against §3.1's placement, to serve a window measured in the RPC's own latency —
  and the reward is credited regardless, with the row reading 받았어요 on return. Accepted as a small degradation.
- **A queue length cap.** With errors restored to last-wins (below) and the notice capped per resolution, there is no
  producer left that can flood the queue, so a cap would guard nothing.

**A second review pass (a parallel agent) found more, all applied:**

- **A failed read rendered as "you have no achievements."** `isPending` is false once a query settles into error and the
  entries fall back to `[]`, so a failed list showed the empty-state copy — the surface lying about the user's history,
  with no toast and no retry. The error is surfaced now; the empty line is only for a successful empty answer.
- **My own queue change had regressed errors from last-wins to an unbounded FIFO.** A failing API can raise a dozen of
  the same refusal in seconds; queued at 6s each that is a minute of already-stale toasts. The error path now clears its
  own pending entries before pushing, which restores the previous behavior while leaving a queued notice alone.
- **`packages/achievement` was the one package whose `typecheck` never ran** — a script existed but was in no chain.
- **`progressRatio` was dead code** and duplicated the geometry the two `Progress` primitives each compute, so its clamp
  test guarded a function no pixel depended on. Deleted; the meter owns its own geometry.
- **The notice host was byte-identical in both apps** and platform-pure, which §3.5 says belongs in a package — proven by
  having to write the same fix into it twice. The body is now `useAchievementUnlockNotice`; the hosts keep only the copy
  and the queue, which is what actually differs.
- **`useAchievements` spread the query result**, marking every one of TanStack's tracked getters as read, so a background
  refetch that moved only `isFetching` re-rendered the whole list. It returns named fields now.
- **`Progress` announced a `max` its geometry ignored** (a full bar reporting 0 of 0), and the axis heading for an unknown
  axis fell back to a row's copy rather than a heading's.
- Post-await sends are fenced against unmount; the replaced deep-link assertion now asserts something the LIST renders
  (the panel element belongs to `MePage` and was there before, so it proved nothing); one orphan style removed.

**Two bugs I introduced while fixing the above, caught by running the real app:**

- A cleanup-only `mounted` fence latches false on React's development remount, so every claim silently discarded its own
  result and the reveal never opened. It sets the flag on mount too.
- The same shape in the notice's queue cleanup would have dropped the notices the host had just queued. Clearing is now
  keyed on a CHANGE of the signed-in identity — the one thing the host can see and the queue must never learn — instead
  of on a cleanup.

**The refactor moved two more things, because the gates said so rather than because the job asked:**

- `apps/{web,mobile}/src/app/providers/error-provider.tsx` **no longer exists.** Once errors pushed into the queue instead
  of rendering a `Toast`, the two files became normalized-equivalent and `lint:fsd:layout` refused them — correctly, since
  a platform-pure module duplicated per app is exactly what §3.1 forbids. `ErrorToastProvider` now lives in
  `@cosimosi/errors/react` and each app's toast host wraps it, handing over the queue it already holds. The host stays
  forked because it renders the platform's `Toast`; nothing else needed to be.
- `apps/web/steiger.config.js` gains the vertical's `insignificant-slice` exemption, in the shape every other vertical
  already uses: two slices because they are two user moments, each with one host by design.
