# Job 137: Refetch identity cascade damping (refactor)

> Implementation work doc. Source spec: [code-review/12.frontend-rendering-performance-audit](../code-review/12.frontend-rendering-performance-audit.md).

The GetUniverse read path propagates **identity** changes with no seam asserting **content** equality, so the
cheapest event in the system (a no-op refetch: 30 s staleTime + window refocus) buys the most expensive work — a sim
worker respawn, a sky TSL shader recompile, and full instance-channel rebuilds (R003). The same
subscription-placement theme puts web hover state in the canvas host (R014). Built after job 136, before job 138
(whose extraction then carries these fixes once).

## Acceptance Criteria (from code-review/12 — R003, R014)

- [x] A1 **A content-identical GetUniverse refetch causes no downstream cascade.** When the response carries the
      same data, the entity stores keep their previous `byId`/`ids` references, the `universe` snapshot keeps its
      identity, the sim worker is not respawned, the sky material is not rebuilt, no instance attributes re-upload,
      the canvas host is not remounted, and graph/material/handler identities stay stable. One re-render of the
      query consumer itself is allowed — protobuf-es gives each refetch a fresh `query.data` Message identity, so
      the `useQuery` consumer renders once before the post-mapping bails hold. (R003.)
- [x] A2 **Genuine changes still propagate exactly as today.** A launch (optimistic-tail merge preserved), an edit,
      a decay step, an emotion change — each still updates stores/graph/sky; sim continuity across a real graph
      change (coordinate remap + seeding) is unchanged.
- [x] A3 **The sky material rebuilds on content, not identity.** `SkySphere` recompiles only when the effect key,
      emotion count, weight **values**, opacity, or headroom change — a stops array with identical numbers does not
      rebuild it; color-only changes keep taking the ramp-repaint path.
- [x] A4 **`bridge.start` with a sim-equivalent graph keeps the running worker.** Equivalence preserves the ordered
      node-slot identity and every force/placement input (including neuron connectivity, synapse strength,
      activations/weights, and seed/position hints); otherwise the graph takes today's remap+reseed path. This is
      defense in depth beneath A1's store-level bail, never a topology-only shortcut.
- [x] A5 **Hovering between stars re-renders only the glimpse surface, not the scene tree.** The hover id moves out
      of `UniverseCanvasHost`; hover UX is pixel-identical. (R014.)
      — The label became `ui/HoverGlimpse`, subscribing to `model/hovered-memory-store`; its markup and classes moved
      verbatim, so the pixels are identical by construction. What crosses the seam is the **instance index**, not the
      resolved id — which is what makes the layer's `onHover` a module-level function with no dependency on the id
      list, so the prop identity never moves either. Hover cannot be exercised from the headless probe (the widget is
      auth-gated), so this one rests on the code move plus `pnpm check`.
- [x] A6 **No behavior change / no regression.** All gates green; force-sim golden/parity tests untouched; a
      just-launched star remains immediately pickable.
      — `pnpm check` green (the force-sim golden/parity suites among them — the new equivalence check is a pure
      addition and touches no simulation code). The optimistic-tail merge is untouched: the bails compare what the
      merged collection contains, so a tail entry the server has not caught up to is a difference and still writes.
      One thing the gate caught rather than a reviewer: two new comments used the rendering word "star" in a `model/`
      segment and in pure force-sim code, which `lint:ubiquitous-language` rejects (§4 — rendering vocabulary stays on
      visual paths). Reworded to `EpisodicMemory` / "node".

### How the cascade is actually stopped

Three seams, outermost first, each one a full stop rather than a mitigation:

1. **The query** (`createGetUniverseQueryOptions`) carries a `structuralSharing` comparator built on protobuf-es
   `equals(GetUniverseResponseSchema, …)`. A content-identical response keeps the cached `Message` identity, so
   `useMemo([query.data])` never re-maps and the `universe` snapshot never moves. T002 offered this as the optional
   stronger form and a `useRef` snapshot compare as the primary; the comparator was taken as primary instead, because
   it is the same guarantee one layer earlier, with no ref written during render and no second copy of "are these the
   same facts". It also removes the one consumer re-render A1 was willing to allow the mapping to cost. (The consumer
   still renders on the `isFetching` toggle — that is Query's own flag, not the cascade.)
2. **The stores** (`sameStoredCollection`, shared by all three) keep their `byId`/`ids` references on an
   order-and-content match.
3. **The sim bridge** (`sameForceSimGraph`) keeps the running worker on an ordered, all-inputs match.

Two equality helpers were added rather than one, because they answer to different owners: `@cosimosi/memory` owns "are
these the same facts" for the domain mirrors it defines, and `@cosimosi/force-sim` owns "would this lay out the same"
for the graph it defines — and force-sim sits below memory, so it cannot borrow it. Both walk structurally rather than
comparing a hand-listed field set: a field added to a mirror or to `ForceSimGraph` and forgotten in a comparator would
report a real change as equal, which is a frozen universe with no failing test. A structural walk cannot forget.

      way.
