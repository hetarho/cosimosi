Finding: R001 (P2). **Scope note discovered while filling this job:** R001 found one unregistered
reason; a full diff of the backend reason set against `ERROR_REASONS` found **four**. All four are
genuinely emitted, so all four are in scope — R001 is the instance, the parity gate is the fix.

| Reason                            | Emitted at                  | Connect code      | In `ERROR_REASONS` | In policy §2 |
| --------------------------------- | --------------------------- | ----------------- | ------------------ | ------------ |
| `ADMIN_USER_SEARCH_TOO_BROAD`     | `admin/rpc/server.go:351`   | ResourceExhausted | ❌                 | ❌           |
| `ADMIN_MODEL_LISTING_UNAVAILABLE` | `admin/rpc/server.go:349`   | Unavailable       | ❌                 | ❌           |
| `ACCOUNT_MOOD_COLOR_INVALID`      | `account/rpc/server.go:250` | InvalidArgument   | ❌                 | ❌           |
| `TWINKLE_LEDGER_CURSOR_INVALID`   | `twinkle/rpc/server.go:173` | InvalidArgument   | ❌                 | ✅           |

**As built — the gate found more than the audit did.** Once `check-error-reasons.mjs` existed it reported **13
problems across 10 reasons** on the pre-change tree, not the 4 above. The extra six were all registered in
`ERROR_REASONS` but missing from the policy §2 table: `MEMORY_ENCODE_BODY_TOO_LONG`,
`MEMORY_DIARY_SEARCH_QUERY_TOO_SHORT`, `MEMORY_DIARY_MOOD_FILTER_INVALID`, `MEMORY_DIARY_DATE_RANGE_INVALID`,
`MEMORY_DIARY_SORT_INVALID`, `MEMORY_DIARY_COUNT_RANGE_INVALID` (all `memory` / InvalidArgument / fallback). All ten
are now registered on both sides and the gate is green at 81 emitted reasons.
The 13 problems are 10 reasons counted per side: three missing from **both** the FE registry and the
policy table (6), `TWINKLE_LEDGER_CURSOR_INVALID` missing from the FE registry only (1), and the six
`MEMORY_*` missing from the policy table only (6).

- [x] A1 A too-broad admin user search tells the operator what to do about it. The console no longer
      renders `m.error_resource_exhausted()` ("현재 한도에서는 이 작업을 마칠 수 없어요." / "That action
      cannot be completed with the current allowance.") for `ADMIN_USER_SEARCH_TOO_BROAD`; it renders
      copy that names the remedy (narrow/lengthen the search), and says nothing about an allowance or
      a limit — the search failed on `admin.search_scan_max_accounts`, which no amount of waiting
      changes.
- [x] A2 All four reasons above are members of `ERROR_REASONS` (as built: **ten** — see the note below), so `isReason()` can branch on them
      and a future surface can add recovery without first discovering the reason is unregistered.
- [x] A3 All four appear in `spec/policy/platform/errors.md` §2 (as built: **ten** rows touched) with their real Connect code and an
      honest FE column (`reason copy` for A1's, `fallback` for the rest) — the registry update that
      file's own rule already requires.
- [x] A4 A gate fails when a reason constant in any `internal/*/rpc/reasons.go` is absent from
      `ERROR_REASONS` **or** from the policy §2 table. It asserts _registry membership only_, never
      that a reason has bespoke copy — plan 59 §Non-goals deliberately allows unmapped reasons to fall
      back to the coarse code, and a gate demanding copy would fight that.
- [x] A5 The gate has a negative probe proving it bites: a reason constant planted in a fixture
      `reasons.go` with no registry entry makes the gate fail (`ARCHITECTURE.md` §4 _Gates fail loudly_ / _A gate's scope is part of the rule_ — a claimed executable
      rule needs a scanner _and_ a probe that proves an offender fails).
- [x] A6 No behavior change beyond the copy in A1: every other reason resolves to exactly the
      message, severity and `showId` it does today. The fallback reasons in A2 — three as scoped, **nine** as built — keep their coarse
      copy — registering them changes what code _can_ branch, not what the user currently reads.

- [x] T005 Write the parity gate, e.g. `scripts/check-error-reasons.mjs`:

  - Parse the emitted set from `apps/api/internal/*/rpc/reasons.go` — the string literal of each
    `reasonX = "..."` constant (6 files, 81 constants today).
  - Parse the FE set from the **`ERROR_REASONS` object literal** in `packages/errors/src/core.ts`,
    not from every uppercase string in the file. `fallbackReason`/`codeName` below it return bare
    code names (`NOT_FOUND`, `ABORTED`, …) that are _not_ registry entries; a naive
    all-string-literals scan silently treats them as members and hides real gaps.
  - Parse the policy set from the §2 table in `spec/policy/platform/errors.md` (cells hold
    comma-separated backticked reasons).
  - Fail on any emitted reason missing from either the FE set or the policy set. Report each
    missing reason with its owning file so the message is actionable.
  - Allow the platform-owned FE entries that no `reasons.go` emits (`INTERNAL`, `UNKNOWN`,
    `PLATFORM_*` — 5 today) via a named, commented allowance; do **not** make the check
    bidirectional-strict, or the `PLATFORM_<CONNECT_CODE>` family fails it.

- [x] T006 Wire it into the root gate: add `lint:error-reasons` to `package.json` and into the
      `lint` chain beside the other `check-*` scanners, so CI runs it via `pnpm check`.
- [x] T007 Add the negative probe (A5) and wire it into `test:guards` next to the other `*:probe` entries.
      **Deviation from the planned approach, deliberate:** built as an in-scanner `--probe` mode over in-memory
      fixtures rather than a `.probe-ws-*` workspace. The workspace machinery exists because ESLint resolves
      plugins and `extends` from the config file's own location, so its probes need real files in a real
      resolution chain. A text scanner has no such requirement, so running its pure functions over string
      fixtures writes nothing at all — strictly more hermetic, and the same shape
      `lint-public-copy.mjs`/`lint-raw-strings.mjs` already use.
- [x] T008 Extend `packages/errors/src/index.test.ts` with a case pinning A1 (the reason presents its
      own copy, not the coarse line) and a case pinning A6 for one untouched reason.
