- [x] A1 The grant form never silently submits a different number than displayed: `1.9`,

      idempotency key is minted; the input carries `step={1}` and the generated

      operator's input and shows the failure.
- [x] A3 Typing in the user search cannot fire one expensive request per keystroke: the query
      is debounced through a generated value (or an explicit submit boundary), and superseded
      requests are cancelled/ignored.
- [x] A4 Feature-local UI tests cover: decimals, exponent notation, over-cap, double-submit
      (new grant id per deliberate submit — existing semantics), server refusal (input
      preserved), success (fields cleared).
- [x] A5 Server behavior unchanged (`0 < amount <= admin_grant_max`, append-only recording).
