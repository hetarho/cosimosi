## Review

`/code-review` is not installed as a skill in this session (the repo ships `create-code-review`, which writes an audit
report, not the inline reviewer), and the codex CLI on this box is a Windows npm install reached through WSL whose module
resolution fails — so no codex review was obtained, and none is claimed. Two independent review subagents ran instead,
with different lenses. Both reproduced their findings by running code rather than reading it.

**Fixed (correctness):**

- **The commit ate what the reader typed.** The keyword commits trimmed, and the re-seed then wrote the trimmed value
  back over the draft: typing `coffee ` and pausing lost the space, and the next word arrived as `coffeebeans`. Worse on
  a composing IME, where the controlled value was replaced mid-syllable. The re-seed now runs only when the incoming
  value is not merely the trimmed draft (`shouldAdoptCommitted`), and the guard moved from a ref to state so an
  interrupted render cannot skip it permanently.
- **A mood chip erased a keyword still on its way into the URL.** Web writes conditions by navigating, which lands a
  tick later, so `{...value, moods}` built from a captured `value` was last-write-wins over the whole object — verified:
  `q=[] moods=[JOY]` where `q=[coffee]` was expected, with the field cleared too. Conditions now commit through an
  **update function** the host applies to its live state (`navigate({ search: (previous) => … })` on web, the `useState`
  updater on mobile).
- **Typing a date fired a refused read per keystroke on mobile**, replacing the whole archive with an error while the
  reader was mid-date. Half-typed dates and inverted ranges are now withheld at the draft, with the hint that was
  specced for exactly this and had been left unwired.
- **The highlighter marked the wrong characters.** It indexed a lowercased copy but sliced the original, and case folding
  is not length-preserving — `İstanbul` + `stan` marked `tanb`, and `aİbcİd` + `c` marked `İ`, a character absent from
  the query. It now matches on the body itself via an escaped case-insensitive pattern; six regression cases cover it.
- **A query covering the whole text rendered unmarked** — the one-segment shortcut did not check whether that segment
  was the match.
- **`?q=a` was a dead link.** The URL parser validated every field except the one the server enforces a minimum on, so
  a hand-shortened link showed only an error, permanently. `parseDiarySearch` now applies the same minimum.
- **A star's 원본 일기 deep link could silently do nothing** with conditions active: the shared diary read-model now
  holds only the filtered subset, and the deep-link effect paged a filtered archive until it ran out. It lifts the
  conditions first.
- **`SegmentedControl` was keyboard-unreachable** for a `value` outside its item set (every segment `tabIndex={-1}`, both
  arrows landing on item 0). The first segment is now the focus anchor, and `preventDefault` no longer swallows arrow
  keys on a disabled control.

**Fixed (spec compliance):**

- Mobile's mood line was a bare `View` carrying an `accessibilityLabel` with no `accessible`, so iOS never announced it
  and Android would have replaced the star count with it; the dots and `+N` were readable as unnamed elements. It is now
  one announced element carrying count _and_ feelings, with the swatches marked decorative — matching web's
  `aria-hidden` + `VisuallyHidden`.
- The paid door had the hint sentence but no stardust marker, and the destructive delete sat shoulder to shoulder with
  it. Both apps now show a stardust badge beside the control and put the delete on its own line behind a rule.
- Mobile pinned the conditions above a `flex: 1` list, leaving the archive a sliver of the phone; they moved into
  `ListHeaderComponent` so they scroll with the rows, as they do on web.
- `diary_search_range_invalid` was defined and unused (it is now the date hint); `useDebouncedValue` was an undeclared,
  untested export in `packages/ui` — it had one consumer and is inlined in the hook, so the design system carries no
  stray utility.
- English `{count} stars` had no plural form; the copy is now `Stars: {count}`.
- The ~34 lines of identical draft/debounce/commit logic in both apps' `SearchDiary` were promoted to
  `useDiaryConditions` in `@cosimosi/universe/react`, with the pure rules in `@cosimosi/memory` — the §3.5 rule R4

**Accepted, not fixed:**

- **A failed _next-page_ fetch still replaces the loaded archive with the error line.** TanStack Query marks the whole
  infinite query errored, and the early return predates this job — but infinite scroll turns it from "the reader pressed
  a button" into "the reader scrolled". Keeping the loaded pages and showing a retriable footer is a change to the
  shipped error contract on both platforms, so it belongs in its own change rather than smuggled in here.
- **`diaryPreview` cuts code points, not grapheme clusters**, so a cut at exactly the boundary can split a flag pair or
  drop a skin-tone modifier. `Intl.Segmenter` is the fix; the comment no longer overclaims.
- **A hand-typed `?q=123` loses the keyword** (the router's `JSON.parse` search parser yields a number). The app's own
  writes round-trip correctly, verified across 13 shapes.
- **Mobile's `onEndReached` can burn a content-length slot** when the guard swallows a call; RN resets the marker when
  the reader scrolls out of the threshold and back, so it is degraded rather than stuck.
- **Web has no jsdom test environment** and only `packages/ui` carries testing-library, with no network to add
  dependencies — so the observer effect, the scroll reset and the hook's React wiring are untested. The rules those
  behaviours turn on were extracted into pure functions and covered instead (35 tests in `@cosimosi/memory`, plus the
  `diary-search` suite).
