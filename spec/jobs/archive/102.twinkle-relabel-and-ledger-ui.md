## Review

- [x] Self-review of the staged diff + **codex (`gpt-5.5`, read-only)** — merged. Codex independently confirmed the
      first three, which self-review had already caught and fixed in the same pass. - **HIGH — mobile pagination was dead.** A `FlatList` with `scrollEnabled={false}` nested in `/me`'s own
      `ScrollView` never scrolls, so `onEndReached` never fires: any account past page one silently stopped. The
      job specified `onEndReached`, but a listener that cannot fire is not an implementation of it. **Deviation:**
      mobile paginates by an explicit `me_stardust_history_more` affordance. A nested scroller was the worse fix —
      it traps the gesture and hides the rest of the page. - **MEDIUM — the web observer could over-fetch.** The effect depended on the whole query result, which is a
      new object every render, so the `IntersectionObserver` was torn down and rebuilt continuously; a still-visible
      sentinel re-reports immediately on `observe()`, fetching without a new scroll crossing. Now depends on the
      stable `fetchNextPage` plus `canLoadMore`. - **MEDIUM — an unknown reason crashed the row.** The `Record` is total over the generated enum (a new member
      fails typecheck, as intended), but protobuf-es keeps an out-of-enum numeric value as-is, so a row written by a
      newer server evaluated `undefined()`. Now falls back to `me_stardust_reason_unknown`. - **Applied (codex #4, low/medium):** a failed `GetLedger` rendered the EMPTY state — telling the reader
      nothing had ever come or gone when the request merely broke, which is the one thing a ledger never says
      ([I1]). Split into its own `me_stardust_history_error` line on both apps. - **Applied (codex #5, low):** mobile's `Me` tab param was an initializer only and unvalidated. Navigating to an
      already-stacked `/me` merges params onto the mounted screen, so the earn guide's achievements link landed on
      whatever tab the reader last chose; and a deep link could index `tabViews` with anything. Now validated with
      the existing `isMeTab` and followed on change. - **Applied (self):** a day split across two fetched pages keys on the group rather than the bare date, so React
      cannot see two siblings with one key. - **Rejected:** none. Codex confirmed the day grouping merges correctly across page boundaries, the marker is
      structurally separate (no reason, no id, outside the day groups), payment removal is complete in executable
      code, and both catalogues carry identical key sets.

**Deviations from the job doc, and why:**

- **`onOpenMe(tab)` became a second intent, `onOpenAchievements`.** A page cannot name a tab without importing another
  page's tab type, which is a `pages`→`pages` cross-import FSD forbids. The app layer owns the router and therefore the
  tab ids; every layer below states an intent it can express without knowing a route. Same effect, legal placement.
- **Mobile pagination is an explicit affordance, not `onEndReached`** — see the HIGH finding above.
- **The refill marker carries no date, only an amount.** Its place is positional (always the head of the history), so it
  needs no "is the newest group today?" comparison — the one question the client cannot answer honestly, since it has no
  server-supplied notion of the user's today and reading the device clock is exactly the arithmetic [U7] forbids.
- **`apps/api/db/gen/models.go` is touched, which A15 nominally forbids.** It was stale from job 101 (that migration's
  column comment changed after the last `gen:sql`), so `pnpm check:gen` — a CI gate — was red. Leaving CI broken to
  preserve a scope line would have been the wrong trade. `apps/api/internal/platform/values/values_gen.go` and
  `packages/config/src/values.gen.ts` also move, but only because T003 explicitly retires `twinkle.charge_pack`.
- **Two i18n keys were added beyond the job's list:** `me_stardust_history_more` (the mobile pagination affordance) and
  `me_stardust_history_error` (the failed-read line). Both exist because of review findings above.
