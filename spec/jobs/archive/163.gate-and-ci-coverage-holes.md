## Acceptance Criteria (from code-review/15.full-codebase-runtime,-gate,-and-cross-p)

Findings: R005, R006, R007, R009, R010 — the report's "a guard was written, and then not run" theme.
Each of these has a rule written down and a scanner that exists; what is missing is the wiring that
makes an offender fail. Grouped as one job because they share that root cause and all land in
`scripts/`, `package.json` and `.github/workflows/`.

**As built.** Artifacts created: `scripts/check-test-reachability.mjs` (new, with its `--probe`), and the
installed-tree preflight, which landed **inside** `scripts/check-node-version.mjs` rather than as the separate
`check:install` sibling T010 offered — the runtime pin and the install freshness are one preflight, and it already ran
first in both `lint` and `check`. Package scripts added: `lint:test-reachability`, `lint:test-reachability:probe`,
`lint:observability:probe`.

- **T007 (`app/diagnostics/`) resolved without a props refactor.** The gate's own message says a screen belongs in
  `pages/<slice>/ui`, but `DiagnosticsScreen` reads `app/providers` (transport, session, base URL) and
  `app/navigation/routes` — from `pages` those are upward imports the boundary rules forbid. It is not product
  composition either: it reports locale/theme/session/transport and renders no product data, which its own deep-link
  suite asserts. That is the same bar `BootScreen` already meets, so it moved to
  `app/navigation/screens/DiagnosticsScreen.tsx` and joined `MOBILE_NAVIGATION_SCREEN_ALLOW` with that reason
  recorded. Both apps now show only documented segments.
- **`.github/workflows/ci.yml` needed no change.** CI runs `pnpm check`, so pointing `check` at `build:site` was
  enough to bring the staging assertions into CI. T002's `sharp` question turned out moot — `build:site` completes
  green with the postinstall still skipped.
- **T004 built as a naming rule rather than a runner query.** Both runners collect by filename and neither config
  overrides the pattern, so comparing names is exact and needs no app dependency loaded. Jest's `--listTests` would
  have been authoritative but slow, and this runs inside `test:guards`.
- **T009's probe is in-scanner, like job 159's.** The `.probe-ws-*` workspace exists because ESLint resolves plugins
  from its config's location; a text scanner needs no files, so the rule is driven over string fixtures.
- **The preflight was verified against the exact R010 condition** by removing
  `packages/ui/node_modules/@cosimosi/config` and confirming the failure names the package pair and says
  `run pnpm install`.

**A5's negative probe found a bug in its own fixture, worth recording:** the first version planted identical
`thing.ts` files across both apps' segments, which trips the pre-existing promote-on-reuse rule. Segment fixtures now
use per-app names, since that test is about the segment set alone.

- [x] A1 (R005) CI builds the site the way production does. `pnpm build:site` — the command
      `DEPLOY.md` §2 and `wrangler.jsonc` both name as the production build — runs in CI, so
      `scripts/stage-blog.mjs` and its two deliberate assertions execute there. A regression in the
      staging step, the blog output path, or the build **order** fails CI instead of failing at the
      Cloudflare Pages build (or shipping `/blog/**` missing, the "production 404 that nothing in the
      build output complains about" the script's own header describes).
- [x] A2 (R005) There is one build path, not two. `check`'s `build:web && build:blog` no longer
      disagrees in order with `build:site`'s `build:blog && build:web && stage-blog`, so the ordering
      the script exists to protect cannot be validated in an order production never uses.
- [x] A3 (R006) The mobile shared-client probe runs under `pnpm test:mobile` with real assertions.
      (As built the two exported `probeShared*` functions became two `it()` cases asserting the
      `mobile-import-probe` / `mobile-cache-probe` round trips, giving
      mobile the coverage web already has via `apps/web/src/app/providers/api-client.test.ts` — plus
      the client-cache half, which no web test covers.
- [x] A4 (R006) The class is closed, not just the instance: no file under `apps/*/src` can be a
      probe/test that its app's runner silently ignores. Either `.probe.*` is deliberately added to the
      mobile `testMatch`, or a guard asserts every such file is reachable by that app's runner. (Root
      cause: `apps/mobile/jest.config.js` sets no `testMatch`/`testRegex` and
      `@react-native/jest-preset` defines neither, so Jest's defaults apply and `.probe.ts` matches
      nothing.)
- [x] A5 (R007) The app-layer segment set is enforced against **directories**, not only files.
      `scripts/lint-fsd-layout.mjs` currently guards with `!entry.isDirectory() && CODE_EXT.test(...)`
      (`:158`), so an unknown _segment_ passes while a single loose file fails — even though the
      failure message already enumerates the closed set (`:160-162`) and the main block only `note()`s
      the segments it finds (`:231-235`). After this job, an unknown app-root directory fails, and
      `lint-fsd-layout.test.mjs` has a negative case proving it.
- [x] A6 (R007) `apps/mobile/src/app/diagnostics/` is resolved — moved into a documented segment (or a
      `pages` slice), or `ARCHITECTURE.md` §3.1 is amended to admit it explicitly. The gate and the
      doc agree either way; §3.1 must not keep claiming a closed set the tree violates.
- [x] A7 (R009) The observability boundary gate covers `apps/api/cmd` (the composition root, where a
      direct SDK import is most tempting and where §2.4's "sees everything" makes it look permitted)
      and `apps/blog/src` (a shipped build target with no telemetry today). Neither has a live
      violation now, so this is closing a latent hole, and the allowlist for both is empty.
- [x] A8 (R009) That gate has a negative probe, like every other guard in the gate: a forbidden import
      at a non-allowlisted path makes it fail. (**As built the fixture is in-memory, not a `.probe-ws-*`
      workspace** — see the As-built note; a text scanner needs no files on disk, so it writes none.) Its
      existing three-file liveness anchor (`check-observability-boundaries.mjs:49-70`) proves the
      detector works on real content but never proves the allowlist is not over-broad — that is the
      untested half.
- [x] A9 (R010) A stale install fails the preflight with an actionable message, not a misleading type
      error. `pnpm check` on a tree whose `node_modules` predates a `package.json` dependency change
      says "run `pnpm install`" rather than surfacing
      `TS2307: Cannot find module '@cosimosi/config'` from a package whose dependency is correctly
      declared and correctly locked. The check runs in the same first position as `check:node`, before
      any linter or compiler can produce the confusing error.
- [x] A10 No gate becomes slower than it needs to be, and none becomes flaky. A9 in particular must not
      add a network round trip to every `pnpm lint` — a lockfile/tree comparison is local.
- [x] A11 No behavior change to what the gates _accept_: every guard this job widens is green on the
      tree as it stands after A6, and the full `pnpm check` still passes.
