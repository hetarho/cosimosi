# Job 95: Locale reactivity and i18n seam convergence (refactor)

> Implementation work doc. Source spec: [code-review/09.epic-k-account-runtime-and-gate-audit](../code-review/09.epic-k-account-runtime-and-gate-audit.md).
> /cosimosi:implement-job 95 builds it via the two checklists below. When done, reflect the result into the
> SSOT (plan/policy/values) and set status: done. Write it in English.

Covers **R002** (P1) and **R012** (P3). R002 is a user-visible break in plan 64's shipped my-page language toggle:
the locale store updates and nothing re-renders.

## Acceptance Criteria (from code-review/09.epic-k-account-runtime-and-gate-audit)

- [ ] A1 A locale change after first paint re-renders the mounted UI on **web**: switching language in `/me` updates the
      page title, the tab labels, and every other mounted surface — not just the `AccountProfile` panel that owns the query.
- [ ] A2 The same holds on **mobile**: `MobileLocaleBootstrap` applying the profile locale re-renders the mounted product
      screens. Mobile currently has no app-level locale subscriber at all.
- [ ] A3 First load in a mismatched locale converges: a profile stored as `ko` opened in an `en` browser/device paints
      Korean once the profile query resolves, without a navigation or reload.
- [ ] A4 The covering tests assert **rendered copy**, not the store value. A test that renders a component calling `m.*()`
      fails if the subtree does not re-render — i.e. it would have caught R002. The existing assertion
      `expect(getActiveLocale()).toBe('ko')` alone is not sufficient and must not be the only check.
- [ ] A5 The optimistic locale switch in `AccountProfile` still rolls back correctly on a failed `UpdateProfile`: the UI
      returns to the previous language _and_ re-renders back into it.
- [ ] A6 The web app has **one** app-facing i18n entry point. `apps/web/src/shared/i18n/index.ts` is the only path
      product code imports; a direct `@cosimosi/i18n` import from `apps/web/src` fails the gate rather than review.
- [ ] A7 **No behavior change** beyond the fix: the negotiation precedence stays as documented (web: stored → navigator →
      default; mobile: device → default), `packages/i18n` stays platform-pure (no DOM/native deps), and no message key
      changes.

## Implementation Checklist

- [ ] T001 Write the failing test first (A4): render a component that calls `m.*()` under the provider, apply a locale
      change through `setActiveLocale`, and assert the rendered text changes. Confirm it fails against today's code —
      this pins the React bailout the audit argued but did not execute, so verify that step here before fixing.
- [ ] T002 Make the locale a real render input. Choose one and apply it to **both** apps identically:
      (a) have the provider subscribe and key its subtree on the locale so the referential-identity bailout cannot
      apply, or (b) put the locale in React context so consuming components re-render on change. (b) is the more honest
      model and makes T006 moot; (a) is the smaller change. Record the choice and why in `spec/tech/i18n.md`.
- [ ] T003 Fix web: [i18n-provider.tsx](../../apps/web/src/app/providers/i18n-provider.tsx) currently calls
      `useActiveLocale()` and then returns `<>{children}</>`, which re-runs the provider and skips the subtree.
- [ ] T004 Fix mobile: [i18n-provider.tsx](../../apps/mobile/src/app/providers/i18n-provider.tsx) has **no** subscriber.
      Also correct its now-stale comment — "Product screens render only after the boot gate — by then this effect has
      run" was true for device negotiation, but Epic K's profile-driven write lands after product screens have painted.
- [ ] T005 Replace the store-value assertion at
      [locale-bootstrap.test.tsx](../../apps/web/src/app/providers/locale-bootstrap.test.tsx) — it renders a literal
      `<span>product-child</span>` and passes whether or not anything re-renders. Add the mobile counterpart, which has
      no equivalent test today.
- [ ] T006 [P] Converge the web i18n import path (R012): migrate the 40 files under `apps/web/src` importing
      `@cosimosi/i18n` directly onto the `shared/i18n` barrel (which routes through `@cosimosi/i18n/react` and adds
      `moodLabel`). Leave `shared/i18n/index.ts` and `shared/lib/locale-storage.ts` on the direct import — they _are_
      the seam.
- [ ] T007 Add the executable guard for A6: a restricted-import rule in the web app's lint config forbidding
      `@cosimosi/i18n` outside `src/shared/i18n/` and `src/shared/lib/locale-storage.ts`. Confirm it fails on a
      deliberate violation before trusting it.
- [ ] T008 Verify the whole path end-to-end by hand, not just by unit test: sign in with a `ko` profile in an `en`
      browser and confirm first paint converges (A3); switch language in `/me` and confirm the header and tab labels
      follow (A1). Repeat on mobile (A2) — mobile has no automated coverage of this path.
