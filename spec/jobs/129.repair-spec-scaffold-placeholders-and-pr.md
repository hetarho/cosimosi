# Job 129: Repair spec scaffold placeholders and probe scaffold output (refactor)

> Implementation work doc. Source spec: [code-review/11.jobs-116-128-demo,-sequence,-landing-and](../code-review/11.jobs-116-128-demo,-sequence,-landing-and.md).
> /cosimosi:implement-job 129 builds it via the two checklists below. When done, reflect the result into the
> SSOT (plan/policy/values) and set status: done. Write it in English.

Covers **R002 (P1)**. Build this **first**: it is the cheapest job in the set, and until it lands every
`pnpm spec:code-review` and `pnpm spec:change` keeps emitting documents whose frontmatter is garbage.

**The trap to understand before editing.** The naive fix — writing `title: {{TITLE}}` back into the
template — makes `pnpm format:check` **fail**, and `format:check` is the second step of `pnpm lint`.
Prettier's YAML pass is what corrupted these placeholders in the first place: unquoted `{{TITLE}}` in a
frontmatter block parses as a nested flow mapping, so Prettier normalizes it to `{ { TITLE } }`. The fix
is therefore to **quote** them, which review 11 verified passes `prettier --check` under the repo's
pinned 3.9.4 _and_ still substitutes through `fill()`. `review: '{{NN}}'` in the same file is the
existing precedent, and `scripts/templates/job.md` (9 quoted placeholders, all intact) is the proof the
pattern holds.

## Acceptance Criteria (from code-review/11)

- [ ] A1 `scripts/templates/code-review.md` and `scripts/templates/change.md` contain no `{ { … } }`
      sequence; every frontmatter placeholder is single-quoted (`title: '{{TITLE}}'`,
      `created: '{{DATE}}'`, `plan: '{{PLAN}}'`), matching `review: '{{NN}}'`'s existing form.
- [ ] A2 `pnpm format:check` passes with the corrected templates — i.e. the correct form is now the
      Prettier-stable form, so `pnpm format` cannot reintroduce the corruption.
- [ ] A3 A freshly scaffolded doc of **each** of the four kinds (`plan`, `change`, `code-review`,
      `job`) contains no `{{` and no `{ {` anywhere in its output, and its `title`/`created`/`plan`
      frontmatter holds real values.
- [ ] A4 A guard fails the gate when a template regains an unquoted frontmatter placeholder — proven by
      a probe, not by inspection. Running the probe against a deliberately corrupted template must
      report the failure; against the repo's templates it must pass.
- [ ] A5 No behavior change to the scaffold scripts' numbering, slugging, file placement or console
      output — only placeholder substitution is affected. Existing docs under `spec/**` are untouched.

## Implementation Checklist

- [ ] T001 Quote the four corrupted placeholders: `scripts/templates/code-review.md:4-5`
      (`title:`, `created:`) and `scripts/templates/change.md:3,5` (`plan:`, `title:`). Change only the
      quoting — do not reword or reorder the frontmatter keys.
- [ ] T002 [P] Audit `scripts/templates/plan.md` and `scripts/templates/job.md` for the same hazard and
      quote any **unquoted** frontmatter placeholder found, even though both currently scaffold
      correctly. This is what stops the defect recurring in the two files that happen to be fine today.
- [ ] T003 Run `npx prettier --check scripts/templates/*.md` and confirm it passes. If Prettier still
      rewrites a placeholder, the quoting is wrong — fix the template, never add a `.prettierignore`
      entry (an ignored template is a template no gate formats, which trades one silent drift for
      another).
- [ ] T004 Add a scaffold-output probe to `scripts/check-spec-hygiene.mjs` (its `section(...)`/
      `problems[]`/`ok()`/`fail()` shape is already the right harness). For each of the four kinds it
      must scaffold into a **temp directory**, assert the output contains neither `{{` nor `{ {`, and
      assert the frontmatter `title`/`created` (and `plan` for `change`) are non-empty and not literal
      placeholder text. Remove the temp files whether or not it passes — follow
      `scripts/probe-demo-isolation.mjs`'s `try/finally` cleanup shape, which review 11 cites as the
      house pattern.
- [ ] T005 Make the probe self-verifying the way the other guards are: prove it fails on a corrupted
      template (an in-probe fixture with `title: { { TITLE } }`), so this is a rule someone has seen
      fail rather than a rule nobody knows is wired. Follow `--probe` flag precedent
      (`lint:raw-strings:probe`, `lint:comments:probe`) if a separate entry point reads better than an
      inline fixture.
- [ ] T006 Do **not** rewrite the frontmatter of already-created docs (this review 11 report and jobs
      129–135 were hand-corrected at authoring time). Confirm with a grep that no doc under
      `spec/**` still carries a spaced-brace placeholder — if one does, fix that doc's frontmatter by hand in this job and
      note it in the SSOT step.
- [ ] T007 Run the full gate: `pnpm lint` (which now includes the widened `lint:spec`) and
      `pnpm test:guards` if the probe lands in that family.
