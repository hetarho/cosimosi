## Acceptance Criteria (from plan/63.signup-flow-ui)

<!-- The source spec's acceptance criteria. After building, verify each is true in the running code. -->

- [ ] A1 A **sign-up surface** exists on both apps — a public `/signup` route on web and a `SignUp` screen in the mobile login stack — offering **both** methods: Google and email+password, with reciprocal navigation to and from the sign-in surface ([U5][U6]).
- [ ] A2 `packages/auth` exposes `signUpWithPassword` on the adapter and the facade, returning `'signedIn' | 'confirmationRequired'`; the Supabase and fake adapters both implement it, and the **session machine's status set and `gateDecision`'s arms are unchanged** (change 02).
- [ ] A3 A Supabase sign-up that returns no session leaves the surface in a `confirmationSent` state and the session settled `signedOut` — never `failed`, never stuck in `signingIn`; clicking the confirmation link later lands the user in the nickname step with no wizard state to restore ([U5][U6]).
- [ ] A4 An **app-layer profile gate** on both apps reads `GetProfile`† and renders exactly one of: routed children (profile present), the nickname step (profile absent), or a neutral retry-or-sign-out state (read refused). It sits above the palette bootstrap, so **no product route and no product read mounts for a profile-less session** ([U1][I11]).
- [ ] A5 Absence of a profile is an **unset message field**, not an error reason: the gate performs no error-reason sniffing, and the "refused" arm is reached only by a genuine transport/authorization failure ([U1]).
- [ ] A6 The nickname step asks for **exactly one field** and submits `SignUp` with the nickname, the **auto-detected** timezone, and the negotiated locale — the timezone is never presented as a question and no other field exists on the surface ([U6][U7]).
- [ ] A7 Nickname validation is trimmed, non-empty, and bounded by `VALUES.account.nicknameMinLength` / `nicknameMaxLength` counted in **Unicode code points**; there is **no** nickname availability check, lookup RPC, or uniqueness claim, and the server's refusal is rendered as authoritative ([U6]).
- [ ] A8 `SignUpRequest` carries **no `user_id`** and **no provider field** — the scope and the `AuthProvider` are derived from the authenticated token — and it has **no field** for any memory, palette, ornament, or amount ([I11][U1]).
- [ ] A9 Arriving at `<origin>/invite/<token>` (web) or `cosimosi://invite/<token>` (mobile) captures the token, **replaces** the URL/route so the token leaves the address bar and history, and shows the sign-up surface; **no code-entry field exists anywhere in the app** ([U8]).
- [ ] A10 The captured token survives the Google OAuth round trip on both apps and is sent with `SignUp`; it is cleared when `SignUp` consumes it and when the gate resolves _profile present_; it is deliberately **not** in the user-scope reset registry, and that exception is documented at the seam ([U8], [tech/auth.md](../tech/auth.md)).
- [ ] A11 The invite acknowledgment names **no inviter and no reward amount**, and an expired / self-referential / withdrawn-inviter token is **inert**: `SignUp` still succeeds and the user still reaches their universe — there is no invite-failure branch ([U8][G6]).
- [ ] A12 On `SignUp` success a **one-shot completion signal** is recorded and readable exactly once, and it is cleared by the user-scope reset seam registered in both apps' `reset-user-state.ts` inventories ([O3], [tech/auth.md](../tech/auth.md)).
- [ ] A13 The credential step's control state is one XState machine (`form → creating → confirmationSent | failed`) and the nickname submit reuses the shipped `asyncCommandMachine`; the profile is Query data and machine context holds control metadata only (§3.2).
- [ ] A14 A first-run user who completes signup lands on the **empty universe with the gray latent field** and the single 일기 쓰기 affordance — [53.auth-universe-gate](../plan/53.auth-universe-gate.md)'s first-run welcome is reused, not reimplemented, and nothing is seeded ([U2][V7]).
- [ ] A15 **All** user-visible copy resolves through the i18n seam in both `en.json` and `ko.json` under `signup_*` / `invite_*` (`pnpm lint:raw-strings` and `pnpm check:gen` pass), in a literary, restrained voice with no reward figure and no [I12]-violating claim on the public surfaces.
- [ ] A16 **web + mobile parity** ([00.overview](../plan/00.overview.md) §4): the same surfaces, the same gate, the same shared modules from `packages/auth` and `packages/api-client`; `features/sign-up` carries no `model`/`api` segment, and `pnpm lint:fsd:layout`, `pnpm lint`, `pnpm typecheck`, `pnpm test:web`, `pnpm typecheck:mobile`, and `pnpm build:web` pass with **no BE change** (no proto, migration, or query authored here).

## Grounding

- Constitution ([I1]–[I13]): [00.overview](../plan/00.overview.md) §3 (_The constitution_), incl. the v2 risk

    therefore no product read can mount for a profile-less session (00.overview §3, the Epic K [U1] row). A gate,
    not a check each page repeats.
  - **[I2]/[I11] the meaning layer** — `SignUpRequest` carries a nickname, a timezone and a locale and **has no
    field** for anything else: no memory, no palette, no ornament, no amount. Unrepresentable rather than reviewed.
  - **[I1] nothing is deleted** — sign-out and an abandoned sign-up destroy nothing; an abandoned Supabase
    credential simply has no profile, and the gate shows the nickname step again on the next sign-in.
  - **[I12] public copy honesty** — `/signup` and `/invite/*` are public: no therapeutic claim, no "뇌처럼
    작동한다", and **no promised reward amount**.
  - **[U2] the first universe is empty** — this job seeds nothing on the way in, and job 64's first-run welcome is
    reused verbatim.
- Architecture (placement): [ARCHITECTURE.md](../ARCHITECTURE.md) **§3.1** (layers and segments — the router/nav
  library stays in `app/routes` / `app/navigation`; the nickname step is a `features/sign-up` component and the
  gate rendering it is an `app/providers` module, since `app` is **segmented, never flat** — `lint:fsd:layout` R1),
  **§3.2** (control state in XState, data in Query/Zustand; reuse the shipped `asyncCommandMachine` rather than a
  second copy of the same lifecycle), **§3.5** (web↔mobile parity — `model`/`api` and all of `packages/` shared
  verbatim, `ui` per platform; a byte-identical pure module in both apps fails R4, which is **why** every shared
  piece lands in `packages/auth` or `packages/api-client`), **§2.7** (`GetProfile†` is classified exactly once in
  `packages/client-cache/src/http-policy.ts` — **by job 89**, and a duplicate entry hard-fails the transport, so do
  not add one here). Invoke `/fe-architecture` **and** `/mobile-architecture` for every file placed. **No BE
  surface.**
