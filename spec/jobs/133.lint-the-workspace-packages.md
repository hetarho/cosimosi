# Job 133: Lint the workspace packages (refactor)

> Implementation work doc. Source spec: [code-review/11.jobs-116-128-demo,-sequence,-landing-and](../code-review/11.jobs-116-128-demo,-sequence,-landing-and.md).
> /cosimosi:implement-job 133 builds it via the two checklists below. When done, reflect the result into the
> SSOT (plan/policy/values) and set status: done. Write it in English.

Covers **R004 (P2)** — the largest gate hole in the repo.

**The gap.** No `package.json` under `packages/` declares a `lint` script (all 23 checked), and no
ESLint or oxlint config exists anywhere under `packages/`. The root `pnpm lint` reaches packages only
through the bespoke Node scanners (`lint:language`, `lint:raw-strings`, `lint:comments`,
`lint:style-escapes`, `lint:fsd:layout`); the two real JS/TS linters are `lint:web`
(`oxlint --deny-warnings`, cwd `apps/web`) and `lint:mobile` (`eslint .`, cwd `apps/mobile`), and
neither can see `packages/`. So the cross-app core — the highest-leverage code in the repo — is the
least checked code in the repo.

This batch alone added `packages/sequence/src/react.ts`: four `useEffect`s, a `setTimeout` lifecycle, a
promise whose result is written to state after an `await`, and a nine-entry `useMemo` dependency array
— none of it checked by `react-hooks/exhaustive-deps`, `no-floating-promises` or `no-unused-vars`.

Build this **after job 132**, so the ratchet baseline is measured on a tree whose manifests are already
correct.

**Owner decision to settle before building** (review 11, _Questions / Tradeoffs_): a first run over 23
packages will almost certainly report a backlog. Land the gate at the **current warning count and
ratchet down**, rather than blocking this job on a clean sweep. That temporarily sits awkwardly beside
§4's "gates fail loudly", so it is an explicit, time-boxed exception — record the starting count and
the target in the SSOT step so the ratchet is visible rather than forgotten.

## Acceptance Criteria (from code-review/11)

- [ ] A1 A JS/TS linter runs over `packages/**/*.{ts,tsx}` as part of the root `pnpm lint`, and
      therefore inside `pnpm check` and CI (CI delegates to `pnpm check`, so no workflow edit is
      needed — confirm that rather than editing `.github/workflows/ci.yml`).
- [ ] A2 The rule set includes, at minimum, `typescript-eslint` recommended plus **`react-hooks`** —
      the plugin the React seams actually need. `exhaustive-deps` must be **on**, since it is the rule
      whose absence review 11 names as the concrete risk.
- [ ] A3 The gate is proven to bite: a deliberate violation in a `packages/*` file (a missing hook
      dependency, an unused import) fails `pnpm lint`. A rule nobody has seen fail is a rule nobody
      knows is wired — the repo's own standard, per `probe-demo-isolation.mjs`'s framing.
- [ ] A4 The gate is green at its configured threshold, with the **starting warning count recorded**
      in the job's completion note and in the config as a comment. If the count is not 0, the config
      says so explicitly and names the target.
- [ ] A5 Any violation actually fixed in this job is a **behavior-preserving** fix. Where a real bug is
      found, do not fix it inline — record it and raise it as its own finding/job, so a lint-wiring
      job does not smuggle in a semantic change.
- [ ] A6 The existing `apps/web` and `apps/mobile` lint setups are unchanged, and no package gains a
      per-package `lint` script that would duplicate the root pass.

## Implementation Checklist

- [ ] T001 Survey first: run a throwaway ESLint over `packages/**` with the intended rule set and
      **record the violation count per rule and per package** before configuring anything. That number
      is what A4's threshold and the ratchet plan are built from, and it decides whether "land at 0" is
      actually reachable in this job.
- [ ] T002 Add one shared flat config at the repo root covering `packages/**/*.{ts,tsx}`. Model it on
      `apps/web/eslint.config.js`'s structure (flat config, `defineConfig`, scoped `files` blocks) —
      and carry over its hard-won lesson, documented at `apps/web/eslint.config.js:119-121`: **ESLint
      flat config replaces rule options per matching file rather than merging them**, so any scoped
      block must restate the shared rules or silently lose them.
- [ ] T003 Add `react-hooks` for the packages that have React seams, scoped to the files that are
      actually React: `packages/sequence/src/react.ts`, `packages/achievement/src/react/**`,
      `packages/*/src/react.ts` and `packages/ui/**`. The package roots are deliberately React-free by
      design (`packages/sequence/src/index.ts:19-21`), so a blanket React config would misreport them.
- [ ] T004 Wire a root `lint:packages` script into `package.json` and add it to the `lint` chain,
      placed beside `lint:web` / `lint:mobile` so the three JS/TS linters read as one group.
- [ ] T005 Exclude generated output explicitly: `packages/config/src/values.gen.ts`,
      `packages/api-client/src/gen/**`, `packages/i18n/src/gen/**`, `packages/ui/src/theme.gen.css`.
      Generated files are owned by their generators (`.prettierignore` already states this principle);
      linting them produces noise nobody can act on.
- [ ] T006 Fix what is safely fixable — unused imports, unused locals, trivially missing hook
      dependencies where the dependency is genuinely stable. For each `exhaustive-deps` warning, decide
      deliberately: add the dependency, or add a narrowly-scoped disable **with a comment saying why**
      (several seams intentionally omit a dep — `packages/sequence/src/react.ts:151-153` already
      documents one such choice in prose, and that reasoning should become the disable's comment).
- [ ] T007 Anything that looks like a **real bug** goes in the completion note as a proposed finding,
      not into this diff (A5).
- [ ] T008 Add the bite-proof for A3: either a `--probe` entry point in the existing
      `test:guards` family (following `lint:raw-strings:probe` / `lint:comments:probe` precedent) or a
      documented manual verification recorded in the completion note. Prefer the probe — it is the
      house pattern and it survives the next config refactor.
- [ ] T009 Confirm CI needs no edit: `.github/workflows/ci.yml` runs `pnpm check`, which runs
      `pnpm lint`. State this explicitly rather than assuming it.
