## Acceptance Criteria (from changes/05.per-memory-source-text-at-encode-time)

<!-- The source spec's acceptance criteria. After building, verify each is true in the running code. -->

- [ ] A1 `SplitDiary` / `ReviseSplit` return a **`source_text` per proposed memory** — the diary passage that memory was encoded from — and the writing-flow UI renders it on the proposal card and lets the user edit it within the write session, on **both web and mobile** ([W2][W4]).
- [ ] A2 Launching a diary that splits into N memories produces **N distinct `current_text` values**, each the confirmed passage for that memory, and **not** the whole diary body. ([E1][E2])
- [ ] A3 The passages are **the writer's own words**: a source text whose tokens are not traceable to the diary — beyond inflectional variation and a typo budget of `encode.source_text_max_corrected_ratio` within `encode.source_text_typo_max_edit_distance` — is rejected and re-prompted through the existing repair loop, and exhausts to `ErrEncodeRetryExhausted` (→ `CodeResourceExhausted`) rather than being persisted. A paraphrase, a synonym substitution, or an invented sentence never reaches the database.
- [ ] A4 The passages **cover the diary**: their union accounts for at least `encode.source_text_min_coverage` of the diary's tokens, and a split that drops a scene is a repair condition. The writer's whole entry survives across the N memories.
- [ ] A5 `PersistEncoded` re-validates each confirmed source text **structurally** — present, non-blank, length-bounded against the submitted body — and deliberately does **not** re-apply criteria A3–A4, because a passage reaching it may be the writer's own edit. The existing re-validation of count / mood / neuron type / semantic-neuron floor is unchanged.
- [ ] A6 The four downstream surfaces are per-memory: star detail shows that memory's (decayed) passage, `DecayStages` erase words from that passage, the four gist stages compress that passage, and 변천사의 created/original baseline is that passage. Two stars from one diary no longer show identical text at any of them. ([R1][D1][F1][C7][R8a])
- [ ] A7 The **[W4a] boundary is intact** — the encode schema and the wire carry no position, color, strength, seed, time, or delete field, and the new text field is structurally constrained to the diary's own words, so a prompt injection can at most echo the writer back at themselves.
- [ ] A8 **[I2] holds** — the `Diary` row is byte-identical to what the user submitted; export ([W6]) and search ([D10]) still read the original, and no code path writes to it.
- [ ] A9 **No regression on existing data** — memories launched before this change keep their `current_text`, decay stages, gist stages, and provenance unchanged; recall, reconsolidation, forgetting, consolidation, and the universe read behave exactly as before for them.
- [ ] A10 SSOT is consistent: the PRD defines `CurrentText`'s initial value, and plan 20, `policy/encode-boundary.md`, `policy/ux/writing-flow.md`, and `tech/memory-encode.md` all describe the per-memory passage. `pnpm lint`, `pnpm test`, `pnpm vet:api`, `pnpm build:api`, `pnpm typecheck`, `pnpm build:web`, and `pnpm check:gen` pass.

- [ ] T001 (gen:values) `spec/values.yaml` `encode.*` — add `source_text_min_coverage`,
      `source_text_max_corrected_ratio`, `source_text_typo_max_edit_distance` (each with the comment convention the

      `ai.per_call_token_cap` together** — the split output now carries the diary redistributed across the memories,

- [ ] T002 Domain check (BE `internal/memory`, pure — new `sourcetext.go` + `sourcetext_test.go`): the token-level
      fidelity + coverage verification the extractor output must pass (A3, A4). Tokenize the body and a passage; a
      passage token is accepted verbatim, as an inflectional variant of a body token (shared stem, differing
      ending/particle), or as a typo correction within `values.EncodeSourceTextTypoMaxEditDistance` of a body token —
      corrections bounded by `values.EncodeSourceTextMaxCorrectedRatio` of the passage's tokens. Separately, the union
