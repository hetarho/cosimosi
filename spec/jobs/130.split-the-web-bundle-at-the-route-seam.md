# Job 130: Split the web bundle at the route seam (refactor)

> Implementation work doc. Source spec: [code-review/11.jobs-116-128-demo,-sequence,-landing-and](../code-review/11.jobs-116-128-demo,-sequence,-landing-and.md).
> /cosimosi:implement-job 130 builds it via the two checklists below. When done, reflect the result into the
> SSOT (plan/policy/values) and set status: done. Write it in English.

Covers **R001 (P1)**. The measured baseline from a real `pnpm build:web`:
`apps/web/dist/assets/index-*.js` is **3.1 MB raw / ~920 KB gzipped**, one of only two emitted JS files.
Job 120 made the landing page the public origin root, so that is what every cold visitor and every
crawler downloads before the hero paints — including the admin console, the whole demo sandbox and its
three fixture sets, and the entire signed-in universe.

**Owner decision to settle before building** (review 11, _Questions / Tradeoffs_): the landing page
genuinely needs part of `@cosimosi/3d-renderer` for `LandingHeroScene`/`LandingWalkthroughScene`, so
"lazy-load three.js" is not on the table. This job takes the **conservative split** — the boundary is
"the signed-in product + admin + demo", leaving the renderer, landing, login and blog-not-found in the
entry chunk. A reduced renderer entry for the landing's two scenes is a larger change and deliberately
**not** in scope; if the entry chunk is still unacceptable afterwards, that is a follow-up job with its
own measurement, not scope creep here.

## Acceptance Criteria (from code-review/11)

- [ ] A1 `AdminPage`, `DemoPage`, and every auth-gated page (`UniverseHomePage`, `DiaryReaderPage`,
      `MePage`) load through a dynamic import rather than a static one, so none of them appears in the
      entry chunk.
- [ ] A2 The entry chunk that a first visit to `/landing` downloads is **materially smaller** than the
      3.1 MB / ~920 KB gzipped baseline, measured the same way (a real `pnpm build:web`, `du -h` plus
      `gzip -c | wc -c` on the emitted entry chunk). Record both before and after numbers in the job's
      completion note — an unmeasured split is not a verified one.
- [ ] A3 `build.chunkSizeWarningLimit` is set **down** to just above the new entry chunk's size, so a
      regression warns immediately instead of hiding under the stock 500 kB default that this batch
      already exceeded sixfold.
- [ ] A4 **No behavior change.** Every route still resolves to the same screen, the `/` auth guard
      still runs in `beforeLoad` before any product route mounts, `/test` stays gated on
      `diagnosticsEnabled`, and `/blog/$` still has no `beforeLoad` of any kind.
- [ ] A5 A route that is still loading shows a deliberate pending state rather than a blank frame or a
      layout jump — chosen once at the router level, not per route.
- [ ] A6 `apps/web` tests pass, including `App.test.tsx`'s route-render cases, which currently assert
      synchronously against routes that will now resolve asynchronously.

## Implementation Checklist

- [ ] T001 Re-measure and record the **baseline** before touching anything: `pnpm build:web`, then the
      raw and gzipped size of `apps/web/dist/assets/index-*.js` and the total count of emitted JS
      files. A1–A3 are all relative to this number.
- [ ] T002 Convert the split-eligible screens in `apps/web/src/app/routes/route-screens.tsx` to
      dynamic imports. Use TanStack Router's own `lazyRouteComponent` (exported from
      `@tanstack/react-router`, confirmed present in the pinned 1.170.16) rather than bare
      `React.lazy` — the route tree is hand-built, and `lazyRouteComponent` is the API that integrates
      with the router's own pending and preload lifecycle. Convert `AdminRoute` (`:19`), `DemoRoute`
      (`:20`), `UniverseRoute`, `DiaryReaderRoute` and `MeRoute`.
- [ ] T003 [P] Leave `LandingRoute`, `LoginRoute`, `SignupRoute`, `InviteRoute` and `BlogNotFoundRoute`
      **static**. They are the public entry surface — lazy-loading the very page the visitor asked for
      adds a round trip to the path this job exists to speed up.
- [ ] T004 Keep `AuthenticatedLayout` and the guard static. The guard must keep running in
      `beforeLoad` before any product route mounts (`route-tree.tsx`, the pathless authenticated
      subtree); moving it behind a dynamic import would let an unauthenticated frame render first,
      which is a correctness regression, not a perf trade.
- [ ] T005 Set the router's `defaultPendingComponent` once in
      `apps/web/src/app/routes/router.ts`'s `createRouter({...})` call, beside the existing
      `trailingSlash` and `context` options — one pending state for the whole app rather than a
      `Suspense` boundary hand-placed per route (A5).
- [ ] T006 Add `build.chunkSizeWarningLimit` to `apps/web/vite.config.ts` (the config has no `build`
      block today — add one), set just above the measured post-split entry chunk. Comment it with the
      measured number and the date, so the next author knows what it was calibrated against and does
      not raise it reflexively when it fires.
- [ ] T007 Fix `apps/web/src/app/App.test.tsx`'s route assertions for the now-async routes. It already
      uses `initialEntries` plus `vi.waitFor` in several cases (`:208`, `:297`), so extend that
      pattern — prefer `findBy*` / `waitFor` over adding arbitrary timeouts. The cases at `:212`
      (`/`), `:244` (`/diary`), `:286` and `:302` (`/me`) and `:109` (`/test`) are the ones that touch
      converted routes; `:259` (`/landing`) should still resolve synchronously and is a useful control.
- [ ] T008 Verify the split landed: `pnpm build:web` must now emit **more than two** JS files, and the
      entry chunk must be measurably smaller. Confirm the admin, demo and universe chunks are separate
      files, not merely reordered inside the entry.
- [ ] T009 Sanity-check the routes by hand or via the existing test harness: `/landing`, `/demo`,
      `/login`, `/blog/anything`, and one auth-gated route each for signed-out (redirects) and
      signed-in (renders).
