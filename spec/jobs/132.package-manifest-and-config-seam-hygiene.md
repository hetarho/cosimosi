Covers **R005**, **R006** and **R007** — three small placement corrections that share one theme: the
batch established where a thing belongs and then put a sibling somewhere else, leaving the next author
two contradictory precedents to copy.

## Acceptance Criteria (from code-review/11)

- [ ] A1 (R005) `packages/demo/package.json` declares `@cosimosi/i18n` in `dependencies` — production
      source imports it (`src/diary-set.ts:2`, `src/resolve.ts:10`) — and `@cosimosi/config` in
      `devDependencies`, since only `src/integrity.test.ts:3` uses it. The manifest matches the
      import graph in both directions.
- [ ] A2 (R005) `packages/demo` carries a manifest assertion of its own dependency closure, the way
      `packages/onboarding/src/anchors.test.ts:88-93` does. `packages/demo` is the package whose
      dependency list carries the `[I13]` isolation argument and it is currently the one without the
      test that pins it.
- [ ] A3 (R006) `packages/onboarding` no longer declares a `react` peerDependency or the `react` /
      `@types/react` devDependencies — no file under `packages/onboarding/src/` imports React and the
      package has no `./react` export. The assertion at `anchors.test.ts:93` is updated to match
      reality rather than pinning the stale entry.
- [ ] A4 (R007) `WALKTHROUGH_FADE_SPAN_DAYS` and `WALKTHROUGH_MIRROR_RECALLS` come from a `landing:`
      group in `spec/values.yaml` through `pnpm gen:values`, read as `VALUES.landing.*`. Both are
      product-shaping scalars tuned against other generated values, which is
      [tech/config-values.md](../tech/config-values.md) §1's definition — and the same batch already
      put the demo's direct analogues (`demo.time_travel_month_days`) in `values.yaml`.
- [ ] A5 (R007) `WALKTHROUGH_EPOCH` stays in code. A fixed authored date is content, not tuning.
      Likewise the visual constants nearby (`RING_PADDING_PX`, `CAPTION_BAND_HEIGHT_PX`,
      `ATTACH_GAP_PX`, `AWAKEN_DURATION_S`) are correctly code per §4's visual-language carve-out and
      must **not** be moved — review 11 excluded them from the finding on purpose.
- [ ] A6 **No behavior change anywhere.** The generated `VALUES.landing.*` values equal the current
      literals (150 and 5) exactly, so the walkthrough renders identically. The two manifest changes
      are type-only imports and an unused peer, so nothing resolves differently at runtime.
