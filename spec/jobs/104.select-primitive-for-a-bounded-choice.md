## Acceptance Criteria (from changes/06.select-primitive-for-a-bounded-choice)

<!-- The source spec's acceptance criteria. After building, verify each is true in the running code. -->

- [ ] A1 `Select` exists at `packages/ui/src/primitives/select.tsx` + `select.native.tsx`, both honoring one API (`items` · `value` · `onValueChange` · `FieldOwnProps` · `ariaLabel` · `disabled`), exported from the web and native barrels.
- [ ] A2 The primitive owns the field contract: web associates its `label` with the control and wires `aria-describedby` (description) and `aria-invalid` (error); native exposes the same name, value and invalid state through accessibility props. A `Select` with no visible `label` is named by `ariaLabel`.
- [ ] A3 The web sibling renders a real `<select>` element — keyboard interaction and the platform menu are inherited, not re-implemented — and takes its material from the design system, not from a class string in a slice.
- [ ] A4 The native sibling is a field-shaped Pressable that opens a modal option list: the current value is marked selected, picking reports it and closes, dismissing leaves the value unchanged.
- [ ] A5 Every existing call site consumes it — `features/revise-split` (web + mobile) and `features/admin-ai-config` (both selects) — and no select class string remains in `apps/web/src` (grep-clean, with `lint:style-escapes` still green).
- [ ] A6 **No regression of [W4a][I3]:** both `ReviseControls` tests still prove the emotion surface offers exactly the `MOODS` set and no scalar / date / colour control, re-asserted against the new control set.
- [ ] A7 `/design` and the native design showcase each render `Select` in default · disabled · error states (plus focus on web), so both review surfaces can score it.
- [ ] A8 `tech/design-system.md` §4 lists Select under **Shipped**; `tech/design-language.md` §6 documents the picker (web element + native modal list) as the language's bounded-choice control.
- [ ] A9 A §8 re-review round scores the dimensions this touches (component consistency · web↔mobile parity) with every note closed, recorded in the job's ledger.
- [ ] A10 Gates green: `lint:raw-strings` (no embedded copy in the primitive), `lint:style-escapes`, `packages/ui` contrast + primitive tests, both apps' typecheck · lint · test, and the web build.

**The primitive (the delta itself)**

- [ ] T001 Add the shared prop fragment to `packages/ui/src/primitives/types.ts`: `SelectItem`
      (`{ value: string; label: string }`) + `SelectOwnProps` (`items` · `value` · `onValueChange` ·
      `ariaLabel` · `disabled`) intersected with the existing `FieldOwnProps`, so a picker declares the
      same field contract as `TextField`.
- [ ] T002 Build the web sibling `packages/ui/src/primitives/select.tsx` around a real `<select>`:
      `useId`-derived label association, `aria-describedby` for `description` + `error`, `aria-invalid`
      when `error` is set, the `field-surface` well, `CONTROL_SIZES` parity with `TextField`, and the
      disabled treatment. Mirror TextField's markup so the two read as one family.
- [ ] T003 Build the native sibling `packages/ui/src/primitives/select.native.tsx`: a field-shaped
      `Pressable` trigger (well material, current label, trailing chevron, `accessibilityRole="button"`
      naming from `label`/`ariaLabel`, `accessibilityState.disabled`) that opens an RN `Modal` option
      list. Each option is a `Pressable` with `accessibilityState.selected`; picking calls
      `onValueChange` and closes; dismissing leaves the value unchanged. This is the first consumer of
      the reserved `tokens.z.dropdown` layer — use it rather than inventing a stacking value.
- [ ] T004 Export `Select` + `SelectProps` from **both** barrels (`index.ts`, `index.native.ts`) beside
      the other field primitives, and the new types from the shared type block.
- [ ] T005 [P] Cover it in `packages/ui/src/primitives/primitives.test.tsx`: label/description/error
      wiring (one `aria-describedby` carrying both), `ariaLabel` naming a labelless control, keyboard
      selection through the native element, and the disabled state.

**Adoption — the three call sites the change names**

- [ ] T006 `apps/web/src/features/revise-split/ui/ReviseControls.tsx` — replace the hand-rolled
      `MoodField` (its `SELECT_CLASS` string, `useId`/`htmlFor` wiring, and raw `<select>`) with
      `Select`, keeping the `MoodDot` beside the label and the `MOODS` item list.
- [ ] T007 `apps/mobile/src/features/revise-split/ui/ReviseControls.tsx` — replace the 13-chip mood row
      (and its `chip*` styles) with the same `Select`. The emotion stays a bounded selection of `MOODS`
      ([W4a][I3]); only the affordance changes.
- [ ] T008 [P] `apps/web/src/features/admin-ai-config/ui/AiConfigSection.tsx` — both selects in
      `CapabilityRow` (provider slot ~L229, model id ~L260) consume `Select`; delete the file's own
      `SELECT_CLASS`. Give the model select the `error` slot it never had, so a rejected id can say so
      beside the control.
