# 05. Change: Per-memory source text at encode time

> A **change proposal** (a WHAT delta) that modifies the already-shipped behavior of [plan/20.encode-usecase](../../plan/20.encode-usecase.md).
> Filled by /cosimosi:create-change through a user interview — a reviewable doc, not a one-line prompt.
> The STEPS live in the job that /cosimosi:create-change-job creates. Write it in English.

## As-is

`Encode` splits a diary into 2–5 episodic memories on event boundaries ([E1][E2]) and the split carries
`{name, mood, neurons}` per memory — that part works and stays.

**What a split memory does not carry is any text of its own.** The encode output schema, the wire
(`ProposedMemory`/`ConfirmedMemory`), and the domain DTO (`ExtractedMemory`) all stop at name + mood + neurons, and
`PersistEncoded` therefore fills every new `EpisodicMemory.current_text` with **the whole diary body**
(`tech/memory-encode.md` §2: "`current_text` = the diary body until reconsolidation rewrites it"). An N-way split
produces N rows holding N identical copies of the entire diary.

Nothing in the PRD authorizes that. §3.2 defines `EpisodicMemory.CurrentText` as "마지막 회상 시 재구성된 서사" and
[R8a] describes how it is _rewritten_, but **neither defines its value before the first recall** — the whole-diary
copy is an as-built decision filling a spec gap, not a stated rule.

Everything representational downstream reads `current_text`, so the gap propagates:

- **Star detail ([R1][D1])** — clicking each of the N stars born from one diary shows the same whole diary.
- **Forgetting ([F1])** — `DecayStageText(currentText, stage, seed)` erases words from the whole diary, N times over.
- **Semanticization ([C7])** — `SemanticizeMemory.CurrentText` is the whole diary, so all N memories get the same
  four-stage gist ladder.
- **변천사 ([R8a])** — `GetProvenance` synthesizes the created/original baseline from `MemoryOrigin.DiaryBody`, so the
  first history entry is the whole diary for every star.

The result contradicts the product's core metaphor — [PRD §2](../../PRD.md) "큰 별 = 기억의 흔적 … 뉴런들의 희소
앙상블", one star = one scene — because each trace carries the entire day.

## To-be

**Each proposed memory carries its own source text: the passage of the diary that memory was laid down from,
preserved in the writer's own words.**

### The text itself

The extractor returns, per memory, the span of the diary that scene occupies. It is **derived from the original, not
composed from it**:

- **Permitted** — repairing a cut edge so a passage does not end mid-clause ("…지하철에 발을 디뎠고," → "…지하철에
  발을 디뎠다."), correcting the writer's typos, and adjusting connective endings/particles that only exist because
  the sentence continued in the original.
- **Forbidden** — substituting a word for a synonym, paraphrasing, summarizing, condensing, reordering, adding a
  transition the writer did not write, or inventing any content. The writer's vocabulary is the writer's.
- **Coverage** — the passages together account for the diary. A sentence that belongs to no scene is a split defect,
  not an editorial choice; the writer's whole entry survives across the N memories.

The passages are ordered as the diary is and do not overlap.

### Fidelity is enforced structurally, not trusted

The [W4a] double defense extends to the new field. Free text cannot violate [I3]/[I5]/[I10] — there is still no
position, color, strength, seed, or time field — but it _can_ silently overwrite the writer's own account, so the
domain verifies it against the diary rather than trusting the prompt:

- Every token of a source text must be traceable to the diary — verbatim, or as an inflectional variant of a diary
  token (same stem, different ending/particle), or as a typo correction within `encode.source_text_typo_max_edit_distance`
  of a diary token.
- Typo corrections are budgeted: at most `encode.source_text_max_corrected_ratio` of a passage's tokens may be
  non-verbatim.
- The union of the passages must cover at least `encode.source_text_min_coverage` of the diary's tokens.

A violation is **repairable** — it re-prompts through `ReviseSplit` within `encode.max_revise_retries`, then
`ErrEncodeRetryExhausted`, exactly like the existing count / semantic-neuron rules. It runs in the use-case (the
`Encode`/`ReviseSplit` enforcement loop) over the diary body it already holds.

**This check constrains the extractor, and only the extractor.** It is deliberately _not_ re-applied at
`PersistEncoded`, because by then a passage may have been edited by the writer — and a writer editing their own
account is not a threat the server defends against. What `PersistEncoded` re-validates is structural: each confirmed
passage is present, non-blank, and bounded in length against the submitted body. The rest of the confirmed split
(count, moods, neuron types, semantic-neuron floor) keeps its existing re-validation. The line is drawn where the
threat is: the model can silently rewrite the writer, so the model is verified; the writer cannot be wrong about
their own words.

### Where it appears

The source text is part of the **preview** ([W2] "이 결과를 사용자가 본다") and is **editable within the write
session** ([W4]), alongside name and mood:

- `SplitDiary` / `ReviseSplit` return `source_text` per `ProposedMemory`; the writing-flow sheet renders it under the
  name and lets the user correct it.
- `LaunchStars` accepts the user-confirmed `source_text` per `ConfirmedMemory`; `PersistEncoded` writes it to
  `current_text` instead of the diary body.
- A user edit is the writer editing their own words and is **not** subject to the fidelity check — that check
  constrains the model, not the person. The Diary stays untouched either way ([I2]).
- The touch edits stay local pure functions, as they are today: **merge** concatenates the two passages in order;
  **divide** cuts the passage at the sentence boundary nearest its midpoint, which is faithful by construction (a
  substring of an already-verified passage). A cut that reads awkwardly is repaired the same way any other proposal
  is — a natural-language `ReviseSplit`, which re-runs the extractor under the full rule set ([W4][W4a]).

### What follows for free

`current_text` becoming per-memory fixes the four downstream surfaces without touching their algorithms: star detail
shows that scene, `DecayStageText` erases words from that scene, the gist ladder compresses that scene, and 변천사의
created/original baseline becomes that scene's passage. **`GetProvenance`'s baseline moves from the Diary body to the
memory's own text** — the immutable Diary remains reachable through "원본 일기 보기" ([D1][D5]), so nothing is lost.

### The spec gap this closes

The PRD gains the missing definition: **`EpisodicMemory.CurrentText`'s initial value is the diary passage that memory
was encoded from** — the writer's words, typo- and ending-repaired only — and reconsolidation rewrites it from there
([R8a]). [E1]/[E2] gain the statement that the split partitions the diary rather than merely labeling it.

## Scope / Non-goals (regression boundary)

**In scope**

- **Contract** — `source_text` on `ProposedMemory` and `ConfirmedMemory` (`proto/cosimosi/memory/v1/memory.proto`,
  regen), `SourceText` on `memory.ExtractedMemory`, and the field in `ai.ExtractOutputSchema()`.
- **Prompt** — the extractor's split and revise prompts state the passage rules (own words, permitted repairs,
  forbidden substitutions, coverage, order, no overlap).
- **Enforcement** — the fidelity + coverage verification in `internal/memory` (domain-pure comparison against the
  diary body), wired into the `Encode`/`ReviseSplit` repair loop and re-checked in `PersistEncoded`.
- **Persistence** — `PersistEncoded` writes the confirmed `source_text` to `current_text`. **No DDL** — the column
  already exists.
- **Provenance** — `MemoryOrigin`/`GetProvenance` synthesize the created/original baseline from the memory's own text
  instead of `DiaryBody`.
- **UI** — the writing-flow proposed-memory card renders and edits the source text (web + mobile, at parity), with
  the i18n strings that needs.
- **Values** — the new `encode.*` keys below, and a raised output budget (see Grounding).
- **SSOT** — PRD §3.2 + [E1][E2][W2][W4][R8a], plan 20, and the consequent statements in plans 27 / 35 / 37 / 40 /
  46; `policy/encode-boundary.md`, `policy/ux/writing-flow.md`, `tech/memory-encode.md`, `tech/ai-worker.md`.

**Non-goals / regression boundary (must NOT change)**

- **[I2] The `Diary` is untouched.** It stays the immutable, byte-verbatim original — written once at launch, never
  edited by this path, and still the sole target of search ([D10]) and export ([W6]).
- **Already-launched memories keep their whole-diary `current_text`.** No migration, no backfill, no LLM re-run. Their
  existing `DecayStages` / `SemanticStages` / provenance rows stay coherent with the text they were generated from —
  rewriting the basis under an already-risen gist ladder is exactly what [C7] forbids. The change applies from the
  next diary forward.
- **The split itself is unchanged** — event boundaries not emotion boundaries ([E1]), `[encode.min_memories,
encode.max_memories]` scenes ([E2]), ≥1 semantic neuron ([E4]), the three neuron types ([E3][E5]), no time neuron
  ([E6]), conservative type-differentiated dedup ([E10]).
- **The [W4a] structural boundary holds.** No position, color, strength, seed, universe-time, or delete field is added
  to the encode schema or the wire.
- **The forgetting, semanticization, reconsolidation, and provenance algorithms are unchanged** — they receive better
  input, not new behavior. `Recall`'s prediction-error compare, `Reconsolidate`'s rewrite of `current_text`, seed
  reshape, and remaining-stage regeneration ([R6][C7]) all stay as-is.
- **No economy, emotion, position, clock, or linking change** ([I3][I5][I6][I10]).

## Acceptance Criteria

1. `SplitDiary` / `ReviseSplit` return a **`source_text` per proposed memory** — the diary passage that memory was
   encoded from — and the writing-flow UI renders it on the proposal card and lets the user edit it within the write
   session, on **both web and mobile** ([W2][W4]).
2. Launching a diary that splits into N memories produces **N distinct `current_text` values**, each the confirmed
   passage for that memory, and **not** the whole diary body. ([E1][E2])
3. The passages are **the writer's own words**: a source text whose tokens are not traceable to the diary — beyond
   inflectional variation and a typo budget of `encode.source_text_max_corrected_ratio` within
   `encode.source_text_typo_max_edit_distance` — is rejected and re-prompted through the existing repair loop, and
   exhausts to `ErrEncodeRetryExhausted` (→ `CodeResourceExhausted`) rather than being persisted. A paraphrase, a
   synonym substitution, or an invented sentence never reaches the database.
4. The passages **cover the diary**: their union accounts for at least `encode.source_text_min_coverage` of the
   diary's tokens, and a split that drops a scene is a repair condition. The writer's whole entry survives across the
   N memories.
5. `PersistEncoded` re-validates each confirmed source text **structurally** — present, non-blank, length-bounded
   against the submitted body — and deliberately does **not** re-apply criteria 3–4, because a passage reaching it may
   be the writer's own edit. The existing re-validation of count / mood / neuron type / semantic-neuron floor is
   unchanged.
6. The four downstream surfaces are per-memory: star detail shows that memory's (decayed) passage, `DecayStages` erase
   words from that passage, the four gist stages compress that passage, and 변천사의 created/original baseline is that
   passage. Two stars from one diary no longer show identical text at any of them. ([R1][D1][F1][C7][R8a])
7. The **[W4a] boundary is intact** — the encode schema and the wire carry no position, color, strength, seed, time,
   or delete field, and the new text field is structurally constrained to the diary's own words, so a prompt injection
   can at most echo the writer back at themselves.
8. **[I2] holds** — the `Diary` row is byte-identical to what the user submitted; export ([W6]) and search ([D10])
   still read the original, and no code path writes to it.
9. **No regression on existing data** — memories launched before this change keep their `current_text`, decay stages,
   gist stages, and provenance unchanged; recall, reconsolidation, forgetting, consolidation, and the universe read
   behave exactly as before for them.
10. SSOT is consistent: the PRD defines `CurrentText`'s initial value, and plan 20, `policy/encode-boundary.md`,
    `policy/ux/writing-flow.md`, and `tech/memory-encode.md` all describe the per-memory passage. `pnpm lint`,
    `pnpm test`, `pnpm vet:api`, `pnpm build:api`, `pnpm typecheck`, `pnpm build:web`, and `pnpm check:gen` pass.

  the diary body"), `tech/ai-worker.md` (the extractor's task knowledge).
- Affected `spec/values.yaml` (`encode.*` — all new keys go here, never hardcoded):
  - `source_text_min_coverage` — minimum fraction of the diary's tokens the passages must jointly account for.
  - `source_text_max_corrected_ratio` — maximum fraction of a passage's tokens that may be non-verbatim.
  - `source_text_typo_max_edit_distance` — maximum per-token edit distance for a non-verbatim token to count as a
    typo correction rather than a substitution.
  - **`max_output_tokens` must be raised, and `ai.per_call_token_cap` with it.** The split output now carries the
    diary redistributed across the memories, so the current `encode.max_output_tokens: 1000` under
    `ai.per_call_token_cap: 1200` would trip on any diary of ordinary length. The job sets both from the intended
    maximum diary length; the existing comment invariant (encode's guard trips before the generic guard) still holds.
