# 06. Change: select primitive for a bounded choice

> A **change proposal** (a WHAT delta) that modifies the already-shipped behavior of [plan/09.design-system](../../plan/09.design-system.md).
> Filled by /cosimosi:create-change through a user interview — a reviewable doc, not a one-line prompt.
> The STEPS live in the job that /cosimosi:create-change-job creates. Write it in English.

## As-is

[tech/design-system.md](../../tech/design-system.md) §4 already names this primitive. It lists
**Select/Menu** under _"Deferred (added when a Phase-4 slice needs them, promote-on-use)"_.

Three call sites have since needed it, and none of them promoted it. Each hand-rolled a `<select>` and
copied the field recipe into a class string of its own:

- `apps/web/src/features/revise-split/ui/ReviseControls.tsx` — the primary-emotion picker
  (`'field-surface w-full rounded-lg px-3 text-base text-text h-10 …'`), carrying a comment that says
  there is no Select primitive.
- `apps/web/src/features/admin-ai-config/ui/AiConfigSection.tsx` — two selects (provider slot, model
  id) sharing one string of its own (`'field-surface h-10 rounded-lg px-3 text-base text-text …'`).

The two strings **already disagree** — one carries `w-full`, the other does not — which is exactly the
drift a primitive exists to prevent in a system whose premise is that appearance is expressed once.

What is missing is not only the look:

- **The field contract is re-derived per site.** `TextField` gives every consumer the label↔control
  association, `aria-describedby` for its description, and `aria-invalid` for its error
  ([design-system.md](../../tech/design-system.md) §5). The emotion picker hand-wires `useId` + `htmlFor`
  to win part of that back; the admin selects have **no error slot at all**, so a rejected
  provider/model has nowhere to say so beside the control.
- **There is no native counterpart.** `apps/mobile/src/features/revise-split/ui/ReviseControls.tsx`
  forks to a row of 13 mood chips with its own selected-state handling. The same domain choice — pick
  one mood — is therefore two unrelated affordances with no shared API, and
  [ARCHITECTURE.md](../../ARCHITECTURE.md) §3.5's "same props, one sibling per platform" rule has nothing
  to hold onto.
- **The stacking layer was reserved and never used.** `tokens.z.dropdown` generates
  `--z-dropdown: 1000` into `theme.gen.css`, and **no code references it** — the token map kept a floor
  for a picker that never arrived.
- **The language documents a rule the system cannot enforce.**
  [design-language.md](../../tech/design-language.md) §6 says fields are recessed wells whose validation
  rides the border and the focus ring. For a picker that rule currently lives in two copied strings
  instead of a primitive, so the next dropdown either re-derives it or drifts again.

Not every absent dropdown is an accident: `AccountProfile.test.tsx` asserts `queryByRole('combobox')`
is **null**, pinning the deliberate decision that the timezone is not chosen from a list. This change
leaves that alone.

## To-be

**A `Select` primitive in `@cosimosi/ui` — one bounded choice, one API, one sibling per platform.**

### The API

Controlled like `Tabs`, and sharing `FieldOwnProps` with `TextField` so a picker sits in a form the way
a text input does:

- `items: readonly { value: string; label: string }[]` — the fixed set, in the order it is offered.
- `value` + `onValueChange(value)` — controlled; the selection stays in the app layer.
- `label` · `description` · `error` · `size` — the `FieldOwnProps` fragment, honored as `TextField`
  honors it.
- `ariaLabel` — required when no visible `label` is given, so the control is never unnamed
  (design-system.md §4).
- `disabled`.

Both barrels export the same API; only the element beneath it differs.

### Web — the platform control, wearing the system's material

The web sibling renders a real `<select>`. Keyboard interaction, type-ahead and the platform's own menu
come with it and are **not re-implemented**; a custom listbox would mean hand-rolling roles, focus and
arrow keys for nothing the product asked for. What the primitive owns is everything the slices are
copying today: the recessed well, the label association, `aria-describedby`, `aria-invalid`, and the
disabled treatment.

### Native — a field that opens a list

React Native has no `<select>`. The native sibling is a **Pressable that reads as a field** (the same
well material, the current label, a trailing chevron) and opens a **modal option list** on press:

- the list marks the current value as selected (`accessibilityState`);
- picking an option reports it and closes;
- dismissing leaves the value unchanged;
- RN `Modal` manages its own focus, which is what `Dialog` already relies on (design-system.md §5).

This affordance was chosen over keeping a chip row: it follows the platform's convention for a form
picker and scales to any number of options, where a chip row becomes a wall.

### What it replaces

All three web call sites consume it. The mobile emotion picker's 13-chip row is replaced by the same
`Select`, which is the point of having one API — but the **editable-surface invariant does not move**:
the surface still offers exactly the fixed `MOODS` set and no scalar control ([W4a][I3]). Both platform
tests are re-asserted against the new control set rather than deleted.

The primitive gets a specimen on **both** review surfaces (`/design` and the native showcase), because
[policy/ux/design-review.md](../../policy/ux/design-review.md) §2 is explicit that a dimension which
cannot be seen cannot be scored.

## Scope / Non-goals (regression boundary)

**In scope**

- `Select` + its native sibling in `packages/ui`, exported from both barrels, with the shared prop
  fragment in `primitives/types.ts`.
- The picker's material owned by the design system (the existing `field-surface`, or a class of its own
  in `base.css` if the recipe needs one).
- Adoption at all three web call sites and the mobile emotion picker.
- Specimens on `/design` and the native showcase; `design-system.md` §4 moves Select from _Deferred_ to
  _Shipped_; `design-language.md` §6 gains the picker's paragraph.
- A §8 re-review round on the dimensions this touches, recorded in this change's job.

**Non-goals — these stay deferred**

- **Multi-select.** No screen needs it; an unused API would be built on a guess.
- **A searchable combobox.** It means hand-rolling listbox semantics and losing what the native
  `<select>` gives for free. If a long option set ever needs filtering, that is its own change.
- **Menu** (action menus), **SegmentedControl**, **Slider/Stepper**, **Drawer** — still
  promote-on-use in design-system.md §4.

**Must NOT change (the regression boundary)**

- **[W4a][I3]** — the writing flow's editable surface stays name / emotion / passage / membership, the
  emotion offered as a bounded selection of `MOODS`, with **no** control that could set position,
  colour, strength or time. Both platform tests keep asserting it.
- The admin console's provider/model semantics and its admin gate
  ([plan 58](../../plan/58.admin-console.md)) — this swaps the control, not what `SetAIConfig` accepts.
- The timezone field stays a non-list control; `AccountProfile.test.tsx`'s combobox-is-null assertion
  holds.
- Web keyboard and screen-reader behavior must not regress — retaining the native element is how.
- No token **values** change, and the writing-flow chrome signed off in
  [job 38](../../jobs/archive/38.2d-ui-design-language.md) keeps its states and rhythm.
- **[I11]** — presentation only. No domain, cache, emotion, strength or layout meaning moves.

## Acceptance Criteria

1. `Select` exists at `packages/ui/src/primitives/select.tsx` + `select.native.tsx`, both honoring one
   API (`items` · `value` · `onValueChange` · `FieldOwnProps` · `ariaLabel` · `disabled`), exported from
   the web and native barrels.
2. The primitive owns the field contract: web associates its `label` with the control and wires
   `aria-describedby` (description) and `aria-invalid` (error); native exposes the same name, value and
   invalid state through accessibility props. A `Select` with no visible `label` is named by
   `ariaLabel`.
3. The web sibling renders a real `<select>` element — keyboard interaction and the platform menu are
   inherited, not re-implemented — and takes its material from the design system, not from a class
   string in a slice.
4. The native sibling is a field-shaped Pressable that opens a modal option list: the current value is
   marked selected, picking reports it and closes, dismissing leaves the value unchanged.
5. Every existing call site consumes it — `features/revise-split` (web + mobile) and
   `features/admin-ai-config` (both selects) — and no select class string remains in `apps/web/src`
   (grep-clean, with `lint:style-escapes` still green).
6. **No regression of [W4a][I3]:** both `ReviseControls` tests still prove the emotion surface offers
   exactly the `MOODS` set and no scalar / date / colour control, re-asserted against the new control
   set.
7. `/design` and the native design showcase each render `Select` in default · disabled · error states
   (plus focus on web), so both review surfaces can score it.
8. `tech/design-system.md` §4 lists Select under **Shipped**; `tech/design-language.md` §6 documents the
   picker (web element + native modal list) as the language's bounded-choice control.
9. A §8 re-review round scores the dimensions this touches (component consistency · web↔mobile parity)
   with every note closed, recorded in the job's ledger.
10. Gates green: `lint:raw-strings` (no embedded copy in the primitive), `lint:style-escapes`,
    `packages/ui` contrast + primitive tests, both apps' typecheck · lint · test, and the web build.
